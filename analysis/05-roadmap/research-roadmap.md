# 后续技术调研路线

本路线只描述调研，不代表开始实现新引擎。

## R1：建立函数语义索引

目标：把 1202 个输出函数按子系统归类，优先命名主循环直接或间接触达的函数。

产物：

- 地址到语义名称映射
- 子系统调用图
- 全局变量用途索引
- 结构体候选布局

完成条件：启动、资源、渲染、输入、剧情、地图、战斗、音频、视频和存档都有明确入口。

## R2：恢复公共容器与压缩规格

目标：先解决多个系统共用的底层格式。

顺序：

1. 已完成 `sub_4399E0` 与 LZO1X 2.10 的 16/16 有效状态对照：20,091 个 TSW 帧逐字节一致，四个合法向量补齐真实流未覆盖状态；损坏输入的安全错误域已明确不同。
2. 已记录全部 4 个直接调用与 11 个包装调用的输入长度、目标容量来源、输出长度和错误策略。
3. TSW、ACT 与 SND 的固定索引和当前样本载荷路径已完成；继续确认 SND 非零类型和 Miles 对非标准 RIFF 边界的实际消费规则。
4. 已恢复 13 个 DAT 样本的外层组织：9 个 MZ 包装文件不走公共解压，另外 4 个 DAT 分属固定表、环境记录、缓存目录和存在性标记；内部业务命令移交对应系统阶段。
5. 已恢复 19 个 ANI、40 份存档及 309 张 LMF 地图的容器边界；LMF 的 1,094 条真实流全部与 LZO 2.10 逐字节一致，CM 末块完整解压后只写前缀的行为已固定。

完成条件已满足：当前主要包条目均有机器目录，全部已知真实压缩流和容器边界均已全量验证。业务命令与字段按 R3–R7 继续恢复。

## R3：恢复 16 位渲染与输入时序规则

目标：确定内部像素格式、核心混合算法、输入边沿和时间推进规则。

重点函数：

- 已闭环 `sub_423400` 像素格式选择链、四条 forward 公式与当前 CM 缓存的 RGB565 实证
- 已闭环 `sub_416D90/sub_4170E0` 的 43 个稀疏槽、RLE/span 物理命令和原始矩形选择方向
- 已闭环普通 copy、饱和加减、覆盖调色、run 边缘、常量覆盖、灰度、邻像素涂抹、`0x14` 的 16 档项式和 `0x1C` RLE 纵向淡出
- 已闭环 `0x08` 的逐像素 coverage composite、原始常量淡出和正反向特殊 run；当前 TSW/ACT 资产链没有 coverage 生产者或 mode `0x08` 命令，RLE 路径不可达
- 已恢复 `0x0C/0x20` 的 10.10 行选择、逐行横移、顶部裁剪差异和静态调用条件；正常生产链不产生 `0x004CDC00` 指针，动态 `0x20` bit 1 恒零，空指针/空槽只保留为强制异常状态合同
- 已闭环 `sub_420490–sub_4207E0` 与 `sub_421FB0`：三/单通道有符号偏移、双 lane packed 运算、overflow-to-zero 双输入查表、除以四灰度、无效计数边界和全部 50 个直接调用
- 已闭环 `sub_435240–sub_436F66` 的 `細明體` GDI 生产、固定 64×64 surface/物理 pitch、非零阈值 1-bit 缓存、原始一/二字节协议和五种软件 footprint；跨平台确定性 glyph-mask oracle/字形源仍待选定
- 已闭环游戏软件 surface、实测 pitch/行偏移、19 条 Lock 后发布地址再立即 Unlock 的全局帧地址路径，以及固定 640×480 操作并存的合同
- 已穷举 32 个 DirectDraw Blt 和 21 个 primary 提交：18 个 NULL RECT、两个战斗动态矩形、一个 Bink `{0,0,639,479}` 固定矩形；原 7 个地址仅为稳态分支代表
- 已确认当前唯一初始化选择 `0x4E22`、`640×480×16` 独占全屏；普通 cooperative 辅助 surface 分支当前不可达；`sub_437AE0` 仅是显示恢复循环
- 已闭环 256-byte 键盘快照、20 条候选/18 条活动归一化记录、四字段状态机、严格 `>150` 的连按链、左键倒计时清零与 451 次静止采样门槛
- 已确认中央状态机没有统一 repeat：方向、菜单/商店和战斗消费者使用不同采样计数谓词，部分分支还保留汇编中的旧 AL 奇偶依赖；77 个 raw query 和 5 个合成 raw-key 写入已目录化
- 已闭环三条 `timeGetTime`、八条 CRT `time`、0/35/70 interval、无符号回绕、拒绝帧 busy poll、接受后不 catch-up、27 个 Sleep 和九类关键等待；当前 EXE 没有多媒体 timer callback API
- 已固定 19 个原程序动态探针、11 类产物和 EXE/DLL/asset/PE 基线；当前工作区没有 Wine/Windows 调试执行后端，实际 framebuffer/glyph/Bink/time 样本待旧参考环境捕获，静态逆向继续推进

完成条件：选定截图可由独立算法逐像素复现；固定设备采样与时钟序列可复现相同输入边沿和 repeat。

## R4：恢复剧情 VM 与 Ani

目标：把 `sub_427920` 从一个 6304 行汇编函数拆成 opcode 规格。

当前已完成一级分派骨架：命令字取低 14 位，两张 PE jump table 覆盖 `1..98` 与 `100..193`，五个表外专用值和全部未映射范围行为已经固定；192 个表项与原 EXE 字节逐项一致。

第一版 198 行物理编码/长度目录也已建立。四个 TALK 文件共纳入 3992 个索引候选；3984 个可接受线性前缀均能无解码错误走到结束或明确的跨窗口转移，累计 58,782 个唯一物理指令记录并观察到 143/198 个显式 opcode。该探针在跨窗口转移处停止，不声称完成运行时图遍历。下一步恢复参数语义、状态读写、等待/让出与错误路径，并递归验证转移目标。

31 个可重载窗口 opcode 的全分支候选图现已补齐：138,988 个窗口上下文节点覆盖 99,092 个唯一物理指令位置并观察到 152/198 个显式 opcode；除四个重复无效 TALK3 根外，所有枚举目标都能继续解码。该图保留条件两侧和 opcode 41 的终止值异常边，仍不是具体游戏状态下的实际轨迹。

逐值人工语义当前完成 opcode 0–124。第五批补齐角色 Talk 字段和状态位、stream/音量、两类批量角色操作、bit30 条件转移、dialog 链及 Scene_Music 表；异常 `FFF0` 查找、16 位 IP 回绕、消费后让出、未读 padding 和 bit0 等待方向均按汇编原样登记。其余 opcode 从第二张一级表的 125 起继续审计。

产物：

- opcode 编号
- 指令名
- 参数格式
- 指令长度
- 状态读写
- 同步/异步行为
- 错误处理

同时恢复 `.Ani` 头部、帧表、压缩块和播放时序。

完成条件：可以离线遍历所有 `TALK*.DAT` 指令，不发生未知 opcode 或越界。

## R5：恢复地图与角色系统

目标：完整说明 `huge.lmf`、`maps.dat`、`path.dat`、`.cm`、`.tsw` 和 `.act` 的组合关系。

完成条件：可以离线还原一个地图的层、tile、对象、角色初始状态和寻路数据。

## R6：恢复战斗与数值系统

目标：拆解 `sub_469D20` 和相关函数，建立战斗阶段、行动队列、伤害、状态、AI、胜负和掉落规格。

完成条件：固定初始状态和随机序列时，每步战斗状态可与原程序对照。

## R7：恢复存档规格

目标：形成字段级存档文档。

完成条件：所有现有存档都能完整解析，重新序列化后仍可被原程序读取。

## 进入实现的条件

至少完成 R1 至 R4，并完成一个地图和一个存档的端到端解析后，再决定正式工程结构和依赖版本。
