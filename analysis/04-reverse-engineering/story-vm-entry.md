# 剧情解释器入口与让出规则

最后更新：2026-08-02

范围：P1.5 顶层契约

本文件不提前替代 P5 的完整 opcode 规格。这里只固定 `0x00427920` 的参数、载入、取指、继续、等待、结束和返回约定。

## 证据范围

- 函数：`0x00427920` 至 `0x0042D4F3`
- 第一跳转表：`0x0042D4F4`
- 第二跳转表：`0x0042D67C`
- 调用者：单帧主循环 `0x0040AA56`
- 实际参数：`0x004B72A0`

函数只有三个机器级返回点：

- `0x00427A4B`：`EAX = 0`
- `0x0042D4D6`：`EAX = 0`
- `0x0042D4F3`：`EAX = 1`

## 状态块

Talk 结束路径以 `rep stosd` 将 `0x004B72A0` 起的 `0x36` 个双字写成 `0xFFFFFFFF`。

因此当前顶层 Talk 状态块大小可确认是：

```text
0x36 × 4 = 0xD8 = 216 字节
```

已确认字段：

- `+0x14`：当前脚本数据偏移/已载入标记。零时进入 Talk 文件载入路径。
- `+0x1E`：Talk 脚本编号。用于选择 `TalkN.dat` 和文件内索引。
- `+0x20`：16 位当前指令偏移。
- `+0x24`：当前 Talk 上下文编号；`0xFFFF` 表示未激活，`0xFFFD` 是特殊上下文哨兵。

这些名称只描述已确认用途，不等同于最终 C++ 结构体字段名。

## 入口条件

### 未激活

若 `word [state + 0x24] == 0xFFFF`，函数直接返回一，不读取 opcode。

### 尚未载入

若 `[state + 0x14] == 0`，函数准备载入脚本。

在载入前，它检查当前主角状态的两个双字低四位。任一非零时直接返回一，本帧不载入。

## Talk 文件定位

`script_id = word [state + 0x1E]`。

文件号和条目号按 2000 分组：

```text
file_number = script_id / 2000 + 1
entry_index = script_id % 2000
filename = Buffer + "Talk" + file_number + ".dat"
```

载入顺序：

1. 打开 `TalkN.dat`。
2. 定位到 `0x200 + entry_index × 4`。
3. 读取一个 32 位条目值到 `[state + 0x14]`。
4. 定位到 `0x200 + [state + 0x14]`。
5. 将全局脚本缓冲区 `0x004B8860` 的 `0x8000` 字节预填为 `0x0C`。
6. 从文件读取脚本块到该全局缓冲区。
7. 设置 `[0x004A9920]` 的 `0x8000` 位。

打开 Talk 文件失败时：

- 同步发送 `WM_DESTROY`。
- 从 `0x00427A4B` 返回零。

## 取指

载入完成或已有脚本时：

```text
instruction_pointer = 0x004B8860 + word [state + 0x20]
raw_word = word [instruction_pointer]
opcode = raw_word & 0x3FFF
```

因此：

- 指令对齐单位至少为 2 字节。
- opcode 是 14 位值。
- 原始指令字的 `0x4000` 和 `0x8000` 两位不会进入 opcode 编号；多个 handler 会单独检查这些修饰位。
- 指令长度不是统一长度。每个 handler 显式同时推进 `[state + 0x20]` 和当前机器指针。

## 顶层分派空间

第一层：

- `1..98` → 第一跳转表
- `99` → 独立分支
- `0` → 默认错误路径

第二层：

- `100..193` → 第二跳转表
- `0x400` → 特殊控制路径
- `0x401` → 特殊控制路径
- `0x402` → 特殊控制路径
- `0x3FFF` → Talk 结束路径
- 其他值 → 默认错误路径

跳转表范围不等于所有编号都具有独立实现；多个编号会共享 handler 或落到默认路径。完整映射属于 P5。

## 同帧继续与让出

解释器在每个 handler 结束后汇合到 `0x0042B0AE`。

该处计算：

```text
continue_now = local_var_28 | ESI
```

- 结果非零：跳回 `0x00427B40`，在同一帧继续取下一条指令。
- 结果为零：先调用 `_AIL_serve@0`，再返回一，让出到下一帧。

这两个继续量由 handler 设置。是否推进指令偏移也由 handler 自己决定。

因此“等待”不是统一 sleep：

- 某些指令先推进 IP，再让出。
- 某些指令在条件未满足时不推进 IP，让下一帧重试同一 opcode。
- 某些指令设置继续量，在同一函数调用中连续执行多条 opcode。

P5 必须为每个 opcode 分别记录这三项，不能只记录参数长度。

## 三个特殊控制 opcode

### 0x400

- `[state + 0x20] += 2`
- 当前机器指针 `+= 2`
- `local_var_28 = 1`
- 进入同帧继续判断

### 0x401

- `[state + 0x20] += 2`
- 当前机器指针 `+= 2`
- `ESI = 0`
- `local_var_28 = 0`
- 正常让出并返回一

### 0x402

- `[state + 0x20] += 2`
- 当前机器指针 `+= 2`
- `ESI = 1`
- 在同一帧继续取指

## Talk 结束：0x3FFF

结束路径执行：

- 清理当前 Talk 相关角色状态。
- 将脚本缓冲区首个 16 位字写为 `0xFFFF`。
- 将全局 `0x004B72A0` 起的 216 字节全部写为 `0xFF`。
- `[0x004CAD24] = 0`。
- `[0x004C9A24] = 0`。
- 进入公共继续/让出判断。

## 默认错误路径

未知或未分派 opcode 会：

- `MessageBeep(0)`。
- 记录当前与上一个 opcode 的诊断参数。
- 进入公共继续/让出判断。

该路径没有统一自动推进 IP。不能在重写时私自把未知 opcode 当作两字节 NOP。

## 返回值

### 返回一

包含多种语义：

- 状态块未激活。
- 载入前置条件未满足。
- handler 正常等待或让出。
- Talk 正常结束后的让出。

所以返回一不能单独解释成“成功完成”。

### 返回零

已确认两类：

- Talk 文件打开失败并同步发送 `WM_DESTROY`。
- 某个 fatal handler 设置 `[0x004B7A9C]` 的关闭请求位 `0x04`。

### 调用者行为

单帧主循环调用 `0x00427920` 后不检查 `EAX`。

剧情系统的实际控制效果来自：

- 状态块字段。
- 指令偏移。
- 全局位标志。
- 战斗请求和模式请求。
- 关闭请求。

重写时不能只靠函数返回值驱动剧情状态机。
