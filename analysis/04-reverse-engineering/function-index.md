# P2 函数语义索引

最后更新：2026-08-02

状态：P2.1–P2.4 已完成；P2.5 调用约定、参数宽度和返回值消费复核进行中

## 证据规则

完整汇编仍是唯一逻辑真值。

IDA 的函数边界、名称、调用者列表和独立输出只用于建立导航索引。一个函数只有在实际汇编分支、参数、返回值和内存读写经过复核后，才会在本文件中取得“已确认”语义名。

## P2.1 清单核对结果

IDA 的两个导出清单登记了 1486 个唯一地址。它们在导出清单内部可以无缺口地分为：

- 1197 个独立反编译输出。
- 5 个独立汇编回退输出。
- 284 个被导出器标记为 library function、未生成独立函数文件的地址。

关系为：

```text
1197 decompile
   5 disassembly-fallback
 284 skipped library function
----
1486 unique function addresses
```

`function_index.txt` 中的 1202 项正好等于 1197 个反编译文件加 5 个汇编回退文件。

五个回退函数是：

- `0x00402F80`：反编译器返回空。
- `0x00427920`：函数大小 23508 字节，超过导出限制。
- `0x0043A610`：反编译器返回空。
- `0x00446700`：反编译器返回空。
- `0x00469D20`：函数大小 16918 字节，超过导出限制。

`.export_progress` 是追加式状态日志，不能直接按每行计数。它包含 1486 个唯一地址，其中 289 个地址有多条记录；按每个地址的最后一条状态归并后，结果同样是 1197 / 5 / 284。

P2.5 回到完整汇编后发现，以上“无缺口”只适用于导出器自己的清单，不代表完整函数边界：完整汇编有 1215 个 `proc` 标记，只有 1191 个与 1486 地址清单重合；另有 24 个只见于汇编的 `proc`，同时有 295 个清单地址没有展开 `proc`。24 个仅汇编标记又分成 16 个被函数化的跳转表/公共尾片段和八个真实间接菜单回调，不能一概视为独立函数。

完整集合关系、`RETN` 清理量和返回值消费初筛见 `evidence/function-abi-triage.md`。P2.1 的 `function-catalog.tsv` 保留为“导出清单目录”；P2.5 的 `function-abi-candidates.tsv` 才是两个导航来源的 1510 地址并集，并且仍需人工判定真实边界。

## 机器可读目录

机械清单位于：

- `inventory/function-catalog.tsv`

生成脚本位于：

- `tools/build_function_catalog.py`
- `tools/build_function_abi_inventory.py`

TSV 每一行对应一个唯一函数地址，字段为：

- `address`：统一为八位大写十六进制虚拟地址。
- `ida_name`：IDA 导出名称；不自动视为真实业务名。
- `export_status`：`decompile`、`disassembly-fallback` 或 `skipped`。
- `exported_file`：独立输出相对于 `swd3.exe_export_for_ai/` 的路径。
- `fallback_or_skip_reason`：回退或跳过原因。
- `ida_called_by_count`：IDA 导出记录的直接调用者数量。
- `ida_call_count`：IDA 导出记录的直接内部调用目标数量。

最后两个计数只用于导航，不能代替汇编调用图。间接虚表调用、导入 API、尾调用和 IDA 未识别边界可能不在计数中。例如 `0x00437AE0` 的 IDA 内部调用数为零，但汇编中存在 DirectDraw 虚表调用。

## 语义记录格式

P2.2 起，每个经过审查的函数记录以下字段：

- 地址与 IDA 名称。
- 证据级语义名。
- 所属子系统。
- 调用者和关键被调者。
- 调用约定、参数宽度与返回值。
- 关键全局状态读写。
- 可信度和证据文档。

可信度只允许：

- 已确认：相关机器级行为已经回查汇编。
- 局部已确认：只确认当前阶段所需的入口或出口契约。
- 待确认：只有导航价值，不形成实现规格。

## P2.2 顶层直接调用覆盖结论

完整汇编中的实际 `call sub_*` 目标数为：

- `0x00409EC0`：8 个。
- `0x0040A0D0`：20 个。
- `0x0040A570`：37 个。
- 三组去重后：59 个。

IDA 独立输出头部的 `9 / 23 / 38` 只保留为导航信息，不能覆盖实际汇编调用集合。59 个目标已经按启动、生命周期、输入、存档、文件映射、普通世界、剧情、菜单、战斗、渲染、音频、视频和资源释放分类。

逐地址覆盖和仍然保留的未知项见：

- `evidence/top-level-direct-call-coverage.md`

P2.3 从这些入口读写的关键全局地址继续建立读者、写者和状态所有权。
