# P2 全局状态与所有权索引

最后更新：2026-08-02

状态：P2.3 已完成并复核；P2.4 候选结构体偏移审计进行中

本文件记录已复核的地址、直接读者、直接写者和状态所有权。业务名称只有在写入点与消费点共同核对后才固定。

完整汇编是唯一真实依据。IDA 伪码只辅助定位。

“所有权”不等于只有一个函数可以写入。这里区分：

- 生产者：提出请求或建立初始状态。
- 协调者：消费请求并完成顶层迁移。
- 子系统驱动器：在活动期间更新或结束状态。
- 观察者：只读取，不取得修改权。

机器可读摘要位于 `inventory/global-ownership.tsv`。对单值全局，读者/写者列记录直接符号交叉引用；对结构块或全局对象，该列只记录已复核的基址或字段入口，不声称覆盖所有寄存器别名访问。字段级偏移已转入 `structure-candidates.md` 和 `inventory/structure-fields.tsv`。

## 0x004CC2AC

状态：已确认是全局帧执行门控；旧称“手动暂停/运行门控”范围过窄，已修正

- `WinMain` 进入消息循环前写一。
- 非零时继续检查 `0x004B7A9C` 和 `0x004BABA4`，满足条件才执行 `0x0040A570`。
- 零时不执行正常帧；若 `0x004B7CAC == 1`，显示暂停提示，否则 `Sleep(0)`。
- `WM_KEYUP` 的 F8 路径在零和一之间切换本值。
- 视频活动位 `0x20` 非零时，F8 只能将本值强制写一，不能进入暂停。
- 剧情 VM opcode `180` 在 `0x0042D044` 写零，因此脚本也能暂停顶层帧执行。
- 隐藏调试对话框路径在 `0x00403363` 临时写零，取消时在 `0x00403397` 写一；对话框回调 `0x0040F8E3` 也恢复为一。

直接写者：`0x00402F80`、`0x00409EC0`、`0x0040A0D0`、`0x0040F890`、`0x00427920`。

直接读者：`0x00409EC0`、`0x0040A0D0`、`0x0040A570`。

所有权结论：平台消息循环是协调者；F8、剧情 VM 和调试对话框都是生产者。新引擎不能把该状态私藏在键盘输入模块中。

## 0x004B7A9C

状态：已确认是位标志集合；各位业务名尚未全部确认

在 `WinMain` 空闲路径中：

- 位 `0x20`：视频对象活动。转入 `0x00484950` 解码/呈现，再执行 `0x0040CF10` 音频维护；`0x00484920` 释放视频对象并清除此位。
- 位 `0x01`：不执行单帧主循环，调用 `Sleep(0)`。
- 位 `0x04`：顶层关闭请求。单帧在音频维护后据此同步发送 `WM_CLOSE`；`WM_DESTROY` 也用它决定是否执行完整资源释放。
- 位 `0x10`：单帧函数入口立即返回；设置来源和业务名待后续交叉验证。
- 位 `0x02`：由剧情 VM 设置、`0x004154A0` 清除；当前只确认它跨帧抑制一条资源/界面路径，最终业务名待确认。
- 位 `0x10` 的写入和清除集中在 `0x004118B0` 的同步选择/装载流程；失败出口同时设置关闭位 `0x04`。

其他位由 `0x0040A570`、`0x00427920` 和更多函数使用，不能只凭一处读访问命名整个字段。

直接写者：`0x00402F80`、`0x004118B0`、`0x004154A0`、`0x00424EF0`、`0x00425BE0`、`0x00427920`、`0x004490C0`、`0x0044C160`、`0x00484730`、`0x00484920`、`0x00484950`。

协调读者：`0x00409EC0`、`0x0040A0D0`、`0x0040A570`。

所有权结论：这是进程级生命周期位集合，不属于世界、视频或输入中的任何单一模块。新引擎应拆成明确的关闭请求、视频活动、临时操作抑制等状态，并在顶层协调器统一组合。

## 0x004BABA4

状态：已确认是平台或异步过渡期间的单帧抑制条件；旧称“显示状态切换抑制”范围过窄

- 非零时，`WinMain` 不调用 `0x0040A570`，而是 `Sleep(0)`。
- 初始化 `0x00424B90` 写零；多处模式切换代码写一。
- `sub_40AB50(0)` 在停用/最小化窗口时写一。
- `sub_40AB50(1)` 恢复并重新绑定图形对象后写零。
- 初始化失败、剧情 VM 的一条异步资源路径和 `0x0044C160` 的过渡出口也会写一。

直接写者：`0x00402F80`、`0x0040AB50`、`0x00424B90`、`0x00427920`、`0x0044C160`。

直接读者：`0x00409EC0`、`0x0040A570`。

所有权结论：`WinMain` 只消费该门控；显示生命周期是唯一已确认的零/一完整恢复者，其他生产者用于阻止过渡期间继续推进普通帧。

## 0x004ACBA0

状态：已确认是 P1 各画面分支提交给 DirectDraw 的公共源 surface

- 普通世界、战斗、特殊模式、暂停、高优先级画面和视频的 `Blt` 都读取本值作为源 surface。
- `0x0040AB50(1)` 对该 surface 调用虚表 `+0x6C` 恢复，并交给 `0x00416D30` 重建关联状态。

- `0x00424EF0` 在 DirectDraw 初始化成功后调用 `0x00437B60(640, 480)`，其返回值是本地址的唯一直接写入来源。

所有权结论：平台图形初始化/销毁拥有 surface；各游戏模式只取得绘制或提交使用权。SDL3 重写不需要复刻 COM 指针，但必须保留统一源画面及各分支提交顺序。

## 0x004B8740

状态：已确认是顶层特殊模式请求/活动复合字段；模式 `3..6` 的最终业务名待恢复

- 零表示普通世界路径。
- 非零时跳过 `0x00427300`、`0x00402F80` 和剧情解释器。
- 低 28 位 `1..6` 进入模式跳转表；模式二调用 `0x0044EA60`，其余已列模式调用 `0x00439FD0`。

- `0x20000000` 是商店返回/重建位；`0x20000002` 使商店重建界面后继续模式二。
- 低 28 位保存模式编号。
- 已确认请求值包括 `0x80000001`、`0x80000002`、`0x80000003`、`0x80000004`、`0x80000005`；其他动态写入必须保留原位组合，不能只按常量表实现。

直接读取者：`0x00402F80`、`0x0040A570`、`0x004149B0`、`0x00439FD0`、`0x0043A610`、`0x0044EA60`。

直接写者：

- 菜单/模式驱动器：`0x00439FD0`、`0x0043E770`、`0x00441590`、`0x00443BD0`、`0x004441A0`、`0x004453F0`、`0x00446700`、`0x004490C0`、`0x0044A250`、`0x0044C160`。

所有权结论：这是跨剧情、世界、菜单和商店的共享状态总线。剧情/世界提出请求，单帧按低位模式分派，具体模式驱动器清除初始化位、写返回位或结束为零。新引擎应建立显式模式迁移接口，不能允许任意模块直接写一个裸整数。

## 0x004B72A0–0x004B7377

状态：已确认是 216 字节 Talk/剧情执行状态块；P2.4 前不固定完整结构体

- 块大小由两条独立清零/失效路径确认：`0x36` 个双字，即 `0xD8` 字节。
- `0x00425B50` 初始化时把全块写为 `0xFFFFFFFF`。
- 剧情 VM 的 `0x3FFF` 结束路径在 `0x0042D47F–0x0042D48C` 再次把全块写为 `0xFFFFFFFF`。
- `0x0040A570` 把块首地址作为唯一参数传给 `0x00427920`。

已确认字段：

- `+0x04`、`+0x08`：事件/角色触发时写入的地图空间位置；更精确单位留待 P2.4。
- `+0x10`：触发对象状态/标志快照；完整位语义待确认。
- `+0x14`：当前脚本数据偏移或未载入标记；零时剧情 VM 进入 Talk 文件载入。
- `+0x1E`：16 位 Talk 脚本编号。
- `+0x20`：16 位当前指令偏移。
- `+0x24`：16 位 Talk 上下文；`0xFFFF` 未激活，`0xFFFD` 地图事件，普通角色路径写实际上下文值。

直接生产者包括 `0x00402F80`、`0x0040F160`、`0x004120B0`、`0x00427300`、`0x0043BFC0` 和 `0x00446700`。它们按世界碰撞、鼠标交互、模式事件等不同入口写入字段。

直接协调/消费函数包括 `0x0040A570` 和 `0x00427920`。`0x0040AFF0`、`0x0040C130`、`0x00412930`、`0x00413910`、`0x00413FE0`、`0x004149B0` 等普通世界绘制或交互函数读取部分上下文字段。

注意：剧情 VM 会把块首地址继续传给多个下游函数，所以只统计文本符号的直接交叉引用并不足以恢复全部别名访问。P2.4 必须结合 `[base+offset]` 的寄存器数据流继续补齐。

所有权结论：世界、角色和菜单事件是状态生产者；剧情 VM 拥有脚本装载、指令偏移和结束失效；单帧调度只负责门控与调用，不拥有块内业务字段。

## 0x004BABA8–0x004C83A7

状态：已确认是最多 256 条、每条 216 字节的角色记录区；字段恢复留待 P2.4

- 固定步长为 `0xD8`，已经由 `0x00402F80`、`0x00427300`、`0x004120B0` 和剧情 VM 多处地址运算共同确认。

## 普通世界四个移动分量

状态：四个普通世界移动分量均已确认；此前关于 `0x004A948C` 跨模式复用的结论已撤销

- `[0x004B7518]`：玩家与镜头共同使用的 X 分量。
- `[0x004B7920]`：玩家与镜头共同使用的 Y 分量。
- `[0x004A9488]`：只加入玩家坐标的 X 分量。
- `[0x004A948C]`：只加入玩家坐标的 Y 分量。

`0x004120B0` 的实际计算是：

```text
player_x += [0x004AB2D0] × ([0x004B7518] + [0x004A9488])
camera_x += [0x004AB2D0] × [0x004B7518]

player_y += [0x004AB2D0] × ([0x004B7920] + [0x004A948C])
camera_y += [0x004AB2D0] × [0x004B7920]
```

`0x00402F80` 根据方向输入和碰撞结果写入分量；`0x004120B0` 消费、边界校正并在帧尾更新；剧情/地图辅助函数 `0x0042DAF0`、`0x0042E280`、`0x0042E5A0`、`0x0042E790` 可以注入或清零移动。

## 0x004A9490–0x004A949F

## 0x004AB384–0x004AB783

状态：已确认是 0x400 字节、8192 位的通用状态位集合

- 位编号 `n` 使用字节索引 `n >> 3` 和掩码表 `n & 7`。
- `0x0040DC50(n)` 查询，`0x0040DC80(n)` 设置，`0x0040DCB0(n)` 清除。

- `0x0040E0B0` 清空全部 0x400 字节后建立默认位。
- `0x004070A0` 的地图/存档装载路径以整块形式读取或恢复它。
- 剧情 VM 和角色更新既使用公共位函数，也存在按字节直接访问。

所有权结论：这是跨剧情、地图、输入和菜单的持久状态位仓库。新引擎应提供集中位访问接口，同时为已确认位逐步增加强类型别名；不能把整个集合归入输入系统。

## 0x004ACBD0–0x004ACCCF

状态：已确认是 64 个 32 位通用整数变量；第零项是玩家银币

- 总大小为 `64 × 4 = 0x100` 字节。
- 剧情 VM 的成组 opcode `29/181` 写值、`30/182` 加值、`31/183` 减值且负数钳制为零；索引必须小于 64。
- `0x00405500` 另有对应的赋值、加、减和比较操作，其中加值路径可钳制到 1000。
- 初始化 `0x0040E0B0` 把第零项设为 100；新游戏特定初始化 `0x00449D80` 可设为 500。
- 隐藏调试热键把第零项增加 1000。
- 商店总价、余额检查和成交扣款只访问第零项，因此 `[0x004ACBD0 + 0]` 可确认是玩家银币。

所有权结论：剧情 VM 拥有通用变量数组的规则级修改；商店只拥有第零项上的交易操作。不能把整个 64 项数组命名成“金钱”。
