# B1 `compat + platform_sdl3 + app` 工作包

状态：`module_closed_pending_oracle`

当前单元：已移交 B2；只保留原程序动态差分阻塞

## 1. 范围与非范围

本工作包只实现进程/窗口平台端口、顶层空闲分派、单帧互斥调度、失焦恢复编排和退出顺序。对应汇编根为 `0x0048A740`、`0x00409EC0`、`0x0040A0D0`、`0x0040A570`、`0x0040AB50`、`0x00424B90` 和 `0x004251B0`。

当前 17 个游戏自有 `runtime_platform` 函数以及一个外部 CRT 根边界的逐项去向见 [`runtime-platform-implementation-map.tsv`](../inventory/runtime-platform-implementation-map.tsv)。`external_boundary_platform_adapted` 表示原静态 CRT 私有实现不复制，只保留由现代 hosted runtime/SDL main 承担的游戏可见入口和退出合同。`implemented_with_deferred_ports` 表示游戏函数由 B1 负责的汇编可见控制流、状态写入、调用位置和返回合同已经映射，端口内部按冻结所有权交给后续模块；两种状态都只算 B1 映射，不算后续模块完成，也不算最终 1:1 差分完成。`partial` 或 `pending` 才不算 B1 实现映射完成。

剧情 opcode、世界移动、模式 UI、战斗内部、资源解析、输入状态机、像素算法和音视频后端语义不在 B1 实现；它们先由明确的请求/结果或假端口占位，之后按冻结模块顺序替换。

## 2. 汇编合同

- 空闲分派：帧门开启时依次检查视频 `0x20`、空闲抑制 `0x01`、过渡抑制，再进入单帧；帧门关闭时只有显示值精确等于一才呈现暂停。
- 单帧入口：进程位 `0x10` 先直接返回；显示为零时 `Sleep(0)`；之后才采样秒/毫秒时钟。
- 有效帧互斥：高优先级模式排除战斗/世界；战斗排除世界/剧情；无战斗时再按特殊模式值选择世界或模式。
- 剧情执行要求帧门非零，并且过渡抑制、特殊模式、战斗和高优先级状态全为零。
- 特殊模式低 28 位 `2` 进入商店，`1/3/4/5/6` 进入共享处理，其他值没有上述 handler。
- 战斗返回 `0/2/3` 分别走三条明确出口；所有其他非零值直接保持活动并结束本帧。
- 未提前返回路径在音频维护后检查进程位 `0x04`，再同步请求关闭。
- 显示停用和恢复都先查询 `0x2711` 显示后端；对象不存在时直接返回且不改变任何生命周期状态。

完整证据见 [`main-frame-0040a570.md`](../evidence/main-frame-0040a570.md)、[`winmain-00409ec0.md`](../evidence/winmain-00409ec0.md)、[`wndproc-0040a0d0.md`](../evidence/wndproc-0040a0d0.md)、[`presentation-lifecycle.md`](../evidence/presentation-lifecycle.md) 和 [`runtime-platform-basic-block-review.md`](../evidence/runtime-platform-basic-block-review.md)。

## 3. 接口与状态所有权

- `compat` 只提供精确宽度整数和值类型，不持有可变状态。
- `app` 拥有帧执行门、进程标志、过渡抑制、模式/战斗请求和顶层生命周期。
- `platform_sdl3` 拥有 SDL 窗口、renderer、texture 和宿主事件；不持有游戏模式状态。
- 世界、剧情、模式和战斗以后返回生产者自己的同步结果值；`app` 在汇编对应时点消费，生产者不反向依赖 `app`。

## 6. 平台兼容隔离

SDL3 smoke 创建可调整大小的 960×720 初始窗口，而不是复刻旧 DirectDraw 独占 `640×480×16` 模式。这是只为现代系统启动的 `platform_adapted` 外壳；兼容核心仍持有 640×480 RGB565 framebuffer，SDL 以 4:3 letterbox 等比呈现并把鼠标转换回原逻辑坐标。Windows 模态拖拽缩放期间由 `SDL_EVENT_WINDOW_EXPOSED` event watcher 在主线程重绘。后续所有画面规则和分支提交时点继续按汇编实现；此适配不授权修改任何游戏逻辑 BUG。

当前 SDL3 事件适配如下：

- `SDL_EVENT_WINDOW_MINIMIZED/MAXIMIZED/RESTORED` 分别翻译为原尺寸值 `1/2/0`；焦点丢失/获得翻译为激活值 `0/1`。
- `SDL_EVENT_KEY_UP` 只把 Esc、F8、P 翻译为原虚拟键值；Alt+Enter 的 key-down 翻译为原系统键分支。
- 左键按下时从 SDL 当前鼠标键和 Shift/Ctrl 状态重建旧 `WM_LBUTTONDOWN.wParam` 位图，因此原程序要求精确值 `0x1B` 的异常分支没有被改成普通左键。
- 原 `ShowWindow(..., 6)` 明确映射为 SDL 最小化请求；恢复映射为 SDL 恢复请求和 640×480 客户区尺寸请求。SDL 窗口操作是异步平台请求，不改变核心状态写入顺序。
- SDL 不暴露跨平台的 Win32 `DefWindowProcA` 或同一组 `WM_SYSCOMMAND`；四个完整值的原合同保留在核心 UT，宿主默认行为作为 `platform_adapted` 边界记录。
- SDL 事件队列排空后调用同一个 `run_idle_iteration` 合同，不另造固定刷新循环：视频位、两个抑制门、活动单帧和暂停呈现仍由汇编恢复的谓词选择。活动帧再经 `run_frame_preparation`，把 SDL3 的 64 位单调毫秒截成原 32 位域后执行最短间隔门；拒绝帧不呈现、不主动睡到下一帧。当前 smoke 的接受帧/暂停端口只重新上传黑色 RGB565 framebuffer；它只验证平台接线，不代表任何游戏帧逻辑或渲染模块已经完成。

`src/platform/sdl3/main.cpp` 已在同步启动初始化返回后、事件循环前调用两次独立取秒的播种编排。两个实际 RNG 算法仍属于 B3，当前端口只保留调用位置而不伪装成算法实现。单实例探测、原始命令行尾、音频、字体、战斗、截图和各业务模块端口目前仍是 B1 smoke 占位或待接线；它们不表示对应模块已经实现。SDL3 翻译与空闲循环源已使用真实 SDL 3.4.12 头文件和 Windows LLVM 编译。应用配置优先使用已安装的 SDL3 3.4+；找不到时由 CMake `FetchContent` 获取固定的 `release-3.4.12`，只构建静态 SDL3 并关闭其测试、示例和安装规则，避免 smoke EXE 额外依赖未部署的 SDL3 动态库。`core` 配置不查找也不下载 SDL3。

启动自定义消息现在进入资源驱动的 SDL 模态启动页；背景与悬停图不再是占位画面。当前存档扫描仍返回无存档，启动与悬停声音为空音频端口，辅助文本对话框回调尚未接线。它们分别等待持久化、音频和输入/UI 模块，不能据此宣称完整启动业务已经恢复。

`0x004303D0` 的 RGB565 framebuffer 到 BMP 写入仍是 render 端口，不能把
编号循环 UT 当成像素文件已经验证。
