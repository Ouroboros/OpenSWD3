# 战斗更新入口与返回值契约

最后更新：2026-08-02

范围：P1.6 顶层契约

本文件不提前替代 P7 的完整战斗规格。这里只固定 `0x00469D20` 的入口、指令分派、指令指针推进、等待方式和对主循环可见的返回值。

## 证据范围

- 战斗入口：`0x00469D20` 至 `0x0046DF35`
- 跳转表：`0x0046DF38` 至 `0x0046E088`
- 战斗帧/呈现核心：`0x00453200` 至 `0x00453570`
- 结果状态写入：`0x0045E5D6`、`0x0045E5E5`、`0x0045E5F8`、`0x0045E646`
- 调用者：单帧主循环 `0x0040A879`

IDA 因函数大于其单函数导出上限，只为 `0x00469D20` 生成了汇编回退文件。本文结论已回查完整汇编；伪码不构成结论依据。

## 调用前门控

主循环只在 `[0x004CAEB4] != 0` 时调用 `0x00469D20`。

进入该分支后：

- 本帧不会执行普通世界更新。
- 本帧不会执行剧情解释器。
- 战斗入口的返回值由主循环立即消费。
- 无论返回哪一个值，本次战斗分支随后都直接结束当前主循环调用。

因此 `0x00469D20` 是战斗活动期间的单帧顶层入口，不是一次调用完成整场战斗的函数。

## 入口取指

函数没有栈参数。入口实际执行：

```text
ESI = [0x0053CE84]
raw_command = sign_extend(word [ESI])
dispatch_index = raw_command + 1
```

随后把 `dispatch_index` 作为无符号值与 `0x54` 比较，并通过 `0x0046DF38` 的 85 项跳转表分派。

可确认：

- `[0x0053CE84]` 是当前战斗指令的机器指针。
- 指令操作码是有符号 16 位值。
- 跳转表覆盖原始操作码 `-1..83`。
- 原始操作码 `0`、`7`、`32`、`38` 与越界值都进入默认出口。
- `-1` 有独立的战斗清理/结束 handler。

这只是顶层分派范围。各操作码的参数、业务名和状态写入留待 P7 逐项恢复。

## 指令指针推进

没有统一的隐式 `IP += 2`。

各 handler 直接改写 `[0x0053CE84]`，已观察到的固定推进量包括：

- `+2`
- `+4`
- `+6`
- `+8`
- `+0x0A`
- `+0x0C`
- `+0x10`
- `+0x16`

另有 handler 根据指令内字段计算下一地址，或通过 `0x0046E1E0` 改变控制位置。

默认出口不推进 `[0x0053CE84]`。多个等待型 handler 也会在条件未满足时保持当前指令不变，让下一帧再次执行同一条指令。

重写时必须为每个战斗操作码单独记录长度、跳转和等待规则，不能建立统一定长指令假设。

## 返回值闭包

对 `0x00469D20` 的全部机器级 `retn` 反查 `EAX`，再反查其唯一向上传递结果的 `0x00453200`，可确认返回值集合严格为：

```text
{ 0, 1, 2, 3 }
```

没有确认到其他对主循环可见的返回值。

### 返回一

绝大多数 handler 明确执行 `mov eax, 1` 后返回。

少数表面上执行 `mov eax, esi` 或 `mov eax, ebx` 的出口，其对应路径已先把该寄存器固定为一，所以结果仍是一。

默认出口也固定返回一，并且不自动推进指令指针。

在操作码一的等待路径中：

1. 调用 `0x00453200`。
2. 若返回一，直接从默认出口返回一。
3. 不执行完成清理。
4. 不把当前指令指针推进四字节。

因此返回一的机器级含义只能固定为“战斗仍由该入口继续驱动”；它不等价于“当前操作码已经完成”。

### 返回零

已确认三个来源：

- 操作码 `-1`：清理两组战斗对象，调用 `0x0045B630` 和 `0x0046E260`，然后返回零。
- 操作码 `31` 的边界错误路径：显示消息框后返回零。
- 操作码 `1` 调用 `0x00453200`，下层返回零后，入口完成清理、推进四字节并原样返回零。

`0x00453200` 的零来自两条汇编路径：

- `0x0045D8F0` 返回零时直接上送零。
- `0x0045E580` 在其已确认条件下把 `[0x0053BDC8]` 写零，函数尾返回该值。

### 返回二

`0x00453200` 先把 `[0x0053BDC8]` 初始化为一。

`0x0045E580` 在 `0x0045E5D6` 明确把该值写为二；若后续两个归零条件都未触发，`0x00453200` 从 `0x00453569` 返回二。

操作码一的完成路径把它保存到 `[0x0053CCE8]`，执行清理并原样上送给主循环。

当前只确认数值和传播链。其最终业务名称留待 P7，不以主循环后续动作反向猜名。

### 返回三

`0x00453200` 在调用 `0x0040DC50(0x11)` 后检查结果。

若结果非零，`0x00453489` 明确执行 `mov eax, 3` 并返回。操作码一的完成路径随后把三原样上送给主循环。

当前只确认数值和传播链。其最终业务名称留待 P7。

## 主循环对结果的消费

`0x0040A570` 对四个值的实际处理如下。

### 结果一

- 不进入零、二、三的专用分支。
- 保持 `[0x004CAEB4]` 非零。
- 直接结束本帧。

### 结果零

- 清零 `[0x004CAEB4]`。
- 根据保存的地图字段选择恢复或重载路径。
- 执行战后地图恢复相关调用。
- 直接结束本帧。

### 结果二

- 清零 `[0x004CAEB4]`。
- 将 `[0x004B8740]` 写为 `0x80000004`。
- 清理相关全局状态。
- 直接结束本帧。

### 结果三

- 清零 `[0x004CAEB4]`。
- 进入地图重映射/恢复路径。
- 直接结束本帧。

这里的“地图恢复”和“模式四”只描述主循环的可见写入与调用。零、二、三的游戏设计名称仍未确认。

## P1 结论

P1 可以安全依赖以下战斗接口契约：

```text
活动门控 [0x004CAEB4] != 0
  → 调用 0x00469D20 执行一帧战斗状态机
  → 1：战斗保持活动
  → 0 / 2 / 3：清除战斗活动门控并走各自顶层后续分支
  → 当前帧不再执行世界或剧情更新
```

不能在 P1 阶段写死的内容：

- 85 项跳转表中每个操作码的业务名。
- 零、二、三对应的最终胜负/退出术语。
- 战斗对象结构体类型。
- 行动、伤害、AI、随机数和结算规则。

这些内容必须在 P7 继续以汇编逐项恢复。
