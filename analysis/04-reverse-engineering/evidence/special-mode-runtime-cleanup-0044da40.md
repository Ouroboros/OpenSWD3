# 释放特殊模式运行资源并清空工作区链 `0x0044DA40`

状态：`platform_adapted`

## 1. LST锁

权威范围为`swd3.exe.lst`的`0x0044DA40..0x0044DA9E`，40行，无外部FUNCTION CHUNK。唯一caller为尚待审计的`0x0044E9D0`。callee `0x0044D5A0`已关闭并直接复用；三个`0x004885A0`调用由资源释放窄端口表达。

## 2. 严格顺序

1. 以当前外部owner调用释放；返回后立即把该owner清零。
2. 释放D920建立的第一帧缓冲。
3. 释放第二帧缓冲。
4. 把两个帧缓冲owner清零。
5. 以44-dword工作区首项地址直接调用D5A0链清理：每条记录先把next发布为新head，再释放名称owner和记录。
6. 链完整结束后，才把44个dword全部清零。

指向工作区首项的独立head绑定不清除；其目标内容被清零后仍指向同一固定工作区。

## 3. typed-stop

工作区链出现已释放节点环时，D5A0在即将重复读取处停止。此前三个资源owner已释放并清零，已访问记录也已按名称owner→记录顺序释放；但44-dword最终清零不执行，当前链head保留重复节点。

释放端口即使收到零owner也照常调用，不能用modern空值判断跳过原三次释放。

## 4. 验证

UT覆盖两节点链：三个资源释放、两个节点各两次释放、head归null、44个dword清零和固定head绑定保留。自环测试验证三个资源先清、首节点释放一次、head仍指向该节点且工作区哨兵不清。
