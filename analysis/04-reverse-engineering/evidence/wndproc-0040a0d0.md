# 窗口过程汇编证据：0x0040A0D0

状态：已从原 EXE 字节逐分支复核

来源：`swd3.exe`

SHA-256：`0bac897a7557735b22607d8c8f0a79a3e7ae7729deb56593fd91c21e10baee0c`

函数范围：`0x0040A0D0` 至 `0x0040A533`

数据范围：跳转表位于 `0x0040A538` 至 `0x0040A567`

提取命令：

```text
objdump -d -M intel --start-address=0x40a0d0 --stop-address=0x40a570 swd3.exe
```

## 1. 前置文本输入过滤器

函数首先查询内部位编号 `0x50`：

```text
0x0040A0EB → sub_40DC50(0x50)
```

该位为零时直接进入普通消息分派。

该位非零时，以 `0x004CACD8` 为对象调用 `0x00438B50(hWnd, Msg, wParam, lParam)`。这个下游函数处理 `WM_KEYDOWN`、`WM_CHAR`、输入法状态和字符编辑。

- 下游返回非零：继续普通消息分派。
- 下游返回零：窗口过程直接返回一，不调用 `DefWindowProcA`。

## 2. 消息分派表

`0x0040A14F` 至 `0x0040A163` 对消息 `1..28` 使用两级跳转表。

实际非默认项：

- `0x0001` `WM_CREATE` → `0x0040A1D7`
- `0x0002` `WM_DESTROY` → `0x0040A1FA`
- `0x0005` `WM_SIZE` → `0x0040A16A`
- `0x001C` `WM_ACTIVATEAPP` → `0x0040A1B1`

范围外另有：

- `0x0101` `WM_KEYUP` → `0x0040A229`
- `0x0104` `WM_SYSKEYDOWN` → `0x0040A40E`
- `0x0112` `WM_SYSCOMMAND` → `0x0040A386`
- `0x0201` `WM_LBUTTONDOWN` → `0x0040A433`
- `0x0404` 应用自定义初始化消息 → `0x0040A45F`

其他消息进入 `DefWindowProcA`。

## 3. WM_CREATE

`0x0040A1D7` 将当前 `HWND` 写入 `0x004C9A1C`，然后调用 `0x00425B40`。

若返回零，则同步发送 `WM_DESTROY`。但当前二进制中的 `0x00425B40` 只有：

```asm
mov eax, 1
ret
```

因此这个失败分支在当前 EXE 中不可达。随后仍进入 `DefWindowProcA`。

## 4. WM_DESTROY

先查询内部位编号一：

- 若该位非零，调用 `0x004251B0` 执行资源释放。
- 若该位为零，但 `[0x004B7A9C] & 0x04 != 0`，也执行同一释放函数。
- 其他情况跳过该释放函数。

之后无条件调用：

```text
CoUninitialize()
PostQuitMessage(0)
```

最后仍调用 `DefWindowProcA`。`WinMain` 随后从 `GetMessageA == 0` 路径返回零。

## 5. WM_SIZE 与 WM_ACTIVATEAPP

两条路径都要求内部位编号一非零，否则只进入默认窗口过程。

### WM_SIZE

按 `wParam` 原值分派：

- `1`、`3`、`4` → `sub_40AB50(0)`
- `0`、`2` → `sub_40AB50(1)`
- 其他值不调用

`sub_40AB50(0)` 的汇编行为包括：

- 释放/暂停多个图形对象。
- `ShowWindow(hWnd, 6)`。
- `[0x004B7CAC] = 0`。
- `[0x004BABA4] = 1`。

`sub_40AB50(1)` 的汇编行为包括：

- `ShowWindow(hWnd, 9)`。
- `SetWindowPos` 到 `0,0,640,480`。
- `[0x004B7CAC] = 1`。
- 重建或重绑多个图形对象。
- 完成后 `[0x004BABA4] = 0`。

因此这两条调用分别是停用/最小化与恢复显示路径。

### WM_ACTIVATEAPP

- `LOWORD(wParam) == 0` → `sub_40AB50(0)`
- `LOWORD(wParam) != 0` → `sub_40AB50(1)`

## 6. WM_KEYUP

### 视频播放期间的 Esc

若 `[0x004B7A9C] & 0x20 != 0` 且 `wParam == 0x1B`，调用 `0x00484920`。

`0x00484920`：

- 释放 `0x0053D070` 指向的视频对象。
- 将该指针写零。
- 清除 `[0x004B7A9C]` 的 `0x20` 位。

因此 `0x20` 位可确认表示该视频对象处于活动状态。

### F8 暂停

当 `wParam == 0x77`：

- 视频活动位 `0x20` 为零时，将 `[0x004CC2AC]` 在零和一之间切换。
- 视频活动位 `0x20` 非零时，强制 `[0x004CC2AC] = 1`。

结合 `WinMain` 在该值为零时绘制“遊戲暫停  按F8繼續遊戲”，可确认 F8 把 `0x004CC2AC` 当作暂停/运行开关。P2.3 的完整写入交叉引用进一步证明该地址是更广义的全局帧执行门控：剧情 VM 和调试对话框也能改写它。

### P 截图

只有同时满足以下条件才执行：

- 内部位编号一非零。
- `[0x004B7A9C] & 0x01 == 0`。
- `wParam == 0x50`，即 P。
- 可用磁盘空间结果大于 `0x40` MiB。

路径随后：

- 分配 `0x800` 字节文件名缓冲。
- 调用 `MessageBeep(0)`。
- 从 `%sScrnShot\%05d.bmp` 的编号零开始查找未占用文件名。
- 调用 `0x004303D0(framebuffer, 640, 480, filename)` 保存画面。

编号上限比较立即数为 `0x1869E`。本文不把异常边界美化成新规则。

## 7. WM_SYSKEYDOWN

仅处理 `LOWORD(wParam)` 的低字节等于 `0x0D`，即系统键路径中的 Enter。

- `[0x004B7CAC] == 1` → `sub_40AB50(0)`
- 其他值 → `sub_40AB50(1)`

因此该路径在原程序中切换停用/最小化与恢复显示状态。处理后仍进入 `DefWindowProcA`。

## 8. WM_SYSCOMMAND

当 `wParam` 精确等于以下任一值时，窗口过程直接返回一，不调用默认窗口过程：

- `0xF130`
- `0xF140`
- `0xF170`
- `0xF090`

比较前没有执行 `wParam & 0xFFF0`。重写若追求行为一致，必须保留“精确比较”这一事实，不能先替原程序修正。

## 9. WM_LBUTTONDOWN

仅当视频活动位 `0x20` 非零且 `wParam == 0x1B` 时，调用 `0x00484920` 释放视频对象。

`WM_LBUTTONDOWN.wParam == 0x1B` 并非常见组合，但汇编确实如此比较。当前只记录，不改写为更合理的条件。

## 10. 自定义消息 0x404

这是 `WinMain` 在窗口创建后同步发送的初始化消息。

按顺序执行：

1. `PlaySoundA` 播放资源 `0x78`，标志为 `0x42007`。
2. 调用 `0x00424390` 写入 16 个默认按键 dword。旧 IDA/FLIRT 名称把它误识别为 `__cfltcvt_init`；完整函数体和四个游戏调用者证明该名称错误。
3. 调用 `0x00425040` 初始化工作目录、路径配置，并创建 `Save`、`Data`、`Music`、`ScrnShot`、`Video` 目录。
4. 清除内部位编号 `0x12`。
5. `0x00409C10` 扫描 `save\0.sav` 至 `save\98.sav`。
6. 若至少存在一个存档，设置内部位编号 `0x12`。
7. 打开资源模板 `0x6B` 的模态对话框，过程地址为 `0x00424440`。

对话框返回值处理：

- 返回 `1`：调用 `0x00424910`，它继续调用主初始化 `0x00424B90(hWnd)`；随后重置一组开局状态并调用 `0x00406D30`、`0x00409A10`。
- 返回 `2`：调用 `0x00424910`，进入同一主初始化，但不执行上述额外状态重置。
- 返回 `6`：同步发送 `WM_DESTROY`。
- 其他值：不执行上述三条路径。

这些数字路径已确认；“新游戏”“读档”等业务名要与后续主循环和对话框控制交叉验证后再固定。

## 11. 返回规则

除两个特例外，所有专门处理的消息最终仍调用 `DefWindowProcA`，并返回其结果。

特例：

- 前置文本输入过滤器返回零时，窗口过程直接返回一。
- 四个被拦截的 `WM_SYSCOMMAND` 值直接返回一。

## 12. 当前实现映射

以下宿主无关分支已经进入 `include/openswd3/app/`、`src/app/` 及其对应
`tests/unit/app/` 测试，并按上述汇编常量、状态写入和调用顺序验证：

- `WM_SIZE`、`WM_ACTIVATEAPP` 与系统 Enter 的显示切换选择；
- 前置文本输入位、下游调用门和“下游返回零才消费”的反向结果语义；
- 四个系统命令的完整值拦截；
- Esc、F8、P 和左键异常比较路径；
- 截图五位十进制文件名、逐候选音频维护/打开/关闭顺序，以及上限全占用时覆盖 `99997.bmp` 的原始行为；
- `WM_DESTROY` 的总销毁门、COM 反初始化与退出消息顺序。

SDL3 的尺寸、焦点、键盘、左键和关闭事件翻译已写入
`src/platform/sdl3/event_translation.cpp` 并接入 smoke 主循环，但因当前环境
缺少真实 SDL3 头文件与规定编译器，该部分仍是
`implemented_pending_toolchain`。

该根函数仍为 `partial`：`0x00438B50` 的编辑/IME 内部语义归 B3 输入模块
替换当前端口；`0x004303D0` BMP 写入端口以及 Win32 默认宿主分派的
跨平台边界仍未闭合，不能据此宣称整个 `0x0040A0D0` 已实现。
