# DAT 文件族、MZ 包装头与原始偏移读取规格

最后更新：2026-08-02

状态：13 个当前 DAT 样本已分类；9 个 MZ 包装文件的外层布局和全部直接加载公式已按汇编复核

来源：`swd3.exe` 完整汇编与工作区原始 DAT 样本

完整汇编是唯一真实依据。IDA 伪码只辅助定位。

## 结论修正

此前把 `FIGTALK/LEVEL/MAPS/MON/PATH/TALK1..4` 开头的 `MZ` 视为工具误判，并推测这些文件或其块统一进入 LZO1X 解压。该结论错误，现已撤销。

这九个文件确实具有结构完整的 DOS MZ 风格头；头部声明长度正好是 `0x200` 字节，页数和末页字节数可以逐个精确重建文件大小。它们并不是由游戏当作程序执行，而是以 `0x200` 后的载荷作为原始相对偏移数据库、标记流或内存映像直接读取。

已闭环的 `0x004399E0` 全部调用环境中没有这九个文件的加载器。对应读取路径也没有间接进入该解压器。因此：

- 共同的 `MZ` 头不等于共同的内部业务格式。
- 共同的 `.DAT` 后缀不等于共同的压缩格式。
- 这九个当前文件的外层加载路径不执行 LZO 解压。
- `Fame.dat`、`Env.dat`、`Data/mcache.dat` 和 `swd3_dvd.dat` 又是四种单独用途，不能并入 MZ 文件族。

## 九个 MZ 包装文件

九个文件的 DOS 头字段一致，只有文件大小字段不同：

| 偏移 | DOS 字段 | 当前共同值 | 含义 |
|---:|---|---:|---|
| `+0x00` | `e_magic` | `MZ` / `0x5A4D` | MZ 签名 |
| `+0x02` | `e_cblp` | 各文件不同 | 最后一页有效字节数 |
| `+0x04` | `e_cp` | 各文件不同 | 512 字节页数，向上取整 |
| `+0x06` | `e_crlc` | 0 | 无重定位项 |
| `+0x08` | `e_cparhdr` | `0x20` | 头长 `0x20 × 16 = 0x200` 字节 |
| `+0x0A` | `e_minalloc` | 0 | 当前共同值 |
| `+0x0C` | `e_maxalloc` | `0xFFFF` | 当前共同值 |
| `+0x0E..+0x17` | `SS/SP/checksum/IP/CS` | 全零 | 当前共同值 |
| `+0x18` | `e_lfarlc` | `0x001E` | 重定位表偏移；项数为零 |
| `+0x1A` | `e_ovno` | 0 | 当前共同值 |
| `+0x1C` | 第一个保留字 | 1 | 该文件族共同的自定义值 |
| `+0x1E..+0x1FF` | — | 全零 | 固定头部填充 |
| `+0x200` | — | 各文件载荷 | 原程序实际使用的数据基址 |

文件长度由头部精确给出：

```text
size = (e_cp - 1) * 512 + (e_cblp != 0 ? e_cblp : 512)
```

当前九个样本全部满足该公式，且 `e_cparhdr * 16 == 0x200`。这不是只因前两个字节碰巧为 `MZ` 而产生的识别结果。

原加载器同时也没有验证这些字段。它直接使用硬编码的 `0x200`；所以重写的资产读取器应识别并校验原样本，1:1 核心语义则不能虚构“原程序会拒绝损坏 MZ 头”的分支。

逐文件大小、所有头字段和 SHA-256 见 `../inventory/dat-files.tsv`。

## 汇编确定的读取拓扑

### `MAPS.DAT`

`0x0040F174–0x0040F1B5`：

1. `0x0040F174` 取得文件大小。
2. `0x0040F17E` 减去 `0x200`。
3. 按剩余大小精确分配内存。
4. `0x0040F19A` 定位到文件 `0x200`。
5. 把整个剩余载荷原样读入 `dword_4C9A10`。

没有块头、压缩长度或解压调用。载荷中的 32 位值作为相对载荷基址的偏移使用。例如 `0x0040F1D1–0x0040F1D8` 读取 `base + u32(base+0x10)`，再消费该目标的 16 位字段。`MAPS.DAT` 的内部对象、地图和角色字段仍归 P6 恢复；P3 已确定其外层是原始载荷内存映像，不是统一 LZO 流。

### `PATH.DAT`

`0x0040F094–0x0040F0F3` 打开并映射整个文件，包括 `0x200` 字节头。消费者明确采用：

```text
relative = u32(mapped_base + 0x200 + path_id * 4)
stream   = mapped_base + 0x200 + relative
```

`0x00405529–0x00405535`、`0x00405B3F–0x00405B50` 和 `0x0040D2B8–0x0040D2D4` 都直接形成该地址。流由 16 位命令字解释，不先解压。

当前样本的 `payload[1] == 0x0C88`，恰为 `802 × 4`；机器目录据此列出槽 `0..801` 的样本切片。槽零的值为 `0x64`，正常路径编号是否会使用零仍由调用域决定，不能把样本推导的 802 写成原函数安全边界。

### `TALK1.DAT..TALK4.DAT`

`0x0042E490–0x0042E582` 以剧情编号选择文件和偏移：

```text
file_number = floor(story_id / 2000) + 1
slot        = story_id % 2000
relative    = u32(file + 0x200 + slot * 4)
stream      = file + 0x200 + relative
```

函数从目标请求读取 `0x8000` 字节到剧情缓冲区，随后由剧情解释器消费。它不检查槽范围、相对偏移或记录长度。

当前样本中，TALK1、TALK2、TALK4 的槽一值分别能给出 `1202`、`701`、`1101` 个双字的首段样本索引跨度。TALK3 没有同样的自描述边界，机器目录按汇编的 `% 2000` 可寻址域探测 2000 个位置，其中大量位置是 `0xFFFFFFFF` 或越界值。该探测只记录原地址公式的结果，不宣称所有 2000 个位置都是有效物理条目。

剧情 opcode、单条记录终止方式和跨记录跳转属于 P5；本阶段不把脚本字节误写成压缩块。

### `FIGTALK.dat`

`0x0046E129–0x0046E189` 的目标公式为：

```text
relative = u32(file + 0x200 + id * 4)
stream   = file + 0x200 + relative
```

`0x0046E18B–0x0046E1C6` 分配并清零 `0x8000` 字节，再请求固定读取 `0x8000` 字节。当前 `payload[0] == 0x04B4 == 301 × 4`，所以当前首段索引恰好有 301 个不同且在文件内的目标。

函数的正常战斗入口传入一基编号；汇编仍没有在本函数内验证范围。最后一个流的有效长度也不是固定 `0x8000`，实际由后续脚本终止语义决定。

### `MON.DAT`

该文件有两条不同索引拓扑。

`0x00476DB0` 的定义流：

```text
relative = u32(file + 0x200 + id * 4)
stream   = file + 0x200 + relative
```

它清零 `0x400` 字节缓冲区、请求固定读取 `0x400` 字节，要求首个 16 位命令为 `1000`，然后解释到命令 `5`。名称和说明的 `$$` 终止复制、`0xA4` 定义快照等字段已另见 `item-node-mon-dat.md`。

`0x00476A80` 的辅助流先读取 `payload[1]` 作为二级表根：

```text
root     = u32(file + 0x204)
relative = u32(file + 0x200 + root + id * 4)
stream   = file + 0x200 + relative
```

它同样清零并读取 `0x400` 字节，但要求首命令为零，再解释到命令 `5`。当前 `root == 0x1AEC`，根处首偏移为 `0x2244`，两者相差 `470 × 4`；因此当前二级表样本可列出 470 个在文件内的目标。

机器目录还列出 payload 起点至辅助根前的 1723 个双字作为“主索引前段样本”。这是由当前 `payload[1]` 切出的物理区间，不是原函数的范围检查；原函数接收 16 位编号并直接寻址。

### `LEVEL.DAT`

`0x00477300–0x00477359` 与 `0x00477472–0x004774CB` 使用相同公式：

```text
entry_file_offset = 0x70 + 4 * (level + 100 * group)
relative          = u32(entry_file_offset)
stream            = file + 0x200 + relative
```

正常调用把对象/队员序号加一作为 `group`，所以 `group == 1` 时表起点恰为 `0x200`。每组跨度固定为 100 个双字。加载器分配并清零 `0x400` 字节后固定读取同样大小；首命令必须为零，命令 `5` 结束。

当前 `payload[0] == 0x0648 == 402 × 4`，机器目录因此列出首段 402 个双字，并按每 100 个映射为组号和组内编号。这个样本跨度也不替代汇编缺失的范围检查。

## 固定读取窗口是行为的一部分

`FIGTALK/TALK` 请求 `0x8000` 字节，`MON/LEVEL` 请求 `0x400` 字节。`FIGTALK/MON/LEVEL` 在读取前先把整个分配区清零，但随后不根据实际读取字节数裁切解析视图，也不从相邻索引值计算记录长度。

这意味着原程序依赖“终止命令 + 预清零尾部”的组合，而不是安全的 `[offset,next_offset)` 记录切片。初步重写不得把它们自动改造成按下一偏移截断的现代容器，因为这会改变损坏资源、短读和某些尾部流的可见行为。必要的现代安全隔离必须放在兼容边界并对原样本证明等价。

## 另外四种 DAT

### `Fame.dat`

`0x00409CE0` 分配并清零精确 `0x400` 字节，对编号 `1..500` 把 16 位值写到 `buffer + id*2`，然后完整写出 1024 字节。`0x00409DD0` 完整读回 1024 字节，再按相同编号范围恢复。

因此当前格式是 512 个物理 `u16` 槽，其中槽零和槽 501..511 不在这两个循环的业务编号域内。存档载入函数 `0x00477F10` 调用公共解压器处理的是存档内部的 Fame 块，不是磁盘 `Fame.dat`。两者不得混淆。

### `Env.dat`

`0x00423B74–0x00423DB7` 使用最大 `0x1000` 字节临时缓冲。当前布局以 `0xFFFFFFFF` 开头，随后是 16 个全局字节、一个 32 位参数、6 个字节参数、16 字节迁移/保留区，以及从 `+0x2E` 开始的两个 NUL 终止字符串和尾随字节。

若旧文件不以 `0xFFFFFFFF` 开头，`0x00423BB0–0x00423BC2` 会把原内容向后移动 4 字节并进入迁移分支；迁移会把 `+0x1E` 起部分字段清零。它不是 MZ 数据库，也不压缩。

当前样本的两个字符串后为字节 `02 01`。`0x00423FB0` 使用第一个尾随字节，第二个不在该读取路径消费；当前写入路径 `0x00423D83–0x00423D8C` 会把最后一字节写零，因此当前样本的末字节一可能来自其他版本或其他生产路径。该差异保留为样本事实，不擅自“修复”文件。

两种布局、旧版迁移 BUG、写回不截断行为和当前样本的逐字节实现验证见 [`legacy-environment-00423af0-00423fb0.md`](legacy-environment-00423af0-00423fb0.md)。

### `Data/mcache.dat`

`0x00426944–0x0042699D` 读取整个文件，用 `file_size >> 4` 得到记录数；每条记录为四个 32 位字段：地图编号、缓存字节数、使用计数、槽号。当前文件为 `24 × 16 = 0x180` 字节，槽 0/1 分别登记地图 24 和 81。

该文件只是 `Data/<slot>.cm` 的目录和淘汰状态。`.cm` 生成路径确实会调用公共解压器，但不能据此把 `mcache.dat` 自身称为压缩流。

### `swd3_dvd.dat`

`0x0041197C–0x004119E5` 只构造光盘/路径候选并检查该文件是否存在，从不打开读取其内容。当前 384 字节内容对该 CD 检查函数没有语义；重写若移除旧光盘检查，应作为启动/新系统兼容例外记录，而不是把这 384 字节猜成游戏数据库。

## 1:1 重写约束

- 不再把九个 MZ 包装文件送入 LZO 解压器。
- 相对偏移必须以文件 `+0x200` 载荷为基准；`PATH` 的映射基址仍包括整个文件头。
- `TALK` 文件选择必须保留 `/ 2000` 与 `% 2000`；不得按当前有效项数钳制剧情编号。
- `LEVEL` 必须保留 100 项组跨度和文件偏移 `0x70` 的原公式。
- `MON` 的主定义表和 `payload[1]` 二级表不能合并成一个现代数组。
- 保留固定窗口读取、预清零、终止命令和原调用顺序；不以“下一偏移”替换原解析边界。
- 原加载函数没有范围检查。实现阶段可以在隔离层防止宿主进程内存破坏，但必须证明所有原资产有效调用产生相同字节、相同命令顺序和相同失败结果。
- `Fame.dat` 的原始 1024 字节表、存档内 Fame 压缩块、`mcache.dat` 目录和 `.cm` 压缩内容是四个不同层次，不得因名称相关而复用错误解析器。
