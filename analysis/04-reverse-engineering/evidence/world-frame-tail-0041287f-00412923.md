# 世界帧动画层与视口恢复（`0x0041287F..0x00412923`）

状态：`assembly_exact`、`unit_verified`；尚未 `runtime_integrated`、`original_diff_verified`

本文只以 `swd3.exe.lst` 的机器码和指令为行为真值，恢复 `sub_4120B0` 在普通世界呈现、
角色快照更新之后的最后两个状态单元。IDA 全局名只用于地址定位。

## 1. 地图动画层状态

`0x0041287F..0x004128DA` 使用七个 32 位单元：

| 地址 | OpenSWD3 字段 | 已证明的作用 |
|---:|---|---|
| `0x004CC2DC` | `cycle_counter` | 每次外层世界帧调用递增的有符号比较计数器 |
| `0x0049E0BC` | `cycle_interval` | 从地图配置记录 `+0x08` 读取并限制为至少 1 的循环间隔 |
| `0x004B7940` | `frame_count` | 地图 tile 层帧数 |
| `0x004B7944` | `frame_index` | 当前 tile 层帧索引 |
| `0x0049E0C0` | `frame_direction` | 通常为 `+1/-1` 的折返方向 |
| `0x004B7A98` | `tile_layer_stride` | 地图宽乘高，即一帧 tile 索引数量 |
| `0x004B873C` | `tile_layer_offset` | 底图读取时叠加到 tile 索引位置的当前层偏移 |

地图装载尾部 `0x0040C743..0x0040C772` 把 stride 设置为宽乘高，把 counter 设置为 1，
把 frame index 和 layer offset 清零。`0x0040C537` 把 direction 设置为 1。间隔还会被
原程序的按键路径在 `1..64` 内调整；这不改变帧尾算法。

## 2. 精确推进算法

机器顺序不能写成常见的取模动画：

```text
cycle_counter = wrapping_i32(cycle_counter + 1)
if signed(cycle_counter) < signed(cycle_interval): return
if frame_count == 1: return

frame_index = wrapping_u32(frame_index + bits(frame_direction))
cycle_counter = 0
if unsigned(frame_index) >= unsigned(frame_count):
    frame_direction = frame_direction == 1 ? -1 : 1
    frame_index = wrapping_u32(frame_index + bits(frame_direction) * 2)
tile_layer_offset = wrapping_u32(tile_layer_stride * frame_index)
```

方向变化来自原来的 `DEC → NEG → SBB → AND 2 → DEC`。它不是普通的一元取反：旧值恰好
为 1 时得到 -1，任何其他 32 位值都得到 1。实现按这个位级条件处理。

以下原始边界也保留：

- `frame_count == 1` 时，达到阈值后直接返回，已经递增的 counter 不清零；
- `frame_count == 0` 没有保护，会经过无符号越界和折返，产生 `frame_index = UINT32_MAX`
  等异常状态；
- counter 的 `INC`、frame index 的加法和 layer offset 乘法全部按低 32 位回绕；
- 阈值比较是有符号 `JL`，frame 边界比较是无符号 `JB`，两者不能统一成同一种比较。

## 3. 选择序列结束后的视口恢复

`0x004128DF..0x0041291D` 在函数返回前检查两个门：

1. `word [0x004ACE70] == 0xCFCF` 时不恢复；这是选择序列的空槽哨兵；
2. 地图 ID `[0x004A9A10] == 0x16` 时也不恢复。

其余情况把先前保存的 left/top 写回相机矩形，再用 32 位回绕加法构成固定 640×480：

```text
left   = [0x004A93E4]
top    = [0x004A992C]
right  = left + 640
bottom = top  + 480
```

前置函数 `0x004148F0` 在选择序列活跃时先保存当前 left/top，再按序列中的有符号坐标增量
滚动整个矩形。剧情 opcode 63 建立序列并保存初始相机，opcode 64 只把序列重新填成
`0xCFCF`；因此这里是选择序列驱动的帧后视口恢复，不是通用相机夹值或新格式行为。

## 4. 实现与验证

`advance_legacy_world_tile_layer_animation` 和
`restore_legacy_world_viewport_after_selection_scroll` 位于独立 frame-tail 单元。UT 固定：

- 阈值前不推进、`INT32_MAX → INT32_MIN` 与有符号比较；
- 单帧 counter 不清零；
- 中间帧、上界折返和下界无符号折返；
- 非规范 direction 的原始映射、零 frame count BUG 和乘法回绕；
- 空选择、地图 22 两条恢复门，以及 640×480 坐标加法回绕。

Linux Clang `core` 131/131、Windows LLVM `app` 135/135 CTest 通过。该单元尚未接入
完整 `0x004120B0` runtime coordinator。动态差分需要时只准备 Frida spawn 工具并等待
用户执行，不由开发流程启动原版。
