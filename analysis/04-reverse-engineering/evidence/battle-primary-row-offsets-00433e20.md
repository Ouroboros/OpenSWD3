# 战斗绘制对象主行偏移表重建 `0x00433E20`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 范围与调用

权威LST函数范围为`0x00433E20..0x00433E8C`，入口`proc`至`endp`连续，没有外部`FUNCTION CHUNK`。

函数只有两个直接caller：

- `0x00433C40`；
- `0x00433DC0`。

两处都以`row_stride = 0x500`、`row_count = 0x300`调用，即为768行建立1280字节步长的主行偏移表。

两个caller当前都未进入现代实现，因此没有既存opaque callback可回收。后续关闭caller时必须直接调用本typed入口。

## 2. thiscall ABI与对象切片

ECX指向旧战斗绘制对象，两个栈参数依次为：

1. signed 32位行步长；
2. signed 32位行数。

对象切片：

- `+0x0B40`：主行偏移表指针；
- `+0x0B48`：主行步长；
- `+0x0B4C`：主行数。

现代`LegacyBattleRenderGeometry`用独占数组、`primary_row_stride`和`primary_row_count`映射该切片。

IDA把函数标为返回`int`。完整LST显示：

- 分配失败返回EAX零；
- 分配成功且行数小于等于零时返回EAX零；
- 正行数成功填充后，EAX等于行数；
- 若乘法回绕造成表容量小于循环写入域，typed-stop的兼容EAX保留到达原越界写入前已经递增的行索引。

两个直接caller都不立即消费EAX；`0x00433DC0`会短暂透传，唯一上层随后覆盖。typed结果仍显式记录`legacy_return_value`。

## 3. 旧存储释放 `0x00433E20..0x00433E41`

LST顺序：

1. 读取`[this+0x0B40]`；
2. 指针非零时调用CRT free；
3. free返回后把`[this+0x0B40]`清零；
4. 指针原本为零时直接跳到申请。

现代独占数组在申请前先`reset()`。可注入分配器测试在进入allocate时反查状态，证明旧表已经清空。

旧步长与旧行数此时不变。分配失败路径不会清理或重写它们。

## 4. 32位申请大小与指针发布 `0x00433E41..0x00433E5F`

函数把行数载入EDI，以`lea eax,[edi*4]`计算申请字节数。该乘法只保留32位低位，不检查signed符号或溢出。

随后：

1. 调用CRT malloc；
2. 无论结果是否为空，先把返回指针写入`+0x0B40`；
3. 测试该指针；
4. 空指针立即退出。

因此：

- 行数`-1`申请`0xFFFFFFFC`字节；
- 行数`0x40000001`只申请4字节；
- 行数零仍调用零字节malloc，其返回可以成功或失败；
- 分配失败时主表保持空，旧步长和旧行数保持原值。

现代分配器接收精确`u32 requested_bytes`，返回独占数组与实际word容量。默认适配器使用未初始化`new (nothrow) u32[]`，测试适配器可稳定构造成功、失败、零字节和乘法回绕域。

## 5. 成功后的元数据发布 `0x00433E5F..0x00433E75`

只有分配指针非零后，函数才：

1. 读取行步长到EDX；
2. 清EAX为零；
3. 测试signed行数；
4. 写`+0x0B48 = row_stride`；
5. 写`+0x0B4C = row_count`；
6. 行数小于等于零时立即退出。

元数据写入发生在行数测试的跳转之前，所以零行和负行的成功分配都会发布新步长与新行数，只是不进入填充循环。

## 6. 逐行填充 `0x00433E75..0x00433E8A`

正行数路径：

- EAX为已递增的1基行计数；
- ECX为当前字节偏移，初始零；
- 每轮都重新读取`[this+0x0B40]`到EBX；
- 随后`inc eax`；
- 写`table[eax - 1] = ecx`；
- 以32位回绕执行`ecx += row_stride`；
- signed比较`eax < row_count`决定是否继续。

循环内没有callee或其他可重入点。现代状态每次写入都从对象重新取得独占数组，保持原对象owner边界。

正常固定caller结果：

- 第0行为`0`；
- 第1行为`0x500`；
- 第`0x2FF`行为`0xEFB00`；
- 返回EAX为`0x300`。

## 7. 乘法回绕与typed-stop

原代码只按回绕后的字节数申请，但循环按原signed正行数写入。例如`row_count = 0x40000001`：

1. 旧表已释放；
2. 申请字节数回绕为4；
3. 成功后发布新步长和巨大正行数；
4. 第一项写入合法；
5. 第二轮EAX先递增为2，随后在第二项写入破坏分配边界。

现代实现不提前拒绝该输入。它保留释放、申请、指针发布、元数据发布、第一项写入和第二轮EAX递增，仅在原第二项写入点返回`write_out_of_range`。此时：

- 表仍由对象持有；
- 第一个偏移仍为零；
- 新步长和新行数已发布；
- `legacy_return_value == 2`。

这遵循“只在原实际写入点typed-stop并保留此前副作用”，不伪造成功状态。

## 8. 双向追溯

LST到C++：

- `0x00433E20..0x00433E41`映射为旧独占数组释放；
- `0x00433E41..0x00433E5F`映射为行数乘4回绕、申请及指针先发布；
- `0x00433E5F..0x00433E75`映射为成功后步长/行数发布和signed非正门；
- `0x00433E75..0x00433E8A`映射为指针重读、索引递增、偏移写入、步长回绕累加及signed循环；
- `0x00433E8A..0x00433E8C`映射为EAX残值返回和callee清理参数。

C++到LST：

- `requested_bytes`只对应`lea [edi*4]`低32位；
- `allocation_failed`只对应malloc返回空；
- `write_out_of_range`只隔离原表写入的内存破坏域；
- 独占数组、步长、行数分别对应`+0x0B40/+0x0B48/+0x0B4C`；
- 每个元数据变化和表项变化均有对应LST写指令；
- 没有新增行数夹值、清零、成功返回或预先范围拒绝。

完整正向与反向追溯未发现未解释基本块、额外副作用或遗漏出口。

## 9. 测试

LST独立测试覆盖：

- 三行正常填充及步长加法回绕；
- 固定caller的768行、1280字节步长结果；
- 旧表先释放后申请；
- 分配失败只清表指针并保留旧元数据；
- 零字节成功分配后发布新元数据且不写表；
- 负行数保留回绕申请大小且不写表；
- 巨大正行数乘4回绕后的第一项前缀与第二项写入typed-stop；
- 各出口的申请字节数与EAX兼容返回。

本函数只消费整数参数与堆分配，没有适用的物理游戏资产读取。固定状态直接来自两个权威LST caller。

定向battle聚合测试通过。

## 10. 动态差分

当前没有可用原版战斗绘制对象堆表捕获后端，`original_diff_verified`为`blocked_runtime_oracle`。该阻塞不改变完整LST、分配前缀、回绕域、typed实现和固定caller状态已经闭环的结论。
