# 输入归一化、连按与重复语义

最后更新：2026-08-04

状态：核心状态机、当前绑定、鼠标坐标、左键抑制、静止检测、原始键查询与合成写入已闭环

完整汇编是唯一真实依据。IDA 伪码只用于导航；本结论以 `swd3.exe.asm` 的指令、调用点和数据访问为准。

## 结论

原程序的输入不是“SDL/Win32 事件直接变成 pressed/held/released 三个布尔量”。它有两层可变状态：

1. `0x004B8748` 起的 256 字节键盘快照，以及同一 wrapper 内的 DirectInput 键盘、鼠标对象和鼠标绝对轴基准。
2. `0x004B7CB0` 起最多 20 条、每条 16 字节的归一化记录；其中 18 条每次更新，记录 11 和 13 保留但不更新。

每条 16 字节记录同时保存当前连按次数、释放时间、连按链阶段和连续按住采样数。中央状态机不生成统一的 `released` 或 `repeat` 脉冲；各消费者直接组合字段，并拥有不同甚至带原始寄存器瑕疵的重复判定。重写不能把这些规则收敛成通用 UI repeat 服务。

## 单帧采样顺序

主帧固定顺序为：

```text
0x0040A73A  ECX = input wrapper 0x004B8748
0x0040A744  sub_4372B0：读取 256-byte 键盘状态
0x0040A749  sub_4050E0：鼠标采样并更新 18 条归一化记录
              ↓
          世界、菜单、商店、战斗等消费者
```

`0x004372B0` 调用键盘设备虚表 `+0x24`，目标就是 wrapper 基址的 256 字节区。HRESULT 不检查，函数无条件返回一，两个调用者都不读取这个一。

`0x00437310` 向栈上局部区请求 `0x1C` 字节鼠标设备状态，同样不检查 HRESULT。键盘目标是持久缓冲；鼠标目标是未完整预初始化的栈区。因此失败路径存在旧快照或未定义局部数据被继续解释的旧平台风险。它不是玩法逻辑，应只在“新系统输入设备必须稳定启动”的平台兼容例外中隔离；正常成功路径的采样次序和结果不得改变，也不应把未定义内存随机值伪造成兼容规则。

显示停用/恢复函数 `0x0040AB50` 不调用 DirectInput wrapper，也不重新 Acquire 设备。其三个对象是字号 20、16、12 的字体 renderer，不是输入设备；输入只因正常帧门控而停止被采样。

## DirectInput wrapper 与鼠标格式

当前 wrapper 字段为：

| 偏移 | 汇编可见用途 |
| ---: | --- |
| `+0x000` | 256-byte 键盘设备状态；`sub_4372D0` 读取，`sub_437300` 合成置位 |
| `+0x100` | DirectInput 接口 |
| `+0x104` | 键盘设备 |
| `+0x108` | 鼠标设备 |
| `+0x10C` | 鼠标 X 绝对轴基准 |
| `+0x110` | 鼠标 Y 绝对轴基准 |
| `+0x114` | 整数灵敏度尺度 |

`0x00436FB0` 使用 DirectInput 版本 `0x500`，键盘和鼠标 cooperative flags 都是原始值 `0x0A`，各自只在初始化时 Acquire 一次。鼠标自定义数据格式的机器合同是：

- format size `0x18`，object size `0x10`；
- flags `1`，data size `0x1C`；
- X 在偏移 `0`，Y 在偏移 `4`；
- button 0 在偏移 `0x0C`，button 1 在偏移 `0x10`。

启动时 `0x004374C0` 收到浮点值 `2.0`，乘静态常量 `10.0` 后把整数 `20` 写入 `+0x114`。鼠标逻辑位移按等价关系 `(absolute_axis - baseline) * scale / 10` 推进，再分别夹到闭区间 `0..639` 和 `0..479`；触边时同步移动绝对轴基准。

`0x00437430` 不是写归一化记录，而是把目标逻辑坐标夹到上述范围后调整绝对轴基准。完整汇编有八个调用点：总初始化请求 `(480,360)`，战斗建立请求 `(320,200)`，另有五次 `(240,198)` 和一组寄存器参数。逐点参数见 `inventory/input-mouse-coordinate-rebases.tsv`。

## 16 字节记录的精确字段

| 偏移 | 语义 |
| ---: | --- |
| `+0x00` | 当前快速连按 multiplicity；正常序列为 1、2、3，封顶 3 |
| `+0x04` | 释放时间戳；连续按住期间为零 |
| `+0x08` | 快速连按链阶段 0..3 |
| `+0x0C` | 当前连续 raw-down 归一化调用次数；释放样本立即归零 |

`0x004053C0` 的状态转移是：

| 输入与旧状态 | 精确写入 | 返回 |
| --- | --- | ---: |
| `raw=0, +4=0` | `+0x0C=0`，`+4=current_input_clock`，保留 `+0/+8` | 0 |
| `raw=0, +4!=0, elapsed<=150` | `+0x0C=0`，`+0=0`，保留 `+4/+8` | 0 |
| `raw=0, +4!=0, elapsed>150` | 再把 `+8=0`；比较是严格大于 `0x96` | 0 |
| `raw!=0, +4!=0` | `v={1,2,3,3}[+8]`；`+0=v,+8=v,+4=0,+0x0C=1` | 1 |
| `raw!=0, +4=0` | 只递增 `+0x0C`，保留 `+0/+8` | 新 `+0x0C` |

由此得到几个不能丢失的边界：

- `+0x0C==1` 才是正常情况下的新按下采样；大于一表示连续按住，零表示当前 raw 已松开。
- 中央状态机没有单独保存“一帧 released”。第一次松开时 `+0` 仍可保留，第二个连续松开样本才清零。
- `+0` 单独非零不能证明当前物理按住；消费者通常还检查 `+0x0C`。
- 连按链只在 raw 仍为零的归一化调用里检查是否超过 150。暂停期间不归一化，链也不会自行过期；重新按下分支本身不重新比较时间。
- 整条记录被清零后，若第一份样本已经按住，则走 `raw!=0,+4=0` 分支：`+0x0C` 增长但 `+0` 仍为零。这一原始起始状态不可擅自正规化成 fresh press。

机器级八种转移摘要见 `inventory/input-state-transitions.tsv`。

## repeat 属于消费者，不属于中央状态机

`+0x0C` 是连续采样计数，不是中央产生的 repeat pulse。已确认的消费者至少存在以下不同规则：

- `0x00406F70` 的方向/翻页处理要求 `+0>0`，并在 `+0x0C==1` 或 `+0x0C>3` 时动作：第 1 次触发，2、3 暂停，从 4 起每个采样触发。
- `0x0043A470` 和商店 `0x0044F920` 的多组方向处理要求 `+0>0`，常见分支在计数等于 1，或计数大于 7 且为偶数时触发，即 1、8、10、12……。
- 上述两个函数的后两组 ECX 计数分支执行 `test 1, AL`，而不是测试当前 ECX 的低位；AL 来自较早路径，属于汇编中真实存在的寄存器依赖。初步还原必须按每个基本块重现，不能“修正”为对当前计数统一取奇偶。
- 战斗消费者还存在首拍触发、达到 15 后每三拍触发等另一套判定。

因此移植时只能保留记录字段并逐消费者翻译原谓词。把所有菜单、世界和战斗统一成 SDL 键盘重复事件会改变帧级行为。

全部 242 条直接符号访问已写入 `inventory/input-state-direct-accesses.tsv`；它是逐消费者复核入口，不把间接地址访问虚构成直接符号引用。

## 鼠标多击与左键抑制

`0x0043BA40` 只在对应鼠标记录 `+0x0C==1` 时产生点击位：

- 左键 multiplicity 1 产生位 `1`，大于 1 产生位 `2`；
- 右键 multiplicity 1 叠加位 `4`，大于 1 叠加位 `8`。

全局 `0x004CAE94` 是只针对左键记录 15 的倒计时。完整汇编只有两个显式生产点 `0x0042FB4E`、`0x004451FB`，都写入 `12`。每次 `0x004050E0` 先正常更新左键记录，然后若旧计数大于零：

1. 计数减一；
2. 把记录 15 的四个 dword 全部清零。

这会精确抑制接下来的 N 次归一化调用，不是 N 毫秒。若 raw 左键一直按住，每次刚更新的记录仍会被清除；倒计时结束后继续按住会从全零记录的 `raw!=0,+4=0` 路径恢复，保留其原始异常起步语义。右键记录不受影响。

## 鼠标静止状态位

每次归一化先调用 `sub_40DCB0(9)` 清内部状态位 9。随后：

- 当前 X/Y 与上次相同且原始鼠标按钮 mask 为零：`0x004C8BFC` 加一；新值严格大于 `0x1C2` 时重新置位 9，因此第一次置位是稳定样本 451。
- 坐标变化或任一原始鼠标按钮按下：计数清零。

判断使用原始鼠标 mask，所以即使左键记录被倒计时清除，raw 左键仍会重置静止计数。这也是归一化调用次数规则，不是已确认的毫秒规则。

## 原始键旁路与合成置位

`0x004372D0` 直接读取 256-byte 快照的指定字节并返回 `byte & 0x80`。完整汇编共有 77 个直接调用：16 个在归一化函数内，另 61 个由世界、菜单、战斗或调试路径直接查询。归一化记录不是唯一键盘入口。

`0x00437300` 对快照字节执行 `OR 0x80`。完整汇编只有五个调用：

- `0x00406EC9` 合成键 `0x01`；
- `0x00440A7D`、`0x00443013`、`0x0044580B` 合成当前 `0x004B73D0` 绑定，当前 `Env.dat` 为 F1；
- `0x0044B149` 合成键 `0x0E`。

这些写入发生在该帧设备采样和归一化之后，用于同帧后续 raw-key 路径；它们不是 SDL 事件队列，也没有对应的中央 release。下一次设备读取可覆盖快照。五个调用与操作数见 `inventory/input-synthetic-key-writes.tsv`，77 个 raw query 见 `inventory/input-raw-key-queries.tsv`。

## SDL3 平台合同

SDL3 可以作为跨平台设备与窗口边界；兼容核心不能直接依赖 SDL repeat/event 语义。最低合同是：

1. 每个逻辑帧先生成等价的 256-byte DirectInput scan-code 域快照，再轮询鼠标，之后运行原状态机。
2. 保留当前 `Env.dat` 绑定是 scan-code 字节而非字符码的事实；SDL scancode 到 0..255 DIK 域需要显式、可测试的映射。
3. 快照在本帧内仍可被五条合成路径原地置 `0x80`，供后续 raw query 使用。
4. 保留四字段记录、严格 `>150`、连按表 `{1,2,3,3}`、左键整记录清零、451 次静止采样和逐消费者 repeat 谓词。
5. 保留 640×480 逻辑鼠标坐标、绝对轴基准和八个 rebase 调用边界；宿主窗口缩放只允许在平台层映射到该逻辑域。
6. 不因 SDL 自动合并事件、键盘自动重复、焦点变化或高刷新率而增加或减少一次归一化推进。

DirectInput 初始化返回值、设备失败时未检查 HRESULT 等旧错误合同继续保留在规格中。只有阻断启动或新系统可用性的失败允许平台层最小隔离；不得借此修改游戏可见的成功路径、重复节奏、连按、鼠标门控或原始寄存器依赖。

## B3.7 实现验证

`LegacyInputNormalizationState` 显式持有 0x80 字节绑定块、20 条连续 0x10 字节记录、当前/前帧鼠标坐标、两个输入时钟镜像、左键抑制计数和鼠标静止计数。`begin_input_normalization` 先镜像 accepted-frame 的同一份 32 位毫秒样本，SDL3 随后轮询鼠标，`normalize_input_frame` 再完成记录更新，保留 `0x004050E0` 的先时钟、后鼠标顺序。
