# LMF 相对引用目录 `0x00426256..0x004262BD`

状态：B2.17 已实现；`assembly_exact`、`asset_verified`、`platform_adapted`、`blocked_runtime_oracle`

完整汇编是唯一行为真值。IDA 伪码和符号名只用于定位。本单元从 B2.16 最后一条变长记录的 NUL 后位置继续，只恢复下一相对偏移目录和每个目标记录的单个探测字段，不解释目标记录的业务职责。

## 1. 目录复制与循环边界

`0x00426256..0x0042626A` 从先前固定 64 KiB 窗口的当前游标读取一个 `u32` 计数，把紧随其后的 `count` 个 dword 复制到全局相对偏移数组。复制使用 `rep movsd`；计数为零时不读取表项。

复制结束后，`0x0042626C` 才对同一计数执行有符号 `<= 0` 判断。当前计数范围为 0 至 168；高位为一时原程序会先发生失控的大块复制，现代实现将其归入目录越界安全状态。

## 2. 相对目标探测

对每个表项，`0x00426274..0x004262A0` 按 32 位加法定位：

```text
field_position = map_offset + relative_offset + 0x0C
```

随后从该位置读取一个 dword，按目录序号保存到另一全局数组。seek 和四字节读取返回值都不参与原分支；资源层只交付 `{relative_offset, field_0c}`，目标记录的其余布局和用途继续留给对应业务模块。

## 3. 实现与验证

`legacy_lmf_read_referenced_record_directory` 保留计数、表项顺序、32 位位置加法、带符号 seek 和 `+0x0C` 精确读取。它同时要求目录仍位于 B2.16 的实际固定窗口内，并把失败 seek、短读和失控计数隔离为确定状态，属于 `platform_adapted` 损坏文件边界。零计数直接成功返回空目录，不调用旧文件包装器所拒绝的零字节读取。

合成 UT 覆盖三条不同目标、精确 `+0x0C` 字段、零目录、固定窗口越界和负向 seek。真实 `huge.lmf` 中 273 张地图目录非空、36 张为空，共 5,376 个引用；单图最多 168 个，所有目标均位于对应地图物理跨度内。按尾索引顺序对每个 `{relative_offset, field_0c}` 的小端字节计算 FNV-1a64，结果为 `0xCCEF13F8B2CB5BC7`。Windows LLVM `core` 的 33/33 CTest 与显式真实档案测试均通过；原程序动态轨迹仍登记为 `blocked_runtime_oracle`。
