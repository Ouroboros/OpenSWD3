# LMF 地图业务对象转换：`0x004261CE..0x00426798`

状态：`assembly_exact`、`asset_verified`；原程序动态差分待统一 oracle

唯一行为来源：`swd3.exe.lst`。IDA 伪码与物理字段名只用于定位，行为以指令为准。

## 1. 地表后事件链

`0x004261CE..0x00426245` 对每条物理记录分配 `0x34` 字节节点并插到
`0x004ACAC0` 链头。节点字段为：

| 节点偏移 | 来源 |
|---:|---:|
| `+0x04` | `u16 +0x00` 零扩展为 `u32` |
| `+0x08` | 非对齐 `u32 +0x02` |
| `+0x0C` | 非对齐 `u32 +0x06` |
| `+0x10` | 非对齐 `u32 +0x0A` |
| `+0x14` | 包含 NUL 的名称字节 |

现代 `events` 以原链表的遍历顺序保存，因此与物理记录顺序相反。名称使用拥有型字节容器，
隔离原固定节点尾部可能发生的越界复制，不改变正常资产顺序和内容。

## 2. `header +0x14` 角色

`0x00426324..0x0042641E` 从调用者已经设为 1 的角色计数开始建立地图角色；索引 0
保留给玩家。每个候选槽先清零 `+0x40..+0xD7` 的 `0x98` 动作记录并调用
`0x0040DC00`，随后写入：

| 角色字段 | 指令合同 |
|---|---|
| `world_x +0x04` | `sign_extend(i16 record+2) << 4` |
| `world_y +0x08` | `sign_extend(i16 record+8) << 4` |
| `flags +0x10` | `0x9000 \| (packed & 3)` |
| `guid +0x24` | `0xFFFF` |
| `+0x28` | `packed >> 12` |
| `+0x2A` | `(packed >> 8) & 0x0F` |
| `action+0x00` | `0` |
| `action+0x10` | `0` |
| `action+0x14` | `(u16(record+8) - u16(record+4)) << 4` |
| `action+0x4C` | `u16(record+0) - 1` |

只有 `world_y < (height + 20) << 4` 且按有符号比较 `world_y > -320` 的记录进入计数
与空间链。被拒记录会先令全局计数减一，循环尾再加一，净效果是不保留该槽。

## 3. `header +0x1C` 角色

`0x004266B8..0x00426798` 使用另一种十字节记录：

| 角色字段 | 指令合同 |
|---|---|
| `action+0x00` | `u16 record+0` 零扩展 |
| `action+0x08` | `u16 record+2` 零扩展 |
| `world_x +0x04` | 先零扩展 `u16 record+4`，再以 16 位 `shl 4` 截断 |
| `world_y +0x08` | 先零扩展 `u16 record+6`，再以 16 位 `shl 4` 截断 |
| `flags/+0x28/+0x2A/guid` | 与 `+0x14` 目录相同 |
| `action+0x88` | `0` |

该目录只接受 `world_y < height << 4`，没有负 Y 分支，因为坐标先按 `u16` 读取。

## 4. 三组按行空间链

`0x00411620` 只分配并清零三个 `(height * 4 + 0xA0)` 表；`0x00411490` 用
`flags & 3` 选择表，用向零截断的 `signed(world_y) / 16 + 20` 选择行，再按原 Y/GUID
比较分支插入单链。现代实现把旧指针改成角色索引，但逐分支保留链头、链中和链尾插入
结果。

packed 低两位为 3 会越过这三个已分配指针，读取相邻全局值。对全部 309 张当前地图的
5,471 条 `+0x14` 记录和 329 条 `+0x1C` 记录检查后，组 3 次数为零；组分布为：

```text
+0x14: group0=2407, group1=2888, group2=176, group3=0
+0x1C: group0=12,   group1=309,  group2=8,   group3=0
```

因此现代边界只建立三组；遇到当前资产不可达的组 3 返回明确状态，不猜测第四张表。

## 5. 角色格索引

地图装载调用者在 `0x0040CD53..0x0040CD78` 对索引 1 起的全部角色调用
`0x0040F280`。其中 `0x0040F2C1..0x0040F31B`：

```text
cell = (world_y >> 4) * map_width + (world_x >> 4)
role.+0x0C = map_base + cell * 4
```

它先把 `action+0x18` 清零，并用 `flags &= 0xDF0FFFFF` 清除旧映射位。只有 flags
位 8 置位时才读取格值：格位 11 投影到 flags 位 29，格 `0xF000` 投影到 flags
`0x00F00000`。现代记录在 `+0x0C` 保存受检格索引；未要求读取格值的离图角色仍保留
原回绕索引，要求读取而越界时返回明确失败。
