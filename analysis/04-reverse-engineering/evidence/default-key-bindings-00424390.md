# 默认按键与运行时兼容块 `0x00424390`

状态：`assembly_exact`、`asset_verified`

完整汇编是唯一行为真值。旧 IDA 导出目录把 `0x00424390` 标为 `__cfltcvt_init`，但去除 FLIRT 名称后的函数体和 LST 机器字节证明它是游戏自有的默认按键初始化器；旧名称只可用于追溯误识别，不能作为语义依据。

证据输入：

```text
swd3.exe.asm sha256 = f1ee7f32a79c156b75837e176abb733df7a2143d134252e507343e36857affb4
swd3.exe.lst sha256 = 701732b5481ba34876b62ca97535c9463f65ec3feb2ed745c03772dd4bc3ad8b
```

## 1. 函数体

`0x00424390..0x00424430` 没有参数、没有外部调用，只向 16 个全局 dword 写入常量后返回：

```text
4B7384=01  4B7388=39  4B738C=36  4B7390=CB
4B7394=C8  4B7398=CD  4B739C=D0  4B73A0=C9
4B73A4=D1  4B73A8=9D  4B73AC=CF  4B73B4=1C
4B73C4=13  4B73C8=1E  4B73CC=22  4B73D0=3B
```

四个直接调用点分别位于：

- `0x0040A473`：窗口自定义消息 `0x404` 的启动初始化。
- `0x00411CA4`：创建配置记录前恢复默认按键。
- `0x004240B0`：无标记 `Env.dat` 迁移写回前恢复默认按键。
- `0x0044C027`：按键设置界面的重置路径。

调用环境与连续常量写入共同排除 CRT 浮点初始化解释。A2 已把该函数从 `external_crt` 改归 `input_time_rng`。

## 2. 运行时布局与文件布局

运行时兼容块覆盖 `0x004B7384..0x004B7403`，总长 0x80 字节。上述 16 个字段是块内稀疏 dword，不是连续 16 字节：

- `0x00423FB0` 在首次成功打开 `Env.dat` 后清零完整 0x80 字节，再只向 16 个字段的低字节载入文件值。
- `0x00424390` 向这些字段写完整 dword。
- `0x0044BDA0` 的设置重置和提交路径以 0x20 个 dword 复制完整 0x80 字节，包括当前未命名的间隙和高字节。

`0x00423AF0` 按以下独立顺序把 16 个全局低字节写入 `Env.dat +0x04..+0x13`：

```text
4B7394 4B739C 4B7390 4B7398 4B7388 4B73B4 4B73A8 4B7384
4B73AC 4B738C 4B73C4 4B73C8 4B73CC 4B73D0 4B73A0 4B73A4
```

因此默认绑定的文件顺序是：

```text
C8 D0 CB CD 39 1C 9D 01 CF 36 13 1E 22 3B C9 D1
```

当前 63 字节 `Env.dat` 的 16 个绑定字节与该序列逐字节一致。B2 的 `LegacyEnvironmentRecord::binding_bytes` 只表示物理文件顺序；后续输入运行时实现必须保留 0x80 字节兼容块的字段和复制语义，不能把两种布局混为一个数组。

## 3. B3.4 实现验证

`LegacyKeyBindingBlock` 明确保留 0x20 个 dword、总长 0x80 字节；默认初始化只写相对 word 索引 `0..10,12,16..19`。UT 先以哨兵填满整块，再验证 16 个物理位置的完整 dword 和其余间隙不变。

Windows LLVM `core` 与 `app` 均完成构建并通过 38/38 CTest；验证状态仍为 `assembly_exact`、`asset_verified`。
