# RLE 纵向重采样与逐行横移 `0x0041F8D0/0x0041FEA0`

状态：`assembly_exact`、`unit_verified`、`asset_verified`；原程序动态 framebuffer 差分仍为 `blocked_runtime_oracle`。

## 证据边界

唯一汇编主证据是完整 LST `swd3.exe.lst`：

- 分派器目标高度、裁剪、纵向和横向 10.10 步长：`0x00417130–0x0041733C`；
- 正向函数：`0x0041F8D0–0x0041FE9B`；
- 水平反向函数：`0x0041FEA0–0x0042048E`；
- 15 条真实 flags 构造和调用路径：`0x0041461F–0x004146D6` 及 `0x004723A0–0x0048446C`。

`analysis/tools/build_blitter_resampling_inventory.py` 只读取完整 LST，机械锁定 17 条 transform 调用和 16 项行映射合同。ASM 与伪码不参与取证。

## 四个分派槽

| 槽 | 函数 | 水平目标方向 | 目标行方向 |
|---|---|---|---|
| `0x0C` | `0x0041F8D0` | 左到右 | 向下 |
| `0x0D` | `0x0041FEA0` | 右到左 | 向下 |
| `0x0E` | `0x0041F8D0` | 左到右 | 向上 |
| `0x0F` | `0x0041FEA0` | 右到左 | 向上 |

bit 0 选择正反函数；bit 1 不改变函数地址，而由分派器反转目标扫描线状态。四个槽全部有赋值。15 个真实构造点都先执行 `flags & 0x8000000F` 再 OR `0x0C`，因此低槽只可能是这四项。

## 分派器输入

令：

```text
Hs = source_height
Ht = target_height
D  = initial horizontal displacement
```

`Ht != 0` 时的纵向步长和目标高度裁剪与 `0x20/0x21` 共用：

```text
Ht > Hs:
    enlarge = 1
    vstep = signed_idiv(wrap32(Hs << 10), Ht)

Ht <= Hs:
    enlarge = 0
    vstep = signed_idiv(wrap32(Hs << 10), Ht) - 0x400
```

顶部和底部裁剪保留目标高度路径的两个减一，底边相等也进入裁剪。`Ht == 0` 才走普通源高度纵向路径。

横移建立过程为：

```text
if Ht != 0 and D == 0:
    D = +1

xdir  = D > 0 ? -1 : +1
xstep = signed_idiv(wrap32(abs(D) << 10), Ht != 0 ? Ht : Hs)
```

强制 `+1` 只属于 `Ht != 0` 路径；`Ht == 0 && D == 0` 会停留在普通水平路径。15 条真实调用都从源记录 `+0x0E` 的零扩展 `u16` 高度构造这两个量：

- 其余 14 条路径以乘法常数 `0x55555556` 得到 `Ht=height/3`，并以右移两位得到 `D=height/4`；
- 首条 `sub_4145F0` 先令 `Ht=height/2`、`D=±height/4`，若 `arg_10` bit 3 非零，再把 `Ht` 减半为 `height/4`。

当前 20,091 个 TSW 帧最小高度为 3。其余 14 条路径的 `Ht` 因此至少为一；首条特殊路径在 bit 3 有效且高度为三时会得到 `Ht=0`。高度三也会产生 `D=0`，但只有 `Ht != 0` 才会触发分派器的强制 `+1`。

## `Ht == 0` 继承前次放大状态

分派器入口 `0x00417136/0x0041713E` 每次都把纵向和横向步长清零；但 `Ht == 0` 会在 `0x00417144` 转入普通矩形裁剪，绕过 `0x0041723D/0x0041724D` 对 `dword_4CD2FC` 的两次写入。因此该全局的 bit 0 沿用同一进程内上一次非零 `Ht` 调用留下的状态：PE 零填充初值为零，非零 `Ht` 的缩小路径写零，放大路径写一。

`0x0C..0x0F` 函数仍会读取这个遗留位。纵向步长为零时，无条件预处理在两种状态下都先丢掉一条源行；正常输出的差异为：

```text
inherited enlarge bit == 0: 每条输出后推进一条源行
inherited enlarge bit == 1: q 恒为零，重复当前源行
```

现代无全局 blitter 请求用 `vertical_resample_enlarge_state` 显式携带这个原始状态，只读取 bit 0。默认零对应进程尚未经历纵向放大时的初始状态；不能直接把所有零目标高度调用固定解释为缩小路径。

分派器仍先按未横移的原始矩形执行一次普通水平裁剪和整矩形拒绝。进入函数后，每一输出行再把可见宽度重置为完整源宽，并依据当前横移重新裁剪；不能删除前一次拒绝，也不能只保留前一次裁剪结果。若初次左裁产生非零 source skip，两个函数入口都会把后续 X 基准改成该 skip 的相反数。

## 两个从零开始的相位

本族不继承 `0x20/0x21` 的未初始化相位：

- 正向 `0x0041F963` 显式把纵向余数清零；
- 反向 `0x0041FF33–0x0041FF4F` 通过零值传递链把纵向余数清零；
- 正反函数的横向余数也都从零开始。

每次横向更新为：

```text
sum   = wrap32(xfrac + xstep)
q     = unsigned(sum) >> 10
xfrac = unsigned(sum) & 0x3FF
D     = wrap32(D + xdir * q)
```

初始预处理和每一输出行各更新一次；输出行使用更新后的 `D`：

```text
row_x = function_x_base + D
```

RLE run 和 literal 宽度不缩放，源像素也不做水平插值。横向变化只是整条输出行的目标 X 位移。

## 无条件 `top_clip + 1` 预处理

正向 `0x0041F9F2–0x0041FA9F` 和反向 `0x0041FFDF–0x0042008C` 都在比较顶部裁剪计数前先执行一次完整预处理。因此实际次数严格为：

```text
prepass_count = top_clip + 1
```

每次预处理：

1. 无条件推进一条源 RLE 行；
2. 更新纵向余数；缩小时再推进 `q` 行，放大时只在 `q != 0` 时再推进一行；
3. 更新一次横向余数和 `D`；
4. 比较旧计数与 `top_clip`，不相等才把计数加一并继续。

所以 `top_clip == 0` 也必定丢掉至少第一条源行。顶部裁一行会执行两次预处理。这不是 `0x20/0x21` 的双递增 BUG，也不能改成对正常输出映射的常规预演。

## 正常输出行与目标 Y

每条输出先使用当前源行，随后按纵向 10.10 规则决定下一条源行：

```text
enlarge != 0:
    q == 0 -> 重复当前源行
    q != 0 -> 只推进一条源行

enlarge == 0:
    推进 1 + q 条源行
```

遇到零长度 RLE 行立即结束，剩余目标不补写。

输出计数在计算目标行前先加一。正向目标行槽使用：

```text
row_y = clipped_destination_y + processed_count
```

因此第一条输出写到 `y+1`，不是 `y`。bit 1 槽使用：

```text
row_y = clipped_destination_y + visible_height - processed_count
```

所以 `0x0E/0x0F` 第一条写到底部可见行，再逐行向上。该逐行重算覆盖了分派器建立的普通 destination row base，是本效果族独有的纵向 footprint。

## RLE coverage 与颜色运算

literal run 的 payload 位置会被消费，但其中的 `u16` 颜色完全不读取。对应目标像素只执行：

```text
outc = clamp(dc + offset_c * channel_unit_c, 0, channel_max_c)
```

公式与 mode `0x10` 的目标颜色偏移一致；高位 run 全部透明跳过。因此源 RLE 在这里是 coverage mask，不是参与缩放或加色的源颜色。

与 `0x10/0x11` 不同，即使三个颜色偏移全为零，本族也不会在读取 RLE header 前提前返回；源遍历和 phase 副作用仍然发生。

## jitter 的覆盖与正反出口不对称

两个函数都建立 0x84 字节 jitter cursor，并在每一候选输出行读取下一个偏移。但随后逐行 X/Y 重算重新覆盖目标指针，所以读取到的 jitter 像素偏移不影响最终写入位置。它仍然必须被读取，短表仍属于显式安全边界。

出口 phase 不对称：

- 正向函数在 `0x0041FE63–0x0041FE89` 把共享 phase 推进四字节并按 `0x84` 回绕；
- 反向函数 `0x0042047C–0x00420488` 直接退出，不写共享 phase。

不能因两个函数共享其余算法就统一该副作用。

## 验证

合成 UT 固定：

- `0x0C..0x0F` 四种水平/纵向目标方向；
- 首个目标行为 `y+1`，bit 1 槽从底部可见行向上；
- `top_clip+1` 次无条件源行预处理；
- `7 -> 3` 缩小时选择源行 `2,4,6`；
- 每条输出行先推进 X 相位、重新裁剪并正确处理被裁 source prefix；
- `Ht != 0` 时零位移强制为 `+1`；
- `Ht == 0` 时分别固定继承 shrink 状态的逐行推进和继承 enlarge 状态的源行重复；
- literal payload 颜色被忽略；
- 非零 jitter 偏移不移动像素，但短表仍报边界；
- 正向 phase 前进四字节，反向保持不变；
- 三个颜色偏移全零也不走 `0x10` 的早退。

真实 `all_sys.tsw` 的 16×16 RLE 帧以 `16 -> 8`、初始横移 4 执行后得到固定 framebuffer FNV-1a `0x197E513708F44317`；第 0 目标行保持原值，源行映射遇到终止行后不补满剩余目标。

## 1:1 约束

- 不做双线性插值或水平像素缩放。
- 不把强制首行预处理改成普通顶部裁剪。
- 不把首个目标行从 `y+1` 修正为 `y`。
- 不读取 literal payload 作为颜色。
- 不对全零颜色偏移增加早退。
- 不把已被覆盖的 jitter 偏移重新应用到目标坐标。
- 不统一正向和反向的共享 phase 出口副作用。
