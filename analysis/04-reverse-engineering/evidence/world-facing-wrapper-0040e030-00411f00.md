# 世界角色中心朝向链 `0x0040E030/0x00411E20/0x00411F00`

## 1. 结论

本证据以 `swd3.exe.lst` 为唯一事实来源，独立复核三个函数的完整边界、全部出口和全部
调用点。三者在现代实现中分别对应：

| 原函数 | 汇编合同 | C++ 落点 |
|---|---|---|
| `sub_40E030` | 读取当前受控角色中心，返回其朝目标点的八方向值 | `measure_legacy_world_controlled_role_direction` |
| `sub_411E20` | 32 位回绕距离、五度正弦查表和量化角度 | `measure_legacy_world_facing` 的距离/角度阶段 |
| `sub_411F00` | 将量化角度折叠为原版 `0..7` 方向 | `measure_legacy_world_facing` 的方向阶段 |

## 2. `sub_40E030` 的角色中心

`0x0040E030..0x0040E07B` 从 `dword_4AB378` 取得受控角色索引。角色步长由汇编中的
`index * 3 * 9 * 8` 得到 `0xD8`，记录基址为 `0x004BABA8`。传给 `sub_411E20` 的
源点为：

```text
source_x = role.world_x + role.action.field_2c * 8
source_y = role.world_y + role.action.field_30 * 8
```

这里读取的是角色内嵌动作记录的 `role +0x6C/+0x70`，不是角色前部同名的
`role +0x2C/+0x30`。目标点直接取两个调用参数；第二个参数所在栈槽同时作为距离输出
临时值。函数随后把角度传给 `sub_411F00`，最终只返回方向。

新增单测故意给角色前部与动作记录设置不同的 `field_2c/field_30`，固定这一易混布局；
另以无符号边界输入固定中心加法的 32 位回绕行为。

## 3. 距离与角度 `sub_411E20`

`0x00411E20..0x00411EFF` 先以 32 位整数计算：

```text
dx = source_x - target_x
dy = source_y - target_y
square_sum = dx * dx + dy * dy
```

乘法、加法和 `dy << 13` 都只保留低 32 位。平方和经 x87 `fsqrt` 和原程序的截断转换
得到整数距离，并写入第五个参数；距离为零时立即返回角度零。非零时计算
`abs((dy << 13) / distance)`，按 `dx/dy` 符号选择象限，然后在 90 度范围内以五度步长
扫描 `0x0049F250` 的正弦表。比较使用 `<=`，相同误差选择较后的角度。现代实现保留了
这些回绕、符号、零距离和同误差覆盖语义。

## 4. 方向折叠 `sub_411F00`

`0x00411F00..0x00411F8D` 计算 `angle * 16 / 360`，再从栈上构造的 17 项表取方向：

```text
3, 7, 7, 0, 0, 4, 4, 2, 2, 6, 6, 1, 1, 5, 5, 3, 0
```

`sub_411E20` 的可达输出范围为 `0..355` 且以五度递增，因此索引严格位于 `0..15`；
第 17 项零值仍按汇编保留，但三个原版调用点都只读取前 16 项。

## 5. 双向调用核对

原版直接调用关系为：

- `sub_40E030` 共四处：`sub_402F80` 两处、`sub_427300` 两处。
- `sub_411E20/sub_411F00` 各三处：`sub_40E030`、`sub_427300`、`sub_427920`。

现代反向映射完全对应：

- 碰撞对话、面向确认对话、鼠标 NPC 对话和地图事件点击统一调用角色中心包装层。
- 鼠标相对玩家的光标方向直接调用完整距离/角度/方向链。
- 剧情 VM opcode 76 直接调用同一完整链，并使用距离门槛与方向结果。

不存在额外的 C++ 角色中心朝向副本，也没有遗漏的原版直接调用点。

## 6. 验证

- `legacy_world_facing_test` 固定零距离、四正向、四对角、非正方位、负平方和转换、
  内嵌动作范围字段和坐标回绕。
- `legacy_world_facing_talk_test`、`legacy_world_collision_talk_test`、
  `legacy_world_interaction_test` 固定四条 `sub_40E030` 业务路径。
- 实现完成后再次按 C++→LST 方向逐项核对角色字段、参数顺序、回绕算术、查表覆盖条件、
  方向表和全部调用点，结论收敛为 `assembly_exact`。
