# LMF 地表后变长记录目录 `0x00426195..0x00426247`

状态：B2.16 已实现；`assembly_exact`、`asset_verified`、`platform_adapted`、`blocked_runtime_oracle`

完整汇编是唯一行为真值。IDA 伪码和符号名只用于定位。本单元从 B2.15 解压块后的尾随记录数继续，只恢复紧随其后的相对偏移表和变长记录物理布局，不提前赋予地图业务语义。

## 1. 固定窗口和偏移表

`0x00426195..0x004261AC` 把地表压缩块后的尾随 `u32` 保存为记录数，并从当前文件位置固定请求读取 `0x10000` 字节。原调用点不检查读取返回值，随后直接执行：

```text
record_cursor = window + record_count * 4
```

因此窗口开头是 `record_count` 个四字节相对偏移，记录数据紧随表后。原循环不使用表中偏移定位记录，只按顺序推进 `record_cursor`。当前 309 张地图的 813 个表项全部恰好等于相应顺序记录相对地图块起点的位置；这是资产事实，不能反向改写原控制流。

## 2. 变长记录布局

当记录数按有符号比较大于零时，`0x004261CE..0x00426245` 每轮分配并清零 0x34 字节运行时节点，把节点链接到全局单链表，再从物理记录复制：

```text
+0x00  u16 field_00，零扩展到运行时 dword
+0x02  u32 field_02
+0x06  u32 field_06
+0x0A  u32 field_0a
+0x0E  byte name[]，包含终止 NUL
```

固定字段共 14 字节。字符串循环逐字节复制到节点 `+0x14`，包含 NUL，并用 NUL 后的位置作为下一记录起点。原程序没有窗口边界或节点字符串容量检查。最后一条记录的 NUL 后位置就是 `0x00426256` 消费的下一目录起点。

## 3. 实现与验证

`legacy_lmf_read_post_surface_records` 保留固定 64 KiB 请求、记录数乘四跳表、未对齐字段宽度、NUL 包含关系和顺序游标；同时公开声明偏移与实际顺序位置，避免把当前资产中两者相等误写成原解析依赖。物理字段保持中性命名，业务解释留给 `world_map`。

高位为一的记录数、表或固定字段越过实际读取范围、相对位置溢出和无终止字符串返回确定状态，隔离原程序的失控指针与越界复制，属于 `platform_adapted` 损坏文件边界。短于 64 KiB 但系统读取成功的窗口保留实际长度，再在解析点进行边界判断，不把普通 EOF 短读直接改写成失败。

合成 UT 覆盖 `MSFp/MSF2`、三个不同长度记录、未对齐字段、原始双字节名称、下一目录位置，以及“声明偏移被篡改但顺序解析不变”的原控制流。真实验证覆盖 309/309 张地图、813 条记录，单图记录数为 0 至 21，全部 813 个声明偏移与顺序位置相等。Windows LLVM `core` 的 33/33 CTest 与显式真实档案测试均通过；原程序动态轨迹仍登记为 `blocked_runtime_oracle`。
