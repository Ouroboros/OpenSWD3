# ANI 四槽漂移动作效果（`0x004161C0`）

状态：`assembly_exact`、`asset_verified`；原程序动态 framebuffer 差分仍为
`blocked_runtime_oracle`。

唯一行为真值：`swd3.exe.lst`。本文只使用 LST 指令、物理全局地址和已闭环的
ACT/TSW/动作记录实现；IDA 函数签名与伪码不作为行为依据。

## 1. 调用与生命周期

- 普通世界帧协调器在 `0x00412AB8..0x00412AC3` 依次压入三个零、调用
  `0x004161C0`，再回收 `0x0C` 字节。被调函数没有读取这些物理栈槽，因此它们是
  调用侧遗留参数，不构成重写接口的输入。
- 函数是普通世界 ANI 小组的首项，后续依次为 `0x00416590`、`0x004167B0`、
  `0x00415B70`、`0x004163C0`、`0x00416CC0`。
- `0x0040E61C..0x0040E66C` 对四个连续 `0x98` 动作记录分别调用
  `0x0040DC00`，随后把四个 `action_id` 都写为 `0x232B`。
- 进程初始化 `0x0040C1D4..0x0040C1EA` 和场景重置 `0x0040F670..0x0040F689`
  都只把四个状态槽的 `x` 写为 `0x7FFFFFFF`；`y`、两个速度字段和动作记录不清零。

## 2. 物理状态

状态块从 `0x004B86F8` 开始，共四个连续 `0x10` 字节槽：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| `+0x00` | `i32` | 世界 x；`0x7FFFFFFF` 是待重生哨兵 |
| `+0x04` | `i32` | 世界 y |
| `+0x08` | `i32` | 水平速度 |
| `+0x0C` | `i32` | 垂直速度 |

动作记录基址依次为 `0x004AD0D8`、`0x004AD170`、`0x004AD208`、
`0x004AD2A0`。循环中的 `EDI` 指向各记录 `+0x08`，每轮增加 `0x98`，在
`0x004AD340` 停止，因此严格处理四个一一对应的状态槽和动作记录。

## 3. 启用门与地图边界

`0x004161D5..0x004161F5` 先以参数 6 调用 service 查询。返回零时立即退出，不读取
地图尺寸、不消耗 RNG、不改状态，也不触发 ACT、TSW 或绘制。

启用后把 `dword_4B7930/dword_4B7934` 分别左移四位，得到像素尺度的地图宽高。
每槽按有符号比较执行以下边界：

```text
x <= -120
x >= map_width * 16 + 120
y <= -120
y >= map_height * 16 + 120
```

任一成立只把 `x` 写成哨兵。左移、加法和后续坐标运算均为 x86 32 位回绕；不以
C++ 有符号溢出替代。

## 4. 重生与活动槽 RNG

### 哨兵槽

哨兵槽同帧完成建立、动作更新、TSW 查询、绘制和移动，不像粒子槽那样跳过创建帧：

1. `x = -64`；
2. `random(map_height * 16)` 写入 `y`；
3. `random(5) - 2` 写入垂直速度；
4. `random(7) - 3` 写入水平速度；
5. 水平速度为零时强制改为 2；
6. 水平速度为负时把 `x` 改为 `map_width * 16 + 64`。

原函数会把零或异常回绕后的地图高度直接传给 RNG；重写不在有效资产路径上偷偷
修正这一合同。

### 已活动槽

每个活动槽先无条件消耗 `random(1000)`。结果无符号严格大于 250 时，继续按顺序：

1. `horizontal_delta = random(3) - 1`；
2. `vertical_delta = random(3) - 1`；
3. 垂直速度加第二个增量并夹在 `[-3, 3]`；
4. 水平速度加第一个增量并夹在 `[-5, 5]`；
5. 若新水平速度恰好为零，写成 `-horizontal_delta`。

最后一步是原指令的特殊行为：当增量本身为零时速度可以继续为零；当 `1 + (-1)`
归零时又会变回 1。不能替换成通用“零速度改为固定方向”。

## 5. 变体、动作和绘制

函数在栈上构造八个有符号字节：

```text
[52, 52, 52, 54, 56, 56, 56, 54]
```

以 `vertical_velocity + 3` 取基变体；水平速度严格大于零时再加一。正常状态只使用
垂直速度 `[-3, 3]` 对应的前七项，得到动作 `0x232B` 的变体 `52..57`；第八项是
物理存在但正常状态不可达的尾字节。

每槽随后严格执行：

1. 把变体写入动作记录 `+0x08`；
2. 对记录基址调用 `0x004321E0`；
3. 以记录 `+0x4A/+0x4C` 调用 `0x004315D0` 查询 TSW 帧；
4. 把帧主流发布到旧全局 `0x004CD730`；
5. 调用 `0x004170E0`，目标坐标为
   `slot.xy - record(+0x10/+0x14) - camera.xy`，宽高取 TSW 帧，flags 取记录
   `+0x18`，最后一个参数为零；
6. 忽略 blitter 返回值，再把两个速度分别加到世界坐标。

绘制坐标不按帧宽高居中；动作记录的两个偏移就是该函数唯一的图像定位修正。动作
更新或帧查询失败在原版有效资产路径上不会发生；重写端口把这两种宿主失败隔离为显式
状态，blitter 失败仍按原调用者语义忽略并继续。

## 6. 实现与验证

- 实现：`legacy_ani_drift_effect.hpp/.cpp`。
- 固定 UT 覆盖四槽 `0x10` 布局、只写 x 的重置、service 零副作用、四个包含边界、
  三步重生 RNG、活动概率与两步扰动、速度夹取、归零特殊行为、八字节变体表、
  ACT/TSW 键、动作偏移/摄像机坐标、同帧移动、端口失败和被忽略的 blit 失败。
- seed 39 的四槽重生向量依次为：
  `(y=433, vy=0, vx=3)`、`(896, 1, -2)`、`(456, -1, 1)`、
  `(1170, 0, 1)`，共消耗 24 个 secondary-RNG 状态字。
- 正确原版数据目录上的动作变体 `53/54/57/56` 已经通过
  ACT runtime → action updater → TSW runtime → software blitter 全链验证，四帧逻辑
  framebuffer FNV-1a64 为 `0x53695F8D8D2219DF`。
- Linux Clang `core` 96/96、Windows LLVM `app` 100/100 CTest 通过；原程序本体未由
  OpenSWD3 自行启动。
