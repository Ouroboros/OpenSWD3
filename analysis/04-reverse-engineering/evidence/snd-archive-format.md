# SND 音效包、运行时索引与 RIFF 现场重建规格

最后更新：2026-08-02

状态：`all.snd` 的 3000 个物理索引槽、664 个查找视图、662 个连续物理块和 `0x00486490` 返回缓冲区已全量验证

来源：`swd3.exe` 完整汇编与工作区 `all.snd`

完整汇编是唯一真实依据。IDA 伪码只辅助定位。

## 总结

`all.snd` 不是普通 WAV 文件的简单拼接。`0x004862B0` 固定读取 3000 个 44 字节索引槽，把每槽压缩为 16 字节运行时记录；`0x00486490` 再按一基音效编号读取指定视图，并根据两位类型现场构造返回缓冲区。

当前样本有 664 个非空查找项、662 个唯一数据偏移。662 个基础物理块从 `0x203BC` 连续覆盖到文件末端；另外两个索引项是从已有块起点开始、跨越大量后续物理块的长视图，不能按重复偏移去重或改成下一个块的长度。

当前 664 项全部是类型零，都会走原程序的 RIFF 现场重建路径。该路径生成的字节并非严格自洽的标准 WAV：它覆盖源载荷最前两个音频字节，声明的数据长度又排除最后四个已复制字节；两个样本甚至不能形成 `data` 块标签。初步 1:1 还原必须保留这些行为，不得顺手修 WAV。

## 文件头与固定索引

| 文件偏移 | 宽度 | 当前结论 |
|---:|---:|---|
| `+0x00` | `0x18` | 当前样本全零；初始化汇编不读取 |
| `+0x18` | 4 | 声明项数，当前为 664 |
| `+0x1C` | `3000 × 44` | 固定物理索引区 |
| `+0x203BC` | — | 索引区末端和第一个基础物理块起点 |

`0x00486353–0x00486375` 先绝对定位到 `0x1C`，再精确读取 `0x203A0 = 3000 × 44` 字节。随后 `0x00486382–0x00486412` 无条件循环 3000 次，不使用头部声明值控制循环。

当前声明数恰好等于非空项数，槽 665 至 3000 全零；这只是样本事实，不能推翻汇编已经确定的固定 3000 槽布局。

## 44 字节磁盘索引记录

| 记录偏移 | 宽度 | 初始化器用途 |
|---:|---:|---|
| `+0x00` | 20 | CP950 名称字节区；运行时编号查找不读取 |
| `+0x14` | 4 | 原始长度字段；只保留低 26 位作为运行时读取长度 |
| `+0x18` | 4 | 载荷绝对文件偏移 |
| `+0x1C` | 4 | 存储元数据编号；当前非空样本等于一基物理槽号，运行时不读取 |
| `+0x20` | 4 | 只取低 2 位作为运行时类型 |
| `+0x24` | 4 | 初始化主路径不读取；当前样本全零 |
| `+0x28` | 4 | 初始化主路径不读取；当前样本全零 |

`0x00486391–0x00486402` 对第 `i` 个磁盘记录生成：

```text
runtime[i].file_offset = disk[i].field_18
runtime[i].packed      = (disk[i].field_14 & 0x03FFFFFF)
                       | ((disk[i].field_20 & 3) << 26)
runtime[i].ref_count   = 0
runtime[i].buffer      = 0
```

运行时表分配大小为 `0xBB80 = 3000 × 16` 字节。

## 16 字节运行时记录

| 记录偏移 | 宽度 | 当前结论 |
|---:|---:|---|
| `+0x00` | 4 | 载荷绝对文件偏移；零表示查找失败 |
| `+0x04` | 4 | 低 26 位读取长度，高位保存由磁盘 `+0x20` 低 2 位移入的类型 |
| `+0x08` | 4 | 当前活动样本引用计数 |
| `+0x0C` | 4 | 当前登记的已分配返回缓冲区指针 |

`0x00486496–0x004864A5` 使用：

```text
entry = runtime_table + (sound_id - 1) * 16
```

音效编号是一基。函数本身不检查 `1..3000` 范围；零和越界编号会访问表外内存。安全拒绝只能放在不改变有效调用的诊断/平台边界，不能把原函数内部行为改写成静默钳制。

查找成功后：

```text
read_size = entry.packed & 0x03FFFFFF
type      = arithmetic_shift_right(entry.packed, 26)  // 当前只会是 0..3
seek(entry.file_offset)
```

当前 664 项的磁盘 `+0x20` 都是零，因此类型全为零。类型一、二、三的分支由汇编确认，但没有当前 SND 样本可验证其有效载荷格式。

## `0x00486490` 的返回缓冲区

类型控制分配和后处理：

| 类型 | 读取前缀 | 读取位置 | 读取后是否改写头部 |
|---:|---:|---:|---|
| 0 | 24 字节 | 返回缓冲区 `+0x18` | 是 |
| 1 | 0 | 返回缓冲区 `+0x00` | 否 |
| 2 | 0 | 返回缓冲区 `+0x00` | 是 |
| 3 | 0 | 返回缓冲区 `+0x00` | 是 |

无论类型，`0x004864FC–0x00486523` 都先复制包含结尾零的 43 字节模板：

```text
RIFF....WAVEfmt ....0123456789012345data..\0
```

随后文件读取覆盖相应位置。只有类型恰好等于一时，`0x00486537` 跳过全部头部改写。

### 当前类型零的精确字节映射

设索引低 26 位长度为 `N`，源载荷为 `source[0..N)`。有效样本读取成功后，返回缓冲区分配 `N + 24` 字节，最终为：

| 返回偏移 | 最终内容 |
|---:|---|
| `+0x00..+0x03` | `RIFF` |
| `+0x04..+0x07` | 32 位值 `N` |
| `+0x08..+0x0F` | `WAVEfmt ` |
| `+0x10..+0x13` | 32 位值 16 |
| `+0x14..+0x23` | `source[0..16)`，即 16 字节基础 PCM 格式 |
| `+0x24..+0x25` | `source[16..18)` |
| `+0x26..+0x27` | 汇编写入字节 `ta` |
| `+0x28..+0x2B` | 32 位值 `N - 24` |
| `+0x2C..` | `source[20..N)` |

其中 `0x0048653C–0x00486546` 调用本 EXE 内的 `_memcpy(返回+0x14, 返回+0x18, 0x12)`。`_memcpy` 的真实实现位于 `0x00489EB0`：它检测重叠区间，本例目标低于源，走前向复制。因此上表不是根据 C 标准库行为猜测，而是由本 EXE 汇编确定。

这条映射有三个必须保留的结果：

1. 原先位于 `source[18..20)` 的两个字节被 `N - 24` 覆盖，不进入最终音频数据区。
2. 当 `source[16..18) == "da"` 时，最终 `+0x24..+0x27` 才组成 `data`。
3. `data` 声明长度是 `N - 24`，但返回缓冲区 `+0x2C` 后实际仍有 `N - 20` 字节；最后四个已复制字节位于声明数据之外。

外层 RIFF 大小字段是 `N`，其声明边界、`data` 块声明边界和实际分配边界也不一致。重写前必须继续确认 Miles 对这三种边界的实际采纳规则；不能先用现代 WAV 修复器正规化。

## 当前样本全量结果

- 文件大小：54,596,397 字节。
- 固定索引：3000 槽，664 个非空查找项。
- 唯一载荷偏移：662 个。
- 662 个基础物理块从 `0x203BC` 连续覆盖至文件末端，共 54,464,369 字节，无缝隙、无越界。
- 664 个运行时视图的低 26 位读取长度合计 117,128,703 字节。
- 664 个类型零返回分配合计 117,144,639 字节。
- 16 字节源 PCM 格式头出现 13 种组合，格式标签均为 PCM 一；声道数为一或二，采样率、位宽和块对齐的逐项分布见机器目录。
- 662 项的 `source[16..18)` 是 `da`，最终形成 `data` 标签。
- 音效 ID 506“機關聲1”和 507“機關聲2”的 `source[16..18)` 是零，最终标签为 `00 00 74 61`，原加载器不会修复。
- 按音效编号拼接全部原加载器返回缓冲区的 SHA-256 为 `38ecbbcbb7473ab8c8ec116837b8c472fa7ed274ad42e4a0e0f04aaef6241e27`。

### 两个跨块长视图

| 音效 ID | 名称 | 原始长度字段 | 低 26 位读取长度 | 起点 | 同起点基础项 |
|---:|---|---:|---:|---:|---:|
| 270 | 逃跑 | `0x81DE1747` | `0x01DE1747` | `0x0110B1E8` | 271 `runaway` |
| 277 | 靈契中 | `0x81DE1747` | `0x01DE1747` | `0x011D943E` | 278 `靈契失敗` |

`0x00486395` 无条件执行 `& 0x03FFFFFF`，所以最高位不是应保留到运行时长度的普通长度位。这两个查找项会按低 26 位读取 31,332,167 字节，跨越许多后续基础块，但仍在文件范围内。不得因偏移重复而把它们合并成 ID 271/278 的短块。

## 播放与所有权

`0x00485CE0` 检查返回缓冲区前四字节：

- 等于 `RIFF`：调用 Miles `AIL_set_sample_file`。
- 不等于 `RIFF`：调用 `AIL_set_named_sample_file`，扩展名参数固定为 `.mp3`。

当前 SND 的 664 个类型零返回值都以 `RIFF` 开头，所以当前包内样本不走命名 MP3 分支。该 MP3 分支仍属于通用播放函数的汇编行为，不能据当前包删除。

播放成功后，`0x00485E0D–0x00485E2C` 增加对应运行时槽 `+0x08` 引用计数，并把当前缓冲区指针写到 `+0x0C`；Miles 样本 user-data 保存一基音效编号。停止、自然回收和全部停止路径会按 user-data 找回槽位，递减引用计数，只在变成零时释放 `+0x0C`。

当前四个 `0x00485CE0` 直接调用点都给“已有缓冲区”参数传零，因此会重新进入 `0x00486490`。同一音效重叠播放时，单个 `+0x0C` 只能登记最后一次写入的指针；其精确可见后果仍要结合 Miles 生命周期做差分验证，初步还原不能先改成现代共享指针或每实例所有权模型。

销毁路径 `0x00486430` 逐个检查 3000 个运行时槽的 `+0x0C`，释放非零缓冲区，随后释放整个 48,000 字节表并关闭文件。

## 1:1 重写约束

- 固定保留 3000 个物理索引槽和一基编号公式；不得把声明数改成运行时表边界。
- 磁盘长度必须先清除高 6 位；类型必须只取磁盘 `+0x20` 的低 2 位并移入运行时记录。
- 不得按重复偏移去重两个跨块长视图，也不得把其长度改成同起点基础块长度。
- 类型零的模板、24 字节前缀、18 字节重叠复制、字段覆写和最终字节映射必须保留到 Miles 消费规则完成差分验证。
- 不得修复 ID 506/507 的块标签，不得自动补齐或正规化 RIFF/data 长度。
- 游戏逻辑层不得擅自改写单槽引用计数和缓冲区指针所有权。必要的现代内存安全保护必须隔离，并证明不改变有效原调用的顺序和结果。
- 非零类型没有当前样本覆盖；在找到证据前只能按汇编保留分支，不能假设类型一必为 MP3、类型二/三必为某种已知编码。
