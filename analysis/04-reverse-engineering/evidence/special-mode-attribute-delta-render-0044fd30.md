# 绘制四名角色的三项候选属性差值 `0x0044FD30`

状态：`platform_adapted`

## 1. LST锁

权威范围为`swd3.exe.lst`的`0x0044FD30..0x0044FF89`，275行，无外部FUNCTION CHUNK。唯一caller为`0x0044EA60`；callee为角色存在查询、三次颜色合成和六个静态文字绘制点。

入口无条件依次合成三色：

- 主色：RGB `0x19,0x17,0x11`。
- 正值色：RGB `0x1F,0x1F,0x1F`。
- 负值色：RGB `0x1A,0,0`。

依次查询角色ID `0x1E..0x21`。不存在角色不绘制；存在角色绘制三列，每列先标签再值，style恒4：

- 原Big5 `A7 F0`，即“攻”。
- 原Big5 `A8 BE`，即“防”。
- 原Big5 `B1 D3`，即“敏”。

四名角色中心x依次为`0x35,0xAD,0x125,0x19D`；三列x为中心`-0x14,0,+0x14`。标签y=`0x44`，值y=`0x58`。

## 2. 值格式

每列默认主色文字`----`。只有该角色候选类别匹配非零且差值非零时改为：

- 正数：正值色，`+`加十进制绝对值。
- 负数：负值色，`-`加十进制绝对值。

原汇编以32位补码求绝对值，再把结果作为有符号`%d`参数。`INT_MIN`的绝对值仍为`0x80000000`，因此原结果是`--2147483648`；typed实现明确保留该格式异常，不使用会溢出的`std::abs`。

每次角色查询和文字绘制都覆盖机器返回，最终返回最后一次实际操作结果。即使全部角色不存在，三色仍已合成并执行四次查询。
