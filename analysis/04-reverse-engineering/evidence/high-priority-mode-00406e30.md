状态：P2.2 顶层职责已确认；内部业务模式名待确认

来源：`swd3.exe` 完整汇编

函数范围：`0x00406E30` 至 `0x00406EA5`

直接调用者：`0x0040A570`

参数：无

## 1. 帧前状态

函数先递减 `[0x004CB240]`：

- 结果为负时写零。
- 结果大于 1000 时也写零。
- 其他结果保留。

随后：

- `[0x004CC2A4] += 1`。
- 若 `[0x004CAEB0] == 3`，改写为一。
- `[0x004ACD20] = 13`。
- 调用 `0x00406EB0`。

这些写入证明本函数不只是呈现包装，还推进该高优先级模式自己的计数和状态。

## 2. 子模式分派

函数读取 `[0x004CAEBC]`：

```text
0 → 调用 0x00406F70
1 → 调用 0x004070A0
其他 → 跳过这两个处理函数
```

`0x004070A0` 与存档菜单/读写大流程有关，但仅凭这个调用位置，不能把 `[0x004CAEBC] == 1` 的整个模式直接命名为“存档模式”。

## 3. 呈现出口

子模式处理后再次读取 `[0x004CAEB0]`：

- 为零时直接返回。
- 非零时尾跳转到 `0x00408CF0`。

`0x00408CF0` 在 `0x00408D5E` 调用 DirectDraw `Blt`。因此高优先级画面的呈现位于这一尾跳转下游，不在 `0x0040CF10`。

本函数没有统一布尔返回契约：零门控路径以当时的 `EAX == 0` 返回，非零路径尾跳转后继承 `0x00408CF0` 的机器级结果。主循环不读取它的返回值。
