# 存档预览与大型存读写入口 ABI

最后更新：2026-08-02

状态：`0x00409600` 与 `0x004070A0` 顶层机器合同已确认

完整汇编是唯一真实依据。本文件只固定存档子系统进入 P2.5 所需的调用边界和调用者策略；存档磁盘字段、压缩段和完整读写规格继续在 P8 恢复。

## `0x00409600`：存档槽预览记录装载

### 参数和清栈

函数读取两个 32 位正栈槽：

```text
[esp+4]  预览记录指针
[esp+8]  存档槽号
```

槽号在 `0x00409621` 载入，并作为 `%ssave\%d.sav` 的整数参数传给 `wsprintfA`。记录指针在 `0x004096A0` 载入 EBP，后续所有预览结果都相对此指针写入。

函数普通 `retn`，不清理参数。21 个直接调用点都先压槽号、再压记录指针，由调用者延后统一回收八字节栈参数。因此合同是普通内部 cdecl，不是 `retn 8` 的 stdcall。

### 记录身份

所有调用点只传三个静态记录基址：

```text
0x004CB968
0x004CBC10
0x004CBEB8
```

相邻地址差均为 `0x2A8`，证明它们是三个连续同尺寸预览记录，而不是三个互不相关的全局对象。调用者按当前槽组三连号分别传入 `group*3+0`、`group*3+1`、`group*3+2`。

函数内已见的关键结果位置包括：

- `+0x294`：成功路径分配的 `0x9600` 字节缩略图缓冲；
- `+0x298`：从存档头日期生成的动态字符串；
- `+0x29C`：存档内文本的动态副本；
- `+0x2A0/+0x2A4`：后续摘要和时间文本相关动态缓冲；
- `+0x30`：本次预览记录状态。

上述字段只用于证明参数确实是输出记录。完整字段语义和所有权仍需 P8 专项确认。

### 成功、缺失与机器返回必须分开

文件打开失败从 `0x0040998B` 写：

```text
word [record + 0x30] = 1
```

成功完成映射、解析、解除映射和关闭后，从 `0x00409980` 写：

```text
word [record + 0x30] = 2
```

两条正常路径都汇合到 `0x00409995`，执行文件对象析构，然后在 `0x004099AA` 固定 `xor eax,eax`，普通返回。因此机器返回在正常路径恒为零，成功/缺失只通过记录状态区分。

21 个直接调用点均不检查 EAX。它们连续刷新三条预览记录，再调用 `0x00409B80` 依据记录内容更新界面。

现代重写不能把旧 EAX=0 擅自解释成“失败”，也不能改成返回布尔成功后让上层依赖新语义。内部接口可以返回 `void` 并显式写记录状态；旧行为差分桩仍要断言 EAX 和 `+0x30` 的组合。

### 异常函数块

主函数标有位于 `0x00498050` 的 SEH 函数块。它属于编译器异常展开路径，不增加普通调用参数，也不改变唯一正常 `retn` 的调用者清栈合同。

## `0x004070A0`：大型存档菜单与读写状态机

### 入口

函数没有正栈参数读取，唯一直接调用点是 `0x00406E8B`。调用前没有压入逻辑参数，主体在自己的 SEH 框架内保存 EBX、EBP、ESI、EDI，最终普通 `retn`。

所以合同为：

```text
stack argument bytes = 0
callee cleanup bytes = 0
register inputs = none established
```

模式选择和全部工作状态都来自全局状态块，不从调用 ABI 传入。

### 返回值策略

主体的多个退出分支汇合到 `0x00408CBC`：析构局部文件对象、恢复 SEH 和非易失寄存器后直接返回。公共尾部没有为 EAX 写统一值；最后一次文件对象析构又可能把 CloseHandle、operator delete 或既有寄存器值留在 EAX。

唯一调用者在 `0x00406E8B` 调用后直接跳到 `0x00406E97`，随后以 `mov eax,[0x004CAEB0]` 覆盖 EAX。因此原合同不是布尔成功/失败，而是“没有稳定机器返回，调用者不观察”。

未来重写可以把这个顶层内部入口声明为 `void`，但不能为方便而在现有状态机分支上新增基于返回值的行为。

### 范围边界

`0x004070A0` 内确实包含预览刷新、槽选择、存档读取、写入、状态位恢复和界面呈现，但本文不据此宣布存档格式完成。当前只证明：

- 入口是零参数、调用者不读返回值；
- 预览子入口是两个 cdecl 栈槽；
- 存档槽是否存在通过预览记录状态传播；
- 这两条边界已足够消除 P2.5 中“存档完全没有人工 ABI 合同”的缺口。

## 1:1 还原约束

- 保留 `0x00409600` 正常路径恒返回零的机器行为。
- 保留成功/缺失写入记录 `+0x30` 的一/二状态，不改成返回值协议。
- 保留三条 `0x2A8` 预览记录和三连槽刷新顺序。
- 保留 `0x004070A0` 的返回值不稳定、唯一调用者忽略的策略。
- 不在本阶段修正存档数据、槽范围或界面逻辑 BUG；新系统文件 API 兼容适配必须留在平台/文件边界。
