# 输入归一化与 DirectInput 边界 ABI

最后更新：2026-08-02

状态：帧输入、DirectInput 初始化和键盘状态读取三个 ABI 边界已确认；字段状态机见专项证据

完整汇编是唯一真实依据。未来 SDL3 输入层可以替换设备 API，但必须复现这些入口对全局输入状态、返回值和调用顺序的可见行为。

## `0x004050E0`：单帧输入归一化

函数没有正栈参数读取，唯一直接调用点为 `0x0040A749`。主帧先在 `0x0040A744` 读取 256 字节键盘设备状态，再立即进入本函数。

它以全局输入包装对象、鼠标位置输出地址和一组按键绑定表为输入，依次更新：

- 鼠标坐标和鼠标按键位；
- 18 条带连按次数、释放时间、连按链和连续按住采样数的 16-byte 状态记录；
- 鼠标静止计数和内部状态位九；
- 当前帧与前帧输入快照。

两个出口都是普通 `retn`，没有统一设置 EAX。唯一调用者下一条指令 `0x0040A74E` 直接从 `0x004CAEB0` 重新载入 EAX，因此机器合同是“零参数、返回值不稳定且调用者不观察”，不是布尔输入更新结果。

字段状态机并不提供统一的 pressed/held/released/repeat 枚举。严格转移、20 条记录、左键抑制、451 次静止采样、77 个 raw query 和 5 个合成写入见 `input-normalization-and-repeat-semantics.md`。

## `0x00436FB0`：DirectInput 5 初始化

### 调用形状

唯一调用点 `0x00424F0C` 按以下顺序调用：

```text
ECX       = input wrapper at 0x004B8748
[esp+4]   = HINSTANCE
[esp+8]   = HWND
```

主体在 `0x00436FE0` 读取第一参数并传给 `DirectInputCreateA`，版本固定为 `0x500`；第二参数多次用于键盘和鼠标设备的 cooperative level 以及错误消息窗口。

全部出口执行 `retn 8`，所以这是 ECX 对象加两个 32 位栈参数的成员式清栈合同。

### 返回值不是干净的成功布尔值

最终成功路径在 `0x004372A1` 执行 `xor eax,eax`，返回零。大部分初始化失败路径释放对象后返回一，唯一调用者在 `0x00424F11` 测试 EAX，非零时显示总的 DirectInput 失败消息。

但两条晚期失败路径也返回零：

- `0x004371F8` 的事件通知设置失败，显示自己的消息后在 `0x00437218` 清零 EAX；
- `0x00437230` 的鼠标缓冲区设置失败，显示自己的消息后在 `0x00437250` 清零 EAX。

因此原集合虽为 `{0,1}`，却不能命名成严格的 `false=success,true=failure`：零包含完整成功和两类已经发生的晚期失败。初步还原不得把这两条路径“修正”为一；若新系统输入启动必须隔离兼容处理，应在平台适配层记录例外并证明不改变游戏输入逻辑。

## `0x004372B0`：256 字节键盘设备状态读取

函数以 ECX 接收输入包装对象，无栈参数。它从对象 `+0x104` 取得键盘设备，通过虚表 `+0x24` 调用设备状态接口：

```text
device
0x100 bytes
destination = input wrapper base
```

外部 HRESULT 没有被测试。调用后函数无条件执行 `mov eax,1` 并普通 `retn`。

两个直接调用点均忽略这个一：

- `0x0040A744` 后立即调用 `0x004050E0`，覆盖并消费全局输入状态；
- `0x00411B2E` 后立即查询具体键位，未读取 EAX。

所以不能把 EAX=1 当作设备读取成功证明。真实效果来自 256 字节目标缓冲是否被设备调用更新；设备失败时旧缓冲如何保留属于原 API/内存行为。

## 参数和状态层次

三条边界形成的每帧顺序是：

```text
DirectInput keyboard GetDeviceState
    -> mouse/state normalization
    -> world/menu consumers query normalized blocks
```

初始化只发生在总初始化路径，帧读取和归一化依赖全局对象，不从调用栈传设备状态。未来 SDL3 适配不能只做键码映射，还要保留：

- 设备采样在归一化之前；
- 返回值被忽略的策略；
- 旧缓冲、鼠标坐标和重复/静止计数的跨帧顺序；
- `0x004050E0` 的两个普通出口及其全局副作用。

显示停用/恢复函数 `0x0040AB50` 只处理 DirectDraw、字体 renderer、音频和战斗显示边界，不调用 DirectInput wrapper，也不重新 Acquire 输入设备。旧文档曾把三套字体 renderer 错归类为输入对象，现已按汇编纠正。

## 1:1 还原约束

- 不把 `0x004050E0` 改成上层必须检查的成功布尔接口。
- 保留 DirectInput 初始化的 ECX、两个栈槽和 `retn 8` 旧边界记录。
- 保留两条晚期初始化失败返回零的异常，不作为游戏逻辑 BUG 顺手修复。
- 保留键盘设备 HRESULT 不检查、EAX 固定一且调用者忽略的合同。
- SDL3 平台层必须先产生等价设备快照，再按原顺序推进归一化状态机。
