# 世界音乐请求与介质定位证据：0x0040CDD0–0x00411C8B

状态：B5.10 已按 LST 实现；旧光驱忙等具有已登记的平台替代

唯一行为真值：`swd3.exe.lst`

实现映射：

- `legacy_world_music.*`
- `legacy_media_acquisition.*`
- `legacy_world_music_test.cpp`
- `legacy_media_acquisition_test.cpp`

## 1. 0x0040CF40：8 字节世界音乐映射

`0x0040CF40` 从当前世界数据基址的映射区读取固定 8 字节记录：

```text
+0x00  u16 map_id
+0x02  u16 first_music_id
+0x04  u16 second_music_id
+0x06  u16 flags
```

`map_id == 0` 是表尾。找不到请求地图时，函数把
`0x004B7C78/0x004B7C7C` 清零，并只清除请求状态的 `0x000C0000`。

找到记录但两个音乐 ID 都没有变化时立即返回。发生变化时：

1. 把两个 16 位 ID 零扩展写入 `0x004B7C78/0x004B7C7C`。
2. 若 `0x004ACDBC & 0x00800000 == 0`，先把整个请求状态清零；编号 100
   的 stream 尚在时依次执行 `configure(2, 15)` 和 transition apply。
3. 依次应用掩码 `0x008FFFFF` 和 `~0x000C0000`。
4. 记录 flags 的 `0x8000` 直接结束；`0x4000` 提交 `0x000C0000`，
   `0x2000` 提交 `0x00080000`。

UT 对表尾、未命中、不变早退、普通/替代组和 fade 调用顺序分别断言。

## 2. 0x0040EB60：Music 路径生成

函数经世界数据内的四字节相对偏移表找到源文件名，从调用端提供的前缀开始构造：

```text
<base-prefix> + "Music\\" + <源文件名到首个 '.'（含）> + "mp3"
```

因此 `Story.11.wave` 的结果是 `Music\Story.mp3`，不是按最后一个句点替换。
原函数在复制长度超过 1024 时只调用已为空操作的报告函数，仍继续写；源串没有句点时
还会继续越界扫描。现代实现对有效游戏数据保持相同结果，对无句点的越界前提返回空
结果。这是宿主内存安全边界，不改变有效资产行为。

## 3. 0x0040CDD0：逐帧请求消费

入口调用顺序固定为：

1. `0x004858D0` 轮询 stream transition。
2. `0x00485830` 查询编号 100 的 stream 是否不存在。

只有 stream 不存在才继续。`0x004ACDBC` 的低四位先加一；
`0x00800000` 在两组槽和两组请求位之间选择：

| 组 | restart 位 | first-slot 位 | 槽索引偏移 |
|---|---:|---:|---:|
| 普通 | `0x00080000` | `0x00040000` | 0 |
| 替代 | `0x00020000` | `0x00010000` | 3 |

在选择前，函数先消费槽 3、再消费槽 0 的 `0x80000000` 待处理位；低四位写入
`0x004B7380`，槽 0 因后执行而具有覆盖效果。

递增后的 mode 大于 2 且没有对应 restart 位时，mode 固定为 3 并返回；有 restart 位
时根据 first-slot 位选 mode 1 或 2。最终槽索引为 `组偏移 + mode`。槽值为零或带
`0x00008000` 时不播放；否则严格按以下顺序：

1. `0x0040EB60` 生成路径。
2. `0x004856C0` 建立编号 100 的 stream。
3. `0x00485850` 设置音量。
4. 清除请求状态的 `0x00020000`。

所有出口都令 `AL = 1`；实现同样固定返回 `true`。结尾只重写请求状态低字节，其他位
按上述基本块产生的值保留。

## 4. 0x004118B0：原 DVD 介质获取

`0x004242B0` 先用 `GetDriveTypeA == 5` 枚举 `a:` 到 `z:` 的 CD-ROM 驱动器，并把
盘符写入以 `0xFF` 结尾的数组。`0x004118B0`：

- 入口先 `AIL_serve`，分配并清零 1024 字节路径缓冲区；
- 根据 `0x0040DC50(0x53)` 把内部模式设为 2 或 3；
- 设置进程生命周期位 `0x10`；
- 单光驱每 3000 ms、多光驱每 1000 ms 轮换检查；
- 路径格式固定为 `%sswd3\%s`，标记名是重复存放的 `swd3_dvd.dat`；
- `0x00412050` 只用 `CreateFileA` 判断文件存在，不读取内容；
- 成功时把路径首字节（盘符）写给调用者，清 `0x10`，返回 1；
- 输入取消时返回 2、设置关闭请求位 `0x04`，但没有清除 `0x10`。

遮罩保存、提示文字绘制、500 ms 画面反馈和忙等期间的 `AIL_serve` 都是旧同步光盘
提示的一部分，不是音视频解码。

## 5. 新系统兼容替代

OpenSWD3 已有命令行/TOML 数据目录，因此正常路径不再枚举 Win32 盘符或进入无限忙等。
确定性定位顺序为：

1. `<configured-data-dir>/swd3_dvd.dat`，用于已安装版/免光盘版数据目录；
2. `<configured-data-dir>/swd3/swd3_dvd.dat`，保留原光盘根布局。

定位前仍调用公共音频 service，并按原合同设置/清除生命周期位 `0x10`。两个位置都
不存在时返回明确的 unavailable 且清除 wait 位，避免在 Linux/macOS 或无光驱 Windows
上永久阻塞。单独的 cancel 状态迁移仍保留原版“设置 `0x04`、不清 `0x10`”结果供后续
调用者使用。

这个替代只改变旧介质获取平台机制，不改变脚本、地图音乐选择或媒体文件内容。
MP3/Bink 的解复用与解码不属于本单元，最终统一由项目自有 `libffmpeg` 动态库提供。
