# 战斗单例角色记录静态生命周期注册 `0x00451860`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 完整范围与外部chunk

权威LST主体为`0x00451860..0x00451869`，并声明外部`FUNCTION CHUNK AT 0x00451880 SIZE 0x0C`。完整函数合并13行主体与10行chunk，共23行。

主体无条件跳到chunk，真正返回位于`0x0045188B`；外部chunk必须计入审计。

## 2. 独立静态入口

函数无显式参数、无普通CODE XREF；唯一DATA XREF为`.data:0x0049E060`，位于组A、组B静态入口之后但保持独立。

主体调用`0x00451870`单例构造包装器。`0x00451870`与`0x00451890`各9行，均把固定对象token `0x00521598`装入ECX后分别尾跳公共构造`0x00478250`与公共析构`0x00478300`。两个公共本体均已按独立工作包typed关闭。

原构造寄存器返回不参与正常控制流；当前直接保存基础初始化状态与写入进展，
删除构造token返回、操作结果包装及构造调用计数。若构造在原写访问处
停止，静态入口保留已完成公共前缀并阻断`_atexit`注册。
`cleanup_registered`只有实际登记后才有值，构造停止时为空。
`00487BA0`的返回只有成功0与失败全1，现代接口以true/false表示实际
登记结果，不再暴露寄存器值。

## 3. 外部chunk与退出注册

chunk执行：

1. 压入单例退出包装器`0x00451890`；
2. 调用CRT `_atexit`；
3. caller回收一个参数；
4. plain返回。

最后EAX为`_atexit`结果，初始化迭代器不消费它。
当前直接登记释放同一单例资源的实际函数，删除注册Port与退出编号。
登记失败不回滚构造，见[退出清理所有权](battle-actor-owned-exit-cleanup.md)。

## 4. 两个附件尾跳包装器

`0x00451870`完整9行：`mov ecx,0x00521598`后`jmp 0x00478250`。当前构造函数直接对固定单例数据执行64次原始写入，返回基础初始化状态与写入进展。

`0x00451890`完整9行：`mov ecx,0x00521598`后`jmp 0x00478300`。
当前单例析构直接释放同一owner的文本；非零说明token只在实际释放成功后清零。
析构寄存器参数、端口与操作结果包装已删除，直接返回基础释放状态及失败位置。
退出登记也已迁移到实际函数集合，只在构造完整成功后登记。
此单例模型没有冒充已接通的SDL单例业务对象；当前SDL实际登记队伍和敌方。

## 5. 双向追溯

- `0x00451860..0x00451864`：调用单例构造包装器；
- `0x00451865..0x00451869`：无条件跳到外部chunk；
- `0x00451880..0x00451884`：压入单例退出函数地址；
- `0x00451885..0x0045188A`：调用`_atexit`并回收参数；
- `0x0045188B`：保留注册EAX并返回；
- `0x00451870..0x00451875`：装入固定this并尾跳公共构造；
- `0x00451890..0x00451895`：装入固定this并尾跳公共析构。

主函数及两个尾跳的上述寄存器描述记录原机器事实；构造与析构接口均不返回寄存器残值。
