# 文件对象、TSW 与 ACT 查询入口 ABI

最后更新：2026-08-02

状态：资源子系统三个公共机器边界已确认

完整汇编是唯一真实依据。TSW/ACT 样本只验证资源布局和有效输入，不覆盖汇编已经确定的参数截断、返回值和调用者行为。

## `0x004380B0`：文件对象打开

### 调用形状

ECX 传入文件对象，栈上依次有三个 32 位槽：

```text
[esp+4]   file_name
[esp+8]   creation_disposition
[esp+0xC] desired_access
```

函数在成功和失败出口都执行 `retn 0x0C`。这是 ECX 对象加三参数的成员式清栈边界，不是普通三参数 cdecl。

完整汇编逐项证明三个参数都真实存在：

- `0x004380C2` 读取文件名；
- `0x004380D2` 读取创建方式；
- `0x004380D6` 读取访问权；
- `0x004380DA..0x004380E8` 按 Win32 `CreateFileA` 顺序压入七个参数。

IDA 机械参数引用统计曾只把两个正栈符号计成“被引用”，原因只是中间参数的符号抽取限制，不能据此缩成两个参数。

### 返回和调用者策略

`CreateFileA` 返回 `INVALID_HANDLE_VALUE` 时，函数保存错误信息并在 `0x00438106` 固定 EAX 为零。成功时保存路径副本、把文件指针移到开头，并在 `0x00438138` 固定 EAX 为一。

35 个直接调用点中：

- 33 个立即测试、比较或转换 EAX；
- `0x004240EE` 不检查打开结果，直接查询文件大小并继续读取；
- `0x00426BB2` 不检查打开结果，直接移动文件位置并继续。

这两个忽略点是原行为，初步还原不得为“统一错误处理”擅自加入会改变有效/异常路径顺序的分支。

### 其他原样行为

函数在每次打开前无条件调用 `SetFileAttributesA(file_name,0x80)`，不检查该调用的返回值。若对象旧 `[+0x00]` 不是 `INVALID_HANDLE_VALUE`，入口只关闭这个文件句柄；它不在本入口完整执行映射、视图和旧路径字符串的析构流程。

这些是文件对象方法本身的行为。现代平台层可以用 RAII 表达所有权，但二进制差分和异常路径验证不能假设旧入口已经做了完整安全重置。

## `0x004315D0`：TSW 运行时帧记录查询

### 两个槽只认低 16 位

调用者压入两个 32 位槽：

```text
[esp+4]  resource_id
[esp+8]  variant_index
```

`0x004315D0` 自身把双字原样转交缓存查询 `0x00431DF0` 和装载 `0x00431C50`，但这两个下游入口都明确执行：

```text
resource_id  &= 0xFFFF
variant_index &= 0xFFFF
```

缓存键也由低 16 位资源号和低 16 位变体拼成。多个真实调用点只用 `mov ax,...` 或 `mov cx,...` 写低半寄存器后直接 `push eax/ecx`，上半 16 位并不稳定；下游截断正是实际 ABI 的必要部分。

所以合同不是两个普通 `uint32_t`，也不是只压两字节，而是：

```text
logical width = low 16 bits for each parameter
physical stack width = 4 bytes for each parameter
caller cleanup = 8 bytes
```

### 返回值

入口先查 `(resource_id_low16,variant_low16)` 缓存；命中时把记录移到桶首，未命中时加载并建立节点。最终 EAX 为 `0x004FB0C8` 保存的 20 字节运行时帧记录指针，失败为零。

144 个直接调用点最终都把 EAX 当记录指针消费。机械十二指令窗口立即识别 143 个；剩余 `0x00450AB6` 在检查另一参数的分支后，仍于 `0x00450AE2/0x00450AE9` 从 EAX 读取宽度或主流指针。很多调用点没有先判空就解引用，因此不得在上层虚构另一种错误返回协议。

### 特殊低字值

下游对 `resource_id_low16 == 0xFFFF` 有独立路径，使用变体低字参与分桶和动态记录装载。现代签名可以用两个 `uint16_t` 表达逻辑宽度，但不能在适配边界提前把 `0xFFFF` 当普通无效编号拒绝。

## `0x00432A50`：ACT 选中命令流查询

### 参数与 TSW 不同

入口同样接收两个 32 位 cdecl 栈槽：

```text
[esp+4] action_id
[esp+8] variant_index
```

但 ACT 下游 `0x00432E40` 直接以完整双字比较缓存节点 `[+4]` 和 `[+8]`，`0x00432D30` 也把完整 ESI/EBX 写入节点。这里没有 TSW 的统一低 16 位截断。

因此虽然 TSW 和 ACT 都是“编号加变体”的两参数查询，ABI 不能合并成同一个无条件 `uint16_t,uint16_t` 模板：

- TSW：两个 32 位物理槽，只认低 16 位；
- ACT：两个 32 位物理槽，完整 32 位参与缓存键和装载计算。

### 返回值与唯一调用点

缓存命中时返回节点 `+0x14` 的命令流指针。未命中时 `0x00432D30` 加载切片；成功返回全局 `0x004FB2E8` 指针，失败返回零。

唯一直接调用点 `0x00432421` 传入 `action+0x00` 的动作编号，以及 `action+0x08 + action+0x34` 的变体值。调用者在 `0x00432439` 回收八字节，写入 `action+0x54`，并立即检查是否为零。

## 共同初始化与范围

TSW 和 ACT 查询入口都在第一次调用时打开六个 `all_char/item/magic/sys/map1/map2` 包。这个延迟初始化不改变每次查询的两个参数和调用者清栈合同。

本文不重复各容器的磁盘格式；它们分别由 `tsw-archive-format.md` 和 `act-action-stream-format.md` 固定。当前新增结论只聚焦调用边界：

- 文件对象打开的 ECX/三栈槽/`retn 0x0C`；
- TSW 的低 16 位逻辑宽度；
- ACT 的完整 32 位键；
- 两种查询均返回指针或零，调用者策略不同。

## 1:1 还原约束

- 不把 `0x004380B0` 错写成 cdecl，也不漏掉创建方式参数。
- 保留文件打开前不检查结果的 `SetFileAttributesA` 调用顺序。
- 保留两个不检查文件打开返回值的直接调用环境。
- TSW 必须在语义上截断两个参数到低 16 位，同时保留旧边界的两个四字节槽。
- ACT 必须保留完整 32 位动作号和变体缓存键。
- 不补 TSW 调用者普遍缺少的空指针检查；兼容性保护若确有必要，只能隔离并证明不改变原有效路径。
