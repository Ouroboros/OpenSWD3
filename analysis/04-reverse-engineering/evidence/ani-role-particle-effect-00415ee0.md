# `0x00415EE0` 角色绑定粒子链

状态：完整 LST 控制流、物理状态、RNG 顺序、ACT→TSW→blitter 路径和链表删除异常已闭环；真实 variant 59 framebuffer 向量已通过。

唯一行为真值是 `swd3.exe.lst`。本文的“角色”和“粒子”只描述已经由汇编证明的坐标来源与动态节点，不从 IDA 函数名或伪码推断玩法名称。

## 调用边界与可见性裁剪

唯一调用点是 `0x00413C03..0x00413C27`。世界角色绘制器只在角色 `+0x10` 的 `AH bit 1` 非零且 service `0x48` 返回零时调用：

```text
sub_415EE0(role_world_x, role_world_y, zero_extend(role[+0x24]))
```

`0x00415EE1..0x00415F25` 在保存非易失寄存器、调用 RNG 和访问资产前，以有符号比较执行四条严格裁剪门：

```text
x <= viewport.left  - 64  -> return
x >= viewport.right + 64  -> return
y <= viewport.top   - 64  -> return
y >= viewport.bottom+ 64  -> return
```

加减保持 32 位回绕。等于外边界也裁掉；立即内侧仍继续。调用者负责角色状态位和 service `0x48`，本函数内部不重复查询。

## 共享动作记录

通过裁剪后，`0x00415F2F..0x00415F74` 按固定顺序执行：

1. `random(5) - 3`，范围是 `-3..1`，保存为本帧所有节点共用的 1/16 像素水平扰动；
2. 把共享 `0x98` 动作记录 `0x004ACAF8` 的 action 写成 `0x232B`、base variant 写成 `0x3B`；
3. 调用 `0x004321E0` 更新动作记录；
4. 以更新后的 `+0x4A/+0x4C` 调用 `0x004315D0`，取得一份供本次所有节点共用的 TSW 帧。

动作和 TSW 操作发生在发射器匹配之前，所以即使四个发射器都不匹配，仍会消耗一次 RNG、更新一次动作并查询一次 TSW。该动作记录不是本效果私有对象：`0x0040E57C/0x0040E601` 初始化它，`0x0040E621..0x0040E627` 设置初始 action/variant，`0x00415B70` 也复用同一记录。重写因此由上层传入共享记录，不能为两个效果复制两份状态。

## 四个发射器的物理布局

`EDI` 从 `0x004CACEA` 到 `0x004CAD1A`、每次加 `0x10`；它指向记录 `+0x0A`。因此 `0x004CACE0..0x004CAD1F` 是四个连续的 `0x10` 字节记录：

| 偏移 | 宽度 | 汇编证明的含义 |
|---:|---:|---|
| `+0x00` | 4 | 动态节点链头，零为空 |
| `+0x04` | 2 | 当前角色世界 X 的低 16 位 |
| `+0x06` | 2 | 当前角色世界 Y 的低 16 位 |
| `+0x08` | 2 | 有符号创建门字段；`>= 24` 禁止本帧创建 |
| `+0x0A` | 2 | 标志；本函数只改低字节 bit 0 |
| `+0x0C` | 2 | 角色 selector |
| `+0x0E` | 2 | 当前生产路径写零，本函数不读 |

已确认三条生命周期路径：

- `0x0040CC92..0x0040CCB8` 在地图角色建立时，把满足角色状态位的角色 X、Y、selector 写入下一个记录，并把 `+0x08/+0x0A/+0x0E` 写零；
- 剧情 opcode 62 的 `0x00429978..0x004299B7` 遍历四槽，对每个 selector 为零的槽写入同一角色；它故意不在首个空槽后退出；
- `0x0040F630..0x0040F66B` 先逐链释放四个链表，再把完整 `0x40` 字节写零。

本函数以 `movsx word [slot+0x0C]` 对比调用者零扩展的 selector。因此带最高位的 selector 存在原始有符号/无符号不对称，重写没有改成简单 `u16 == u16`。

匹配后，`0x00415F8D..0x00415FD2` 调用 `0x0040C0D0` 解析角色索引，从 216 字节角色表的 `+0x04/+0x08` 重读 X/Y，先清 bit 0，再以 `random(1000) > 250` 决定是否重新置位。解析返回值被原函数忽略；重写只在无效角色会造成宿主越界访问时增加明确的 `role_lookup_failed` 隔离状态。

## 动态节点布局与创建顺序

`0x00415FE9` 每次分配并清零恰好 `0x10` 字节：

| 偏移 | 宽度 | 含义 |
|---:|---:|---|
| `+0x00` | 4 | 下一节点 |
| `+0x04` | 2 | 1/16 像素 X |
| `+0x06` | 2 | 像素 Y |
| `+0x08` | 2 | 1/16 像素水平步进 |
| `+0x0A` | 2 | 垂直步进 |
| `+0x0C` | 2 | 寿命 |
| `+0x0E` | 2 | 清零后不再写 |

只有 `slot[+8] < 24` 且 flags bit 0 非零时创建。新节点头插，并严格按以下顺序消耗 RNG：

```text
y              = slot.y
x_1_16         = low16((random(16) + slot.x - 8) << 4)
map_id != 50: lifetime = random(30) + 30
map_id == 50: lifetime = random(16) + 16
horizontal     = random(16) - 8
vertical       = -1 - random(1)     // 结果恒为 -1，但调用仍必须发生
```

创建后立即进入同一帧的节点遍历，不存在“首帧只创建不更新”的延迟。

原节点的 `+0x00` 是 32 位指针。跨平台实现不能在 64 位宿主中把结构静默扩大，所以用零为空的稳定一基 `u32` token 表示链；六个数值字段及链字段仍组成精确 `0x10` 字节。原程序没有可观察的指针数值输出，token 只隔离宿主指针宽度，不改变链序、复制或释放时机。

## 每节点更新、寿命与原始删除异常

对每个实际节点，`0x00416087..0x004160B7` 无条件消耗一次 `random(1000)`，随后按 16 位回绕执行：

```text
x_1_16 += horizontal_step + frame_horizontal_drift
y       += vertical_step
if random(1000) > 50:
    --lifetime
```

寿命仍大于零才绘制。寿命小于等于零时不是普通 unlink：

- 非尾节点：把后继的完整 `0x10` 字节复制覆盖当前节点，链指针继续指向当前地址，释放后继，然后在同一帧重新处理刚复制到当前地址的节点；
- 尾节点：把指向当前节点的 link 写零，释放当前节点，结束该槽遍历。

因此一次物理循环可能更新一个已过期记录、复制后继，再为后继消耗另一份 RNG 并更新/绘制。用常规 `previous->next = current->next; delete current` 会改变节点地址、RNG 消耗和同帧行为，不能替换。

## 颜色、坐标与绘制

寿命为正时，`0x004160F1..0x00416131` 在每个节点绘制前改写三项 blitter 全局颜色偏移。根据 B4 已闭环的通道映射，`0x004CD71C/0x004CD30C/0x004CD304` 分别是红、绿、蓝：

```text
map_id != 50:
    red = green = blue = (signed_lifetime >> 1) - 30

map_id == 50:
    red   = lifetime - 30
    green = lifetime - 38
    blue  = lifetime - 50
```

这些是共享 blitter 状态，最后一次绘制的值会保留；runtime port 在调用 blitter 前写回实际 `LegacyBlitEffectState`，不是只建立无副作用的临时参数。

`0x00416136..0x0041617F` 使用共享动作记录 `+0x18` flags，并按以下位置绘制：

```text
draw_x = trunc_toward_zero(signed_i16(x_1_16) / 16)
         - signed(action.draw_offset_x) - viewport.left
draw_y = signed_i16(y) - signed(action.draw_offset_y) - viewport.top
```

帧宽高直接来自本次共享 TSW 视图，不做居中。blitter 返回值被忽略；重写继续遍历并只把失败次数作为诊断结果暴露。

- `0x10` 节点、`0x10` 发射器和四槽 `0x40` 状态；
- 四条包含边界裁剪、裁剪零副作用和无匹配时仍发生的动作/TSW 前置操作；
- selector 有符号比较、四槽重复 selector、bit 0 单独清写和角色坐标回读；
- 普通地图与 map 50 两套寿命/颜色公式；
- `random(1)` 在内的完整 RNG 次序、创建帧更新和 16 位回绕；
- 非尾复制后继并同帧重处理、尾节点 link 清零；
- 被忽略的 blitter 失败，以及 ACT、TSW、角色索引和损坏 token 的现代隔离门；
