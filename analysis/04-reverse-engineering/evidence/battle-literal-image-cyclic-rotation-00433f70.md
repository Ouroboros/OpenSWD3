# 战斗literal图像四方向循环平移 `0x00433F70`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 范围、ABI与调用图

权威LST函数范围为`0x00433F70..0x004342CA`，入口`proc`至`endp`连续，共378行，没有外部`FUNCTION CHUNK`。

ABI为stdcall：

```text
arg0 = 可写字图像命令流
arg4 = 模式0..3
arg8 = 正移位量
```

callee清理12字节参数。五个静态callsite位于`0x004514F2`、`0x00451678`、`0x004519CC`、`0x004536DE`和`0x00453835`；当前直接callsite可见的水平路径以正值调用模式3，以负值的绝对值调用模式2。

唯一callee为旧申请入口`0x00487C10`四处和旧释放入口`0x004885A0`四处，每个switch分支各一对。没有待关闭游戏callee。

此前计划把该函数临时描述为“四个owner缓冲分配”；完整LST证明该描述不准确。本函数每次只为一张图像申请一个临时块，完成循环平移后释放。

## 2. 入口门与先行副作用

函数顺序为：

1. `shift <= 0`立即返回，不读取图像；
2. 首word不是`0xFFFF`立即返回；
3. 读取u16宽和高；
4. 对图像`+8`首行头执行`&= 0x7FFF`；
5. 重读该行头，若高字节`& 0xC0`非零则返回；
6. 模式大于3则返回；
7. 进入四分支之一。

因此首行bit15清除早于行头flag门和模式门。即使原行头为`0xC00C`，函数也先写成`0x400C`，再因bit14返回。现代实现不回滚该写入。

图像`+6`格式word不读取。宽、高按无符号16位扩展；`row_words = width + 3`，`row_bytes = row_words * 2`。

## 3. literal行布局

函数要求固定literal字行布局：

```text
图像头：magic, width, height, format      8 bytes
每行：  row_header, literal_count, pixels[width], row_end
```

每行正好`width + 3`个word。垂直模式移动完整行记录；水平模式只移动`row+4`开始的`width`个像素word，保留每行行头、literal计数和终止word。

首行门只检查清bit15后的首行头，不逐行重新验证后续行。

## 4. 四个模式

### 模式0：整行循环上移

临时申请大小为：

```text
low32((width + 3) * shift * 2)
```

先把顶部`shift`行保存到临时块，再按从前向后的`rep movsd; rep movsb`把其余`height-shift`行移到图像头部，最后把临时块写到尾部。

### 模式1：整行循环下移

申请大小与模式0相同。先从`(height-shift) * row_bytes`位置保存末尾`shift`行，再从最后一行开始逐行把前部行向后移动，最后把临时块写到图像头部。

行循环方向、源目标差和负row步长都按32位x86运算保留。

### 模式2：像素循环左移

临时申请大小为`width * 2`。每行先把全部像素复制到临时块，再把前`shift`个像素写到行尾，把剩余像素写到行首。

### 模式3：像素循环右移

申请大小同模式2。每行先保存全部像素，再把末尾`shift`个像素写到行首，把前部剩余像素写到其后。

四个分支完成后都调用旧释放入口，包括水平模式高度为零且申请返回空指针的路径。

## 5. 32位域与不安全输入

函数不验证：

- `shift <= height`；
- `shift <= width`；
- 申请大小乘法是否回绕；
- 图像span是否覆盖声明的全部行；
- 申请是否成功；
- 临时容量是否满足请求。

垂直申请按`imul`与`shl`保留低32位。所有源、目标和临时偏移按u32回绕。

水平`shift > width`时，原剩余长度和目标位置回绕；原程序可能先写坏行头/像素，再在后续临时读取越界。现代实现不提前以数学域拒绝，而以逐个原始`movsd`/`movsb`读写检查在首次真实越界处typed-stop，保留此前flag和图像写前缀。

## 6. 临时分配与逐访问typed-stop

`LegacyBattleImageRotationAllocator`返回可注入字节容量：

- 正常分配拥有请求大小；
- 空指针表示旧申请失败；
- 测试可提供不足容量，固定首次越界位置。

每段旧`rep movsd; rep movsb`按原顺序执行：每个dword先完成4字节源读，再检查并完成4字节目标写；尾部逐字节读写。状态区分图像读、图像写、临时读和临时写越界。

申请失败不在申请返回点提前停止。若后续确有复制，先完成原源读，再在首个临时目标写typed-stop；若水平模式高度为零，则不复制，仍调用释放端口并正常完成。

原故障不会到达释放callee。typed-stop结果保留尚未释放的临时allocation与已写前缀供审计；正常路径显式调用release端口。

## 7. typed状态

现代状态包括：

- `completed`；
- 非正移位；
- 图像头短源；
- magic不符；
- 首行头短源；
- 首行flag不支持；
- 模式越界；
- 图像读/写越界；
- 临时读/写越界。

结果还记录宽、高、行字节数、请求临时字节、图像/临时写前缀、首行头是否写过、申请是否失败及临时块是否释放。它们是typed诊断，不宣称为旧返回值；旧callers不消费返回寄存器。

## 8. 双向追溯

LST到C++：

- `0x00433F70..0x00433FC7`：入口门、头字段、首行bit15清除、flag门与四路dispatch；
- `0x00433FCE..0x00434080`：模式0顶部暂存、前移、尾部回写与释放；
- `0x00434083..0x00434134`：模式1尾部暂存、逆序后移、头部回写与释放；
- `0x00434137..0x0043420D`：模式2逐行全像素暂存、前段写尾与剩余写头；
- `0x00434210..0x004342CA`：模式3逐行全像素暂存、尾段写头与前段后接。

C++到LST：

- 每个入口读写和早退有唯一指令；
- 四个申请公式、循环计数、行步长和三段copy来源明确；
- 八处申请/释放call均已映射；
- 通用copy helper只展开原`rep movsd; rep movsb`，不改变顺序；
- 没有新增取模归一化、边界夹值、失败重试、图像重编码或透明色处理。

完整正向与反向追溯未发现未解释基本块、jump-table case、callee、copy段、字段或出口。

## 9. 测试与动态差分

定向测试覆盖：

- 3×3 literal图像四方向各移1的精确像素序列；
- 完整行移动与仅像素移动的边界区别；
- 首行bit15清除；
- 非正移位和magic不符不触图像；
- 不支持flag及非法模式保留先行清位；
- 申请失败停在首个临时写；
- 容量5时保留一个dword加一个byte的5字节前缀；
- 短垂直源在保存首行后停于首个缺失行读；
- 零高度水平模式仍申请、清位和释放；
- 水平shift大于宽度时保留原首个4字节破坏前缀，再停于临时越界读。

本函数不消费物理游戏资产。定向battle聚合测试与零warning构建通过。

当前没有可用原版战斗literal图像变形联合捕获后端，`original_diff_verified`为`blocked_runtime_oracle`。完整378行LST、typed实现与固定状态已经闭环。
