# `0x00438000..0x00438640` 文件对象复核

状态：B2.3a 闭环；`assembly_exact`、`platform_adapted`、`blocked_runtime_oracle`

来源：`swd3.exe` 完整汇编。IDA 伪码只辅助辨认 Win32 参数，不作为行为依据。

## 1. 对象与生命周期

`0x00438000` 把原对象初始化为 80 字节：

- `+0x00`：文件句柄，初值 `INVALID_HANDLE_VALUE`。
- `+0x04`：文件映射句柄，初值零。
- `+0x08`：当前映射视图，初值零。
- `+0x0C`：动态文件名，初值零。
- `+0x10..+0x4F`：64 字节错误文本，逐双字清零。

析构入口 `0x00438030` 依次释放视图、映射和文件；视图或映射释放失败会写错误文本并提前返回。显式关闭 `0x00438150` 使用相同顺序，但返回成功/失败；文件成功关闭后释放文件名，清零错误文本并把文件句柄恢复为无效值。文件句柄本来无效时显式关闭直接成功，不额外清除旧字段。

## 2. 打开、位置和普通读写

`0x004380B0` 先关闭已有文件句柄，再忽略 `SetFileAttributesA(path, FILE_ATTRIBUTE_NORMAL)` 的结果，最后以共享模式零和 `FILE_ATTRIBUTE_NORMAL | FILE_FLAG_SEQUENTIAL_SCAN` 调用 `CreateFileA`。失败时格式化系统错误；成功时复制文件名并把位置移到开头。

当前调用点只出现以下实参：

- 创建方式：`OPEN_EXISTING`（3）和 `OPEN_ALWAYS`（4）。
- 访问方式：`GENERIC_READ`、`GENERIC_WRITE`、`GENERIC_READ | GENERIC_WRITE`。

`OPEN_ALWAYS` 不截断已有内容。`0x00438340` 只返回 `GetFileSize` 的低 32 位，无效句柄返回 `0xFFFFFFFF`。`0x00438360` 在当前位置截断，无效句柄返回失败。

`0x00438380` 与 `0x004383E0` 分别执行普通读写：文件无效、缓冲为空或请求长度为零时失败；系统调用失败时把长度写为零；系统调用成功时把请求长度原位改写为实际长度并返回成功。因此 EOF 短读也是成功。

`0x00438440` 对 32 位有符号距离作符号扩展，再按 begin/current/end 调用 `SetFilePointer`。`0x004384A0`、`0x004384B0`、`0x004384C0` 对底层返回值无条件加一：正常位置是一基值，底层无效句柄的零变成一，底层失败的 `0xFFFFFFFF` 回绕为零。`0x004384D0` 单独查询零基当前位置，失败时不写输出参数。

## 3. 映射和视图

`0x004381E0` 用文件低 32 位大小创建只读映射。`0x00438290` 在建立新视图前释放旧视图；释放失败时保留原指针并返回空，成功后以 `FILE_MAP_READ` 建立新视图。当前所有调用点都传 `offset = 0`、`size = 0`，即完整文件视图。

`0x004382E0` 要求关闭参数与对象保存的视图指针完全相等；不相等时调用 `0x00411F90` 记录 `cFile ,CloseView Src/Dest difference ` 并返回失败。相等的空指针直接成功；非空指针只有在系统解除映射成功后才清零。

`0x00438230` 先关闭活动视图再关闭映射句柄，每一步只在成功后清零对应字段；不存在映射时幂等成功。

## 4. 小型读写与时间

`0x00438520` 是精确写包装：普通写成功且实际长度等于原请求长度才成功。`0x004385A0` 精确写一字节；`0x004385B0` 虽被 IDA 错标为单个 `char`，汇编实际取栈参数地址并写四字节，因此对应小端 `u32`。

`0x004385C0` 调用普通读但不比较实际长度。`0x00438600` 和 `0x00438610` 分别读取一、四字节，所以四字节 EOF 短读会保留目标原值中未覆盖的高位字节。这一看似异常的行为按汇编保留。

`0x00438570` 只在句柄有效时转发 `GetFileTime`；现有唯一调用点 `0x00409A92` 只请求最后写入时间。`0x00438620` 以 `FORMAT_MESSAGE_FROM_SYSTEM` 和固定 64 字节缓冲格式化错误，`0x00438640` 返回该缓冲地址。

## 5. C++ 映射与平台隔离

公共接口位于 `include/openswd3/resource_io/legacy_file.hpp`，实现位于 `src/resource_io/legacy_file.cpp`：

- Windows 后端直接使用文件句柄、共享模式零、顺序访问提示、只读文件映射和真实映射视图。
- 路径从原 ANSI API 隔离为 `std::filesystem::path` 和宽字符 Win32 API，避免新系统路径编码失败；可观察的打开方式、访问权限和文件位置不变。
- POSIX 后端使用 `open/read/write/lseek/ftruncate/mmap` 提供可用的对应合同；Win32 文件属性、共享拒绝和顺序访问提示属于 `platform_adapted`，仍待非 Windows 构建机验证。
- `std::span` 拦截原函数无法表达的缓冲容量越界；合法调用的长度改写和短读语义不变。错误文本仍固定在 64 字节内。
- C++ 对象不复制原 32 位内存布局；它复制该对象的状态机和可观察合同。原始 80 字节 ABI 不暴露给其他重写模块。
- 视图指针不匹配的失败返回已经保留；原 `0x00411F90` 文本日志等统一日志端口接入后再恢复，不改变文件对象返回合同。

## 6. 验证

`tests/unit/resource_io/legacy_file_test.cpp` 覆盖：

- `OPEN_EXISTING` 缺文件、`OPEN_ALWAYS` 创建与不截断，以及只读、只写、读写访问。
- 一/四字节小端精确写、普通 EOF 短读、长度改写和四字节部分覆盖。
- 三种一基定位、零基当前位置、无效句柄特殊返回、大小和当前位置截断。
- 完整只读映射、重映射、错误指针关闭、正确关闭及映射幂等释放。
- 显式关闭幂等、64 字节错误边界、成功关闭清错和最后写入时间。

Windows LLVM `core-debug` 与 `app-debug` 均完成构建和 26/26 CTest；`app-debug` 同时完成最终 `openswd3.exe` 链接。测试夹具只写 `build/<preset>/tests/runtime/` 下的独立目录并在结束时删除，不使用系统 TEMP。

原程序动态错误注入和逐调用差分仍缺运行 oracle，因此不能标记为 `original_diff_verified`。合法路径已经逐基本块复核；Win32 后端和 UT 证明当前实现覆盖 B2.3a 的可观察文件、位置、长度与映射合同。
