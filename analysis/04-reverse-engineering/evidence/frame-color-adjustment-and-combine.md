# 整帧颜色偏移、双输入合成与灰度函数

状态：`0x00420490–0x004208C5` 与 `0x00421FB0–0x00422025` 的六个 packed-16 颜色函数、全部 50 个直接调用点、循环异常边界和四种受支持像素布局已闭环。

## 证据口径与范围

完整汇编是唯一逻辑真值。本文依据函数体 `0x00420490–0x004208C5`、`0x00421FB0–0x00422025`，以及 `0x00423400–0x00423885` 建立的 mask、shift 和查表数据。IDA 伪码只用于定位，不作为类型、公式或循环边界证据。

这次调查也把“`sub_420xxx` 整帧颜色函数群”这个旧工作名精确收窄：

- `0x00420490–0x004208C5` 是五个颜色偏移/双输入函数；
- `0x00421FB0–0x00422025` 是一个原地灰度函数；
- `0x004208D0–0x00422C61` 属于已经单独闭环的软件 blitter；
- `0x00422C70/0x00423020` 是带 10.10 步进的 RLE 精灵写入器，不是整帧颜色函数；
- `0x004233D0` 只把三个 surface mask 写给调用者。

因此本文不因地址相邻而把后面三类函数混入颜色辅助函数规格。

机器目录：

- `../inventory/frame-color-functions.tsv`：六个函数的物理访问宽度、循环步长和无效计数行为；
- `../inventory/frame-color-callsites.tsv`：完整汇编中的 50 个直接调用点；
- `../inventory/frame-color-format-vectors.tsv`：四种受支持 mask 布局下的 24 个精确整数向量；
- `../../tools/build_frame_color_inventory.py`：锁定 EXE 与完整汇编哈希、关键指令和全部调用地址的生成器。

## 共同像素字段

`sub_423400` 对四种受支持 DirectDraw mask 都建立三个实际五位通道。记：

```text
MR, MG, MB = 当前红、绿、蓝有效 mask
sR, sG, sB = 对应右移位数
UR, UG, UB = 1 << sR, 1 << sG, 1 << sB
```

四组运行时有效字段为：

| DirectDraw 输入 mask | 颜色函数使用的有效 mask | shift |
|---|---|---|
| `7C00/03E0/001F` | `7C00/03E0/001F` | `10/5/0` |
| `F800/07C0/003F` | `F800/07C0/003E` | `11/6/1` |
| `F800/07E0/001F` | `F800/07C0/001F` | `11/6/0` |
| `FC00/03E0/001F` | `F800/03E0/001F` | `11/5/0` |

这沿用既有像素格式证据的结论：六位通道会被收窄到五位有效字段，不能在新程序里擅自恢复被原程序舍弃的最低位。

## `sub_420490`：三通道有符号偏移

cdecl 参数的物理顺序是：

```text
sub_420490(buffer, count, red_delta, green_delta, blue_delta)
```

`0x00420496–0x004204C2` 先以有符号 `imul` 计算三个 `delta × unit`。对任一通道，汇编的准确 32 位规则可写成：

```text
field = u32(pixel_dword & M)
x     = u32(field + u32(delta * U))

if (x & u32(~M)) != 0:
    x = (delta >= 0) ? M : 0
```

最后将三个不相交字段按位 OR，并只写回低 16 位。对正常、未发生乘法回绕的 delta 域，它等价于：

```text
out_c = clamp(in_c + delta_c, 0, 31)
```

但实现规格不能只剩一个抽象 `clamp`：原函数先进行模 32 位乘加，再用 `~mask` 测试字段外位；极端 delta 的回绕结果必须以这条机器公式为准。

每次循环在 `0x00420509` 执行 `mov eax,[esi]`，即从逻辑 `u16` 像素地址读取四字节，最后却在 `0x00420549` 只写 `dx`，然后地址加二。因此最后一个像素会额外读取请求区间之后的两个字节。正常调用缓冲都使该读取可用，但这是原始物理访问，不得把伪码中的 `_DWORD *` 误解成四字节像素。

## `sub_420560/600/6F0`：单通道变体

`sub_420560(buffer,count,delta)` 只改变红字段。它仍逐像素执行四字节读取、两字节写回，正负分支与 `sub_420490` 的红通道完全相同。

`sub_420600` 和 `sub_4206F0` 分别只改变绿、蓝字段，但不是简单的逐 `u16` 循环。二者把 mask 与 `delta×unit` 复制到一个 32 位值的高低两个 16 位 lane，一次读取、修改和写回两个像素：

```text
M2 = M | (M << 16)
D2 = u32(delta*U) | u32((delta*U) << 16)
pair = dword(buffer)
```

随后按 delta 正负对 `pair & M2` 做一次 packed 32 位加或减；低 lane 用 `test cx,ax` 判定字段外位，高 lane用高 16 位 overflow mask 判定，各自替换为 mask 或零。正常 delta 和正常两像素输入下，结果等价于两个独立的五位通道饱和偏移；极端乘法回绕、lane 间进位和异常计数仍必须遵循原 32 位指令顺序。

三个单通道函数的当前 9 个调用全部传入偶数正计数：每个函数各有两个 `0x3C000` 和一个 `0x4B000` 调用。因此 packed 两像素循环在当前正常调用链上满足自己的隐含前置条件。

## `sub_4207E0`：溢出清零，不是饱和加色

cdecl 参数是：

```text
sub_4207E0(source, destination, count)
```

循环逐个读取 `u16(source)` 和 `u16(destination)`，将结果写回 destination。函数进入后先把三个全局 mask 与 `0xFFFF`，并把截断结果写回原全局；这个副作用发生在 count 检查之前。正常 `sub_423400` 初始化后高 16 位本来就是零，所以正常路径上幂等，但 count 为零也不能省略该写回。

三个通道分别执行：

```text
index_c = ((source & Mc) >> sc) + ((destination & Mc) >> sc)
out_c   = table_c[index_c]
```

`0x00423835–0x00423855` 为每张表写入前 32 项：

```text
table_c[i] = i * Uc,  i = 0..31
```

紧接着 `0x00423857–0x00423885` 把三张表各自后续 32 项清零。因此完整规则是：

```text
scalar_out_c = scalar_source_c + scalar_destination_c,  和小于 32
scalar_out_c = 0,                                       和为 32..62
```

这不是常见的饱和加色，也不是五位模 32 回绕。任一通道的和达到 32 就把该通道整个清零。24 个格式向量中专门固定了“三通道和都等于 32，结果为 `0x0000`”的用例，防止后续误写成 `min(sum,31)`。

当前完整汇编只有 7 个直接调用，全部传 `count=1`。函数虽然有多像素循环，当前程序只把它作为单像素双输入颜色合成器使用。

## `sub_421FB0`：除以四的暗灰度

对每个 `u16` 像素，函数先提取三个五位标量：

```text
r = (pixel & MR) >> sR
g = (pixel & MG) >> sG
b = (pixel & MB) >> sB
q = (r + g + b) >> 2
out = (q << sR) + (q << sG) + (q << sB)
```

它不是除以三的算术平均，也不是带权亮度公式。最大输入之和为 93，右移二位后最大只有 23，所以全白会变成通道值 23 的暗灰，而不是白色。

当前三个直接调用中，两个处理 `0x4B000` 个像素，另一个在 `sub_43B110` 中按 caller-controlled 的正 `EBP` 跨度逐段处理。

## 循环边界是规格的一部分

这些函数没有统一的空区间语义：

| 函数 | 计数更新 | `count==0` | 奇数/负数 |
|---|---|---|---|
| `sub_420490` | `count -= 1`，尾测 | 若内存不先异常，执行 `2^32` 次 | 非零值按 `u32(count)` 次执行 |
| `sub_420560` | `count -= 1`，尾测 | 同上 | 同上 |
| `sub_420600` | `count -= 2`，尾测 | 若内存不先异常，执行 `2^31` 次 | 奇数永远不能到零；负偶数按模 32 位推进 |
| `sub_4206F0` | `count -= 2`，尾测 | 同上 | 同上 |
| `sub_4207E0` | 先测零，再 `count -= 1` | 不访问像素，但仍写回截断 mask | 负数作为非零 `u32` 大计数执行 |
| `sub_421FB0` | `count -= 1`，尾测 | 若内存不先异常，执行 `2^32` 次 | 非零值按 `u32(count)` 次执行 |

初步 1:1 还原不能给五个尾测循环统一加 `if (count <= 0) return`，也不能给两个 packed 函数补奇数尾像素。这些看似安全的改动会修掉原行为。当前所有真实调用都满足正常计数前置条件，所以不需要用兼容性修复覆盖它们。

## 完整调用可达性

完整汇编没有取得这六个函数地址后再间接调用的路径；全部可见使用都是生成器锁定的 50 个直接 cdecl 调用：

| 目标 | 调用数 | 当前物理范围 |
|---|---:|---|
| `sub_420490` | 31 | 7 次完整 `640×480`、2 次 `0x3C000` 前缀、19 次单像素、3 次动态正跨度 |
| `sub_420560/600/6F0` | 9 | 合计 3 次完整帧、6 次 `0x3C000` 前缀 |
| `sub_4207E0` | 7 | 全部单像素 |
| `sub_421FB0` | 3 | 2 次完整帧、1 次动态正跨度 |

按物理范围汇总是 12 次完整 `0x4B000`、8 次 `0x3C000` 前缀、26 次单像素和 4 次动态跨度。这也纠正了旧工作名的另一处含混：同一函数群既服务整帧/帧前缀，也服务栈上颜色和单像素目标，并非每个调用都遍历整个画面。

## 1:1 重写约束

- 颜色核心仍必须在原 16 位工作缓冲上完成，再由 SDL3 平台层上传；不能用 GPU blend 或 32 位浮点颜色近似。
- `sub_420490/560` 的四字节读取、两字节写回是独立的访问合同；不能因 IDA 类型或现代容器类型而改成四字节像素。
- `sub_420600/6F0` 必须保留双 lane 的 packed 32 位运算和 `count-=2`；不能自动处理奇数尾项。
- `sub_4207E0` 的 overflow-to-zero 查表和 count 为零时的 mask 写回不能改成饱和加色或纯函数。
- `sub_421FB0` 必须使用无权重整数和后右移二位；不能替换成平均灰度、BT.601/BT.709 或 gamma-aware 亮度。
- 原游戏逻辑与异常边界均不在本阶段修复；只有日后被证明阻断启动或新系统运行的平台问题，才允许在平台适配层做单独记录的最小修正。

## 阶段结论

此前未收口的颜色辅助函数现已形成可直接转写和差分验证的汇编级规格。加上既有像素格式、软件 blitter、字体 footprint、帧缓冲呈现、输入状态和时钟证据，P4 的静态规则恢复已完成。跨平台字形 oracle 与原程序截图捕获仍是后续差分验证基础设施，不改变这些已经由汇编确定的整数行为。
