# 世界地图装载进度界面闭环

状态：`platform_adapted`、`assembly_exact`（正常调用域）、`unit_tested`；原程序动态差分
仍为 `blocked_runtime_oracle`。

唯一行为依据是 `swd3.exe.lst` 的 `0x0040ED60..0x0040EFCB`。IDA 给出的
`char __cdecl sub_40ED60(int)` 返回类型不是调用合同：15 个调用点均在调用后直接恢复
栈或继续执行，没有读取 EAX。现代接口因此返回显式诊断结果，不把尾部残留寄存器值
伪装成原版语义。

## 1. 调用域

| 调用者 | 调用地址 | 进度值 |
|---|---|---|
| `sub_40C130` | `0x0040C193/0x0040C51B/0x0040C682/0x0040C7B0/0x0040CD3C/0x0040CDA8/0x0040CDB4` | `-1/2/10/85/90/95/100` |
| `sub_425BE0` | `0x00425E87/0x0042604E/0x00426249/0x004262BF/0x00426420/0x0042665B/0x0042679A` | `15/60/65/70/75/80/85` |
| `sub_426DF0` | `0x00427037` | `15 + unsigned quotient` |

当前新游戏入口只需要承接 `sub_40C130` 的首次 `-1` 与终值 `100`。中间可见进度调用
仍属于尚待独立收敛的 `sub_425BE0/sub_426DF0`，不能在 SDL 层伪造里程碑。

## 2. `-1` 重置与 flag 70

`0x0040ED69..0x0040EDCA` 在参数为 `-1` 时执行以下顺序：

1. 将进度及保留槽 `0x004CC2B8/0x004CC2C0` 清零，并把本次有效参数改为零；
2. 调用 `sub_439070(2)`，结果加一后保存为标记动作 id，因此取值为 `1..2`；
3. 把红、绿、蓝原始分量分别置为 `0x1F/0x73/0xFF`，清零保留槽
   `0x004CC2C4`；
4. 分别以 `sub_40DC00` 初始化背景和标记动作记录。该 helper 只重置指定字段，不能把
   整条动作记录清零。

随后 `0x0040EDCE` 总是查询剧情位 70。该位为一时，本次调用跳过 framebuffer 清屏、
音频维护、进度条、动作绘制和画面提交；有效进度为 `100` 时，仍在函数尾清除 flag 70。
`sub_40E0B0` 初始设置该位，所以新游戏第一次装载只可观察到 `-1` 的 RNG/动作初始化和
`100` 的清位，所有中间进度均被抑制。

## 3. 可见进度界面

flag 70 为零时，`0x0040EDE0..0x0040EFB6` 的顺序为：

1. 锁定公共显示表面并以 `rep stosd` 清零 `0x25800` 个 dword，即
   `640 × 480 × 2` 字节；
2. 调用一次 `_AIL_serve@0`；
3. 以 32 位回绕乘法计算 `limit = trunc_toward_zero(progress * 394 / 100)`；
4. `limit >= 0` 时按包含上界的 `0..limit` 绘制竖列。每列起点为
   `(123 + column, 445)`，沿表面实际 pitch 写 30 个像素；
5. 背景动作使用 id `0x232A`、基础变体 `0x4F`、变体增量零，在 `(120,442)` 更新并
   绘制；标记动作使用重置时选出的 id、基础变体 `0x10`、变体增量 3，在
   `(limit + 107,460)` 更新并绘制；
6. 在 `0x0040EFAE` 以六个原参数提交公共表面，再调用一次 `_AIL_serve@0`。

第 `n` 列的三个原始颜色分量严格为：

```text
red   = 0x1F + trunc_toward_zero(n * 0x246 / 0x400)
green = 0x73 + trunc_toward_zero(n * 0x0DA / 0x400)
blue  = 0xFF + trunc_toward_zero(n * -0x296 / 0x400)
```

三个分量均算术右移三位后交给已收敛的 `sub_4239D0` 像素打包 owner。进度零仍绘制首列，
RGB555 为 `0x0DDF`；进度 100 的 `limit` 为 394，共 395 列，末列原始分量为
`254/198/1`，RGB555 为 `0x7F00`。对 `progress * 394 / 100` 的现代实现另以十万个随机
32 位值和边界值对照汇编的 `0x51EB851F` 有符号除法序列，结果完全一致。

动作更新、动作绘制和画面提交的失败不会改变原函数后续控制流；现代结果只记录诊断，
不将其提升为原版不存在的提前返回。

## 4. 平台隔离

原函数取得 DirectDraw 表面的裸像素指针后立即解锁，后续仍通过该指针清屏和写进度条，
最后另行提交表面。现代实现使用 B4 的受控 `LegacyFramebuffer` 和统一 presentation
端口，保留清屏范围、pitch、像素、绘制顺序及提交时点。小于固定画布或异常进度导致
写入越界时返回明确安全状态；这两项仅隔离原版无效状态，所有已发现正常调用值保持
汇编行为，因此登记为 `platform_adapted`。
