# 16 位软件 blitter 分派与像素效果

状态：分派器、RLE/span 命令、三类 16 档混合表及全部已赋值效果族已闭环；当前 TSW/ACT 的 `0x08` 与正常初始化程序的动态 `0x20` 空槽可达性均已闭环，异常内存状态单列为 1:1 边界。

## 证据口径

完整汇编是唯一逻辑真值。分发表依据 `0x00416D90–0x00416F0E`，裁剪和分派依据 `0x004170E0–0x004174CA`，像素循环依据 `0x004176D0–0x00422C61`，位域掩码建立依据 `0x00423610–0x00423740`。IDA 伪码只用于定位和给局部变量起临时名字；本文公式均回查汇编。

本证据块只恢复原软件 surface 上的 16 位整数行为，不把结果改写成 SDL blending、浮点 alpha 或 32 位近似色。

## 稀疏分发表

`0x00416D90` 以 `0x004CD318` 为基址写入 43 个槽，共 31 个唯一目标函数。槽号由最终调用 `0x0041748A` 的：

```text
call dword_4CD318[ebx*4]
```

直接决定。低两位不是混色模式：

- bit 0 选择水平正向/反向函数；
- bit 1 在 `0x004173C3–0x004173E0` 调整纵向起点和行步长，同一函数地址可能同时填入 bit 1 为零和一的槽；
- `flags & 0x7C` 才是效果族；
- 分发表是稀疏表，不存在的组合没有自动回退路径。初始 BSS 为零时调用未赋值槽会落到空指针，不能在重写中擅自补成普通 copy。

完整逐槽结果见 `../inventory/blitter-dispatch.tsv`。

### RLE/span 与原始矩形的选择方向

`0x004170E0–0x00417103` 在源首字等于 `0xFFFF` 且 `0x004CD764 == 0` 时给 flags 置 `0x80000000`。后续 `0x004173E8–0x00417475` 的实际选择是：

```text
flags bit31 == 1  -> table index = flags & 0xFFFF
flags bit31 == 0  -> table index = (flags & 0xFFFF) + 0x80
```

所以低位槽是 RLE/span 函数族，`+0x80` 才是原始矩形函数族；不能从“设置了高位”字面猜成相反方向。

当前 `+0x80` 族只赋值：

```text
0x80/0x81        原始 copy
0x84/0x85        原始色键 copy
0x88             原始特殊效果
0x94             原始步进透明度
```

`0x004176D0` 还证明原始 copy 有两种源：`0x004CD764 != 0` 时逐字节读取索引并经 `u16` 调色板转换；为零时逐 `u16` 原样复制。

`0x00417840/0x00417E40` 不是原始加色。正向函数对直接 16 位源跳过转换后色键的低字，对索引源跳过索引 1；反向函数却把零扩展的源 `u16` 与高低字重复的 32 位色键比较，正常非零色键永远不相等，因此会被复制。地址级证据和实现验证见 `legacy-blitter-color-key-and-saturated-arithmetic.md`。

## RLE/span 物理命令

RLE 函数先要求源记录 `[+6] & 0x10 != 0`，随后从 `source+8` 读取行记录。每行首个 `u16` 是整条行记录的物理字节数，低 15 位用于跳到下一行；零值结束。行内每个 `u16` 命令：

| 高两位 | 低 14 位 | 普通效果族行为 | 是否携带逐像素源数据 |
|---|---:|---|---|
| `0x0000` | run 长度 | 处理目标像素 | 是，命令后紧跟 `run` 个 `u16` |
| `0x4000` | run 长度 | 透明跳过 | 否 |
| `0x8000` | run 长度 | 多数模式跳过；`0x08` 族有专用处理 | 否 |
| `0xC000` | run 长度 | 因先测试 bit 14，走透明跳过 | 否 |

低 14 位为零时结束当前行的命令消费。普通 copy 的透明不是“把某个 16 位色值当 colorkey”，而是高两位 run 类型；literal run 内的 `0x0000`、`0xFFFF` 等像素值均照常复制。

## `0x14`：15 档步进透明度

`0x00417107–0x00417130` 对 `(flags & 0xFFFC) == 0x14` 先执行全局门：

- `0x004CC2F0 <= 0`：整次绘制跳过；
- `0x004CC2F0 > 15`：把 mode 清成低两个翻转位，退化为普通 copy；
- `1..15`：保留 `0x14`，进入步进透明度函数。

`0x0041D34C` 再把该值左移两位，作为 16 项局部跳转表的字节索引。`0x0041D436–0x0041D4D7` 建立标量正向表，其 16 个目标和逐项项式已由工具从汇编提取到 `../inventory/blitter-opacity-steps.tsv`。

`0x00423686–0x00423740` 为每个实际 surface mask 建立安全右移掩码：

```text
M[k] = duplicate_u16(((R >> k) & R) | ((G >> k) & G) | ((B >> k) & B))
k = 1..5
```

透明度循环使用 `M1=0x004CD788`、`M2=0x004CD78C`、`M3=0x004CD790`、`M4=0x004CD794`，先对源/目标 packed pixel 独立右移并掩掉跨通道位，再直接相加；没有乘法、浮点、进位补偿或舍入常数。

令 `a` 为原全局步进值，逐通道等价权重为：

```text
a == 0:   dst 保持不变
1..14:    sum(binary fractions of src * a/16)
         + sum(binary fractions of dst * (15-a)/16)
a == 15:  直接复制 src
```

关键异常是 `1..14` 的源、目标权重和恒为 `15/16`，不是常见的 `16/16`。例如 `a=1` 的 `0x0041D790–0x0041D7C4`：

```text
(dst >> 1 & M1) + (dst >> 2 & M2) + (dst >> 3 & M3) + (src >> 4 & M4)
```

即 `14/16 dst + 1/16 src`。`a=14` 则是 `14/16 src + 1/16 dst`。只有 15 在 `0x0041DAA5` 直接复制完整源像素。这个系统性暗一档及每个分数项的独立截断都属于原图像语义。

## 已闭环效果族

以下公式按红、绿、蓝三个实际有效通道独立执行；六位 surface 通道已在 `0x00423400` 的表初始化中收窄为原引擎使用的五位有效 mask。

### `0x00`：literal copy

`0x00418350/0x004185C0` 对 literal run 逐 `u16` 原样复制，高位 run 全部只移动目标指针。没有像素 colorkey 比较，也没有颜色转换；资源进入 blitter 前已由 forward 转换器变成当前 surface 格式。

### `0x08`：RLE coverage composite 与原始常量纵向淡出

同一 mode 的 RLE 与原始矩形槽不是同一种输入合同。

RLE 正向函数 `0x00419570` 把第五个 blitter 参数当作逐像素字节平面。顶部裁剪和每个 run 都按像素数同步推进该指针；literal run 对每个字节直接作为 16 项局部跳转表索引，没有 `& 0x0F` 或范围检查。有效值 0..15 的结果为：

```text
coverage == 0:   dst 保持不变，src 不读取
1..14:           exact_packed_src + dst * (15-coverage)/16
coverage == 15:  直接复制 src
```

目标分数仍由 `M1..M4` 的独立右移掩码相加，没有舍入。与 `0x14` 不同，这里 coverage 1..14 的源像素不右移，而是把 packed `src` 原样相加；仅从消费公式不能断言假想生产者是否预乘。16 档目标、权重和项式见 `../inventory/blitter-coverage-composite-steps.tsv`。

RLE 的 `0x8000` run 不携带源像素，也不读取 coverage 字节，但仍按 run 长度推进 coverage 指针。正向 `0x0041A327` 把每个目标写成硬编码 `0xFFF0`。反向 `0x0041B1DC–0x0041B1F1` 则执行：

```text
index = ((u16(dst) >> 1) & 0xFFFE)
dst = *(u16 *)(*(u32 *)0x004CDC00 + index)
```

`0x004CDC00` 位于 PE 零初始化区；完整汇编只有这一次绝对地址读取，没有直接写入或取址初始化。因此在没有未识别的计算地址写入/内存破坏时，反向 `0x8000` run 会从空指针派生地址读取。当前只能把它登记为原始危险路径，不能虚构一张“合理”的阴影表。

#### 当前 TSW/ACT 资产链的可达性结论

两套 TSW 加载包装 `0x00433380` 与 `0x00433720` 都先把六个临时双字清零，再把临时记录 `+0x08` 复制到运行时图像记录 `+0x04`。对应低层加载器 `0x00433540/0x004338F0` 对临时 `+0x08` 的唯一写入都是零；`0x00401C70` 的 8 位源转换只清运行时 `+0x08` 调色板槽。因此当前 EXE 从 TSW 得到的第五个绘制参数不是“通常为空”，而是恒为零。

资产本身仍保留一组未消费辅助数据：7316 个描述符有非零 `+0x0C` 且 `+0x14 == width×height`，其中 7148 个在主流后有共 8,463,829 字节的 `+0x10` 物理载荷。但当前两套加载器都不读这些字节，也不把它们接到运行时 `+0x04`。没有对应消费汇编，不能仅凭尺寸把它命名为 coverage，更不能在重写中主动启用。

全量重解六个 TSW 的 20,091 帧后，首个 `u16` 全部是 `0xFFFF`。普通世界路径在 `0x00412A70` 把 `0x004CD764` 清零，所以这些主流全部选择 RLE/span 族。与此同时，唯一明确把动作 `+0x18` 置为 mode `0x08` 的 `HA/0x4148` 命令在六个当前 ACT 中出现零次；当前已证明的 11 个动作 `+0x18` 外部访问也全部是读取，没有外部写入。

由此可以闭环当前资产驱动路径：没有 ACT 命令选择 RLE mode `0x08`，TSW 加载器也无法提供它必须读取的 coverage 指针。源色是否为假想 coverage 预乘色在当前资产路径没有可观察结果，不能反推也无需虚构。若未识别的计算地址写入、未初始化对象或内存破坏强行制造 mode `0x08`，原函数会按空辅助指针和空 `0x004CDC00` 表的危险机器行为继续执行；这属于仍待调查的任意动态状态，不改变“当前资产链不可达”的结论。

原始 `+0x88` 函数 `0x00417EC0` 完全不同：它先取 `u16(source[0])` 放入栈局部常量，随后覆盖 `ESI` 指向该局部量，所以每个目标像素都使用同一个源颜色，不遍历原始矩形像素。行档位从 15 开始；令 `q = signed(height) >> 4`，每处理到行计数 `> q` 就把档位减一并把计数清零。各档公式逐项与 `0x14` 完全相同，即 1..14 总权重仍为 `15/16`。

当前唯一以立即数 8 直接调用分派器的是 `0x00450A50`。它把自身第五个四字节栈槽地址写入 `0x004CD730`，因此这条真实路径进入原始常量淡出；虽然 IDA 把逻辑参数标为 `char`，汇编实际读取该物理槽的低 16 位。

### `0x04`：逐通道饱和加色

`0x00418840/0x00418EB0` 对每个 literal 源像素先应用三个有符号全局颜色偏移，再与目标相加：

```text
s'c  = clamp(sc + offset_c * channel_unit_c, 0, channel_max_c)
outc = clamp(dc + s'c,                         0, channel_max_c)
```

三个偏移为 `0x004CD71C/0x004CD30C/0x004CD304`。汇编用通道 mask 和反 mask 检测溢出，没有跨通道进位。三个偏移全零时走独立快速循环，结果仍是逐通道饱和 `dst + src`。

### `0x0C`：纵向行重采样、逐行横移的目标颜色偏移

`0x0041F8D0/0x0041FEA0` 的像素核心并不读取 literal payload 中的 `u16` 颜色；它只消费这些位置，并对对应目标执行与 `0x10` 相同的运算：

```text
outc = clamp(dc + offset_c * channel_unit_c, 0, channel_max_c)
```

因此该族不是“二维缩放后的源色饱和加色”，而是把 RLE literal 当覆盖 mask，在纵向选择源行，并逐输出行改变目标 X。正反两个函数只改变水平目标遍历方向；bit 1 的两个槽仍指向同一对函数，由分派器反转目标扫描线顺序。源 RLE 行始终按正向物理顺序推进。

令 `Hs=arg_C`、`Ht=0x004CD75C`。`0x00417239–0x00417269` 建立 10.10 纵向步长：

```text
Ht > Hs:   enlarge = 1; vstep = signed_idiv(Hs << 10, Ht)
Ht <= Hs:  enlarge = 0; vstep = signed_idiv(Hs << 10, Ht) - 0x400
```

对正常已绘制输出行，余数 `vfrac` 初始为零并保留低十位：

```text
q = floor((vfrac + vstep) / 1024)
vfrac = (vfrac + vstep) & 0x3FF
enlarge != 0:  下一输出行前推进 q 条源 RLE 行
enlarge == 0:  下一输出行前推进 1+q 条源 RLE 行
```

放大时由 `q==0` 重复当前源行，缩小时由 `1+q` 跳过额外源行；没有插值。`0x0C` 还保留一条显著不对称的初始预处理：`0x0041F9F2–0x0041FA9F` 和反向对应块无条件执行 `top_clip+1` 次，每次先推进一条源行，再加纵向商。因此即使 `top_clip==0`，首个输出也不会从第一条 RLE 行开始。这是汇编直接行为，不按常规缩放器修正。

逐行横移由 `0x004CD718` 的有符号初始位移控制。分派器若看见零会先强制改成 `+1`，随后建立：

```text
xdir  = displacement > 0 ? -1 : +1
xstep = signed_idiv(abs(displacement) << 10, Ht != 0 ? Ht : Hs)
q     = floor((xfrac + xstep) / 1024)
xfrac = (xfrac + xstep) & 0x3FF
displacement += xdir * q
row_x = arg_0 + displacement
```

初始预处理会推进 X 相位，实际每条输出行在 `0x0041FB06–0x0041FB46` 再推进一次，然后用新的 `row_x` 重新执行水平裁剪。run 长度和 literal 像素本身都没有水平重采样。

完整汇编中共有 15 个 `OR 0x0C` 构造点；每处都先执行 `flags & 0x8000000F`，所以低槽只能为 `0x0C..0x0F`，四槽均已赋值。逐点地址见 `../inventory/blitter-transform-callsites.tsv`。

### `0x20`：仅纵向行重采样的饱和加色

`0x004208D0/0x00420D70` 使用与上节相同的 `Ht/Hs` 和 10.10 正常输出行规则，但不读取 `0x004CD718/0x004CD738`，不改变每行 X，也不重采样 run 内像素。literal 核心逐像素读取源色，公式与 `0x04` 相同：

```text
s'c  = clamp(sc + offset_c * channel_unit_c, 0, channel_max_c)
outc = clamp(dc + s'c,                         0, channel_max_c)
```

顶部裁剪与 `0x0C` 不同。`0x004209BE` 在推进源行之前先比较 `skipped_count==top_clip`；所以 `top_clip==0` 会从第一条 RLE 行开始，其他被裁输出行各按一次纵向规则推进。高位 run 全部透明跳过。

当前有两条明确构造路径：

- `0x00452B95` 以立即数 `0x20` 绘制 640×480 屏幕快照，`Ht=0x280+` 递增奇数计数，用于纵向放大并裁剪的全屏过渡；
- `0x00479AEC` 令 `Ht=source_height+transition_counter`，并由 `((runtime_flags & 0x80000003) & 0x80000023) | 0x20` 构造 flags。

第二条路径的算式表面上可以形成低槽 `0x20..0x23`，但分发表只给 `0x20/0x21` 赋值，`0x22/0x23` 为空。对 bit 1 的完整生产链复核后，该条件已从“隐含假设”提升为正常初始化程序的不变量：

- 两组战斗角色静态数组都位于 PE `.data` 的零填充尾部 `0x004AA000..0x0053E7DC`，对象 `+0x2694` 初值为零；
- `+0x2694` 的 15 条直接写入只有动作标志复制、bit 0 翻转、mode `0x04` 置位和保留式掩码，没有一条产生 bit 1；
- 两个真正的源分别是 `ActionRecord[0]+0x18`（父对象 `+0x2B8`）和 `ActionRecord[3]+0x18`（`+0x480`）；对应动作槽都有整条 `0x98` 字节清零路径；
- `0x004321E0` 对 `+0x18` 的三条键变化重置只会清除或保留 bit 1，`HA/MA/NA/DL/SG/ON/IV` 七种命令变换也全部保留而不产生 bit 1；
- `0x00478FAE` 的整记录复制方向是槽 0 到槽 3，`0x00478625` 的方向是槽 0 到槽 17，均不存在未知槽反灌槽 0；当前已证明的 11 条外部 `+0x18` 访问全为读取。

因此正常初始化执行只可能调用 `0x20/0x21`，`0x22/0x23` 只可能由内存破坏、注入状态或故意不等价的初始化强制产生。原汇编对此没有 fallback；重写不能因正常路径不可达就给两个空槽补函数，也不能在被强制命中时静默改成普通 copy。完整链见 `../inventory/blitter-dynamic-flag-reachability.tsv`，两族定点状态见 `../inventory/blitter-row-resampling.tsv`。

### `0x10`：源覆盖下的目标颜色偏移

`0x0041B280/0x0041B620` 消费 literal 源像素但不读取其颜色值；literal 只充当覆盖 mask：

```text
outc = clamp(dc + offset_c * channel_unit_c, 0, channel_max_c)
```

三个偏移全零时函数不改目标。它不是 alpha，也不是把源颜色加到目标。

### `0x18`：literal copy 后覆盖 run 两端

`0x0041CCF0/0x0041D010` 先复制 literal run，再把实际裁剪后写出的第一个和最后一个目标像素都改成 `low16(0x004CD77C)`。`0x00423610–0x0042361C` 把该全局设为当前绿色有效 mask 在高低 16 位的重复值。因此：

- 长度一的 run 同一像素被写两次，最终仍是绿色 mask；
- 边界是每个 literal run 的边界，不是整张 sprite 的外框；
- 被裁掉的源前缀不算实际写出的首像素。

### `0x24`：源覆盖下的常量填充

`0x00421230/0x00421540` 在 literal run 中消费源像素位置，但每个目标都写调用参数所指向的同一个 `u16` 常量。`0x00417050` 把 flags 强制 OR `0x24`，在原坐标四个对角偏移位置各调用一次，构成四向偏移描边路径。

### `0x28`：源覆盖下的目标灰度化

`0x00421850/0x00421BE0` 不使用 literal 源像素值，只对对应目标像素执行：

```text
q = (normalize(B) + normalize(G) + normalize(R)) >> 2
out = (q << R_shift) | (q << G_shift) | (q << B_shift)
```

这里明确除以 4，不是除以 3；没有加舍入常数。三个五位通道全亮时 `q = (31+31+31)>>2 = 23`，因此白色也会变成较暗的灰色。

### `0x2C`：逐通道饱和减色

`0x00422030` 对 literal 源像素先应用与加色相同的有符号颜色偏移和饱和，再从目标逐通道相减：

```text
s'c  = clamp(sc + offset_c * channel_unit_c, 0, channel_max_c)
outc = clamp(dc - s'c,                         0, channel_max_c)
```

汇编的负结果直接归零，再与本通道 mask 相与；不能改成 16 位整字相减或环绕。

反向 `0x004223A0` 不同：它先把颜色偏移应用到目标通道，再减去未调整的源通道。这是汇编中的方向不对称，不能把正反向合并成同一个对称公式。

### `0x30`：16 步目标邻像素涂抹

`0x00422730/0x004229C0` 入口把 `0x004CD314` 清零。literal run 只提供覆盖，源颜色被消费但不参与输出。每处理一个像素先递增计数，再按 1..16 循环：

| 计数 | 写入当前目标的来源 |
|---:|---|
| 1..4 | `[dst-2]`，左一像素 |
| 5..10 | `[dst+0x500]`，固定下一条 640 像素扫描线 |
| 11..13 | `[dst-0x500]`，固定上一条 640 像素扫描线 |
| 14..16 | `[dst+2]`，右一像素 |
| 下一次 | 只把计数清零，不写当前目标 |

`0x500` 是硬编码字节距离，不读取实际 pitch。正反向函数只改变目标遍历方向，邻居相对地址本身不交换。兼容核心必须保留 640 像素工作缓冲和这个第 17 次不写像素的节拍，不能把它抽象成连续 16 周期卷积。

### `0x1C`：RLE 按行纵向淡出

`0x0041B9F0` 只处理 RLE/span，并使用与 `0x14` 相同的四组对齐/尾像素跳转表。生成器已经逐项验证其标量表 0..15 与 `0x14` 的源/目标项式完全一致。

档位从 15 开始。令：

```text
q = signed(height + 16) >> 4
remaining = q
step = 15
```

顶部裁剪跳过的每一条源行和实际处理的每一条源行都先递减 `remaining`；变成零时重置为 `q` 并执行 `step--`。所以淡出相位按完整源行推进，而不是从裁剪后的第一条可见行重新开始。所有高位 run 均只跳过目标，literal 才执行当前 step 的混合。函数没有 step 下限保护；正常高度/行数合同负责让局部表索引留在范围内。

## 当前闭环边界

所有已赋值软件 blitter 的像素消费公式已经闭环；`0x08` 在当前 TSW/ACT 资产驱动链中没有生产者且不可达，动态 `0x20` 的 bit 1 在正常初始化程序中也已证明恒零，因此 P4 的“透明色、半透明、加色、减色、灰度和舍入规则”完成。

`0x004CDC00` 在 PE 中只有一次绝对地址编码，即反向 RLE `0x8000` run 的读取；相邻表初始化从 `0x004CDC04` 开始向前写，不覆盖该槽。结合 `.data` 零填充、没有直接写入和没有取址生产者，当前正常程序没有该表指针的生产链。这里不对“任意内存破坏能否把任意值写到任意地址”作伪证明：若外部注入或破坏强制制造 mode `0x08`、非空 coverage 指针或 bit 1，原版的空指针/空槽机器结果属于异常状态兼容边界，不能被现代安全 fallback 改写。

## 1:1 重写约束

- 保留稀疏槽和未赋值组合，不自动回退到 copy。
- RLE 透明由 span 命令决定；literal 中任何 16 位值都不是隐式透明色。
- 所有通道运算使用原 mask、移位、截断、饱和顺序和整数比较；不合并成浮点 RGBA 运算。
- 透明度 1..14 保留总权重 `15/16` 和每个二进制分数项的独立截断；不替换为标准 alpha。
- 灰度保留三通道求和后除以 4，涂抹保留固定 `0x500` 邻居距离和第 17 次不写。
- `0x0C` 保留 `top_clip+1` 初始预推进、零 X 位移强制改为 `+1`、逐行重新裁剪和不读取 literal 颜色的行为；不得换成通用二维缩放。
- `0x20` 只重采样源 RLE 行；不得水平插值，也不得为动态 bit 1 形成的空槽补 fallback。
- 不得把 TSW 磁盘辅助载荷自动接到运行时 `+0x04` 或主动启用 ACT 中未出现的 `0x08`；当前 EXE 的恒零/不可达合同本身就是 1:1 行为。
- SDL3 只承担平台窗口、输入和最终纹理上传；这些软件 blitter 必须先在兼容核心中得到逐像素相同的 16 位工作缓冲。
- 原循环的零计数、裁剪边缘和无效 flags 行为后续单独登记，不借实现语言的容器检查或现代 API 默认值修正。
