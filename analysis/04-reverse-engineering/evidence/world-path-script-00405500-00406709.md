# 世界角色 PATH 指令循环：`0x00405500..0x00406709`

状态：`sub_405430/sub_405500/sub_406580/sub_406710/sub_406770` 已完成汇编—C++ 双向
收敛；37 个 PATH opcode 全部实现。动态标签所有权为 `platform_adapted`，opcode 36 的
原版未初始化栈分支已显式隔离；原程序动态差分仍为 `blocked_runtime_oracle`

来源：`swd3.exe.lst` 完整汇编；IDA 伪码仅作导航

## 1. PATH 解释器

`sub_405500` 的 jump table 覆盖 opcode `0..36`。当前实现逐项保留：操作数宽度、32 位
回绕、条件方向、word 光标推进、同帧继续、跨帧返回、动作更新与音频调用顺序、角色和
地表副作用。逐 opcode 合同及验证状态见
[`world-path-opcode-closure.tsv`](../inventory/world-path-opcode-closure.tsv)。

命令地址沿用原式：

```text
relative = u32(PATH + 0x200 + role.path_data_id * 4)
command  = PATH + 0x200 + relative + signed_i32(role.path_word_index) * 2
```

`path_word_index` 的存储宽度为 32 位，寻址时同样按 IA-32 的有符号位型参与地址加法。
`sub_406710` 用目标相对偏移减去当前脚本起点后执行算术右移一位，结果可能为负。真实
PATH 中 path `169/170/171` 各有一条跳到本目录项起点之前的分支。全量资产遍历发现该
边界后，解释器与地图载入前的 PATH 读取均改为保留负光标；不能把它转为 `size_t` 后再
寻址。

公共绝对跳转仍由 `sub_406710` 合同实现。当前资产全部跳转目标与脚本起点保持 word
对齐，因此现代循环按保存的 word 光标重新解析与原版同调用内保留的直接指针等价。文件
越界只在现代所有权边界返回显式状态，不改变有效资源的结果。

## 2. 关键分支与平台边界

- opcode 11 写入时钟后只推进一个 word，故下一轮会把操作数字本身重新解释为 opcode；
  这是原行为，不按通常的双 word 指令修正。
- opcode 15/16 扫描 `0xFFFF` 结尾的 flag 列表，随后读取 32 位目标；空列表语义和
  未跳转时的可变长度推进均按汇编保留。
- opcode 19..23 使用 64 项共享变量；加减、1000 上限、符号位负值钳制及无效索引不
  推进的出口均保留。
- opcode 24 在目标为当前角色时当场切换 PATH 并继续同一次解释；目标 GUID 缺失时沿用
  `sub_40C0D0` 预清零的索引零副作用。
- opcode 30 调用 `sub_406770` 后不推进光标，每帧重复准备随机游走。CRT RNG 与第二
  RNG 的调用顺序未合并。
- opcode 34 按字节寻找 `%Q` (`25 51`) 并复制动态标签。原版 `malloc/free` 指针改为
  owner 持有的 byte vector 与稳定 token；复制字节、零尾、relation 钳制和光标推进
  完全相同，因此该项标记为 `platform_adapted`。
- opcode 33/36 共用角色跟随入口。目标不存在时只读取 selector 并推进两个 word；
  opcode 36 的偏移 word 不会提前读取。opcode 36 的 direction `1/default` 在首次使用
  时读取原版未初始化的两个栈局部量；现代实现返回
  `indeterminate_legacy_stack_state`，不伪造确定值。当前三处 opcode 36 的目标动作方向
  均为 2，不进入该未定义分支。

## 3. `sub_406580` 与 `sub_406770`

`sub_406580` 固定扫描 72 个、每个 `0x21C` 字节的对象槽。普通路线按
`cursor & 0x7FFF` 读取方向；`0xFF` 清空整槽，阻挡时保留帧门并增加 stall，通行时写入
每帧 4 像素步长。stall `<= 8` 使用 `0x60000000` 掩码，否则使用 `0x40000000`。
找不到槽时保留原诊断出口的返回 2 合同，使 opcode 8 前进后继续解释。

`sub_406770` 先调用一次 CRT RNG，再以第二 RNG 取得 `[0,80)`；随后扫描同一 72 槽。
既有 kind 2 槽直接成功，kind 1 槽复用，否则初始化首个空槽。interaction gate 或随机值
大于 60 时置槽高位并把动作基变体清零；其余路径以随机值、碰撞结果和 stall 写回方向、
帧门与 4 像素步长。调用次数和写入顺序均已逐基本块反查。

## 4. `sub_405430` 调度与运行时顺序

角色从索引 1 开始逐项扫描。flags bit 15 是总入口；bit 7 转入队伍路径；bit 31 或
`interaction_gate == 1` 时只按 action 状态恢复地表占用；无 PATH 且带 bit 12 的非受控
角色先更新 action，再按更新后的 action 状态恢复占用；其余非零 PATH 进入 `sub_405500`。

共享 PATH 时钟在五个世界帧门通过后、剧情 VM 前推进：前 20 帧只增加 divider，第 21
帧把 divider 清零、时钟加一，时钟超过 1000 后归零。剧情 VM 返回且 process flags 不含
`0x05` 后，PATH 扫描才执行。SDL runtime 已按该顺序接入真实 PATH 映射、角色数组、
72 槽、A* 节点池、共享剧情状态、两套 RNG、动作更新器和位置音频端口。
