# B6 asset_runtime 有限收口审计

最后更新：2026-08-10

状态：原 78 地址候选已逐项归档；59 个地址属于 B6，19 个机械聚类误归属已转交真实 owner。

唯一行为真值是 `swd3.exe.lst`。本审计只修正模块所有权并补齐 B6 最后三个公共绘制桥，
不把后续模块实现提前搬入 asset runtime。

## 1. 所有权修正

78 地址是早期按地址簇和直接调用图形成的有限候选集，不是预设不可修改的架构结论。
逐函数核对完整汇编及调用者后，实际 B6 范围为 59 个地址：

| 地址 | 转交 owner | 汇编依据 |
|---|---|---|
| `0x0040AD10` | `world_map` | 生产当前地图私有目录和特殊 TSW 数据；B6 只保留 `LegacyTswSpecialFrameLoader` 消费端口 |
| `0x00431150`、`0x004311C0` | `runtime_platform` | 分别是旧式诊断中断和 DirectDraw HRESULT 报告，没有资产所有权 |
| `0x00433AA0` | `battle` | 唯一直接调用族来自 `0x0045FC60`，行为是战斗 UI 的 TSW 命令流像素命中测试 |
| `0x00433C40..0x00434DD0` 的 14 个候选 | `battle` | 共同持有战斗绘制全局、三角表、行偏移、裁剪、线段和粒子状态；外部消费者均落在战斗调用链 |
| `0x004350E0` | `rendering` | 构造共享 framebuffer/font/rendering 对象并调用 `0x004355B0/0x00435660` 绘制初始化入口 |

修正后的 `module-function-ownership.tsv` 不再把地址相邻当成 owner 相同。原 78 项的最终处置
逐项记录在 `asset-runtime-closure.tsv`：59 项由 B6 实现或提供端口，19 项明确转交 B7、
B10 或平台/渲染边界。

## 2. 最后三个公共绘制桥

### `0x0040EBF0`

顺序固定为：

1. 调用 `0x004321E0` 更新 `0x98` 动作记录；失败则报告并停止。
2. 更新后读取 `+0x4A/+0x4C`，调用 `0x004315D0` 查询 TSW 帧。
3. 更新后读取 `+0x10/+0x14`，以 32 位回绕减法计算目标坐标。
4. 更新后读取完整 `+0x18` flags，并将 `+0x8A` 字节零扩展为 opacity。
5. 交给 `0x004170E0` 绘制。

因此 flags、偏移、TSW 键和 opacity 都不能在动作更新前缓存。

### `0x0040EC80`

不更新动作记录。两个四字节参数槽各取低 16 位作为资源号和帧号，查询 TSW 后按原 x/y
绘制，flags 和 opacity 均为零。

### `0x0040ECC0`

动作更新和 TSW 查询顺序与 `0x0040EBF0` 相同；绘制 flags 为：

```text
caller_flags | (updated_record_flags & 0x80000003)
```

掩码只保留动作记录的 bit 31、1、0，且必须读取更新后的 `+0x18`。

重写映射为 `legacy_action_draw_bridge.cpp` 的三个同名公共入口。TSW 装载失败只在现代宿主
安全边界变成显式状态，不改变有效资产路径；旧调用者忽略 blit 返回值的行为也保留，
现代结果仅额外记录诊断计数。

## 3. 收口结论

B6 的资产容器、缓存、通用动作记录、ANI、framebuffer 变形和公共动作绘制桥均已有实现
映射与自动测试。剩余原程序 framebuffer/时序差分统一标为 `original_diff`，不阻塞进入
B7；需要动态原版证据时仍由 Codex 准备 Frida spawn 工具并等待用户运行。
