# 十进制解析汇编证据：0x00430BE0

状态：有效/无效路径已实现；零位数原故障以确定性终止隔离

来源：`swd3.exe` 完整汇编

函数范围：`0x00430BE0` 至 `0x00430C5D`

## 1. 有效输入

函数接受可选的首字节 `+` 或 `-`，其后必须有 1–9 个 ASCII 十进制数字。
它先完整验证，再从末位向前按 `sign, sign*10, ...` 累加：

- 成功返回一并写入 32 位有符号结果；
- 首个 NUL 结束输入；
- 不跳过空白，不接受前后空格或其他字符。

九位上限使有效绝对值不超过 `999999999`。

## 2. 普通验证失败

任一字符不在 `0..9`，或数字多于九位时，函数返回零。到达这些分支前没有
写输出地址，因此调用者原值保持不变。

## 3. 空串与仅符号的原故障

空串、`+` 或 `-` 后立即 NUL 时，验证阶段把数字计数保持为零，却仍进入
转换区：

1. 先把输出写零；
2. 无条件执行一次 `dec ecx` 并向输入前方读取；
3. 把零计数 `dec` 成 `0xFFFFFFFF`；
4. 继续反向读取和写输出，直到 32 位计数回绕。

这不是“返回零”。它会长时间越界、访问冲突或以其他未定义方式终止。

## 4. 可达性

调用域共有三类：

- `0x0040B7F0` 从 `%T<digits>.` 格式片段抽出点号前内容；格式写成 `%T.`
  即形成空串；
- `0x0040F890` 的 `CheatDialog` 多处读取非空编辑框后调用解析器。非空检查
  允许用户输入单独 `+` 或 `-`；该对话框由 `0x00402F80` 的顶层输入路径
  创建，因此不能证明不可达；
- `0x0042ED40` 从脚本片段抽取点号前内容并调用解析器，解析返回值还被忽略。

因此本函数不能标记 `unreachable_current_assets`，也不能把零位数变成普通
`invalid`。

## 5. 重写实现

实现位于：

- `include/openswd3/compat/legacy_decimal.hpp`；
- `src/compat/legacy_decimal.cpp`；
- `tests/unit/compat/legacy_decimal_test.cpp`。

`parse_legacy_decimal_contract` 暴露三态结果，便于 UT 精确检查成功、普通无效
和零位数故障。正式入口 `parse_legacy_decimal_or_terminate` 在故障态调用
`std::abort()`：保留“不返回、进程终止”的可观察级别，而不把原来的反向
越界与四十多亿次循环作为 C++ 未定义行为重新引入。这是
`platform_adapted` 故障隔离，不是游戏逻辑 BUG 修复。

调用者将在各自模块实施时接入正式入口；最终仍需 MSVC/LLVM CTest 和可用
原程序故障 oracle 记录。
