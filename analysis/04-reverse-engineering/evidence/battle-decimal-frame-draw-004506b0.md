# 战斗四段十进制帧逆序绘制 `0x004506B0`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 范围、ABI与调用图

权威LST完整范围为`0x004506B0..0x0045079F`，从`proc`到`endp`共122行，没有外部`FUNCTION CHUNK`。

cdecl四参数依次为数字帧资源号、signed待显示值、最右侧X、Y。三个caller位于`0x0045A496`、`0x0045A6DD`和`0x0045A90B`。

callee为帧查询`0x004315D0`和软件blitter`0x004170E0`，每个实际绘制段各调用一次，均已关闭。

## 2. 入口共享发布

函数在分解前依次发布：

- `0x004FD778 = arg_8`：入口最右X；
- `0x004FD77C = arg_C`：入口Y；
- `0x004FD780 = 0`：尚未出现首个非零商。

当前绘制X只保存在EBX并逐帧回退，不反写入口X共享槽。typed state以`entry_x/entry_y`和独立`final_x`区分这两个合同。

## 3. 固定四段signed分解

局部除数从1000开始，固定迭代四次。每次：

1. 把当前余量发布到`0x004FD788`；
2. 对当前除数执行signed `idiv`，向零取商；
3. 保存32位商到四项局部数组；
4. 以`remainder -= quotient * divisor`求下一余量；
5. 商非零或首个非零已出现时，置leading flag并增加绘制段数；
6. 以magic乘法序列把正除数向零除10，得到100、10、1、0。

由于除数域固定为正数1000、100、10、1，C++20 signed `/10`与LST magic序列结果逐次相同；待显示值的商和余量均使用signed向零语义。

第一项是“除1000的完整商”，不夹为0..9。值超过9999时该项可大于9，并在绘制时以其低16位直接作为帧索引。不得把函数改写为十进制字符串或对首项取模。

最后一次magic除数更新把EDX高字确定为0；随后`mov dx,[digit]`虽只写低16位，实际帧索引仍是商的u16零扩展。typed实现显式转换为u16后再转u32。

分解结束时：

- 首个非零后的所有零商均计入段数；
- 四项全零时leading flag仍为0，但局部段数强制改为1；
- `0x004FD788`保留单位段除法前的signed余量。

## 4. 个位向高位、由右向左绘制

绘制从局部单位项开始，按单位、十位、百位、千位商逆序处理真实段数。每段：

1. 取商低16位为帧索引；
2. 查询同一资源帧并发布record/source；
3. 以记录u16宽高、当前X、入口Y、`flags=0`和记录tail绘制；
4. 正常公共后缀返回后重读当前帧记录宽；
5. 用x86 32位回绕减法执行`current_x -= frame.width`；
6. 再处理左侧一段。

回退使用刚画帧的宽，不是下一帧宽，也不按固定字宽。宽度不同时允许后续左侧帧向右覆盖先前帧，测试保留该可观察顺序。

帧查询或blitter typed-stop时只保留此前分解、共享发布、已画像素和当前失败记录，不继续回退X或处理更高位。

## 5. 负值与typed边界

函数不取绝对值。以`-12`为例，四项商为`0,0,-1,-2`，真实段数2；首次绘制单位商`-2`的低16位`0xFFFE`。现代provider在该真实查询点typed-stop，不提前把负值判为0，也不伪造负号或成功帧。

## 6. 双向追溯

- `0x004506B0..0x004506DF`：局部、入口参数和四个共享状态初始化；
- `0x004506E7..0x00450732`：四轮signed商余量、leading计数及除数除10；
- `0x00450734..0x0045073F`：全零强制一段与signed段数门；
- `0x00450741..0x00450750`：从单位局部开始、商低16位帧查询；
- `0x00450755..0x0045077C`：record/source发布及记录宽高绘制；
- `0x00450781..0x00450796`：重读帧宽、X回退和逆序循环；
- `0x00450798..0x0045079F`：寄存器、局部栈恢复与返回。

C++ state/result字段均对应上述共享槽、局部数组、真实调用计数或最终X；没有引入文本格式化、绝对值、前导零填充、固定字宽或帧号夹值。

完整正向和反向追溯没有未解释基本块、参数、共享写、callee或出口。

## 7. 验证与动态差分

定向测试覆盖：

- `1234`分解为`1,2,3,4`并按帧`4,3,2,1`绘制；
- 不同帧宽按每个当前帧依次回退，最终X为13；
- 后画高位帧覆盖先画低位帧的实际像素顺序；
- `100`保留两个内部0并按`0,0,1`绘制；
- `0`保持leading flag 0但强制只画一帧0；
- `-12`产生`0,0,-1,-2`，在首个`0xFFFE`帧查询点typed-stop且X不回退。
