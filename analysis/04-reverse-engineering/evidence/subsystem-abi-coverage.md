# P2.5 子系统 ABI 覆盖审计

最后更新：2026-08-02

状态：十个必需子系统均已达到 P2.5 顶层 ABI 覆盖口径

完整汇编是唯一真实依据。本审计只判断 P2 是否已有可追溯的子系统入口和机器边界，不把后续 P4–P8 的深层算法恢复冒充成已完成。

机器矩阵见 [`subsystem-abi-coverage.tsv`](../inventory/subsystem-abi-coverage.tsv)。

## 闭环口径

一个子系统在 P2.5 达到“顶层 ABI 已覆盖”，至少需要：

1. 有来自完整汇编的稳定入口地址和实际调用关系；
2. 已核对栈参数字节、寄存器输入和 `retn` 清理量；
3. 已核对机器返回值在真实调用者处是否被消费；
4. 若入口通过函数槽或跳转表分派，已记录实际索引和旧值行为。

这不等于该子系统已经完成 100% 业务规格。像素混合留给 P4，剧情 opcode 和 Ani 留给 P5，地图内部格式留给 P6，战斗 opcode 留给 P7，存档字段留给 P8。

## 当前结果

### 顶层边界已覆盖

- 启动与平台：PE/CRT 入口、WinMain、WndProc、单帧调度和显示生命周期已有人工合同。
- 剧情：`0x00427920` 的状态指针、零/一返回集合和主循环忽略策略已确认；动作记录入口另有全调用点矩阵。
- 战斗：建立、帧核心和指令入口的栈形状及零到三返回集合已确认。
- 渲染：模式、暂停、DirectDraw 包装、战斗、视频与普通世界 `0x004120B0` 的呈现边界已覆盖；深层像素函数不在 P2 展开。
- 存档：预览记录入口和大型存读写状态机已补入人工合同；磁盘字段继续留在 P8。
- 资源：文件对象打开、公共解压、TSW 和 ACT 查询入口均已补入人工合同；容器深层格式继续按 P3 专项收敛。
- 输入：帧归一化、DirectInput 初始化与键盘状态读取已补入人工合同；文本/IME 细节继续留在平台专项。
- 地图：普通世界呈现、LMF 装载与 CM 缓存取得/建立已补入人工合同；地图字段与算法继续留在 P6。
- 音频：世界协调、Miles 维护、初始化、`all.snd` 打开、一基样本取得和六槽播放提交均已有人工合同；解码/混音替换属于以后平台实现。
- 视频：Bink 声音/surface 配置、等待门控和帧呈现均已有人工合同；现代解码器替换不改变旧帧门控合同。

### P2.5 之外仍未完成的内容

十个子系统的顶层入口与机器调用关系均已有汇编证据，但这只完成 P2.5。公共压缩/容器边界、像素、剧情、地图、战斗和存档的深层格式或算法仍分别属于 P3–P8，不能因本审计闭环而标成完成。

## 机械初筛给出的下一批候选

现有 1510 地址 ABI 目录只用于排序，不能代替逐调用点确认。审计时给出的以下候选现已全部完成人工复核：

- `0x00409600`：两个正栈槽、普通 `retn`、21 个直接调用点；逻辑含义和返回策略待逐点确认。
- `0x004380B0`：ECX 文件对象，实际有三个栈槽并 `retn 0x0C`；IDA 只识别到其中两个被读取，必须核对中间创建方式参数。
- `0x004315D0/0x00432A50`：各有两个 32 位栈槽、调用者清理，分别有 144 个和一个直接调用点。
- `0x00436FB0`：ECX 输入对象、两个栈槽、`retn 8`。
- `0x004372B0`：ECX 输入对象、无栈参数、普通 `retn`。
- `0x00425BE0`：两个栈槽、普通 `retn`。
- `0x00426840`：四个栈槽、普通 `retn`，另有函数块。
- `0x004859B0/0x004862B0/0x00486490`：ECX 音频对象、一个栈槽、`retn 4`；分别固定非统一初始化返回、SND 打开返回和一基缓冲区指针合同。
- `0x00485CE0`：ECX 音频对象、六个栈槽、`retn 0x18`，成功失败均返回零。
- `0x00484550`：三个 cdecl 栈槽，Bink 后端选择只读第二槽低八位，surface 类型通过全局副作用传播。
- `0x004846F0`：ECX Bink 对象、无栈参数，把 `BinkWait` 非零归一化成一并由帧调用者消费。

最终参数业务名、逻辑宽度、返回值和调用者策略已回查具体指令并写入 `critical-abi-contracts.tsv`；机械目录本身仍不升级为人工证据。

## 执行顺序

1. 存档预览读取、大型存读写入口、文件对象和 TSW/ACT 查询已经补齐。
2. 输入与地图三入口已经补齐。
3. Miles/SND 与 Bink 对象边界已经补齐，P2.5 顶层覆盖闭环。
4. 后续返回 P3 尚未完成的公共压缩状态机对照和资源边界验证，不提前进入实现。

这个顺序只调整调研优先级，不进入实现，也不改变 P4–P8 的专项恢复范围。
