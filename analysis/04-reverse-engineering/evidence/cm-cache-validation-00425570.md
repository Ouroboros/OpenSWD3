# CM 缓存验证与重置 `0x00425570`

状态：B2.11 已实现；`assembly_exact`、`platform_adapted`、`blocked_runtime_oracle`

完整汇编是唯一行为真值。IDA 伪码和符号名只用于定位。

证据输入：

```text
swd3.exe.asm sha256 = f1ee7f32a79c156b75837e176abb733df7a2143d134252e507343e36857affb4
swd3.exe.lst sha256 = 701732b5481ba34876b62ca97535c9463f65ec3feb2ed745c03772dd4bc3ad8b
```

## 1. 两种验证模式

函数以 `OPEN_EXISTING + GENERIC_READ|GENERIC_WRITE` 打开 `Buffer + "env.dat"`。打开失败、参数不是零或一，以及相应验证没有变化时，都直接进入共同关闭和返回路径。

参数为零时，函数定位到末字节并读取一个字节。零表示缓存可继续使用；非零时，它再次定位到末字节写零，并设置重建标志。定位、读取和写入返回值均不检查。原函数对零长度短读继续检查未初始化的栈字节；现代实现把这个字节预置为零，避免把宿主栈垃圾变成随机缓存删除，这是只影响损坏/空 `Env.dat` 的 `platform_adapted` 安全边界。

参数为一时，`0x004233D0` 返回当前 surface 的红、绿、蓝三个 32 位 mask。函数分别与从 `Env.dat +0x1E/+0x20/+0x22` 载入全局状态的三个零扩展 16 位值比较。任一完整 32 位值不同就设置重建标志；随后从文件 `+0x1E` 读取六字节到预清零缓冲，再用当前三个 mask 的低 16 位覆盖该缓冲并原位写回六字节。读写结果不影响已经设置的重建标志。

两种现代入口分别对应仅有的两个真实调用者，不公开汇编中无调用者的其他整数参数。像素入口显式接收已从环境记录载入的 mask 和渲染层当前 mask，避免在资源 I/O 内反向依赖渲染全局状态。

## 2. 24 个缓存槽重置

重建标志为一时，函数严格遍历槽 `0..23`。每槽以 `OPEN_EXISTING + GENERIC_READ|GENERIC_WRITE` 打开 `Data/<slot>.cm`；成功时定位到文件起点并调用截断，失败时不创建文件。每槽都执行关闭和析构路径。

随后函数以相同的 `OPEN_EXISTING + read/write` 模式打开 `Data/mcache.dat`。成功时生成精确的 24 个 16 字节小端记录：

```text
+0x00 map_id       = 0xFFFFFFFF
+0x04 cached_bytes = 0
+0x08 use_count    = 0
+0x0C slot         = 0..23
```

它定位并截断文件起点，再覆盖写入 `24 * 16 = 0x180` 字节。打开失败时既不创建文件，也不执行该文件重写。原程序同时把这些记录留在共享内存表中；当前 B2 生成完全相同的记录字节，后续地图缓存状态所有者接线时必须复用同一表示，不能另造不同默认值。

## 3. 返回值与验证

无论是否重建，所有路径最后都调用 `0x00425A70`，重新统计重置后的 `0.cm..23.cm` 总字节数并返回。因此成功截断全部已存在槽时返回零；单个槽打开或截断失败时，其剩余长度仍参与结果。

`legacy_cm_cache_validate_session_marker` 和 `legacy_cm_cache_validate_pixel_masks` 保留上述两条调用路径。UT 覆盖环境文件缺失、干净/活动标记、标记清零时点、RGB mask 相等/变化、完整 32 位比较与低 16 位写回、精确 24 槽、槽 24 不受影响、缺失文件不创建、384 字节目录记录和重置后的返回值。Windows LLVM `core`/`app` 的 32/32 CTest 均已通过，`openswd3.exe` 已重新链接；原程序动态差分仍登记为 `blocked_runtime_oracle`。
