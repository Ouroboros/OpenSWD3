# 战斗文件对象静态生命周期 `0x00451900`

本批删除退出登记Port、对象与清理编号、寄存器返回及调用计数。
当前迁移作用域为文件对象的构造、登记及退出销毁，定向验证通过。

## LST依据

主体`00451900..00451909`先调用`00451910`，再跳入
`00451920..0045192B`登记退出函数。构造附件把同一文件对象交给
`00438000..00438021`，建立无效文件句柄和空映射、视图、文件名。
构造返回的对象地址不参与后续分支。

登记入口`00487BA0`只有成功0和失败全1两种结果；旧测试使用的任意
`0x76543210`回复没有该入口的指令依据，随旧寄存器合同删除。
登记失败不回滚已经构造的对象，也不提前执行退出清理。

退出附件`00451930..00451939`将同一对象交给`00438030..004380A9`。
后者先处理视图和映射，再处理文件句柄及动态文件名。视图或映射关闭
失败时记录错误并返回；最终文件关闭的返回值不参与分支。
这些平台操作仍由既有`resource_io::LegacyFile`承担。

## 实际资源与调用方

初始化函数在原时点直接构造`LegacyBattleFileOwner::file`，随后向
`LegacyBattleExitCleanups`追加捕获同一对象引用的实际清理函数。
语义返回布尔值只表示登记是否成功；构造异常在登记前向外传播。

退出集合必须先于借用的文件对象销毁。回调直接清除optional，执行
实际`LegacyFile`析构。回调返回true表示无异常执行了既有析构操作，
不把它解释为每次底层平台关闭调用都成功；未新增关闭错误停点。
登记内存不足时集合不拥有该回调，文件对象仍由原有owner保有。

旧C++构造、析构包装的资源操作已并入初始化及清理回调；同时删除
两层包装和三个结果结构。当前全部调用方为生命周期测试，均改为实际资源与登记
结果检查。未声称该独立静态对象已接入SDL业务路径，也不伪造新的SDL
对象。整项保持待核验，不能由本批协议删除直接计入全链完成数。

## 验证

测试从本源文件只读打开真实文件，创建真实映射和视图，检查映射内容。
Linux同时从`/proc/self/fd`确认文件描述符在清理前存在，登记成功后随
集合退出关闭，登记失败则保持到实际文件owner销毁。
使用null上游的真实PMR分配失败验证登记失败，没有模拟退出回复。

core、ASan的setup定向测试各1/1通过，SDL应用编译链接通过。
本轮增量编译没有警告；完整调用方与删除符号引用已复核。
日志前缀：`build/tmp/runtime/battle-file-exit-`。
既有文件平台适配的依据见[文件状态机](legacy-file-object-00438000.md)。
没有启动游戏或进行原版动态差分，`blocked_runtime_oracle`保持。
