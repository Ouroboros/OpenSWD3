# 世界角色转入队伍

状态：有效输入行为为 `assembly_exact`，宿主容器与损坏输入隔离为 `platform_adapted`（`sub_40D610` 的 `0x0040D610..0x0040D785` 全函数，以及它直接调用的占用清理和空间链迁移行为）；原程序动态差分仍为 `blocked_runtime_oracle`。

## 入口与调用者

唯一行为依据是 `swd3.exe.lst` 的机器码字节与指令。`sub_40D610` 接收运行时角色索引，已确认两个调用点：

- `0x0040CC28`：MAPS 角色物化后的状态门控；该处坐标刚由 tile word 左移四位生成，非整格分支不可达；
- `0x00429B07`：剧情解释器 opcode 65 先用 `sub_40C0D0` 把 GUID 查成角色索引，再调用本函数；角色可能正处于 Path 移动途中，因此需要完整的非整格路径。

本单元恢复共享的角色转移 owner。剧情解释器本身尚未接线，不能据此宣称 opcode 65 已可从脚本执行。

## 活动对象定位

`0x0040D61D` 先检查角色 `+0x1C` 的 Path data id。零值直接进入队伍追加。非零时，`0x0040D633..0x0040D64D` 固定扫描 72 个活动对象槽：

```text
slot size       = 0x21C
slot +0x00 u16  = runtime role index
slot +0x02 u16  = Path cursor，bit 15 不参与索引
slot +0x1C      = Path 方向字节流起点
```

没有匹配槽时同样直接追加队伍，不修改 MAPS，也不清对象。现代 owner 要求 Path 角色提供完整 72 槽状态，避免把“未提供槽”误判成“已经扫描且没有匹配”。

## 非整格坐标恢复

命中对象槽后，`0x0040D668..0x0040D672` 检查 X、Y 的低四位。两轴均为零时跳过本节。任一轴非零时严格执行以下顺序。

### 清除旧表面占用

`0x0040D678` 调用 `sub_40AE20`。角色 `map_cell_pointer_32` 指向旧占用锚点，角色 action `+0x2C/+0x30` 分别是占用宽、高。每个 u32 表面格与掩码：

```text
普通角色：0xCF7FFFFF
选中 GUID：0xCF7FFEFF
```

函数总会先清锚点，再处理三个物理特例：`height=1,width=1` 不再清格；`height=1,width=2` 再清右邻格；`height=2,width=1` 再清下一行同列。其余尺寸按 `height × width` 和地图宽度逐行清理，因此锚点在一般路径会被 AND 两次，最终值不变。

### 按方向退回网格

对象 `u16(+0x02) & 0x7FFF` 选出 `+0x1C` 内的方向字节。方向索引零至七对应两张 i32 表：

```text
X = [ 4,  0, -4, -4, -4,  0,  4,  4]
Y = [ 4,  4,  4,  0, -4, -4, -4,  0]
```

`0x0040D6AC` 反复执行 `world_x -= X[direction]`，直到 X 低四位为零；随后对 Y 执行相同循环。负步长因此会把坐标增加到下一个 16 像素边界。现代边界显式拒绝越出 `0x21C` 槽的 cursor、八以外的方向，以及不能以四像素步长收敛的损坏坐标，避免继承原程序的越界读取或死循环。

### 空间链重排

对齐完成后，`0x0040D6DA..0x0040D6F2` 调用：

```text
sub_411530(
    role.guid,
    role.flags & 3,
    (role.world_y >> 4) - 1,
    0
)
```

`sub_411530` 从给定行扫描到地图高度，在指定空间组的行链中按 GUID 找到第一条角色，解除原链并清零它的 next；末参数不是一，因此再用 `sub_411490` 按对齐后的 Y、GUID 和 flags 低两位插入正确行链。OpenSWD3 在已有 `LegacyRoleSpatialIndex` 上实现同一 GUID 搜索和重插，不建立第二套空间状态。

## MAPS、对象与队伍副作用

命中对象槽后，无论之前是否需要对齐，`0x0040D6FA..0x0040D73C` 都按以下顺序执行：

1. `sub_40D460` 找到同 GUID 的 MAPS 角色源，仅把 flags OR `0x0080`；
2. `sub_40DD40` 用 135 个 dword `0xFFFFFFFF` 覆盖命中的完整 `0x21C` 字节对象槽。

之后所有路径在 `0x0040D741..0x0040D77E` 汇合：把角色索引写入当前队伍位置，用相同的 `sub_40DD40` 清对应队伍对象槽，把 Talk id 清零，清 flags bit 14、置 bit 7，最后递增队伍计数。原物理队伍只有八槽且没有容量检查；现代 owner 在第九项写入前返回显式边界状态。

## 实现与验证合同

`legacy_world_role_transfer` 是共享 owner。MAPS 物化后处理调用它；未来剧情 opcode 65 也必须调用同一入口。固定 UT 覆盖：

- Path 为零、72 槽无匹配、整格命中三条入口路径；
- MAPS flags OR `0x0080` 与完整 `0x21C` 对象清空；
- 方向四把两轴从 `0x24` 增到 `0x30`，并把角色从空间行二重插到行三；
- 普通与选中 GUID 两种表面掩码，以及 `2×2`、`1×2`、`2×1` 三种占用范围；
- 清占用先于方向读取，后续失败不提前产生 MAPS、对象槽或队伍副作用；
- 缺少 72 槽、损坏 cursor/方向、无法收敛坐标、表面越界、空间链缺失和八槽容量边界。

## 验证结果

本函数纳入 114 项闭环矩阵前又进行了一轮独立复核：先只读
`0x0040D610..0x0040D785` 恢复基本块和副作用，再由 C++ 反向逐块映射回 LST。
复核确认 72 槽扫描、两轴低四位门、清占用时点、方向游标掩码、X 后 Y 的对齐顺序、
空间链迁移、MAPS patch、两次对象槽清空及最终 flags 修改均无有效输入差异。

实现对角色零/越界、队伍第九槽、短对象数组、损坏方向游标、不能收敛的坐标、表面越界
和损坏空间链返回显式状态；原程序在这些状态下会越界、死循环或继续写固定全局数组。
因此矩阵最终归类为 `platform_adapted`，不能仅凭有效路径的逐块一致标成
`assembly_exact`。
