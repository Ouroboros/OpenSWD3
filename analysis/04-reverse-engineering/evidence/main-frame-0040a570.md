# 单帧主循环汇编证据：0x0040A570

状态：已从原 EXE 字节逐基本块复核

来源：`swd3.exe`

SHA-256：`0bac897a7557735b22607d8c8f0a79a3e7ae7729deb56593fd91c21e10baee0c`

函数范围：`0x0040A570` 至 `0x0040AB2F`

模式跳转表：`0x0040AB30` 至 `0x0040AB47`

提取命令：

```text
objdump -d -M intel --start-address=0x40a570 --stop-address=0x40ab50 swd3.exe
```

## 1. 入口门控

函数进入后依次检查：

1. `[0x004B7A9C] & 0x10`
2. `[0x004B7CAC]`

位 `0x10` 非零时直接返回。

`0x004B7CAC == 0` 时执行 `Sleep(0)` 后返回。该值已在窗口过程证据中确认由显示停用/恢复路径维护。

## 2. 帧率门控

通过显示门控后：

```text
time(NULL) → [0x004A99FC]
timeGetTime() → now
[0x004AAECC] = now
elapsed = now - [0x004CC2B0]
```

若无符号 `elapsed < [0x004B7BCC]`，本次调用直接返回。

达到帧间隔时才执行：

```text
[0x004CC2B0] = now
```

因此：

- 秒级 `time(NULL)` 在毫秒门控之前读取。
- 帧间隔比较使用 32 位无符号减法和 `jb`。
- 默认门槛为 35，剧情路径可切换为 70；写零时每次调用都通过。
- 接受后直接写 `previous=now`，不按门槛补跑丢失帧，也不保留超出的余量。
- 新引擎若用更高精度时钟，也必须在兼容层截成模 `2^32` 的整数毫秒并保留这一离散更新语义。

完整 interval 变更、直接等待与 Sleep 证据见 `frame-clock-and-wait-semantics.md`。

## 3. 帧前状态迁移

若 `[0x004ACB90] & 1 != 0`，清除内部位编号三和四。

只有 `[0x004B8740] == 0` 时，才执行两组倒计时状态迁移。

第一组：

- 内部位编号 `0x10` 非零时递减 `[0x004CAD20]`。
- 递减结果为负，且 `word [0x004B72C4] == 0xFFFF`、`[0x004B8740] == 0`、`[0x004CAEB0] == 0` 时触发。
- 清除位 `0x10` 和 `0x12`，设置位 `0x11`。
- 调用一组资源/状态释放函数。
- 重置 `0x004B72A4` 起的一组剧情/队伍状态。

第二组：

- 内部位编号 `0x4A` 非零时递减 `[0x004A9918]`。
- 递减结果为负时清除位 `0x4A`，设置位 `0x4B`。

这两组业务名尚未固定，但倒计时、触发条件和位迁移已经确认。

## 4. 时间差与输入更新

随后计算：

```text
[0x004C844C] = now
[0x0049E1C8] = now - [0x004C8444]
[0x004C8444] = now
```

调用顺序：

```text
0x004372B0(&0x004B8748)
0x004050E0()
```

`0x004372B0` 对对象内设备接口调用 `GetDeviceState` 式的 256 字节状态读取。

`0x004050E0` 随后：

- 更新鼠标位置与按钮状态。
- 读取一组键盘扫描码。
- 为 18 条活动记录维护快速连按、释放时间、连按链和连续按住采样数；repeat 由消费者自行判定。
- 用当前毫秒值更新输入时间戳。

因此原帧顺序是“先采样设备，再生成游戏输入边沿”，不是由窗口消息直接驱动游戏按键状态。

严格字段语义见 `input-normalization-and-repeat-semantics.md`。

## 5. 高优先级模式

每个有效帧先写：

```text
[0x004ACD20] = 13
```

若 `[0x004CAEB0] != 0`：

- `[0x004CAD24] = 0x400`
- `[0x004C9A24] = 0x10`
- 调用 `0x00406E30`
- 跳过战斗和普通世界更新，直接进入公共音频维护与关闭检查

该画面分支在 `0x00406E30` 下游的 `0x00408D5E` 自行调用 DirectDraw `Blt`。画面呈现不由后续 `0x0040CF10` 完成。

## 6. 战斗进入判定

只有同时满足以下条件才检查战斗请求：

- `[0x004CAEB4] == 0`
- 内部位编号 `0x0D` 为零
- `[0x004A94AC]` 的最高位为一

随后清除 `[0x004A94AC]` 的最高位。低 31 位为零时不进入战斗。

低 31 位非零时，按顺序：

1. 释放/提交一组显示和世界对象。
2. 关闭当前地图文件映射视图。
3. 将 `[lpBaseAddress]` 写零。
4. 以 `[0x004A94AC]` 的低 16 位调用 `0x00451B10`。
5. `[0x004CAEB4] = 1`。
6. 清除队伍成员状态中的 `0x01000000` 位。

这证明 `[0x004A94AC]` 是带最高位请求标记的战斗入口值，而 `[0x004CAEB4]` 是战斗活动门控。

## 7. 战斗帧

`[0x004CAEB4] != 0` 时：

```text
result = sub_469D20()
sub_40CF10()
```

这里的 `0x0040CF10` 集中维护 Miles 音频对象。战斗画面在 `0x00453200` 内的 `0x0045350A` 自行调用 DirectDraw `Blt`。

`audit_order=161`关闭后，SDL `SdlSmokeIdlePorts::step_battle()`不再固定返回1，而是以`LegacyBattleAssets::script`、唯一`LegacyBattleStartupState`及脚本工作区调用typed战斗脚本分派，并原样返回0/1/2/3。调用仍位于战斗活动门内；typed-stop只记录诊断并保持活动，不会误触发下述世界恢复路径。

之后只按 `result` 分支，不再执行本帧的普通世界/剧情路径。

### result == 0

- 清除战斗请求与活动门控。
- 重建三个显示对象的窗口相关状态。
- 将 `[0x004A99F8]` 写为 `0x0B`。
- 重新打开并映射地图文件。
- 调用 `0x00485710` 后直接返回。

### result == 2

- 清除内部位 `0x10`、`0x12`，设置位 `0x11`。
- 清除战斗请求与活动门控。
- `[0x004B8740] = 0x80000004`。
- 清除 `0x004CAEB0`、`0x004CAEBC`、`0x004CAEC0`、`0x004FBAB0`。
- 调用 `0x00406D30` 后直接返回。

### result == 3

- 清除战斗请求与活动门控。
- 清除内部位 `0x11`。
- 重新打开并映射地图文件。
- 无论映射成功或失败，本帧都直接返回。

### 其他非零结果

直接返回。

这些返回值的数值集合和传播链已经与战斗核心出口交叉确认，业务枚举名称仍留待 P7。

## 8. 普通世界帧

只有战斗活动门控为零才进入：

```text
0x0040CDD0
```

P2.2 已确认该函数消费背景音乐请求，构造 `Music\...mp3`，并建立或调整 Miles stream。随后按 `[0x004B8740]` 分为普通世界和特殊模式。

### [0x004B8740] == 0

固定顺序：

```text
0x00427300
0x00402F80
```

之后只有以下五个门控满足组合条件，才执行剧情解释器：

- `[0x004CC2AC]`
- `[0x004BABA4]`
- `[0x004B8740]`
- `[0x004CAEB4]`
- `[0x004CAEB0]`

注意第一项要求的是 `[0x004CC2AC] != 0`；其余四项要求为零。

通过门控后：

1. `[0x004A94A0]` 每帧加一，在超过 20 时归零。
2. 该计数归零时 `[0x004ACDB0]` 加一，在超过 1000 时归零。
3. 调用 `0x00427920(&0x004B72A0)`。
4. 若 `[0x004B7A9C] & 0x05 == 0`，继续调用 `0x00405430`、三个 `0x00435650` 和 `0x004120B0`。

普通世界的最终 DirectDraw `Blt` 位于 `0x004120B0` 内的 `0x00412716`。

最后记录：

```text
[0x004C8448] = [0x004AAECC] - [0x004C844C]
```

由于两个源值都来自本帧前部，这一字段不是重新读取时钟后的真实 CPU 耗时；必须按原汇编理解。

## 9. 特殊模式分派

`[0x004B8740] != 0` 时：

1. 写入 `[0x004CAD24] = 0x400` 和 `[0x004C9A24] = 0x10`。
2. 调用 `0x0040CF10`。
3. 把三个对象的 `+0xFE0` 字段分别写为 `22`、`18`、`16`。
4. 取 `[0x004B8740] & 0x0FFFFFFF`。
5. 低 28 位在 `1..6` 时进入跳转表。

跳转表：

- 模式 `2` → `0x0044EA60`
- 模式 `1`、`3`、`4`、`5`、`6` → `0x00439FD0`
- 其他值 → 不调用这两个模式处理函数

模式二在 `0x0044F765` 自行调用 DirectDraw `Blt`。其他五个已列模式经 `0x0043A610` 在 `0x0043A854` 呈现。

## 10. 公共音频维护与退出

未在中途返回的路径最终调用：

```text
0x0040CF10
```

该函数依次维护 Miles 的排队音乐/流、stream、sequence 和 sample 对象，不调用 DirectDraw。原程序不存在由 `0x0040A570` 统一调用的单一最终呈现函数；各互斥画面分支在内部完成 `Blt`。

随后检查 `[0x004B7A9C] & 0x04`。

该位非零时同步发送：

```text
SendMessageA(hWnd, WM_CLOSE, 0, 0)
```

因此位 `0x04` 可确认是顶层关闭请求标记。窗口默认过程会继续形成 `WM_DESTROY`，再由窗口过程投递 `WM_QUIT`。

完整呈现、暂停、显示恢复和关闭证据见 `presentation-lifecycle.md`。

## 11. 顶层互斥关系

单帧主循环的核心关系是：

```text
高优先级模式
  或
战斗帧
  或
普通世界 / 特殊模式帧
```

战斗帧所有出口都在进入普通世界路径前返回。重写时不能把战斗、地图和剧情更新简单做成同一帧依次执行的独立系统。
