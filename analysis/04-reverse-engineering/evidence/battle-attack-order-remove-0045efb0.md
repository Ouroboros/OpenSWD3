# 战斗攻击顺序记录移除 `0x0045EFB0`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`、`callers_reclaimed`。

## 1. 完整范围与ABI

权威LST完整主体为`0x0045EFB0..0x0045F01D`，从`proc`到`endp`共65行、36条实际指令、0个call、5个跳转、5个局部标签，没有外部`FUNCTION CHUNK`。

函数为单参数cdecl叶函数。入口把完整u32待移除值载入EDX，ECX清零，EAX指向固定攻击顺序记录首地址；ESI/EDI按callee-saved规则恢复。

## 2. 固定18条首匹配扫描

从`0x00524788`开始逐条读取`+0x00`完整dword并与EDX精确比较。未命中时EAX加`0x1C`、ECX加1，只要物理地址signed小于`0x00524980`便继续。

18条都不匹配时不写任何记录，返回EAX一过尾物理地址、ECX 18和入口EDX。相同值出现多次时只处理第一条。短owner只在下一条真实`+0x00`读取处typed-stop，保留已完成扫描的EAX/ECX/EDX。

命中后的`cmp ecx,0xFFFFFFFF`在固定正向18条扫描中不可达；modern不虚构额外入口状态。随后signed `ecx >= 18`分支同样不可能由合法命中产生，但物理右移和尾清理仍严格按原指令执行。

## 3. 完整七dword左移与一过尾读取

命中索引先换算为`base + index*0x1C`。每轮把源设为目标后一条，固定`ECX=7`执行向前`rep movsd`，再把目标推进到刚才源地址；一直持续到目标达到`0x00524980`。

因此即使命中第17槽，也会从`0x00524980..0x0052499B`读取七个dword并复制到第17槽；命中更早槽时，前面所有后继记录先完整左移，最后同样执行这次一过攻击记录区的读取。该28字节并非不存在的现代哨兵，而是物理相邻的`0x98`字节强度效果记录0前缀，依次对应source、未命名dword、secondary、未命名dword、X offset、Y offset和render flags。lookup key位于`+0x4A/+0x4C`，mode位于`+0x90`，均不在本函数读取范围。typed实现把强度记录补成精确`0x98`物理布局并直接读取效果协调器唯一`intensity_records[0]` owner，不复制平行尾记录。

相邻效果记录缺失时，只在原`rep movsd`首次真实源读取处typed-stop：已完成的左移前缀保留，第17槽尚未被尾清理。攻击记录owner短缺时，在下一条真实源记录读取处同样停止。

## 4. 固定末槽双重填充与返回

完成左移后，不使用当时EDI，而是固定回到`0x00524964`第17槽：先以EAX 0和ECX 7写七个零dword，再以EAX全1和ECX 7写七个全1 dword。最终可观察末槽全部28字节为全1；此前从相邻效果记录复制到末槽的值被覆盖，但其读取时机仍不可删除。

正常命中返回EAX全1、ECX 0、EDX入口值。相邻效果记录本身只读且保持不变。全局重置的`0x00524980`起始物理清零块同步到全部八条强度效果记录，使本函数与强度效果帧共享同一尾部物理状态。

## 5. caller回收与验证

九个静态caller均已属于关闭函数并全部直连typed移除：

- 角色动作主分派四处：三个组B索引和一个组A编码；
- 对手动作分派两处：组A编码与组B阶段编码；
- 最终角色步进两处：组A编码与组B索引；
- 待执行动作提交一处：使用提交后实时重读的角色编码。

旧opaque token全部删除；待执行动作端口的旧移除枚举只保留reserved数值槽且不再调用。每个caller都在原call位置传播typed-stop，保留此前对象查询、状态发布、角色清理或publication副作用，并阻断原call之后的计数、槽清理、阶段发布和后续帧逻辑。

定向测试覆盖无匹配固定18槽返回、首个重复值、任意中间槽完整左移、七dword末槽全1、相邻效果记录只读、末槽命中时一过尾真实读取停止、短owner扫描和左移前缀，以及动作主分派、对手动作、最终角色和待执行动作四类caller直连与stop传播。

当前缺少原版18条攻击顺序、物理相邻强度效果记录、九个caller输入与EAX/ECX/EDX联合捕获后端，`original_diff_verified`为`blocked_runtime_oracle`。
