# 地图名称查询闭环

状态：`platform_adapted`、`assembly_exact`（有效 MAPS 数据域）、`unit_tested`。

唯一行为依据是 `swd3.exe.lst` 的 `0x0040EFD0..0x0040F03F`。该函数从已加载
MAPS payload 的 `+0x50` 相对目录中按逻辑地图编号查询名称，将原始 CP950 字节复制到
调用者缓冲区并追加 NUL。

## 1. ABI 与调用者

物理 ABI 为 `int __cdecl sub_40EFD0(uint32_t logical_map_id, char* output)`；成功返回 1，
未找到返回 0。目录键只读取 16 位并零扩展，但与完整 32 位参数比较，因此
`0x00010003` 不会匹配键 3。

两个直接调用点均已反查：

| 调用者 | 地址 | 用途 |
|---|---:|---|
| `sub_40C130` | `0x0040C778` | 地图装载后写入当前地图名；失败时使用 CP950“`不知道`” |
| `sub_447100` | `0x00447B34` | 特殊模式地图列表生成；返回值未读取 |

当前实现由 MAPS 数据库 owner 提供，地图会话承接第一处调用。第二处调用已固定为
`special_modes` 的后续消费边界，不能复制出另一套解析器。

## 2. 字节流与控制流

目录起点为 `payload + u32(payload + 0x50)`。每项由 `u16 key`、未定长名称字节和未对齐
字节标记 `%Q`（小端 word `0x5125`）组成；下一项紧随标记之后，键 `0xFFFF` 终止目录。

LST 到 C++、C++ 到 LST 的逐基本块追溯结果为：

1. 入口先检查首个 `0xFFFF`，所以终止键本身永远不能命中；
2. 非命中时从当前位置逐字节滑动 16 位窗口，直至 `0x5125`，再前进两字节读取下一键；
3. 当前 word 已是 `0x5125` 时直接前进两字节，不额外扫描；
4. 命中时跳过两字节键，逐字节复制，当前 16 位窗口等于 `0x5125` 时停止；
5. 即使名称为空也写入一个 NUL；未找到时不修改目标缓冲区。

各入口、比较、直接前进、逐字节扫描、空名称、成功及失败返回均有独立测试，当前没有
未决控制流差异。

## 3. 当前游戏数据

对 `/mnt/e/Game/swd3/MAPS.DAT` 去除物理 `0x200` 前缀后独立解析：

- 名称目录：`0x25E2F..0x270E7`（含最终 `0xFFFF`）；
- 346 项、346 个唯一键，最长名称 18 字节；
- 目录 SHA-256：`be8ed0b4148ffa2369598d85d63c4830c15e9a7c6933d9084552afbf945443aa`；
- 前五项：`1000=END`、`3=中東地區`、`4=怛羅斯`、`7=長安`、`6=兩河平原`；
- 键 81 位于 `0x262C2`，原始字节为
  `AB C2 A5 A7 B4 B5 B0 73 AB CE`，即“`威尼斯酒屋`”。

真实 MAPS 测试固定检查目录偏移、键 81 的十个 CP950 字节，以及新游戏世界会话中保留
的完整 NUL 结尾名称。

## 4. 平台隔离

原函数没有目录边界和输出容量检查，且 `sub_40C130` 最终写入 64 字节全局缓冲区。
现代 owner 保留有效数据域的扫描、复制和返回语义，同时将截断 header、越界目录、缺失
终止标记和目标容量不足隔离为显式状态；这些无效输入不再产生原版越界访问。当前地图名
仍保存原始 CP950 字节，UTF-16 转换只允许发生在文本/UI 边界。

- 真实数据测试：MAPS 键 81 和新游戏会话均保持精确 CP950 字节；
