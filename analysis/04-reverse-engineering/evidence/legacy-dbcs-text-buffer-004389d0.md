# `0x004389D0..0x00438B45` DBCS 文本缓冲对象

状态：B2.3c 闭环；`assembly_exact`、`platform_adapted`、`blocked_runtime_oracle`

来源：`swd3.exe` 完整汇编和导出的内存字节。IDA 伪码只辅助辨认参数，不作为行为依据。

## 1. 单元边界与调用图

本单元覆盖以下完整函数：

| 地址 | 行为 | 当前调用者 |
| --- | --- | --- |
| `0x004389D0..0x00438A59` | 构造 32 字节对象和内部字节缓冲 | `0x00449017`、`0x004498A4` |
| `0x00438A60..0x00438A63` | 读取 `+0x14` 输入结果 | `0x004497F0` |
| `0x00438A70..0x00438A79` | 释放内部字节缓冲 | `0x00449857` |
| `0x00438A80..0x00438AB6` | 按 DBCS 边界取得有界字节长度 | 构造、导出以及后续输入编辑族 |
| `0x00438AC0..0x00438AC3` | 读取 `+0x04` X | `0x00411711` |
| `0x00438AD0..0x00438AD3` | 读取 `+0x08` Y | `0x0041171A` |
| `0x00438AE0..0x00438AE3` | 读取 `+0x10` 光标字节偏移 | `0x004117BE` |
| `0x00438AF0..0x00438B45` | 清零目标并导出完整字符前缀 | `0x00411760`、`0x00449844` |

旧工作包把 `0x00438AF0` 误写成范围终点；它实际是最后一个函数的入口。汇编中的 `retn 8` 位于 `0x00438B45`，对齐后下一个独立输入处理入口为 `0x00438B50`，因此本单元边界修正为 `0x004389D0..0x00438B45`。

`0x00438A80` 在 `0x00438E50` 和 `0x00438F60` 等后续输入编辑函数中继续复用。B2.3c 只恢复共享字节缓冲和有界长度合同；Windows 消息、IME、光标移动、插入与删除归后续输入模块，不提前混入本单元。

## 2. 对象布局与当前真实构造

原对象由两个调用点各以 `operator new(0x20)` 分配：

| 偏移 | 宽度 | 汇编语义 | 构造值 |
| --- | ---: | --- | ---: |
| `+0x00` | 4 | `operator new(capacity + 1)` 返回的字节缓冲 | 动态指针 |
| `+0x04` | 4 | 文本框 X | 参数 |
| `+0x08` | 4 | 文本框 Y | 参数 |
| `+0x0C` | 4 | 最大文本字节数 | 参数 |
| `+0x10` | 4 | 光标字节偏移；构造中暂存初始长度 | 先 `0xC0C0`，最后 0 |
| `+0x14` | 4 | 输入结果 | 0 |
| `+0x18` | 4 | IME 状态 | 0 |
| `+0x1C` | 4 | 输入/插入启用门 | 1 |

`0x00438DC0` 无视自己的实参并恒把 `+0x1C` 写成 1，`0x00438DD0` 读取该字段，`0x00438E50` 只有字段等于 1 才执行插入。因此该字段不再保留为“构造时未知一值”；恒写一而无法关闭是原程序行为，后续输入实现不得顺手修复。

两个当前构造点实参完全固定：容量 8、X 为 `0x12C`（300）、Y 为 `0xE6`（230）。导出内存给出两份初始文本：

- `0x0049E188`：`C1 C9 AF 53 00`，CP950 为“賽特”；
- `0x0049E198`：`A9 67 A5 69 00`，CP950 为“妮可”。

`0x004389D0` 分配并清零 `capacity + 1` 字节，调用 `0x00438A80(initial, capacity)`，复制返回的字节数，再把 `+0x10` 重置为零。额外的清零字节保证构造缓冲 NUL 结尾，但后续固定长度导出本身不承诺目标区一定保留 NUL。

## 3. `CharNextA` 与 CP950 字节合同

`0x00438A80` 先对当前指针调用一次 `CharNextA`。返回同一指针表示已经位于 NUL，结果为零；否则把本次指针差加到已接受字节数，以 32 位有符号 `jg` 与上限比较。候选超过上限时返回先前结果，否则接受本字符并继续，因而绝不会在 `CharNextA` 给出的字符边界中间截断。

原函数调用依赖宿主 ANSI code page 的 `CharNextA`。原资产明确为 CP950；让现代宿主 ACP 决定游戏字节边界会导致同一资产在不同系统上产生不同结果。Windows 侧以 `CharNextExA(950, ...)` 对边界探针得到：

| 输入起始字节 | 返回指针差 |
| --- | ---: |
| `00` | 0 |
| `41 00` | 1 |
| `80 00` | 1 |
| `81 00` | 1 |
| `81 20 00` | 2 |
| `81 7F 00` | 2 |
| `81 01 00` | 2 |
| `FE FF 00` | 2 |

因此兼容步进固定为：NUL 不前进；`0x81..0xFE` 且下一字节非 NUL 时前进 2；其他非 NUL 字节前进 1。它只认 lead byte，不验证 trail byte 是否属于合法 Big5。实现显式复制该 CP950 规则，登记为 `platform_adapted`；不得改成 UTF-8 解码、Unicode code point 数或严格 Big5 校验。

## 4. 导出合同

`0x00438AF0` 先按调用者传入的有符号大小清零完整目标区，再取该大小与对象容量的有符号较小值，按 `0x00438A80` 计算内部文本的完整字符前缀并复制，最后恒返回 1。

两个当前调用域均合法且容量充分：

- `0x00411760` 导出到 64 字节全局 `CmdLine`，随后按 `CharNextA` 绘制，并把 `+0x10` 当字节偏移定位光标；
- `0x00449844` 导出到一个 16 字节名字槽，再销毁文本对象。

如果目标大小恰等于文本字节数，先清零的所有字节会被文本覆盖，目标不保留 NUL；该行为已在 UT 固定。负大小会经逻辑右移变成极大的 `rep stosd` 次数并形成灾难性越界写。现代实现对负大小、正大小空目标和负容量执行确定性进程终止，只保留原路径“不返回”的可观察级别，不伪造可恢复返回值，也不允许真实内存破坏。这些输入在完整当前调用图中均不可达。

## 5. 逐地址实现映射

| 汇编地址 | C++ 映射 | 复核结果 |
| --- | --- | --- |
| `0x004389D0..0x00438A07` | `LegacyDbcsTextBuffer` 字段初始化 | X、Y、容量、临时 `0xC0C0`、结果 0、IME 0、启用 1 一致 |
| `0x00438A08..0x00438A2A` | 构造器分配与 `memset` | 标量分配 `capacity + 1` 并清零相同字节数 |
| `0x00438A2C..0x00438A59` | 有界长度、复制、光标清零 | 不拆字符，复制精确字节数并最终写零一致 |
| `0x00438A60..0x00438A79` | `result`、析构 | 原字段读取和内部标量释放一致 |
| `0x00438A80..0x00438AB6` | `legacy_cp950_bounded_length` | 初次步进、同指针结束、有符号上限、接受后再步进和 32 位加法一致 |
| `0x00438AC0..0x00438AE3` | `x`、`y`、`cursor_byte_offset` | 三个字段读取一致 |
| `0x00438AF0..0x00438B10` | `copy_to` 的目标清零 | 合法非负大小清零范围一致；负大小隔离为确定性终止 |
| `0x00438B12..0x00438B45` | `copy_to` 的较小上限、长度、复制和返回 | 有符号较小值、不拆字符复制和恒返回 1 一致 |

C++ 对象用宿主指针宽度表达缓冲所有权，不承诺仍是 x86 的物理 32 字节；跨模块暴露的是字段和状态机合同，不是旧指针 ABI。只读 `snapshot` 用于验证七个标量字段，不增加修改原状态的入口。

## 6. 验证结果

`tests/unit/resource_io/legacy_dbcs_text_buffer_test.cpp` 覆盖：

- 空串、负/零/正上限、ASCII、两字符 CP950 和 ASCII/CP950 混合前缀；
- `0x80`、lead 后 NUL、非法非零 trail、空格 trail 和 `0xFE` 边界；
- 两个真实 CP950 名字、容量 8 的完整构造、容量 3/1 的不拆字符截断；
- 对象七个标量初值和四个原 getter；
- 目标大小 3/4/6、完整目标清零、恰好填满时无 NUL、零长度空目标和恒返回 1。

Windows LLVM `core-debug` 与 `app-debug` 均完成构建和 28/28 CTest；`app-debug` 同时重新链接 `build/app/src/platform/sdl3/Debug/openswd3.exe`。本单元尚未接入当前占位应用的业务调用路径，因此没有把应用启动 smoke 冒充文本对象运行验证。

当前没有可运行的原程序输入对象状态捕获后端，不能把汇编复核、Win32 API 探针、真实静态字节和 UT 升级为 `original_diff_verified`；该项继续标记 `blocked_runtime_oracle`。
