# LMF 世界地图会话组合：0x00425BE0

状态：LMF 子链与地图业务对象转换 `assembly_exact`、`asset_verified`；CM 已由后续单元闭环

来源：`swd3.exe.lst` 完整汇编。汇编是唯一行为真值。

## 当前实现边界

`LegacyWorldMapSession` 把 B2 已验证的物理读取器按 `0x00425BE0` 中的原顺序组合：

```text
尾索引查找地图号
→ 固定头与名称
→ 地表原样表和压缩格
→ 地表后变长记录
→ 相对引用目录
→ 头 +0x14 目录
→ 头 +0x18 索引对象及解压负载
→ 头 +0x1C 目录
```

每一步只在前一步成功后执行，首个失败立即保留为明确阶段状态。地图号仍以完整 `u32`
进入尾索引查找，后续全部读取统一使用查找得到的地图块偏移。

原函数在地表读取前调用
`0x00426840` 取得或生成 CM 映射；该部分现已由
[`cm-cache-runtime-00426840-004272b8.md`](cm-cache-runtime-00426840-004272b8.md) 闭环。
物理目录后的事件、两种角色记录、三组空间链和受检格索引由
[`lmf-map-business-004261ce-00426798.md`](lmf-map-business-004261ce-00426798.md) 闭环。

## 现代边界

资源层继续拥有文件、压缩流和物理目录解析；世界模块拥有一次地图装载的组合顺序和会话
生命周期。接口用拥有型容器代替原全局裸指针，但没有重新排序、合并物理阶段或解释未知
字段。损坏文件的受检失败沿用 B2 已登记的 `platform_adapted` 边界。
