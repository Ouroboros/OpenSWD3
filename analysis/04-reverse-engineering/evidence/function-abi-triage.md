# P2.5 函数边界、栈清理与返回值消费初筛

最后更新：2026-08-02

状态：全局机械初筛完成；关键入口逐函数人工复核进行中

来源：`swd3.exe` 完整汇编、IDA 导出函数清单

完整汇编是唯一真实依据。IDA 的 `proc/endp`、参数标签和原型注释也只是分析器元数据，不能凌驾于指令、控制流和调用点；本轮已经找到两类函数边界差异，证明这一限制不是形式声明。

## 产物

- `../inventory/function-abi-candidates.tsv`：导出清单和完整汇编 `PROC` 地址的并集，共 1510 个候选边界。
- `../inventory/function-abi-summary.tsv`：集合关系、`RETN` 清理量分布和 EAX 消费启发式汇总。
- `../../tools/build_function_abi_inventory.py`：锁定输入哈希的可复现生成器。

TSV 中只有以下内容可以直接视为汇编事实：

- 地址处是否存在展开的 `proc/endp` 主体；
- 主体内每个 `retn` 是否带立即数及其数值；
- 主体注释声明了多少函数块；
- 完整汇编中按符号名直接 `call` 到该展开主体的次数。

`ida_prototype_hint_navigation_only`、参数符号和 EAX 十二指令窗口均明确标为导航/启发式信息，必须人工复核后才能进入 C++20 签名。

## 一、导出函数清单并不等于完整边界集合

精确集合关系为：

```text
IDA 导出清单唯一地址                 1486
完整汇编 proc 标记                   1215
两者交集                             1191
只在完整汇编出现的 proc                24
只在导出清单出现的地址                295
  其中折叠/跳过的 library function    284
  其中已导出但无独立 proc               11
两种导航来源的地址并集                1510
```

因此旧文档所称“1486 个函数无缺口”只能理解为导出器自己的两个清单之间无缺口，不能理解成完整汇编中所有真实或候选入口均已被清单覆盖。

### 24 个仅汇编 `PROC` 不是同一种东西

`0x00417FF4..0x0041830E` 的 16 个标记属于同一段像素组合循环：

- `0x00417FF4..0x00418309` 是 15 个跳转表分支；
- 它们依赖父流程已经建立的 `EDI/ESI/EBP/EDX/ECX`，不是可独立调用入口；
- 多数分支以 `jmp sub_41830E` 汇合；最后一支直接顺落；
- `0x0041830E` 是共享循环尾，最终恢复父栈帧并返回。

这些 `proc/endp` 是 IDA 对控制流片段的函数化标记，不能生成 16 个独立 C++ 函数签名。

另外八个仅汇编地址是特殊菜单回调表中的真实无显式栈参数回调：

```text
0x0043DA30  0x004439A0  0x004452B0  0x00445430
0x004466A0  0x00448C40  0x00448DA0  0x0044BBD0
```

它们都被 `0x0043B480` 一类模式登记器写入全局函数指针槽，再由顶层菜单驱动器间接调用；因为没有直接 `call symbol`，导出清单漏掉了这些真实回调边界。P2.5 后续必须把间接调用槽也作为调用图的一等对象。

### 11 个已导出但无独立 `PROC`

这组包括：

```text
0x00401490 j_unknown_libname_36
0x0044A240 nullsub_1
0x00485330 _AIL_serve@0
0x00486AB0 DirectDrawCreate
0x004876E4 nullsub_2
0x004876F4 nullsub_3
0x00487764 nullsub_4
0x00487774 nullsub_5
0x00487AD8 DirectInputCreateA
0x00487ADE ImmIsIME
0x00497FC6 RtlUnwind
```

它们是跳板、空入口或导入边界，不能仅因存在独立反编译文件就假定有普通函数主体。入口/库边界需直接查看该地址的实际字节和引用方式。

## 二、`RETN` 清理量分布

1215 个展开主体现状：

| 主体内唯一 `RETN` 清理量 | 主体数 |
|---:|---:|
| 无 `RETN` | 44 |
| `0`，即普通 `retn` | 893 |
| `0x04` | 139 |
| `0x08` | 80 |
| `0x0C` | 15 |
| `0x10` | 20 |
| `0x14` | 6 |
| `0x18` | 15 |
| `0x1C` | 1 |
| `0x20` | 1 |
| `0x24` | 1 |

当前没有一个展开主体在主函数体内混用两种不同的 `RETN` 立即数。63 个主体声明了额外函数块；44 个主体现有范围中没有 `RETN`，必须结合尾跳转和外置函数块人工审查，不能推断成“不返回”。

可确定和不可确定的边界：

- `retn 0x10` 确定被调方从栈上弹出 16 字节参数，但单凭这一条仍不能区别 Win32 `stdcall`、成员函数的栈参数部分或其他寄存器参数约定。
- 普通 `retn` 只确定被调方没有额外弹栈；它可能是 cdecl、零栈参数函数、寄存器传参入口、尾包装或被错误切出的控制流片段。
- `0x00437DF0` 使用 `ECX` 保存对象并 `retn 4`，`0x00474FC0` 使用 `ECX` 加两个栈参数并 `retn 8`，说明“有立即清栈值”不能自动统一命名为 `stdcall`。
- `0x00409EC0` 和 `0x0040A0D0` 的全部出口分别 `retn 0x10`，结合 Windows 回调入口才确认四参数 `stdcall`；这是人工闭环，不是仅靠数值猜测。

## 三、参数提示的使用边界

生成器记录形如：

```text
arg_4@+0x8:word ptr:refs=1
```

它只表示 IDA 在函数主体中建立了一个正栈偏移标签，并统计该文本标签在主体现有范围的引用次数。它不保证：

- 参数业务名正确；
- `word ptr` 表示调用者只压入两字节；32 位 x86 调用点仍通常以四字节栈槽传递；
- 未标注的栈访问不是参数；
- `ECX/EDX` 中没有额外参数；
- 外置函数块不会访问更多参数。

例如 `0x00477BD0` 的第二参数在函数内只按 16 位读取，但调用点的栈槽仍是四字节。最终 C++ 签名要同时记录逻辑宽度和 ABI 槽宽度，不能只保留一个 `int16_t` 后假定编译器生成与旧程序完全相同的外部 ABI。

## 四、EAX 返回值消费只是待办排序器

对 7159 个按符号直接调用展开主体的调用点，生成器在调用后最多扫描十二条指令，得到：

| 分类 | 调用点数 |
|---|---:|
| EAX/AX/AL/AH 在再次破坏前被读取 | 1949 |
| 返回寄存器先被明确覆盖 | 2170 |
| 在读取前执行另一 `call` | 1696 |
| 在读取前控制转移/返回 | 834 |
| 在观察前出现条件分支 | 502 |
| 十二指令窗口内仍未决 | 8 |

这不是最终返回值契约，原因包括：

- 函数可能通过 FPU、内存或标志返回信息；
- 调用点可能只读取 `AL` 或只把 EAX 当临时值；
- 条件分支、外置函数块和间接调用需要真实控制流分析；
- “调用者不读”不等于函数没有形成机器级返回值；
- “调用者读取”也不等于业务上是成功/失败布尔值。

它的用途是把 1510 个候选边界分成优先人工复核队列。例如 `0x004321E0` 有 161 个直接调用点，其中 118 个在窗口内消费 EAX，必须优先固定返回契约；公共解压器 `0x004399E0` 的四个直接调用点则已由专项证据证明都不根据 EAX 分支，不能被通用错误处理替换。

## 五、当前可固定的 P2.5 方法

每个最终 ABI 记录至少需要四层证据：

1. 被调函数：实际栈访问宽度、寄存器入口值、所有 `retn`/尾跳转和 EAX/EDX/FPU 出口。
2. 直接调用点：压栈顺序、调用前寄存器建立、调用后清栈方式和返回值消费。
3. 间接调用槽：所有写入者、所有调用者、同一槽可能出现的全部函数目标。
4. 外部边界：Windows、DirectX、Miles、Bink、CRT 的已知 ABI 只用于解释导入契约，游戏内部包装仍以自身汇编为准。

最终记录必须分开写：

- 逻辑参数宽度，例如只读取低 16 位；
- ABI 栈槽宽度，例如调用者压入 32 位；
- 被调方清理字节数；
- 对象/上下文寄存器；
- 返回寄存器及调用者策略。

## 1:1 还原约束

- 不把所有普通 `retn` 强制声明为 cdecl。
- 不把所有 `retn N` 强制声明为 stdcall。
- 不因 C++ 成员函数更自然就改变原寄存器参数、栈槽宽度或清栈责任。
- 不把未消费的返回值统一转成异常或错误退出。
- 不因参数只读低字而缩短调用点栈槽；内部现代接口可以类型安全，但兼容边界必须显式适配。
- 不把跳转表基本块生成为独立业务函数，也不遗漏只经全局槽间接调用的真实回调。
