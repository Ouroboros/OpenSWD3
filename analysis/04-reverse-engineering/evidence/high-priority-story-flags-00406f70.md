# 高优先级剧情标志切换与索引移动 `0x00406F70`

状态：`platform_adapted`

## 1. LST锁

权威范围为`swd3.exe.lst`的`0x00406F70..0x00407090`，共164行，无外部`FUNCTION CHUNK`。唯一caller为逐帧协调`0x00406E30`；该caller已回收原子模式0端口并直接调用本typed入口。

故事位查询、设置和清除已经关闭，现代直接复用`LegacyWorldStoryVmState`。输入读取使用同一20条归一化记录snapshot，不重新轮询设备。

## 2. 入口选中标志切换

记录1的rapid multiplicity按i32大于0，且held sample count字面等于1时，先读取入口时选中的故事位：已置则清，未置则设。

切换发生在所有方向处理和索引循环夹取之前。入口selector超出`0..8191`时，现代只在该实际位表读取点typed-stop；此前没有方向副作用，后续方向也不消费。无切换输入时，污染selector仍可进入原后续加法和夹取域。

## 3. 六组方向覆盖顺序

方向记录只有在rapid multiplicity非零，且held sample count为1或无符号大于3时匹配；count 2、3不匹配。固定检查顺序和赋值为：

```text
记录3 -> -1
记录5 -> +1
记录4 -> -6
记录6 -> +6
记录7 -> -120
记录8 -> +120
```

每个匹配都覆盖而非累加此前delta。因此多键同帧时使用最后一个匹配项；六项全匹配最终为`+120`。

## 4. selector循环

最终只把选出的单个delta按u32加到selector：

- 加后按i32小于0时写`0x1FFF`并立即返回。
- 否则按i32大于等于`0x2000`时写0。
- 其余保持加后值。

这不是模8192的一般算术；一次`+120`越过上界直接到0，一次`-120`越过下界直接到8191。

## 5. 验证

`special_modes.legacy_initial_menu`覆盖：

- 入口selector 10先切换故事位10，再由六方向最终`+120`到130；新索引位不被切换。
- held count 4有效、count 2无效，`0-120`循环到8191。
- `8191+1`循环到0。
- selector 8192在切换读取点typed-stop，后续`+120`不执行。
- `0x00406E30`直接调用本入口；公共输入把submode切到0后，同帧切换目标故事位，再依据activity决定是否绘制。
