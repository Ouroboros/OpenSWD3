# 四个队伍物品链表头与 `0x004A948C` 偏置别名纠正

最后更新：2026-08-02

状态：构造、填充、`level.dat` 追加、普通追加和释放链已闭环

来源：`swd3.exe` 完整汇编

完整汇编是唯一真实依据。IDA 伪码只辅助定位；本结论尤其不能依据 IDA 给表达式选择的符号名判断实际访问地址。

## 结论

此前把 `0x00477400` 中的表达式 `dword_4A948C[ebp*4]` 解释成“世界 Y 移动量 `0x004A948C` 在另一模式下复用为指针数组基址”，这是错误结论。

真实布局是：

```text
0x004A948C  int32 world_player_only_y_component
0x004A9490  ItemNode* party_item_sentinel_heads[0]
0x004A9494  ItemNode* party_item_sentinel_heads[1]
0x004A9498  ItemNode* party_item_sentinel_heads[2]
0x004A949C  ItemNode* party_item_sentinel_heads[3]
```

`0x00477400` 接收的链表参数只有 `1..4`，并故意使用向前偏移四字节的基址：

```text
effective_address = 0x004A948C + party_number_one_based * 4
                  = 0x004A9490 .. 0x004A949C
```

因此这是“一基下标配合负一元素偏置基址”的汇编别名，不是同址复用；有效调用从不读取或写入 `0x004A948C`。

## 一、实存储范围

完整数据段在 `0x004A948C` 声明一个独立双字，随后在 `0x004A9490`、`0x004A9494`、`0x004A9498`、`0x004A949C` 各声明一个双字；下一独立全局从 `0x004A94A0` 开始。

`0x0040E856–0x0040E8A3` 和 `0x0040F442–0x0040F498` 都从 `0x004A9490` 开始，每轮加四，比较上界 `0x004A94A0`，恰好处理四个元素。这两个显式循环共同固定数组边界为：

```text
[0x004A9490, 0x004A94A0) = 4 × 4 bytes
```

## 二、一基下标的完整调用证明

`0x00477400` 只有两个直接调用点：`0x00467D39` 和 `0x00467D4D`，均位于 `0x00467C50` 的同一活动队伍循环。

### 队伍映射的值域

`0x00451D06–0x00451D88` 从四个活动标记建立 `dword_4A75C8[4]`：

- 源索引从零开始；
- `cmp ax, 3 / ja` 把被登记索引限制在 `0..3`；
- 只为活动人数 `[0x0053BCE4]` 写入和消费映射项。

### 调用前加一

`0x00467C8D` 从当前映射项取出 `0..3`，`0x00467CC6` 在传给 `0x00477290` 前加一。相同循环在两次调用 `0x00477400` 前又分别于 `0x00467D2B`、`0x00467D45` 对该映射值加一。

按 cdecl 压栈顺序，增加后的值是 `0x00477400` 的第二参数；函数在 `0x00477472` 将它读入 `EBP`。所以：

```text
EBP = dword_4A75C8[active_party_index] + 1 = 1..4
```

`0x0047754D`、`0x0047757D`、`0x0047758E`、`0x0047759B`、`0x004775BB`、`0x004775C9`、`0x004775D6`、`0x004775EA`、`0x0047760C` 和 `0x00477631` 虽都显示为 `dword_4A948C[ebp*4]`，实际地址只能是四个 `0x004A9490` 起的元素。

## 三、哨兵构造

`0x0044D5D0` 是链表哨兵构造器：

- 分配精确 `0xB0` 字节；
- 用 `0x2C` 个双字清零全部节点；
- `+0x00` 后继指针为零；
- `+0x04` 物品编号写为 `0xFFDC`；
- `+0x08` 写一，`+0x0A` 保持零；
- 向 `+0x0C` 复制公共空/占位字符串；
- 返回节点指针。

这与 `evidence/item-node-mon-dat.md` 已确认的 `ItemNode 0xB0` 布局一致。四个全局元素保存的是哨兵节点指针，不是直接保存首个普通物品节点。

## 四、重建与 MAPS 初始填充

`0x0040E856–0x0040E8A3` 对四个全局元素逐项执行：

1. 若旧哨兵存在，从 `sentinel->next` 开始逐项摘链；
2. 先释放普通节点的 `+0xAC` 动态说明字符串，再释放节点；
3. 释放旧哨兵本身；
4. 调用 `0x0044D5D0` 建立新哨兵并写回全局元素。

随后 `0x0040E8A5–0x0040E96E` 依次读取当前 MAPS 载荷对象 `+0x24/+0x28/+0x2C/+0x30` 指向的四段 `uint16_t` 物品编号序列。每段以零结束；每个非零编号调用：

```text
sub_44D2D0(sentinel, item_id, 1, 1)
```

`0x0044D2D0` 把第一个参数当作可修改的链指针位置；传入哨兵本身意味着实际插入/查找从 `sentinel->next` 开始。找不到编号时它分配新的 `0xB0` 节点、调用 `0x00476DB0` 填充内嵌 `mon.dat` 定义快照，并把节点插入链中。

## 五、`level.dat` 路径的临时头移动与恢复

`0x00477400` 解析 `level.dat` 的固定 `0x400` 字节窗口。命令一在 `0x0047754A` 读取物品编号：

- 零编号触发原错误报告路径，但函数仍按原控制流继续；
- 从对应队伍哨兵开始按 `+0x00` 遍历；
- 若找到同编号节点，不追加；
- 若到链尾且编号不是 `0x8000`，分配、清零和填充一个新 `ItemNode`，接到尾部；
- 新节点建立时把调用方变更标志写一。

遍历期间，函数直接把选中的全局数组元素临时改写为当前节点。`0x0047754D` 先把原始哨兵指针保存在栈槽中，`0x00477631` 在每条命令处理完后无条件恢复。链表内容可以增加节点，但全局根指针仍恢复为原哨兵。

## 六、零基普通追加路径相互印证

`0x00477BD0` 接收零基队伍索引，使用正常表达式：

```text
dword_4A9490[index], index = 0..3
```

它执行与 `0x00477400` 相同的“保存根指针 → 临时移动全局头 → 查找或尾插 → 恢复根指针”操作。`0x00477C84` 把进入函数时保存的哨兵指针写回数组元素。

两条独立路径访问同一实际四元素数组，只是一个调用约定为一基编号，另一个为零基索引。这进一步排除了 `0x004A948C` 自身参与链表存储的解释。

## 七、释放与所有权

`0x0040F442–0x0040F498` 对 `[0x004A9490, 0x004A94A0)` 的每个元素执行完整释放：

1. 从 `sentinel->next` 开始，释放每个普通节点的 `+0xAC` 字符串和节点；
2. 释放哨兵自身的 `+0xAC` 字符串；
3. 释放哨兵；
4. 把全局数组元素写零。

初始化重建路径没有释放旧哨兵的 `+0xAC`，而正式释放路径会释放。当前构造器把该字段清零；这是两条汇编路径的实际差异，初步重写不得擅自合并成自认为更整洁的统一销毁器，除非差分证明所有可见和生命周期行为不变。

## 1:1 还原约束

- `0x004A948C` 必须保持独立 32 位世界移动分量；不能把它并入链表数组。
- 四个数组元素必须对应 `0x004A9490..0x004A949C`，并保留队伍映射的零基/一基换算。
- 不删除哨兵节点，也不把全部路径自动正规化成无哨兵容器操作；调用点是否从哨兵或 `sentinel->next` 开始属于原行为。
- 保留 `0x8000` 不追加、物品零编号错误路径、尾插次序、临时改写全局头再恢复，以及只有新建节点才写变更标志的时机。
- 不借现代容器顺便修正节点顺序、数量字段合并、字符串快照或 `mon.dat` 解释。

## 对既有文档的修正

以下旧结论撤销：

> `0x004A948C` 在普通世界和 `level.dat` 路径中跨模式复用为不同类型。

替代结论：`0x004A948C` 是独立世界 Y 移动分量；`0x00477400` 对它的符号引用只是 IDA 为一基数组表达式选择的偏置基址，所有有效访问都落入真实数组 `0x004A9490[4]`。
