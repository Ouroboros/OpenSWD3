# 剧情 VM 指令长度层与 TALK 线性前缀验证

## 结论边界

本轮建立了 `sub_427920` 的第一版 198 行指令编码/长度目录，并用四个 `TALK*.DAT` 的索引候选做物理线性前缀验证。

汇编是唯一真实依据。IDA 伪码和 switch 注释不决定长度；探针也不是运行时 VM，不会覆盖汇编已经确定的控制流。它只回答：从一个索引入口开始，按当前已恢复的物理指令宽度顺序走字节，是否能稳定到达结束指令或明确的跨窗口转移。

## 静态 CFG 初筛

`tools/build_story_vm_opcode_static_triage.py` 从完整汇编中恢复标签和直接分支，对 198 个显式 opcode 分别构造保守 CFG，直到解释器公共汇合点。两个共享 handler 的内部 selector 按具体 opcode 展开，而不是把同一一级入口错误地当作同义指令。

初筛结果为：

| 分类 | opcode 数 | 含义 |
|---|---:|---|
| 单一固定推进点 | 138 | CFG 内只到达一个固定 IP 加法点 |
| 多个固定点或可变文本扫描 | 15 | 必须按 opcode/分支继续人工拆解 |
| 动态或绝对 IP 写入 | 38 | 包含变长、条件跳转或跨流转移 |
| handler 内未直接写本地 IP | 7 | 默认错误、外部 helper 转移或结束路径 |

全部 198 行没有未解析的直接 CFG 边。这里的“可达”是保守静态可达，不代表运行时条件一定成立。

七个本地无 IP 写入值为：

- `0`：默认错误入口，蜂鸣、诊断、原 IP 让出；
- `15/41/87`：通过 `sub_42E430` 选择同一 TALK 文件的新相对偏移并把窗口内 IP 归零；
- `85`：`sub_484730` 在调用者的指针/IP 上逐字节消费到 `%Q`；
- `161`：`sub_42E480` 切换 TALK 文件/槽并重新装载流窗口；
- `16383`：剧情结束清理。

## 第一版编码与长度规则

`inventory/story-vm-opcode-length-rules.tsv` 对 198 个显式值各保留一行。173 行具有正常固定物理长度，25 行由计数、终止符或控制转移决定；其中 149 行当前只命名为 `fixed_raw_operands`，在状态数据流未审完前不擅自给操作数字段命名。

已由汇编明确的变长/转移族如下：

| opcode | 物理编码或顺序长度 | 控制效果 |
|---|---|---|
| `1..6,89,90` | `4 + %Q 前字节数` | 消费两字节 `%Q` 后顺序执行 |
| `15` | 6 字节，`+2` 为 `u32` 目标 | `sub_42E430` 跨窗口转移，不顺序前进 |
| `20` | `4 + 6 × (u16(+2) & 0x3FFF)` | 首轮置操作数字 bit 14 并让出；就绪轮清 flags 后顺序前进 |
| `23,24` | `8 + 2 × 项数`，`u16` 表以 `0xFF00` 结束，随后 `u32` 目标 | 条件转移或顺序前进 |
| `41,87` | `6 + 4 × 目标数`，`u32` 表以 `0xFF00FF00` 结束 | 分别按索引/随机值选择目标并调用 `sub_42E430` |
| `63` | `6 + 2 × 项数`，带一个 `u16` 前缀，列表以 `0xFF00` 结束 | 顺序前进 |
| `85` | `4 + %Q 前字节数` | helper 同步修改调用者 IP/指针后播放视频 |
| `96` | `4 + %Q 前字节数` | 可消费开头 `%`/`*` flags，随后打开自定义 Ani |
| `109` | `4 + 2 × u16_count` | 顺序前进 |
| `116` | `4 + 6 × u16_count` | 顺序前进；写回 IP 时只取乘积低 16 位 |
| `125` | `4 + %Q 前字节数` | 顺序前进 |
| `133` | `4 + 2 × 非零 u16 项数` | 以零 `u16` 结束后顺序前进 |
| `158,159` | `6 + %Q 前字节数` | `u16` 前缀后为字节串 |
| `161` | 4 字节 | 按 story id 调用 `sub_42E480`，不顺序前进 |
| `169` | `4 + 12 × (u16(+2) & 0x3FFF)` | 与 20 共用入口，但使用 12 字节记录 |
| `171,173` | `4 + %Q 前字节数` | 顺序前进 |

`29..33` 与 `181..185` 虽共享内部 selector，长度仍必须按 opcode 区分：前三个/后三个对应的基础变体是 6/8 字节，带 `u32` 条件目标的变体是 10/12 字节。完整逐值规则以 TSV 为准。

已确认的异常合同也保留：opcode `77/78` 成功找到角色时分别前进 6/4 字节；查找失败路径把未初始化的栈局部量当作推进值。初步 1:1 重写不得自行把该路径改成固定长度。

## opcode 20 纠错

首次长度目录曾把 opcode 20 误记成 12 字节记录步长。重新回查汇编后已撤销：

```text
0x0042B030  cmp word ptr [esp+...+var_3C], 14h
0x0042B036  mov ecx, 6
0x0042B03F  jz  0x0042B04A
0x0042B041  mov ecx, 0Ch
```

`var_3C` 保存有效 opcode，`0x14` 就是十进制 20。因此 opcode 20 使用 6 字节记录，只有共享入口的 opcode 169 使用 12 字节记录。修正后重新生成长度目录和全部 TALK 探针；此前所有 16 条中途“未知 opcode”以及 36 条 opcode 0 假异常全部消失。旧的“汇编步长 BUG”结论不成立，也不应进入重写规格。

## 四个 TALK 文件的物理线性前缀探针

`tools/build_story_vm_talk_linear_probe.py` 锁定四个原始 TALK 文件的 SHA-256，先应用已有外层索引边界，再按长度目录逐条解码。遇到 `15/41/87/161` 时记录该指令物理宽度并停止当前入口，不假装后续相邻字节仍会顺序执行；遇到 `16383` 正常停止。

最终结果：

| 文件 | 纳入探针的索引候选 | 正常结束 | 转移 `15/41/87/161` | 首字即无效候选 |
|---|---:|---:|---:|---:|
| `TALK1.DAT` | 1200 | 1036 | 51 / 20 / 3 / 90 | 0 |
| `TALK2.DAT` | 700 | 676 | 3 / 20 / 1 / 0 | 0 |
| `TALK3.DAT` | 992 | 970 | 6 / 8 / 0 / 0 | 8 |
| `TALK4.DAT` | 1100 | 1074 | 8 / 17 / 1 / 0 | 0 |
| 合计 | 3992 | 3756 | 68 / 65 / 5 / 90 | 8 |

3984 个可接受入口前缀全部无未知 opcode、无越界、无缺失终止符。八个 TALK3 数值候选虽然落在文件内，但首个低 14 位值不属于 198 个显式 opcode；目录将其保留为 `invalid_index_candidate`，没有静默删掉或伪装成流。

探针得到 58,782 个唯一物理指令记录、58,990 次入口实例命中，并在顺序前缀中观察到 143/198 个显式 opcode。剩余 55 个“未观察”只表示这些值未出现在当前线性前缀中，不证明它们不可达、未使用或可删除。

## 不能从本探针推出的结论

- 它没有执行条件表达式，不证明条件跳转的哪一侧在具体游戏状态下发生。
- 它在跨窗口转移处停止，没有递归装载目标窗口，因此还不是全 TALK 控制流遍历器。
- 多个索引入口可能覆盖同一物理指令；唯一物理记录数与运行次数都不是剧情实际执行频率。
- 长度正确不等于参数语义、状态读写、同步/异步和错误行为已经恢复。
- 当前 143 个样本覆盖不能替代剩余 55 个 handler 的汇编审计。

## 跨窗口全分支候选图

线性前缀之后，`tools/build_story_vm_talk_control_flow_graph.py` 又逐一回查了 10 个 `sub_42E430` 调用点、一个 `sub_42E480` 调用点和共享 handler 内的分支条件。结果确认 31 个 opcode 可能重新装载剧情窗口：其中 30 个在当前 TALK 文件内跳转，opcode 161 按 story id 选择文件和槽。

图节点不是单纯的文件偏移，而是：

```text
(TALK 文件, 当前窗口相对偏移, 窗口内 IP)
```

这是因为 `sub_42E430/sub_42E480` 每次从目标读取固定请求长度 `0x8000` 并把 IP 归零。同一物理字节可能从不同窗口入口到达，不能只按文件偏移合并运行时上下文。

图从全部 3992 个索引候选出发。条件跳转同时保留顺序边和目标边；opcode 41 枚举索引表所有候选，opcode 87 枚举随机函数可返回的 `0..count-1`；opcode 161 严格保留汇编的 `movsx` 后无符号文件/槽算术。最终得到：

- 3983 个去重根窗口，对应 3992 个槽；
- 138,988 个成功解码的窗口上下文节点；
- 99,092 个唯一物理指令位置；
- 137,207 条候选边，其中 132,948 条顺序边、3124 条普通条件转移、653 条 opcode 41 表项边、42 条 opcode 87 随机候选边、97 条 story id 重载边和 150 条无条件单目标转移；
- 全图观察到 152/198 个显式 opcode，比只走线性前缀增加九个；
- 四个解码问题恰好是前述八个 TALK3 无效槽合并后的四个重复物理根，没有任何有效转移目标在重新装载后产生未知 opcode、越界或跨越 `0x8000` 窗口的指令。

### opcode 41 的终止值目标边界

汇编先数出终止值前的目标数 `count`，随后执行：

```text
cmp selector, count
jbe use_selector
selector = 0
use_selector:
target = u32([command + 2 + selector*4])
```

因此 `selector == count` 不会回退，而会把紧随列表的 `0xFF00FF00` 终止值直接传给 `sub_42E430`。候选图中 153 个唯一物理 opcode 41 指令形成 193 个窗口上下文，每个上下文都有一条这样的出界边；全部 193 条非 `enqueued` 边均来自此处，没有其他目标越界。

这只是汇编允许的异常边，不证明当前正常游戏状态会让全局 selector 正好等于 count。初步重写仍必须保留原比较关系，不能擅自把 `jbe` 改成严格小于。

opcode 87 调用的 `sub_439070(count)` 先执行 `0xFFFF / count`，再以拒绝采样返回 `0..count-1`；空列表会在除法处出错，而不是选择终止值。当前已遍历样本没有空的 opcode 87 列表。
