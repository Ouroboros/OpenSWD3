# CM 地图缓存运行时：`0x00426840..0x004272B8`

状态：`sub_426840` 已独立完成 `assembly_exact`、`asset_verified`、`platform_adapted`；
`sub_426DF0/sub_4270F0/sub_427140` 继续保持 `pending_audit`，不得从本文件继承关闭状态。
原程序动态差分待统一 oracle。

唯一行为来源：`swd3.exe.lst` 完整汇编。IDA 原型、旧证据和既有 C++ 只用于导航。

## 1. 当前关闭范围

本轮只关闭 `0x00426840..0x00426DED sub_426840`：打开目录、递增记录年龄、命中或 miss、
逐项淘汰、目录提交、调用 CM 生成器并取得槽内容。现代实现位于：

- `legacy_cm_cache_runtime.cpp`：记录年龄、首命中和淘汰/插入算法；
- `legacy_cm_cache_loader.cpp`：文件操作、三条主路径和直接音频维护顺序；
- `legacy_world_render_session.cpp`：从地图加载原槽传入真实 audio-maintenance owner。

以下被调用函数仍须各自重新从 LST 独立闭环：

- `0x00426DF0 sub_426DF0`：LMF CM 分块生成；
- `0x004270F0 sub_4270F0`：声明输出大小读取；
- `0x00427140 sub_427140`：关闭旧映射并打开/映射指定槽。

本文保留它们的现有接口事实用于解释调用顺序，不把这些事实视为函数关闭证据。

## 2. ABI、唯一调用点与返回

`sub_426840` 是四参数 cdecl：

```text
arg_0 +0x04 = map_id
arg_4 +0x08 = LMF map_offset
arg_8 +0x0C = CM relative offset，调用者可按原门控传 0
arg_C +0x10 = 0x200 字节路径 scratch buffer
```

唯一调用点为 `sub_425BE0:0x00426027..0x00426053`。调用者依次压入 scratch、受原 word
门控的 CM 相对偏移、`dword_4CEAA8` 地图块偏移和地图号；调用后把 EAX 直接写入地图状态
`+0x20`。EAX 是命中或生成后槽文件的映射基址，失败时可为 0。现代实现以拥有型
`cache_bytes` 和明确状态替代裸映射指针；scratch 路径缓冲由 `std::filesystem::path`
替代。

`arg_C` 在 `sub_426840` 中传给生成器；传给 `sub_427140` 的第二个实参是该 callee 不读取
的调用者多余参数。现代 loader 不伪造第二个语义参数。

## 3. 目录记录、年龄与命中

`mcache.dat` 按实际读取字节数除以 `0x10` 得到记录数；不足 `0x10` 的尾部不参与记录解析。
每条记录为：

```text
+0x00  u32 map_id       // 0xFFFFFFFF 表示空闲
+0x04  u32 byte_size
+0x08  u32 use_counter
+0x0C  u32 stored_slot
```

非空目录先把全部记录的 `use_counter` 以 `u32` 递增，再从头寻找首个 `map_id`。命中后按
`stored_slot` 取得槽内容；紧随其后的直接音频维护完成后才把该记录计数清零。目录从偏移 0
重写 `record_count * 0x10` 字节并关闭，最后再执行一次直接音频维护。

命中路径不截断 `mcache.dat`，原不足一条记录的物理尾部继续保留。槽文件使用
`OPEN_ALWAYS`；缺失槽会先创建为空文件，随后以明确 `cache_file_empty` 失败，但目录年龄
和命中记录清零仍按原顺序提交。

## 4. miss、容量与逐项淘汰

miss 先调用 `sub_4270F0` 取得新缓存大小。合法域容量上限为：

```text
byte_limit = cache_limit_megabytes << 20
```

加法、减法、左移和记录年龄都保留 `u32` 回绕。满足任一条件时继续淘汰：

- `record_count != 0` 且 `current_total + new_size > byte_limit`；
- 当前没有空闲记录。

每轮从头扫描活动记录：先记住首个严格更小 `byte_size` 的 fallback；遇到首个
`use_counter > unsigned(signed(cache_limit_megabytes) / 4)` 的记录立即停止扫描并选中。
因此它不是 LRU：达到年龄阈值的物理首项优先，否则选择首个严格最小项。

选中后先保存旧 `stored_slot` 和大小，把记录重置为
`{0xFFFFFFFF, 0, 0, record_index}`，执行本轮直接音频维护，再用 `OPEN_ALWAYS` 打开旧槽，
从偏移 `0x10` 截断，最后从总量减去旧大小并重新判断。现代实现可先计算等价淘汰计划，
但文件截断和直接音频维护仍逐项交错，不批量移到循环外。

停止淘汰后扫描第一条空闲记录并写入 `{map_id, new_size, 0, record_index}`。一般 miss
先重写并截断目录、关闭目录，再生成槽并取得全部物理字节。

## 5. 空目录专用路径

`mcache.dat` 大小为零时不进入一般 miss：

1. 先在槽 0 调用 `sub_426DF0` 生成请求地图；
2. 固定建立 24 条目录记录；
3. 第 0 条为 `{map_id, generated_size, 0, 0}`；
4. 第 `1..23` 条为 `{0xFFFFFFFF, 0, 0, index}`；
5. 写入并截断为 `0x180` 字节后关闭目录；
6. 调用 `sub_427140` 取得槽 0。

空目录是“先生成、后提交”；一般 miss 是“先提交、后生成”。测试固定这两个相反顺序。

## 6. 14 个直接 `_AIL_serve` 静态点

本函数自身有 14 个显式 `_AIL_serve@0` 调用点，不包含
`sub_426DF0/sub_427140` 内部的音频维护。动态次数按路径为：

```text
目录打开失败 = 1
命中           = 5
空目录         = 5
非空 miss      = 8 + eviction_count
```

操作位置为：

- 共用：路径准备前、目录打开成功后；
- 非空目录：目录读取后；
- hit：槽取得后且命中计数清零前、目录重写并关闭后；
- miss：大小 helper 后、每个淘汰槽打开前、淘汰循环结束后、目录重写前、目录截断并关闭后、生成并取得槽后；
- 空目录：24 条记录建立后、目录写入/截断/关闭后、槽 0 取得后。

`LegacyCmCacheAudioMaintenanceStage` 只恢复这 14 个直接点。真实 SDL owner 的
`maintain_audio()` 经 runtime → render → file CM source 传入；后续 helper 独立闭环时再恢复
各自内部点，不能在本函数中重复计数。

## 7. 平台适配与危险点

本函数分类为 `platform_adapted`：

- 两个固定 `0x200` malloc 缓冲和裸 Win32 文件/映射全局改为 vector、RAII 文件和拥有型字节；
- Windows `data\\mcache.dat` 与 `%d.cm` 改存 OpenSWD3 自有 cache directory，不改写原游戏 Data；
- seek/read/write/truncate/open 的未检查失败改为对应阶段状态；
- 非零但不足 `0x10` 的目录、单个缓存超过容量且没有活动淘汰候选等原越界域，在首次越界写前停止；
- 只读映射以完整物理文件字节表达，不擅自裁成目录记录的 `byte_size`。

这些适配不改变合法域记录宽度、尾部保留/删除、年龄回绕、首命中、淘汰选择、文件顺序或
直接音频维护顺序。损坏输入上的固定缓冲溢出、未初始化大小和记录数组越界不复现。

## 8. 验证

合成 UT 固定：

- `u32` 年龄/大小回绕、首命中和清零延迟到槽读取后；
- hit 尾部保留、miss 尾部删除和槽 `OPEN_ALWAYS`；
- 空目录五个维护点与 24 槽初始化；
- hit 五个维护点、普通 miss 八个维护点、单淘汰 miss 九个维护点；
- 淘汰维护发生在旧槽从 20 字节截到 `0x10` 之前；
- index-open 失败单维护、零 CM offset 受检停止、短非空目录在 record-zero 越界前停止；
