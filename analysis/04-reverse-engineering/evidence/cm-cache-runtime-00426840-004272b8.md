# CM 地图缓存运行时：0x00426840..0x004272B8

状态：`assembly_exact`、地图 24 `asset_verified`；原程序动态差分待统一 oracle

来源：`swd3.exe.lst` 完整汇编。汇编是唯一行为真值。

## 范围

本单元覆盖四个紧耦合入口：

| 地址 | 职责 |
|---:|---|
| `0x00426840` | 打开目录、递增计数、命中或 miss、淘汰、生成并取得缓存单元 |
| `0x00426DF0` | 从 LMF 解压 CM 分块，按当前像素格式转换并写入槽文件 |
| `0x004270F0` | 只读取 CM 头 `+0x10` 的声明输出大小 |
| `0x00427140` | 关闭上一映射并打开、映射指定 `%d.cm` 的整个文件 |

现代实现分别落在 `legacy_cm_cache_runtime`、`legacy_cm_cache_generator` 和
`legacy_cm_cache_loader`，但公共 loader 保留原函数的物理执行顺序。

## 目录记录与命中

`mcache.dat` 按文件大小除以 `0x10` 得到记录数；不足 `0x10` 的尾部不参与解析。每条
记录为：

```text
+0x00  u32 map_id       // 0xFFFFFFFF 表示空闲
+0x04  u32 byte_size
+0x08  u32 use_counter
+0x0C  u32 stored_slot
```

非空目录先对所有记录的 `use_counter` 执行一次 32 位递增，再从头寻找首个
`map_id`。命中后按 `stored_slot` 打开整个槽文件，把该记录计数清零，最后从目录偏移
零重写 `record_count * 0x10` 字节。命中路径不截断 `mcache.dat`，所以原文件不足一条
记录的尾部仍保留；槽文件打开或映射失败也不跳过后面的目录重写。

目录和槽文件都使用 Win32 `OPEN_ALWAYS`。这意味着缺失的槽会先创建为空文件，随后因
空文件无法建立映射而失败；不能把它实现成 `OPEN_EXISTING`。

## miss、容量和淘汰

miss 先由 `0x004270F0` 在 `map_offset + cm_relative_offset + 0x10` 读取新缓存大小。
相对偏移为零时原 helper 直接返回，不写输出参数；现代实现把该无定义输入隔离为明确
失败，合法 DVD 资产路径不受影响。

容量上限严格为：

```text
byte_limit = cache_limit_megabytes << 20
```

加法、减法和左移都保留 `u32` 回绕。满足以下任一条件便继续淘汰：

- `record_count != 0` 且 `current_total + new_size > byte_limit`；
- 当前没有空闲记录。

每轮从头扫描活动记录：先保留严格更小的 `byte_size` 作为 fallback；若遇到首个
`use_counter > signed(cache_limit_megabytes) / 4` 的记录，则立即选中并停止扫描。
因此它不是普通 LRU：较老记录按物理顺序优先，否则淘汰首个严格最小的记录。

选中后先保存旧 `stored_slot` 和大小，再把记录重置为
`{0xFFFFFFFF, 0, 0, record_index}`。旧槽以 `OPEN_ALWAYS` 打开，文件指针移动到
`0x10` 后调用 `SetEndOfFile`；所以淘汰留下 16 字节，而不是清成零字节。随后从总量中
减去旧记录大小并重复判断。

停止淘汰后使用第一条空闲记录，写入
`{map_id, new_size, 0, record_index}`。miss 路径重写目录后调用 `SetEndOfFile`，会删除
原目录尾部；然后才生成槽文件并取得其完整映射。

## 空目录分支

当 `mcache.dat` 大小为零时，不经过一般 miss 算法：

1. 先在槽 0 生成请求地图；
2. 固定建立 24 条目录记录；
3. 第 0 条为 `{map_id, generated_size, 0, 0}`；
4. 第 `1..23` 条为 `{0xFFFFFFFF, 0, 0, index}`；
5. 写入并截断成 `0x180` 字节；
6. 打开并取得槽 0 的完整映射。

生成发生在目录提交之前；一般 miss 则先提交目录再生成。实现和测试保留了这个顺序差异。

## CM 分块生成

`0x00426DF0` 对非零 CM 相对偏移执行：

```text
header_offset = map_offset + cm_relative_offset
读取固定 0x1A8 字节头
total_size = header[+0x10]
chunk_size = header[+0x14]
buffer_capacity = chunk_size + chunk_size / 1024
chunk_count = (chunk_size + total_size) / chunk_size
```

每个块的压缩大小来自 `header + 0x1C + index * 8`；压缩负载从头后连续读取。每轮完整
LZO 解压一个块，但只写 `min(remaining, chunk_size)` 字节。地图像素位数为 16 时，只对
即将写入的前缀按现有 forward 像素函数转换；最后一块的解压尾部不转换也不写入。

槽文件同样使用 `OPEN_ALWAYS`，只把文件指针移到零后覆盖，不在生成器中截断。因此：

- 正常淘汰后，未被新数据覆盖的 16 字节内尾部仍可能保留；
- 空目录分支若复用一个更长的旧槽，也可能保留新输出后的旧尾部；
- 映射得到的是物理文件全长，不应擅自裁成目录记录的 `byte_size`。

这些均是汇编的可观察行为，不作为游戏逻辑 BUG 修复。

## 现代安全边界

原函数为目录和临时区固定分配 `0x200` 字节，并在损坏目录、单个地图大于容量且无活动
淘汰候选等情况下可能越界。现代实现对记录、块表、解压输出和文件长度做受检失败；有效
原始资产的顺序、计数、回绕、选择规则和文件字节不变。原只读文件映射在公共接口中用
拥有型字节数组表达，避免把平台映射句柄泄漏到世界模块。
