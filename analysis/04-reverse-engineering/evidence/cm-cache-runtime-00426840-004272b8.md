# CM 地图缓存运行时：`0x00426840..0x004272B8`

状态：`sub_426840/sub_426DF0/sub_4270F0/sub_427140` 已分别独立完成
`assembly_exact`、`asset_verified`、`platform_adapted`。原程序动态差分待统一 oracle。

唯一行为来源：`swd3.exe.lst` 完整汇编。IDA 原型、旧证据和既有 C++ 只用于导航。

## 1. 当前关闭范围

已独立关闭四个入口：

- `0x00426840..0x00426DED sub_426840`：打开目录、递增记录年龄、命中或 miss、逐项淘汰、
  目录提交、调用 CM 生成器并取得槽内容；
- `0x00426DF0..0x004270ED sub_426DF0`：打开槽、定位 LMF CM 头、逐块读取/解压/转换/写入，
  更新声明大小、载入进度和直接音频维护；
- `0x004270F0..0x00427135 sub_4270F0`：定位 CM 头 `+0x10`，读取声明输出大小；
- `0x00427140..0x004272B8 sub_427140`：关闭旧槽映射，打开并映射指定槽文件。

现代实现位于：

- `legacy_cm_cache_runtime.cpp`：记录年龄、首命中和淘汰/插入算法；
- `legacy_cm_cache_generator.cpp`：声明大小 probe、块表、解压、转换、写入、进度和直接维护；
- `legacy_cm_cache_loader.cpp`：文件操作、槽映射 typed port、三条主路径和嵌套 helper 顺序；
- `legacy_world_render_session.cpp`：把同一 progress/audio owner 传入地图加载原槽。

本证据范围内的四个入口均已独立关闭；相邻 `sub_4272C0` 不从本文继承状态。

## 2. ABI、唯一调用点与返回

`sub_426840` 是四参数 cdecl：

```text
arg_0 +0x04 = map_id
arg_4 +0x08 = LMF map_offset
arg_8 +0x0C = CM relative offset，调用者可按原门控传 0
arg_C +0x10 = 0x200 字节路径 scratch buffer
```

唯一调用点为 `sub_425BE0:0x00426027..0x00426053`。调用者依次压入 scratch、受原 word
门控的 CM 相对偏移、`dword_4CEAA8` 地图块偏移和地图号；调用后把 EAX 直接写入地图状态
`+0x20`。EAX 是命中或生成后槽文件的映射基址，失败时可为 0。现代实现以拥有型
`cache_bytes` 和明确状态替代裸映射指针；scratch 路径缓冲由 `std::filesystem::path`
替代。

`arg_C` 在 `sub_426840` 中传给生成器；传给 `sub_427140` 的第二个实参是该 callee 不读取
的调用者多余参数。现代 loader 不伪造第二个语义参数。

`sub_426DF0` 是五参数 cdecl。IDA 只计出四个被引用参数，是因为 `+0x10` 的 scratch 实参
完全未读；两处调用仍各压入五个 dword 并由调用者清理 `0x14`：

```text
arg_0  +0x04 = map_id，用于 `%d.cm`
arg_4  +0x08 = LMF map_offset
arg_8  +0x0C = CM relative offset；0 时直接退出
arg_C  +0x10 = 调用者路径 scratch，callee 不读取
arg_10 +0x14 = u32* generated_size，头读取成功后写 header[+0x10]
```

唯一调用者是 `sub_426840`，分别位于一般 miss 和空目录分支。函数所有正常/错误出口都把
EAX 清零，调用者不消费返回值，只消费 `arg_10` 和槽文件副作用。现代 typed result 额外
暴露阶段状态；未使用 scratch 与恒零 EAX 不伪造成业务参数。

`sub_4270F0` 同样占五个 cdecl 参数槽，但只读取第二、第三和第五个：

```text
arg_0  +0x04 = unused map_id
arg_4  +0x08 = LMF map_offset
arg_8  +0x0C = CM relative offset；0 时退出
arg_C  +0x10 = unused scratch path
arg_10 +0x14 = u32* declared_size
```

唯一调用点是 `sub_426840:0x004269E3..0x00426A03`。零 offset 分支经 nullsub 返回，EAX
不具业务定义；非零分支把 `sub_438610` 的读取结果留在 EAX。调用者清理 `0x14` 字节并完全
忽略 EAX，只使用输出 dword。现代 size result 把未检查/未定义域改为显式状态。

`sub_427140` 是两参数 cdecl，IDA 因第二槽未读而误标为一参数：

```text
arg_0 +0x04 = stored_slot，用于 `%sdata\\%d.cm`
arg_4 +0x08 = unused caller scratch path
```

三个调用点均在 `sub_426840`：hit、一般 miss 生成后、空目录生成后；每处压入 slot 与同一
scratch，再由调用者清理 8 字节。EAX 返回只读映射基址；open、mapping 或 view 失败时可为
0。每次调用后 caller 还另有一个直接 `_AIL_serve`，不计入本函数内部次数。现代接口只接收
有语义的 slot/cache-directory，并以状态与拥有型 `bytes` 替代裸借用指针。

## 3. 目录记录、年龄与命中

`mcache.dat` 按实际读取字节数除以 `0x10` 得到记录数；不足 `0x10` 的尾部不参与记录解析。
每条记录为：

```text
+0x00  u32 map_id       // 0xFFFFFFFF 表示空闲
+0x04  u32 byte_size
+0x08  u32 use_counter
+0x0C  u32 stored_slot
```

非空目录先把全部记录的 `use_counter` 以 `u32` 递增，再从头寻找首个 `map_id`。命中后按
`stored_slot` 取得槽内容；紧随其后的直接音频维护完成后才把该记录计数清零。目录从偏移 0
重写 `record_count * 0x10` 字节并关闭，最后再执行一次直接音频维护。

命中路径不截断 `mcache.dat`，原不足一条记录的物理尾部继续保留。槽文件使用
`OPEN_ALWAYS`；缺失槽会先创建为空文件，随后以明确 `cache_file_empty` 失败，但目录年龄
和命中记录清零仍按原顺序提交。

## 4. miss、容量与逐项淘汰

miss 先调用 `sub_4270F0` 取得新缓存大小。合法域容量上限为：

```text
byte_limit = cache_limit_megabytes << 20
```

加法、减法、左移和记录年龄都保留 `u32` 回绕。满足任一条件时继续淘汰：

- `record_count != 0` 且 `current_total + new_size > byte_limit`；
- 当前没有空闲记录。

每轮从头扫描活动记录：先记住首个严格更小 `byte_size` 的 fallback；遇到首个
`use_counter > unsigned(signed(cache_limit_megabytes) / 4)` 的记录立即停止扫描并选中。
因此它不是 LRU：达到年龄阈值的物理首项优先，否则选择首个严格最小项。

选中后先保存旧 `stored_slot` 和大小，把记录重置为
`{0xFFFFFFFF, 0, 0, record_index}`，执行本轮直接音频维护，再用 `OPEN_ALWAYS` 打开旧槽，
从偏移 `0x10` 截断，最后从总量减去旧大小并重新判断。现代实现可先计算等价淘汰计划，
但文件截断和直接音频维护仍逐项交错，不批量移到循环外。

停止淘汰后扫描第一条空闲记录并写入 `{map_id, new_size, 0, record_index}`。一般 miss
先重写并截断目录、关闭目录，再生成槽并取得全部物理字节。

## 5. 空目录专用路径

`mcache.dat` 大小为零时不进入一般 miss：

1. 先在槽 0 调用 `sub_426DF0` 生成请求地图；
2. 固定建立 24 条目录记录；
3. 第 0 条为 `{map_id, generated_size, 0, 0}`；
4. 第 `1..23` 条为 `{0xFFFFFFFF, 0, 0, index}`；
5. 写入并截断为 `0x180` 字节后关闭目录；
6. 调用 `sub_427140` 取得槽 0。

空目录是“先生成、后提交”；一般 miss 是“先提交、后生成”。测试固定这两个相反顺序。

## 6. `sub_426840` 的 14 个直接 `_AIL_serve` 静态点

`sub_426840` 自身有 14 个显式 `_AIL_serve@0` 调用点，不包含被调用 helper 内部维护。
动态次数按路径为：

```text
目录打开失败 = 1
命中           = 5
空目录         = 5
非空 miss      = 8 + eviction_count
```

操作位置为：

- 共用：路径准备前、目录打开成功后；
- 非空目录：目录读取后；
- hit：槽取得后且命中计数清零前、目录重写并关闭后；
- miss：大小 helper 后、每个淘汰槽打开前、淘汰循环结束后、目录重写前、目录截断并关闭后、生成并取得槽后；
- 空目录：24 条记录建立后、目录写入/截断/关闭后、槽 0 取得后。

## 7. `sub_426DF0` 分块生成、进度与直接维护

CM 相对偏移为零时函数不打开槽、不写 `generated_size`，也不执行直接维护。非零时按以下
顺序执行四个循环外 `_AIL_serve`：

1. 路径分配与槽打开前；
2. 槽 `OPEN_ALWAYS` 成功、文件指针移到零并释放路径缓冲后；
3. LMF 指针移动到 `map_offset + cm_relative_offset` 后；
4. 固定 `0x1A8` 字节头读取成功后。

头字段和块数严格为：

```text
declared_size = header[+0x10]
chunk_size    = header[+0x14]
buffer_size   = chunk_size + (chunk_size >> 10)
chunk_count   = (chunk_size + declared_size) / chunk_size
```

最后一式故意不是普通 ceil。`declared_size` 恰好整除 `chunk_size` 时仍多处理一个块；该块
继续读取、解压和维护，但写入长度为零。每块的压缩大小取 `header + 0x1C + index * 8`，
负载在头后连续排列。每块另有三个直接维护点：压缩块读取前、读取成功后、可选像素转换后且
槽写入前。因此成功动态次数为：

```text
direct_AIL_count = 4 + 3 * chunk_count
```

解压完整写入复用输出缓冲，但只向槽写 `min(remaining, chunk_size)`。地图像素位数等于 16
时，只把该写入前缀按 word 数 `bytes_to_write >> 1` 做 forward 转换；解压尾部不转换也不
写入。槽从偏移零覆盖但不截断，旧物理尾部保留。

每块写入后调用 `sub_40ED60`，参数为：

```text
progress(index) = 15 + floor((45 * index) / chunk_count)
```

其中 `index` 从零开始，乘法与除法按 `u32`。真实 map24 四块进度为 `15/26/37/48`，随后
外层 `sub_425BE0` 才发 progress 60。`LegacyCmCacheProgressStage` 与
`LegacyCmCacheAudioMaintenanceStage` 经 loader → render 复用现有 SDL owner；进度函数内部
维护和这些显式 `_AIL_serve` 继续分开统计。

## 8. `sub_4270F0` 声明大小 probe

CM 相对偏移为零时，函数只经过 nullsub 并返回：不写输出、不执行直接维护。非零时严格只有
一个 `_AIL_serve`，位置在 LMF seek 之前；随后以 `u32` 计算：

```text
size_offset = map_offset + cm_relative_offset + 0x10
```

原函数在已打开的全局 LMF 文件上 seek，再调用固定 dword 读取 helper 把结果写入第五参数；
不检查 seek/read，调用者也忽略 EAX。现代 reader 在同一前置位置调用 audio owner，再对
archive-open、负 seek 和短读取显式失败；成功只发布完整 u32。普通一块 miss 的组合维护数
因此是 `sub_426840` 的 8、size probe 的 1、generator 的 7，共 16；单淘汰路径为 17。

## 9. `sub_427140` 槽映射生命周期

函数先构造临时路径 owner，执行第 1 个 `_AIL_serve`，分配 `0x200` 字节并格式化槽路径；
随后依次 unmap 旧 `lpBaseAddress`、将其清零、关闭旧 mapping handle 与旧 file handle。第 2 个
维护点位于新 open 之前。新槽使用只读 `OPEN_ALWAYS`；open 失败在记录诊断、释放路径后以
EAX 0 返回，因此内部动态次数为 2。

open 成功后执行第 3 个维护点并尝试创建 mapping；失败只记录诊断，不退出。保存 EDI 后执行
第 4 个维护点，再尝试映射 offset 0 到 EOF；view 失败同样只记录诊断。无论 mapping/view
是否成功，函数都把当前路径复制到全局缓冲、释放临时路径、执行第 5 个维护点，然后返回
EDI 中的映射基址或 0。因此 open 成功路径固定为 5 个直接点，empty 文件也不提前退出。

现代 `read_legacy_cm_cache_unit` 在第 1 与第 2 个 owner 回调之间清空旧借用输出，在第 4 与
第 5 个回调之间读取完整物理文件；open 失败返回 2 次，ready/empty/read-failed 返回 5 次。
caller 紧随 helper 的维护继续单独保留。普通一块 miss 的完整组合为
`8 + 1 + 7 + 5 = 21`，单淘汰为 22；empty-directory 首次生成是 `5 + 16 + 5 = 26`，
hit 是 `5 + 5 = 10`。

## 10. 平台适配与危险点

四个已关闭函数均分类为 `platform_adapted`：

- 固定 `0x200` 路径/目录缓冲、`0x1A8` 头和两个 `chunk + chunk/1024` malloc 缓冲改为
  vector/array、RAII 文件和拥有型字节；
- Windows `data\\mcache.dat` 与 `%d.cm` 改存 OpenSWD3 自有 cache directory，不改写原游戏 Data；
- generator 与 size probe 使用独立 archive reader 替代已打开的全局 LMF 文件，未读取的
  map-id/scratch 参数被删除；
- 进程期 file/mapping/view globals 与裸基址借用改为 RAII file 和拥有型 bytes；每次调用内
  保留旧借用失效顺序，但多个现代 result 可安全独立持有，不复现悬空映射；
- seek/read/write/truncate/open 的未检查失败改为对应阶段状态，保留失败前已经发生的直接维护；
- 非零短目录、无淘汰候选、块表越界、容量回绕、解压失败和输出不足在原越界/未定义点前停止；
- 原 generator 在头读取或块读取失败时泄漏部分 malloc 缓冲，现代 RAII 不复现泄漏；
- 只读映射以完整物理文件字节表达，不擅自裁成目录记录的 `byte_size`。

这些适配不改变合法域记录宽度、尾部保留/删除、年龄回绕、首命中、淘汰选择、块数 BUG、
转换前缀、写入/进度顺序或直接音频维护顺序。
