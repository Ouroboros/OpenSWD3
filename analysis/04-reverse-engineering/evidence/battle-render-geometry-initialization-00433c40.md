# 战斗绘制宿主与方向表初始化 `0x00433C40`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 范围、ABI与调用图

权威LST函数范围为`0x00433C40..0x00433D67`，入口`proc`至`endp`连续，共134行，没有外部`FUNCTION CHUNK`。

ABI为thiscall：ECX是全局战斗绘制owner；无栈参数；正常出口在EAX返回原owner。

唯一直接caller是`0x004518B0`。该caller把全局owner地址写入ECX后直接尾跳本函数；它本身由全局构造入口`0x004518A0`调用。caller及其外部析构chunk属于后续独立函数关闭，不从本项继承完成状态。

三个直接battle callee均已关闭：

- `0x00433E20`：主行偏移表重建；
- `0x00433E90`：surface行偏移表重建；
- `0x004342E0`：绘制矩形surface边界放置。

另调用`0x00489654`九十次逻辑迭代。该CRT叶子临时把x87控制字改为向零截断，以`fistp qword`转换当前ST(0)，恢复控制字后返回低32位。

现代实现直接组合三个已关闭battle入口，不保留opaque回调。

## 2. 两张旧行表的预清零与泄漏

入口按顺序把owner `+0x0B40`主行表指针和`+0x0B44` surface行表指针写零，随后才调用两个行表重建callee。

因此即使入口owner原本含旧表，两个callee也看不到旧指针，自己的“非空则释放”分支不会执行。旧表被遗失而不是释放。这是原始可观察的所有权顺序，现代实现以`unique_ptr::release()`明确保留，不用`reset()`或直接赋新值无意修复泄漏。

原运行路径由全局构造入口调用，静态owner初值为零；定向测试仍以已有两张表固定重复调用时的泄漏语义，并在测试结束后由夹具回收裸指针，避免测试进程本身泄漏。

## 3. 固定主行表

第一次callee调用参数固定为：

```text
row_stride = 0x500
row_count  = 0x300
```

正常结果：

- 请求`0xC00`字节；
- 发布主步长1280和行数768；
- 写入768个u32字节偏移；
- 首两项为0、`0x500`；
- 最后一项为`0xEFB00`。

申请失败时callee只保持主表为空并保留入口主步长/行数。本函数忽略该失败，继续surface、矩形和方向表。

若typed分配器容量不足，停止位置是callee原首次越界u32写。本函数不执行后续surface调用、矩形或方向表，以此隔离原裸写故障，不伪造正常后缀。

## 4. 固定surface行表与矩形

第二次callee调用参数固定为：

```text
row_stride = 0x280
row_count  = 0x1E0
```

正常结果：

- 请求`0x780`字节；
- 发布surface宽640、高480；
- 写入480个u32偏移；
- 首两项为0、`0x280`；
- 最后一项为`0x4AD80`。

surface申请失败时保留入口surface宽高。本函数仍调用矩形callee，固定参数为左0、上0、宽640、高480。因此入口宽高若为10×20，原矩形规则会发布左`-630`、上`-460`、右10、下20；现代实现不把失败情况修正成640×480。

surface表写typed-stop则发生在矩形前，保留已经完成的主表和新surface元数据，不发布矩形及方向表。

两个申请都失败时也继续矩形和方向表。只有原写访问故障停止，普通空申请不停止。

## 5. x87基础斜率表

首个90次循环对索引`0..89`执行：

```text
horizontal[index] = -1000
vertical[index] = trunc_to_zero(
    tan(x87(index) * double_bits(0x3F91DCF4D98B0955)) * float(-1000.0)
)
```

角度常量的精确double值为`0x1.1dcf4d98b0955p-6`，约`0.017444444444444446`，不是现代`π/180`。比例常量是精确float `-1000.0`。

`fptan`在默认x87扩展精度下执行；随后`0x00489654`设置向零截断再做qword整数转换。所有90个结果都落在i32范围内。

为了避免Linux与Windows的`std::tan`/libm实现差异，现代实现不在运行时重新计算。它以独立x87原指令序列生成并冻结90项低32位结果。关键项：

- 0：0；
- 1：-17；
- 44：-964；
- 45：-999；
- 89：-54816。

这不是近似数学重写，而是原FPU序列结果的平台隔离。

## 6. 第二象限的不对称复制

第二段循环：

- 目标索引为`91..179`，共89项；
- horizontal固定1000；
- vertical依次复制基础表`88..0`。

它**不复制基础索引89**。因此：

- 索引89是`(-1000,-54816)`；
- 索引90稍后成为`(0,-100000)`；
- 索引91是`(1000,-28010)`，不是`(1000,-54816)`。

现代实现保留89项计数和从88开始的源索引，不用数学镜像补齐缺项。

## 7. 第三与第四象限

第三段循环目标索引`180..269`，共90项：

```text
horizontal = 1000
vertical = wrapping_negate(base[0..89])
```

第四段循环目标索引`271..359`，共89项：

```text
horizontal = -1000
vertical = wrapping_negate(base[88..0])
```

第四象限同样跳过基础索引89。因此索引271为`(-1000,28010)`。

原`neg`是32位回绕取反；现代实现调用已有回绕取反，不使用更宽整数。不过当前冻结基础值均不会触发`INT_MIN`。

## 8. 四个正交方向

循环结束后六次写入覆盖四个正交方向：

```text
index   horizontal   vertical
0       -1000        0
90      0            -100000
180     100000       0
270     0            100000
```

索引180的horizontal先被第三段循环写1000，最后覆盖为100000；其vertical写零。索引90和270由此前循环故意留空，最后集中发布。

这些大幅值是方向推进使用的原比例，不归一化到1000。

## 9. 表布局与已关闭consumer

原owner布局是两张连续360项signed i32数组：

- horizontal：owner `+0x000..+0x59C`；
- vertical：owner `+0x5A0..+0xB3C`。

这与已关闭`0x00434420`的两次索引读取完全一致。现代`LegacyBattleDirectionVectors`继续用两张各360项数组；本函数把它嵌入同一typed战斗绘制owner，已关闭consumer可直接借用，不复制或转置。

完整720个i32按值和小端字节计算的FNV-1a锁为`0x62C7B4D936076038`。定向测试同时检查该整表锁和各象限边界值，避免只验证少数样本而漏掉复制计数或源索引。

## 10. 正常出口与typed-stop

正常路径在完成矩形、四段方向表和六个正交分量后返回owner指针。

现代总状态：

- `completed`：包括两个行表申请成功或普通申请失败；
- `primary_row_offsets_write_out_of_range`：主表原写点停止；
- `surface_row_offsets_write_out_of_range`：surface表原写点停止。

后两种状态不发布正常返回owner，不把原内存破坏域伪造为成功。

## 11. 双向追溯

LST到C++：

- `0x00433C40..0x00433C5E`：旧表指针预清零、固定主表；
- `0x00433C63..0x00433C82`：固定surface表及全surface矩形；
- `0x00433C87..0x00433CBD`：90项x87基础表；
- `0x00433CBF..0x00433CE9`：第二象限89项逆序复制；
- `0x00433CEB..0x00433D0B`：第三象限90项取反；
- `0x00433D0D..0x00433D30`：第四象限89项逆序取反；
- `0x00433D32..0x00433D61`：六个正交分量与owner返回。

C++到LST：

- 两次`release()`分别对应两个callee之前的指针零写；
- 两次fixed row rebuild和一次rectangle调用都有唯一LST调用点；
- 90项冻结表均来自精确常量字节、x87 `fptan`和向零转换；
- 三段复制循环的目标起点、89/90计数、源起点和取反均有对应寄存器；
- 全部360项X/Y都有唯一写来源；
- 没有新增随机、裁剪、角度归一化、插值、异常重试或释放。

完整正向与反向追溯未发现未解释基本块、外部chunk、callee、表项或出口。

## 12. 测试与动态差分

定向测试覆盖：

- 两张旧行表在callee前被遗失而未释放；
- 固定1280×768主表和640×480 surface表全部元数据及首尾偏移；
- 固定全surface矩形；
- 720项整表哈希、基础斜率关键值、第二/第四象限缺89项镜像、四个正交方向；
- 两次普通申请失败仍继续，且保留旧元数据形成原矩形结果；
- 主表与surface表容量不足分别只在各自原写点停止，并阻止后缀。

本函数不消费物理游戏资产。定向battle聚合测试与零warning目标构建通过。

当前没有可用原版全局构造后owner行表、720项方向数组与分配失败联合捕获后端，`original_diff_verified`为`blocked_runtime_oracle`。独立x87序列固定了本函数唯一浮点派生数据，但不冒充原版进程动态联合捕获。
