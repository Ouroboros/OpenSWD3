# 普通世界帧后玩家账本（`0x00412719..0x0041287C`）

状态：`assembly_exact`、`unit_verified`、`asset_verified`；尚未
`original_diff_verified`

本文只以 `swd3.exe.lst` 的机器码和指令为行为真值。该区间位于普通世界唯一一次
画面提交之后、tile 层动画之前，负责同步玩家的空间链、地图表面占用、位置历史和动作
记录。它现在由 `advance_legacy_world_player_post_frame` 在原槽整体执行，不再转交三个
占位 stage。

## 1. 对齐门与固定顺序

`0x00412719` 先检查玩家 X 的低四位，`0x00412726` 再检查 Y 的低四位。任一非零都
直接跳到 `0x0041283C`；此时空间链、表面格、四个 transition 和三组历史都保持不变，
但动作校验仍会执行。两轴均按 16 像素对齐时，物理顺序固定为：

1. `0x0041272E..0x00412747`：以玩家 GUID、`flags & 3`、
   `(world_y >> 4) - 1` 调用 `sub_411530`，从旧空间链解开并重新插入。
2. `0x00412747..0x0041274D`：调用 `sub_40AE20` 清除旧地图格占用。
3. `0x0041274D..0x0041277D`：按
   `(camera_y_transition + player_y_transition) * map_width +
   player_x_transition + camera_x_transition` 移动格指针，再调用 `sub_40AEC0`
   标记新占用。
4. `0x00412788..0x0041279A`：把相机/玩家的 X/Y transition 全部清零。
5. `0x004127A0..0x00412801`：X 或 Y 与历史首项不同时，移动三组历史并写入当前值。
6. `0x00412807..0x00412839`：仅当角色 flags bit 8 为一时，从当前地图格刷新投影 flags。
7. `0x0041283C..0x0041287C`：执行不受对齐门限制的动作校验。

原程序 `[role+0x0C]` 保存的是四字节地图格指针，所以步骤 3 在最终和上乘四。现代
owner 保存受检的格索引，故实现使用同一 32 位回绕公式但不乘四；可观察到的目标格
完全相同。

## 2. 表面占用的共享 owner

`sub_40AE20` 与 `sub_40AEC0` 已提取为共享的角色表面占用 owner，帧后同步和
`sub_40D610` 角色转移共同调用，避免维护两份足迹算法。

| 行为 | 汇编值 |
|---|---|
| 普通角色清除 mask | `0xCF7FFFFF` |
| 当前选择角色清除 mask | `0xCF7FFEFF` |
| 普通标记 | `0x10000000` |
| role flags bit 14 标记 | `0x30000000` |
| role flags bit 4 附加标记 | `0x00800000` |
| 当前选择角色附加标记 | `0x00000100` |

两函数都先访问 anchor，再处理 `height=1,width=2`、`1,1`、`2,1` 三条特例；其余尺寸
进入通用双循环。通用路径没有撤销首次 anchor 访问，因此 anchor 会被处理两次，测试
保留了这个原始顺序。

## 3. 三组 32 项历史

- `0x004B7A18`：玩家 X 历史；
- `0x004B7998`：玩家 Y 历史；
- `0x004C8C00`：动作记录 `+0x34`，即当前模型中的 `variant_delta` 历史。

当 X/Y 任一变化时，三次调用都从数组首地址复制到 `base+4`，长度固定为 `0x7C`
字节，因此各自把前 31 个 dword 移到槽 1..31，再写当前 X、Y、动作值到槽 0。
`0x0040C9AF..0x0040C9DD` 的初始世界路径只把初始 Y/X 各填充 32 个 dword；它不在
这里初始化动作历史，实现也不擅自补写第三组。

## 4. 地图格 flags 与动作校验

地图格投影先用 `0xDF0FFFFF` 清角色目标字段，再把格 bit 11 投影为角色 bit 29，并把
格 `0xF000` 投影到角色 bits 20..23。该运算也由初始角色格绑定复用。

动作校验先检查角色 flags bit 30：置位就跳过；否则要求 bit 12 置位，再对嵌入的
`0x98` 动作记录调用 `sub_4321E0`。更新失败只进入原诊断调用，随后继续 tile 动画，
所以现代 port 记录 `action_update_failed`，但不把整帧判为失败。

## 5. 验证边界

UT 已固定：完整对齐顺序、格索引的正负回绕合同、空间链重插、旧格清除/新格标记、
三组 `0x7C` 历史移动、地图格 flags 投影、非对齐仍校验动作、bit 30 抑制，以及动作
更新失败非致命。真实初始世界的 `MAPS + LMF + ACT` 会话也经过该原槽，验证零
transition 时格索引与历史不漂移。
