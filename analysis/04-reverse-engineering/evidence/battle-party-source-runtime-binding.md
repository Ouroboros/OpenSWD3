# B11：队伍基础记录与存档辅助扩展分离

状态：来源修正、生产调用方及定向验证已完成。
完整SDL队伍初始化、战斗帧及实际续玩仍未完成。

## 原版来源与顺序

- `0045223F`形成`004ACF50 + index*0x60`，作为第二参数。
- `00452246`形成`004AB790 + index*0x38`，作为第一参数。
  `00452251`调用`0046E730`；第三参数为placement。
- `00408586`恢复四条基础记录，共`0xE0`字节。
  `00408A52..00408A6E`另行恢复辅助扩展，共`0x180`字节。
  扩展B的前14个DWORD不是基础记录的替代来源。
- `0046E74D/0046E75C`先复制两份placement；`0046E763`将其末DWORD
  写入actor+`2AA0`。`0046E774`再复制基础记录14个DWORD。
- 基础复制完成后，`0046E77A/0046E77F`才发布两个来源指针。
  诊断返回后，`0046E7CF`重新取基础来源；六个WORD按原顺序作signed限幅。
  源记录的限幅不追溯修改已复制的actor记录。
- 召唤`0046E8ED`与护援`0046EA1D`也写actor+`2AA0`。
  配置、这两个物化入口和既有运行时编解码必须使用同一字段。

## 当前实现与真实调用方

世界/剧情的`LegacyWorldStoryPartyMemberResources`继续唯一持有基础记录。
`LegacyBattleStartupState::group_a_configuration_sources`仅保存四个可写字节视图。
核心启动通过必需端口借用来源；SDL现有战斗准备入口直接绑定世界/剧情记录。
没有增加持久基础副本，也没有在配置后整块复制回世界状态。

扩展B继续由既有存档恢复函数读取，改写独立的`group_a_auxiliary_sources`。
SDL已有的存档扩展保存与恢复也使用该辅助存储；不会保存或覆盖基础视图。
辅助记录保留每条完整`0x60`字节，原始字段及尾部不丢失。

配置器通过字节视图读取基础记录，保留14个DWORD的复制顺序。
诊断后逐次读取及限幅同一来源。组A帧按来源token取得同一借用视图，
属性效果计算继续实时读取；旧自有数组入口仅作为接口适配，不复制来源。

删除重复的`placement_tail`，三个写入入口直接写既有`source_runtime_value`。
运行时编解码继续使用这一字段，不再依靠两个字段相互同步。

## 停止与测试向量

来源视图不足时按`REP MOVSD`的DWORD边界停止。已完成的复制保留；
EAX保持来源地址，ECX为剩余次数，EDX保持placement地址。
源指针与辅助指针的发布位于复制之后，失败时不执行。
零来源token和零actor记录token保留既有首次访问停止顺序。

新增或调整的测试包含：

- 真实世界记录类型先复制12000；诊断回调将原字段改为1，后续限幅读取1。
- 无诊断时同一世界字段限幅为9999，actor副本仍为12000。
- 0、3、4、55字节视图保留逐DWORD复制前缀与剩余次数。
- 扩展B恢复不改变基础记录内容或视图地址，完整辅助尾部照常恢复。
- 组A帧、启动、全局重置及召唤测试使用正确来源或同址活动值。
- 既有真实存档扩展测试继续检查`Save/0.sav`，合成向量检查填充尾部。
