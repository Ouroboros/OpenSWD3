# 邻像素涂抹 blitter `0x00422730/0x004229C0`

状态：`assembly_exact`、`unit_verified`；原程序动态 framebuffer 差分仍为 `blocked_runtime_oracle`。

## 证据边界

唯一汇编主证据是完整 LST `swd3.exe.lst`：

- 正向函数：`0x00422730–0x004229BE`；
- 反向函数：`0x004229C0–0x00422C61`；
- 分派槽：`0x30/0x32 -> 0x00422730`，`0x31/0x33 -> 0x004229C0`。

ASM 和伪码不参与范围判定或语义取证。`analysis/tools/build_blitter_dispatch_inventory.py` 直接锁定完整 LST，并机械核对两个函数的计数门、四组邻居地址、源/目标步进和 jitter phase 差异。

## 每次调用的 17 拍状态机

两个入口都先把全局 `0x004CD314` 清零。每个实际进入可见 literal 像素循环的像素先把该值加一，再按以下分支处理：

| 拍数 | 当前目标写入值 | 正向地址 | 反向地址 |
|---:|---|---:|---:|
| 1..4 | 实时 `[dst-2]` | `0x0042289F` | `0x00422B4E` |
| 5..10 | 实时 `[dst+0x500]` | `0x004228B3` | `0x00422B62` |
| 11..13 | 实时 `[dst-0x500]` | `0x004228CA` | `0x00422B79` |
| 14..16 | 实时 `[dst+2]` | `0x004228E1` | `0x00422B90` |
| 17 | 只把计数清零，不读取或写入 framebuffer | `0x004228F0` | `0x00422B9F` |

第 17 个像素仍在公共尾部把源指针加二并移动目标指针，所以它是“消费但不写”，不是 16 拍循环外的额外透明 run。下一像素重新成为第 1 拍。

计数器在函数入口清零，行首和 run 首均不清零。因此它：

- 跨同一调用中的多个 literal run 连续；
- 跨输出行连续；
- 不因高位透明 run 推进；
- 不因顶部裁剪跳过的整行推进；
- 不因左侧裁掉的 literal 前缀推进；
- 在下一次 blitter 调用重新从零开始。

## 源像素与实时目标依赖

literal payload 仍按每像素两字节推进，但像素循环中没有从该位置读取颜色；源像素只提供覆盖 footprint。四组来源都直接读取当前 framebuffer，因此前面像素已经产生的写入可以被后续拍读取，结果依赖原始遍历顺序，不能先把整块邻居复制到临时缓冲再统一写回。

正向公共尾部 `0x004228FD` 执行 `dst += 2`，反向 `0x00422BAC` 执行 `dst -= 2`。反向只改变目标遍历方向；四组邻居地址仍是 `-2/+0x500/-0x500/+2`，没有左右或上下交换。这会使正反向在第 14..16 拍产生不同的实时写后读链。

## 固定扫描线距离

上下邻居距离是指令立即数 `0x500`，没有读取当前 surface pitch。它对应原 640×16-bit 工作缓冲的一条扫描线。即使测试 framebuffer 配置为其他 pitch，函数仍从物理地址 `dst±0x500` 取值；兼容核心不得把它替换为 `dst±pitch`。

原函数没有边界保护，若第 1 拍落在 owned framebuffer 的第一个物理像素，`[dst-2]` 会读取 framebuffer 之前的进程内存。现代实现不复制未定义的相邻内存：在保留此前已完成写入的前提下返回 `destination_out_of_bounds`。这是隔离在兼容边界的内存安全适配，不改变任何有效 640×480 工作缓冲路径的游戏逻辑。

## RLE、裁剪与 jitter

两个函数都要求源头 `+6` 的 bit `0x10`，从 `source+8` 读取按低 15 位字节长度串联的 RLE 行。literal run 仅对裁剪窗口内部分执行涂抹；高位 run 只移动目标。源行 jitter 使用 `0x84` 字节组距，每条输出行在应用偏移前先把游标加四并按组回绕。

退出差异必须保留：

- 正向 `0x00422992–0x004229AE` 在 jitter 启用时把共享 phase 加四并在 `0x84` 回零；源 gate 失败、零行或正常完成都经过该出口。
- 反向 `0x00422C5B–0x00422C61` 直接返回，不更新共享 phase。

## 验证

UT 固定了：

- 完整 18 像素序列，覆盖 `4/6/3/3/第17拍不写/重新第1拍`；
- 正向和反向的固定邻居地址、实时写后读差异；
- literal 颜色被忽略，高位 run 不推进计数；
- 计数跨 literal run 和输出行连续；
- 左裁掉的 literal 前缀不推进计数；
- 非 `0x500` pitch 下仍读取物理 `+0x500`；
- 正向 phase 加四、反向 phase 不变；
- framebuffer 外邻居被安全拦截且不虚构值。
