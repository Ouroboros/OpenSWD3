# 存档预览姓名读取的映射边界

状态：限定映射边界修正已通过定向core/ASan与SDL链接验证。
属于B11战斗结果2返回时的预览重置路径，
不改变完整战斗接线、原版选档界面与实际续玩的验收条件。

## 汇编合同

完整重读`00409600..004099B6`正文402行及`00498050..0049805D`清理chunk。

- `0040980B`执行第三段解压，调用者不检查返回码。
- `00409813..0040981C`用第三段声明压缩长度计算并保存姓名源地址。
- `00409823`写记录`+28`，随后分配并复制0xE0字节角色临时数据。
- `0040984C..00409879`按已有缺席哨兵选择性填写四个角色摘要。
- `0040987D..0040988F`分配并发布0x40字节姓名资源。
- `00409898`按dword复制姓名；`0040989A`才读取游戏秒数。
- `00409980`在全部成功后才把状态word写2。

原版没有提前拒绝超长声明长度。现代有界模型只能在首次未知读取处停止；
不能将这个停止冒充原版正常失败返回，也不能提前丢弃解压结果及记录写入。
原版映射外实际地址与异常行为仍无运行差分证据。

## 缺陷与修正范围

物理预览解析器允许解压EOF在声明段末端之前出现，并按声明长度推进游标。
第三段后在未确认游标仍位于映射内时计算`bytes.size() - offset`，会导致
无符号下溢，继而在姓名复制处形成非法源指针。

限定修正为姓名读取前检查映射边界。保留`role_names`阶段、实际第三段输出、
零已读姓名字节；记录生产者仍执行先前字段写入和姓名资源分配，随后停止。
不修改完整LOAD容器或解压返回码语义。预览解压后的声明长度推进按原32位
`lea`回绕；全1长度相当于源数据起点减1，可能重新落入映射内，不能直接拒绝。
以映射起点为基准计算的相对游标同样保留低32位，再于下一实际读取检查范围。

## 独立回归向量

从原`rep movsd`及随后的dword读取推导，将姓名地址定位到映射末端之前
68、67、64、63、4、3、0字节，以及末端之后1字节；另覆盖0x7FFFFFFF长度、
全1长度回绕至段头末字节，以及回绕至映射起点。

- 68字节时完成姓名与秒数读取。
- 67和64字节时姓名复制完成，停在秒数读取。
- 63、4、3字节分别只复制60、4、0字节姓名。
- 末端及映射外不能读姓名字节，不发布完成状态或游戏时间资源。
- 全1长度与回绕至映射起点均读取回绕地址处的姓名和秒数，正常写完成状态。
- 全部用例保留先前角色解压输出、记录字段、像素转换结果及姓名未写后缀。
