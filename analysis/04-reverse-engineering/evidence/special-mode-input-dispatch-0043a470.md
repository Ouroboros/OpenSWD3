# 标准特殊模式输入分派 `0x0043A470`

状态：`platform_adapted`

## 1. LST锁

权威范围为`swd3.exe.lst`的`0x0043A470..0x0043A60A`。唯一调用者是标准特殊模式总入口`0x00439FD0`；调用者不读取EAX。

函数包含13个间接调用点，对应12个唯一回调槽。除动态前置槽`0x004FB808`外，机器不做空指针检查；其余槽由`0x0043B480`回调绑定器保证。当前入口只保持调用门和顺序，具体回调目标仍归`0x0043B480`及各目标入口独立闭环。

## 2. 固定前置顺序与共享overlay

每帧最先执行：

1. 若`0x004FB808 != 0`，调用动态前置槽。
2. 无条件调用主槽`0x004FC64C`。
3. 输入记录0的rapid字段非零且held字段等于`1`时，调用共享槽`0x004FC838`。
4. 仅当cooldown `0x004FC908 == 0`且输入记录9满足同一严格门时，把cooldown写为`6`并再次调用`0x004FC838`。
5. 无条件对当前cooldown执行32位`dec`；结果符号位为1时钳为0，否则保留递减结果。因此刚写入6的同一帧结束为5，`0x80000000`则递减为`0x7FFFFFFF`而不会钳零。

严格门定义为`rapid != 0 && held == 1`。

## 3. 独立输入门

cooldown之后，各分支独立执行，不因前一个回调成功而短路：

- 记录2严格门调用`0x004FC83C`。
- 记录10严格门调用`0x004FBF7C`。
- 记录6重复门调用`0x004FC828`。
- 记录4重复门调用`0x004FC4E8`。
- 记录8重复门调用`0x004FBF78`。
- 记录7重复门调用`0x004FBA10`。

重复门定义为：

```text
rapid != 0 &&
(held == 1 || (held低位为0 && signed32(held) > 7))
```

这里的`> 7`是有符号比较；高位置位的偶数held不能按无符号大数触发。

## 4. 旧AL门控异常

记录7分支结束时，EAX保存记录7的held；如果其回调执行，机器会在回调后重新读取该held。

随后记录3和记录5的门控虽然分别把自己的held载入ECX，却执行`test bl, al`，实际测试的仍是记录7 held的旧AL最低位：

- 记录3调用`0x004FBAC0`。
- 记录3回调后再次读取记录7 held，供记录5继续使用。
- 记录5调用`0x004FC788`。

两者都使用“自身rapid非零、自身held等于1，或者旧AL为偶数且自身held有符号大于7”的门。现代实现原样保留该异常，不改成测试自身held低位。

## 5. 退出二选一

最后先检查记录1严格门；命中后直接调用退出槽`0x004FC3C0`并跳过记录12。只有记录1未命中时才检查记录12严格门。因此两者同帧都命中仍只调用退出槽一次。

## 6. typed owner与验证

`LegacyStandardModeInputState`保存共享overlay cooldown。分派函数直接消费现有20项`LegacyInputRecord`数组，并通过枚举化端口按原地址顺序发布回调。端口回调可以修改记录和cooldown；后续门始终重新读取实时状态，保持间接回调副作用的可观察时序。SDL标准模式主帧已接入该typed owner；未关闭的回调目标当前不伪造业务结果。

`special_modes.legacy_initial_menu`覆盖：

- 动态前置、主槽和全部独立门的地址顺序。
- 共享槽同帧两次调用、cooldown写6后递减为5。
- 32位`dec+jns`的`0x80000000 -> 0x7FFFFFFF`边界。
- 严格门、重复门和有符号比较。
- 记录3回调修改记录7后，记录5使用重新载入旧AL的行为。
- 记录3/5误用记录7旧AL的原始异常。
- 记录1优先于记录12且退出槽最多调用一次。
- 回调计数、共享槽计数和退出计数。
