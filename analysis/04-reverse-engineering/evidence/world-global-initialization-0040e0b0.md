# 世界全局初始化闭环

状态：`platform_adapted`、`assembly_exact`（已归属的可观察状态）、`unit_tested`、
`asset_verified`；原程序动态差分仍为 `blocked_runtime_oracle`。

唯一行为依据是 `swd3.exe.lst` 的 `0x0040E0B0..0x0040EB53`。该函数同时重建多个
模块的进程期状态，不能按 IDA 推断出的单一返回类型理解。两个调用点
`0x0040F1BA`、`0x00424EC5` 均在调用后直接进入 `sub_439DE0`，没有读取 EAX，故尾部
残留的 EAX 值不是调用合同。

## 1. 世界与剧情 VM 自有状态

| LST 范围 | 原版行为 | 现代归属 |
|---|---|---|
| `0x0040E0C9..0x0040E1E2` | 清零 `0x400` 字节剧情位，并置位 `1/3/4/10/30/70` | `initialize_legacy_world_story_vm` |
| `0x0040E1E7..0x0040E21A` | 只写变量 0 为 `100`；延迟地图 X/Y 为 `-1`、地图号为 0；两个倒计时为 `-1`、过渡值为 0 | VM、倒计时及切换 owner |
| `0x0040E2DA..0x0040E2F0` | 清世界运行前缀并以 `sub_40DD10(0x10)` 设置移动步长 | 世界帧 coordinator |
| `0x0040E2F0..0x0040E448` | 重建鼠标主动作、边缘动作和两个对话指示动作；只立即更新主鼠标和两个指示动作 | cursor 与 dialog runtime |
| `0x0040E448..0x0040E601` | 重建倒计时、八槽头顶标记、对话框与标题动作记录；对话框八条记录此处不更新 | frame coordinator、head-sign、dialog runtime |
| `0x0040E601..0x0040E672` | 重建方向动作、四条漂移动作、跟随与地图切换动作 | frame effect owners |
| `0x0040E672..0x0040E7F1` | 装载遇敌阈值、角色目录和 MAPS 四条队伍属性模板 | 既有受检 MAPS/world 数据库 |

重复初始化不能写成对整个 `LegacyWorldStoryVmState` 的赋零。汇编只覆盖剧情位、变量
0、延迟地图三元组和音频流控制槽；变量 1..63、TALK 窗口、姓名、文字状态、等待状态及
已载窗口元数据均未被该函数写入。现代实现据此改为逐字段写回，并增加重复初始化测试，
防止将相邻但不属于本函数的 VM 状态误清。

动作记录也按原生命周期分别重建：鼠标、对话指示、方向、漂移、跟随、倒计时和头顶
标记均由其长期 owner 复位。C++ 构造器覆盖首次初始化，新游戏路径在 MAPS 角色物化前
显式执行同一轮重建；不依赖旧对象恰好仍处于默认构造状态。

## 2. 音频、战斗与物品状态转交

- `0x0040E0B9` 调用 `sub_451A20`。反查 `sub_451B10`、`sub_46E730` 和存读档函数
  `sub_4070A0` 后，`0x004ACF50/0x004ACFB0/0x004AD010/0x004AD070` 被确认是连续的
  四条、每条 `0x60` 字节的队员扩展状态；四条合计 `0x180` 字节会被存档整体搬运。
  它属于 battle/persistence，不在 B7 复制一份 world 状态。
- `0x0040E0C3` 调用 `sub_433080(1)`，建立 ACT stream cache 模式。SDL 进程期
  `LegacyActionUpdater` 以模式 1 初始化。
- `0x0040E23D..0x0040E2A1` 清除 `0x004B7C74` 起六个 dword，将当前 stream 模式
  `0x004B7380` 写为 1、参数 `0x004B74F0` 写为 0，并清后端完成状态与
  `0x004ACDBC` 控制位。VM 保存可观察的请求、参数与控制状态；后端完成位留给 audio
  owner，不伪造为剧情变量。
- `0x0040E85B..0x0040E970` 重建全局物品链和四个队伍物品 sentinel；
  `0x0040E970..0x0040EB48` 再从 MAPS `+0x34/+0x38/+0x3C/+0x40` 重建四组各
  11 条物品根。节点分配与搬运由 `sub_44D2D0/sub_44D5D0` 完成，归属
  special-modes、battle 与 persistence，B7 只登记原调用顺序和转交边界。

`0x004A94B0 = 0x40000000` 与 `0x004ACDB8 = 3` 在完整 LST 中没有其他读取点，属于
不可观察的遗留常量写入，不为它们制造现代全局字段。

## 3. 平台适配边界

- 原版释放三块裸角色空间工作区后清零指针；现代 `LegacyRoleSpatialIndex` 以 RAII
  表达同一生命周期，不复制悬空指针和重复释放状态。
- 原版把 `0xCFCF` 写入 64 个 selection word；下游只按首个 sentinel 终止读取，现代
  owner 使用一个受界定 sentinel 元素，保留有效读取结果并隔离越界扫描。
- 原版手工释放、重建多组链表；现代 list/vector owner 在相同生命周期点清空并重建，
  不保留 allocator 地址、无效节点或损坏链行为。
- battle、audio、item/persistence 的状态归属已明确转交，不以 B7 的局部占位实现冒充
  跨模块闭环。

## 4. 双向收敛与验证

- LST → C++：逐段覆盖剧情位、变量 0、延迟地图、流状态、移动步长、全部世界动作记录、
  MAPS 数据物化及各跨模块转交；两个调用点均确认不消费返回值。
- C++ → LST：每项初始化写入均可回指到本函数或已登记的 RAII/有界容器适配；删除了
  整体 `state = {}` 这种无汇编依据的扩大写入。
- UT 固定首次值、重复初始化保留未写字段、动作 id/variant、只更新两条对话指示动作、
  倒计时记录、方向/漂移/跟随记录及新游戏重建顺序。
- 真实 MAPS 阈值、角色目录和四条队伍属性模板沿既有资产回归继续验证。

有效状态上的 B7 可观察行为已经零未决收敛。剩余工作仅为登记的原程序动态差分，以及
battle、audio、special-modes/persistence 各自模块中的内部实现，不再阻塞本函数的
world-map 归属关闭。
