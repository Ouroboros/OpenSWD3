# 角色格占用查询：0x00404FD0/0x004050B0

状态：`assembly_exact`；已完成独立双向逐基本块追溯，UT 已覆盖边界和整数回绕；
原程序动态差分待统一 oracle

来源：`swd3.exe.lst` 完整汇编。汇编是唯一行为真值。

## 调用合同

`0x00404FD0(tile_x, tile_y)` 从角色索引 1 开始顺序扫描，返回首个匹配索引；没有
匹配时返回 `0xFFFFFFFF`。角色总数来自 `0x0049E0C4`，角色数组从
`0x004BABA8` 开始，记录大小固定为 `0xD8`。

候选必须同时满足：

- `role + 0x1E` 的 16 位 Talk 脚本编号非零；
- `role + 0x10` 的 32 位 flags 包含 `0x00008000`；
- `role_x >> 4 <= tile_x < (role_x >> 4) + role[+0x6C]`；
- `role_y >> 4 <= tile_y < (role_y >> 4) + role[+0x70]`。

比较均为无符号比较，两个右边界加法保留 32 位回绕。索引 0 即使字段匹配也不参与。
`+0x6C/+0x70` 落在角色内嵌的 `0x98` 字节动作记录中；本查询只把它们称为格范围，
不据此覆盖其他调用点对这两个字段的语义。

`0x004050B0` 先调用上述查询；命中后再读取同一角色 `+0x10`，只有
`test ch,20h` 非零才保留索引。这里测试的是 32 位 flags 的 bit 13，即
`0x00002000`，不是 bit 21 的 `0x00200000`。

## 现代边界

原程序默认总数不超过 256 条物理记录。现代接口用 `std::span` 承载数组，并把扫描总数
限制在实际 span 长度内，避免损坏状态造成越界；合法原始状态的顺序、位测试、比较和
回绕不变。

## 验证

UT 固定以下行为：角色 0 排除、总数 0/1 早退、两个候选门控、首个匹配优先、16 像素
坐标取整、半开矩形、32 位范围加法回绕，以及 `0x2000` 与 `0x200000` 的区别。
本轮重新从两个函数入口推导循环、无符号比较和返回，再从 C++ 反查至每条汇编路径；
现代 span 上界只隔离原版越界状态，合法状态没有新增差异。
