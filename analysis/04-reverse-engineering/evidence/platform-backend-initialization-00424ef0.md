# 平台后端初始化证据：`0x00424EF0`

状态：已从原 EXE 字节逐基本块复核；平台无关调用合同已实现，具体后端待所属模块接线

来源：`swd3.exe`

SHA-256：`0bac897a7557735b22607d8c8f0a79a3e7ae7729deb56593fd91c21e10baee0c`

范围：`0x00424EF0` 至 `0x00425040`

IDA 伪码只用于辅助识别导入和对象候选；以下顺序、条件、立即数和状态写入全部以原 EXE 汇编为准。

## 1. 输入失败路径

函数首先把 `0x004ACB90` 写零，再以实例和窗口句柄调用 `0x00436FB0`。该函数对调用者的合同是零表示成功、非零表示失败。

失败时严格依次执行：

1. `0x004ACB90 |= 0x02`；
2. 显示 DirectInput 失败消息；
3. 同步向主窗口发送消息 `2`（`WM_DESTROY`）；
4. 返回零。

这一分支不启动音频，也不尝试显示后端。

## 2. 音频调用

输入成功后，程序把同一个全局路径缓冲依次传给 `0x00485360` 和 `0x004859B0`。随后三次独立调用 `0x004862A0` 取得音频 driver 值：

- 第一次结果传给 `0x00484DD0`；
- 第二次结果传给 `0x004865B0`；
- 显示初始化成功后的第三次结果传给视频声音配置 `0x00484550`。

不能把三次查询合并成一次缓存。上述音频初始化函数的返回值在本函数中都不检查。

## 3. 显示失败路径

显示初始化 `0x00437570` 的立即数参数为：

- 模式 `0x4E22`；
- 宽 `0x280`（640）；
- 高 `0x1E0`（480）；
- 位深 `0x10`（16）。

返回零时严格依次执行：

1. `0x004B7A9C |= 0x04`，保留其他位；
2. 显示 DirectDraw 失败消息；
3. 同步发送 `WM_DESTROY`；
4. 返回零。

它不创建公共源 surface，也不写显示活动值。

## 4. 成功路径

显示初始化非零时：

1. 调用 `0x00437B60(640, 480)`，无条件把返回值写入 `0x004ACBA0`，即使它为零也不另行失败；
2. 把 `0x004B7CAC` 写为一；
3. 第三次查询音频 driver；
4. 以 selector `0x2711` 调用 `0x00437DF0` 取得显示 surface；
5. 调用 `0x00484550(display_surface, 0, audio_driver)`，其中零选择 Miles 路径；
6. 返回一。

## 5. 重写边界

`run_platform_backend_initialization` 只保留上述调用顺序、失败位、活动写入和未检查结果。SDL3、输入快照、音频设备、视频解码和 framebuffer 的实际资源分别由后续所属模块实现；不在这个协调器里仿造 DirectInput、DirectDraw、Miles 或 Bink 对象。

输入端口把旧函数的“零成功”规范化成 C++ 的 `true` 成功，但 UT 明确锁定规范化边界。具体后端替换属于 `platform_adapted`，不得借此改变调用者可观察行为。
