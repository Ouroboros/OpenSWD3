# B2 `resource_io` 有限收口审计

状态：完成；模块判定为 `module_closed_pending_oracle`

审计对象为 B2 历史范围内的 63 个函数。逐项结果见 [`resource-io-closure.tsv`](../inventory/resource-io-closure.tsv)。本审计只核对既定范围、实现映射和移交归属，不重新展开全局资源调研。

## 1. 结果

- 57 项由 `resource_io` 实现并有对应证据与测试。
- `0x00439C20` 一项有完整不可达证据，不创建伪入口。
- 5 项经完整汇编复核后不属于当前 `resource_io`：3 项整体移交、1 项平台适配、1 项拆分移交。
- 当前机器目录中的 B2 实际范围为 58 项，即 57 项实现加 1 项不可达；没有未登记缺口。

## 2. 五项边界修正

- `0x004118B0` 是媒体/CD 获取与用户提示循环，移交 `audio_video`；底层 `0x00412050` 文件探测仍由 B2 实现。
- `0x00411D90` 动态解析 `GetDiskFreeSpaceExA` 并返回可用 MiB，移交 `runtime_platform`；现有 app 端口为 `WindowEventPorts::free_disk_space_mebibytes`。
- `0x004242B0` 枚举 `DRIVE_CDROM` 盘符，属于平台媒体源发现。现代正常启动由显式数据根替代，后续媒体回退随 B5 接线。
- `0x00425040` 是启动编排器：设置默认值、当前目录、CD 盘、`Env.dat`、缓存策略、目录和剧情标志。职责按 owner port 拆到 `runtime_platform/app` 及对应业务模块，不作为资源算法整体照搬。
- `0x00425B50` 清理世界、角色和对象的大块状态，移交 `world_map`。

两份机器目录已经同步上述归属，避免后续模块重复实现或遗漏。

## 3. 收口时补齐的六项

- `0x0040F040`：maps/path/talk 数据库打开和 path 完整映射。
- `0x00412050`：现有文件独占打开探测。
- `0x00423A10`：先 `OPEN_ALWAYS` 确保文件存在，再进入记录重写器。
- `0x00423AF0`：单句柄读取、按原文件标记保留或清零 16 字节、从开头写前缀且不截断。
- `0x00423E00`：从文件偏移零覆盖 16 个绑定字节且不截断。
- `0x004267E0`：分配 `source_size + 0x20` 输出，调用 14 位压缩器并交付实际长度。

## 4. 验证与剩余阻塞

Windows LLVM `core` 与 `app` 构建均通过，34/34 CTest 全部通过。真实资产回归覆盖 6 个 TSW 档案共 20,091 帧、40 份存档的 200 个压缩块、`huge.lmf`、24 个 CM 缓存文件和 MAPS/PATH/TALK1 数据库；所有入口返回成功。

唯一剩余缺口是原程序运行时状态捕获后端，统一登记为 `blocked_runtime_oracle`。它不阻止移交到 B3，但在补齐原程序差分前不得宣称最终 1:1 动态验证完成。
