# 外部打开汇编证据：0x00424930 / 0x00424A60

状态：调用者可观察结果与 SDL3 宿主适配已实现；待真实平台 smoke

来源：`swd3.exe` 完整汇编

## 1. 两个函数的共同骨架

`0x00424930` 与 `0x00424A60` 除注册类名外结构相同：

1. 在 `HKEY_CLASSES_ROOT` 下查询类；
2. 拼出 `<class>\shell\open\command` 并读取最多 `0x80` 字节的默认命令；
3. 从命令尾部向前清零，直到遇到空格；
4. 追加一个空格和调用者参数；
5. `WinExec(command, 9)`；
6. 无条件返回零。

两条路径都不检查 `WinExec` 返回值。注册表打开/查询失败路径也不会形成
不同的调用者结果；旧实现还可能在打开失败后对未建立的句柄执行关闭。

## 2. 差异

- `0x00424930` 使用注册类 `http`，调用参数为
  `www.softstar.com.tw`；
- `0x00424A60` 使用注册类 `txtfile`，调用参数是工作目录与
  `Readme.txt` 拼成的路径。

原 URL 调用明确走 `http` 注册类。现代适配若补全 URI scheme，应使用
`http://`，不能擅自升级成不同协议并宣称 1:1。

## 3. 重写边界

`include/openswd3/app/external_launch.hpp` 与
`src/app/external_launch.cpp` 保留以下核心合同：

- URL/文档目标各向宿主端口转交一次；
- 无论宿主返回成功还是失败，旧函数结果始终为零。

读取 Windows 注册表、裁切命令行和 `WinExec` 属于被替换的平台机制，不是
游戏业务逻辑。`SdlExternalLaunchPorts` 通过 `SDL_OpenURL` 打开目标；官网补入
原注册类对应的 `http://`，本地文档转换为绝对 `file:///` URI，并对路径字节
做百分号编码。URI 构造 UT 已通过，真实系统打开 smoke 仍待规定 SDL3 工具链，
因此状态为 `implemented_pending_toolchain`，不是 `original_diff_verified`。
