# 世界角色表生命周期重置闭环

状态：`platform_adapted`、`assembly_exact`（有效角色表域）、`unit_tested`；原程序动态差分
仍为 `blocked_runtime_oracle`。

唯一行为依据是 `swd3.exe.lst` 的 `0x0040F3B0..0x0040F40D`。该函数释放当前有效角色
范围内的 `+0x38` 动态载荷，清零完整 256 项角色表，再对每项 `+0x40` 动作子记录调用
`sub_40DC00`。

## 1. ABI、状态与调用者

物理 ABI 无参数；两个调用者均不读取 EAX，因此 IDA 标注的 `int sub_40F3B0()` 不是
有效返回合同。函数读取 `dword_49E0C4` 作为当前最高角色索引，角色表起点为
`0x004BABA8`，每项 `0xD8` 字节，共 256 项。

两个直接调用点均已反查：

| 调用者 | 地址 | 用途 |
|---|---:|---|
| `sub_40C130` | `0x0040C5D4` | 地图装载期间释放旧角色载荷并重建物理角色表 |
| `sub_4251B0` | `0x00425285` | 进程级游戏运行时关闭期间执行同一重置 |

现代实现把地图装载路径映射到旧会话 owner 释放与新会话构造；进程关闭路径由同一
RAII owner 的析构承担，不复制只为手工释放存在的顶层调用。

## 2. 释放循环

`0x0040F3B0..0x0040F3DF` 的控制流为：

1. 入口读取最高角色索引；任意负值都跳过释放循环；
2. 非负时从角色 0 的 `+0x38` 开始，按 `0xD8` 步长扫描；
3. 载荷指针非零才调用 `sub_4885A0`，零指针不调用；
4. 索引从 0 开始递增，比较使用 `jle`，因此最高索引本身也会处理；
5. 每轮重新读取最高索引。原程序该表由单线程地图 owner 操作，循环期间没有已知写入者，
   现代窄接口因此以入口快照表达相同有效调用域。

现代角色的 `path_payload_pointer_32` 保留原非零所有权标记，实际字节由
`LegacyWorldPathScriptState::role_label_payloads[256]` 拥有。非零标记分支使用空 vector
交换，既清除字节也释放容量；只调用 `clear()` 会保留分配，不能等价于原汇编的 `free`，
该差异已在双向复核中纠正并由测试固定。零标记即使对应现代槽含有字节也不释放，避免
擅自修复原程序不会处理的不一致状态。

## 3. 完整清零与动作初始化

`0x0040F3E1..0x0040F3F2` 使用 `rep stosd` 从 `0x004BABA8` 写入 `0x3600` 个零 dword：

```text
0x3600 * 4 = 0xD800 = 256 * 0xD8
```

因此清零范围与最高角色索引无关。随后 `0x0040F3F4..0x0040F409` 从第一项的 `+0x40`
开始，按 `0xD8` 步长对全部 256 项调用 `sub_40DC00`。该 helper 写入动作记录
`+0x1C/+0x20/+0x3C = 0xFFFFFFFF`，并把 `+0x42/+0x44/+0x46/+0x48/+0x90` 清零；
这与已有 `initialize_legacy_action_record` 完全对应。调用发生在整表清零之后，不能合并为
只清零角色，也不能只初始化活动范围。

## 4. 平台隔离

原函数假定最高索引不超过 255，并始终操作静态 256 项表；损坏值会越界。现代 helper
拒绝超过 256 项的 span、`highest >= 256` 以及最高索引超出现有 span 的状态，并保证
失败前不释放或改写任何对象。正常 256 项输入保持原始释放、清零和初始化顺序。

SDL 地图会话只物化真实存在的角色，未物化的静态尾部在现代对象模型中不存在；因此
会话切换时对现有 span 执行同一两遍重置，随后由 owner 析构。首次构造的新角色逐项执行
相同的零初始化和 `sub_40DC00` 初始化。固定物理尾部、裸指针和进程关闭手工释放由
RAII 取代，故总状态登记为 `platform_adapted`，不能标成纯 `assembly_exact`。

## 5. 双向收敛与测试

- LST→C++ 已覆盖负值跳转、非零指针释放、零指针跳过、包含最高索引、整表清零、第二遍
  256 项动作初始化及函数出口；
- C++→LST 已反查所有正常域副作用；三个受检边界状态和 RAII 析构是明确的平台隔离；
- 单元测试以完整 256 项表验证 `highest=2` 的包含端、非零标记所有者真正释放容量、零标记
  不释放、范围外载荷不释放，以及所有角色的逐字节最终状态；
- 另以 `highest=-17` 固定“只跳过释放，仍执行两遍重置”，并验证三种现代边界失败均为
  事务式无修改；
- 最后一轮完整正向与反向追溯在修正 `vector::clear()` 后重新从入口执行，当前没有未决
  控制流、数据宽度、调用顺序或状态写入差异。
- Linux `core` 183/183、Windows LLVM `app` 188/188 CTest 通过；Windows EXE 已重新
  链接且未启动。

核心实现为 `legacy_world_role_lifecycle.cpp::reset_legacy_world_role_table`，SDL owner 接线
位于 `main.cpp::initialize_new_game_state_and_world`。
