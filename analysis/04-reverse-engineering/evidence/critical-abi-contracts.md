# P2.5 关键函数 ABI 合同

最后更新：2026-08-02

状态：39 个高价值入口已人工回查被调体和调用点

完整汇编是唯一真实依据。机器初筛只决定复核顺序，本文件和 `../inventory/critical-abi-contracts.tsv` 中标为确认的合同均已回到具体压栈、寄存器、`RETN` 和返回值消费指令。

## 覆盖范围

首轮 22 个合同覆盖：

- PE/CRT 入口、WinMain 和窗口过程；
- 单帧、高优先级模式、显示停用/恢复；
- 世界控制、鼠标交互和剧情 VM；
- 特殊菜单、商店、暂停和 Bink 呈现；
- Miles 音频维护和世界音乐协调；
- DirectDraw 包装对象的恢复与 surface 选择；
- 公共解压器和通用动作记录更新；
- 战斗建立、战斗帧核心和战斗指令入口。

这批不是按 IDA 函数名挑选，而是按顶层控制流、资源公共依赖和高调用扇出挑选。逐行机器合同位于 `../inventory/critical-abi-contracts.tsv`。

子系统覆盖审计后又补入两个存档入口，文件对象、TSW、ACT 三个资源入口，三个输入入口，三个世界/地图入口，以及四个 Miles/SND 与两个 Bink 对象入口。当前合计 39 个合同。

## 合同字段的含义

### 逻辑宽度和栈槽宽度分开

`0x00451B10` 的战斗编号只读取低 16 位，但三个调用点都压入一个 32 位栈槽，函数普通 `retn`，调用者清理四字节。合同写成：

```text
logical width = low 16 bits
observed stack bytes = 4
callee cleanup = 0
```

这避免把业务上的 `uint16_t` 错写成“旧 ABI 只传了两字节”。现代内部接口可以用窄类型，旧边界适配器仍必须保留实际槽宽。

### 返回寄存器和调用者策略分开

`0x0040CF10` 和 `0x0040CDD0` 都在全部出口令 `AL = 1`，但调用者不消费这个值。合同同时保留：

```text
machine return = AL 1
caller policy = ignored
```

不能因为没人检查就把函数改成“无机器返回”，也不能因为返回一就统一当作需要检查的成功布尔值。

`0x00411FA0` 在暂停提示后直接保留最后一次 DirectDraw `Blt` 的 HRESULT 于 EAX 返回，但 WinMain 不读取；这也是机器结果存在、业务调用者忽略的另一种情况。

## 三个需要原样保留的非标准边界

### 公共解压器额外压入一个无用零

`0x004399E0` 实际只读取四个 32 位参数、普通 `retn`，但四个直接调用点都压入五个双字，最外侧是函数从不读取的字面零，并由调用者清理 20 字节。

合同不能简单写成普通四参数 cdecl 后忘记旧调用点的第五次压栈。重写的现代内部函数可以只有四参数；若建立二进制兼容垫片或逐指令测试桩，必须能复现旧栈形状。

### 显示恢复函数有一个被清理但从不读取的参数

`0x00437AE0` 的唯一调用点先压入 `hWnd`，再以 ECX 传入显示包装对象。函数从不读取栈参数，却在唯一返回路径执行 `retn 4`；EAX 固定为一，调用者也不检查。

所以它的完整合同是“ECX 对象 + 一个未使用但由被调方弹出的 32 位槽”，不是无参函数。初步还原不能因为参数无用就误改旧边界的栈平衡。

### surface 选择器是成员式清栈，不是 stdcall

`0x00437DF0` 通过 ECX 读取显示包装对象，以一个 32 位 selector 栈参数选择 `+4/+8/+0x0C` 三个 surface 指针，全部出口 `retn 4`。27 个直接调用点均使用返回的 EAX。

这里的 `retn 4` 结合 ECX 对象才证明成员式 ABI；它不能被全局规则错归成单参数 stdcall。

## 顶层返回值合同

- `0x00427920`：机器返回集合 `{0,1}`，但主循环不读；剧情效果来自状态块、IP 和全局请求。
- `0x00453200`：机器返回集合 `{0,1,2,3}`；只有部分内部调用路径消费，操作码一路径会继续传播。
- `0x00469D20`：同样返回 `{0,1,2,3}`，主循环立即保存并按数值分派。
- `0x004321E0`：返回 `{0,1}`；161 个直接调用点中机械窗口发现 118 个消费，已存在专项逐调用点矩阵，最终不能用“多数调用者行为”覆盖少数路径。

以上集合只固定数值和传播。战斗二、三的最终业务名仍留待 P7；不根据主循环动作提前猜成胜败枚举。

## Windows 外部 ABI

`0x00409EC0` 和 `0x0040A0D0` 均有四个 32 位栈参数、全部出口 `retn 0x10`：

- WinMain 的 EAX 最终来自 `msg.wParam`，CRT 把它传给 `_exit`。
- 窗口过程的 EAX 是 LRESULT，由 Windows 消费。

这两项可以确定为 Win32 stdcall，不仅因为 IDA 注释如此，而是外部入口契约、实际参数和清栈三者一致。

`0x0048A740` 是 PE/CRT 进程入口，没有普通 C 调用者和返回点；它调用 WinMain 后进入 `_exit`。因此不能为方便测试把它当成普通 `int start()` 并期待 `ret`。

## 存档入口的副作用合同

`0x00409600` 读取“预览记录指针、存档槽号”两个 32 位 cdecl 参数，全部正常路径固定 EAX 为零。打开失败写 `word [record+0x30]=1`，成功写二；21 个调用点全部忽略 EAX，只使用三条 `0x2A8` 记录的副作用。

`0x004070A0` 没有栈参数，唯一调用者不读返回值。公共退出尾没有统一设置 EAX，局部文件对象析构留下的值也不是业务合同。两者的完整证据见 `save-entry-abi.md`。

## 资源入口的参数宽度差异

`0x004380B0` 是 ECX 文件对象加三个 32 位栈参数，并在成功和失败出口都执行 `retn 0x0C`；不能因机械参数引用统计漏掉中间符号就缩成两参数。

`0x004315D0` 和 `0x00432A50` 都占用两个四字节栈槽，但逻辑宽度不同：TSW 下游明确截断资源号和变体到低 16 位，ACT 缓存和装载则使用完整 32 位键。这项差异及全部调用者策略见 `resource-entry-abi.md`。

## 输入平台边界的非统一失败值

`0x00436FB0` 以 ECX 传输入对象，栈上传 HINSTANCE 和 HWND，全部出口 `retn 8`。完整成功返回零、大多数失败返回一，但事件通知和鼠标缓冲区设置两条晚期失败在弹框后也返回零；不能把它简化成严格成功布尔值。

`0x004372B0` 无栈参数，忽略键盘设备 HRESULT 后固定 EAX 为一，两个调用者都不读；`0x004050E0` 则是零参数、返回不稳定但全局副作用被主帧消费。完整证据见 `input-entry-abi.md`。

## 地图边界的栈槽复用和额外参数

`0x00425BE0` 接收零扩展地图号和地图状态指针两个 cdecl 参数，返回零/一且唯一调用者真实分支。函数后半把地图号所在入参槽改写成分配指针，早期失败却可能在改写前把原地图号交给 `operator delete`；这个有效资源不触发的旧 BUG 不修复。

`0x00426840` 有四个物理栈槽并返回 CM 映射视图指针或零。第四槽被继续转发，但所有对应下游位置均不读取；现代内部签名可以省略，旧边界必须保留记录。普通世界 `0x004120B0` 则是零参数、返回不稳定的分支内呈现入口。详见 `map-entry-abi.md`。

## 音视频对象边界的非布尔返回

`0x004859B0` 与 `0x004862B0` 都只承诺 AL，但前者在 Miles 样本句柄分配失败后仍返回一，且唯一上层调用者完全忽略结果。`0x00486490` 以无范围检查的一基完整 32 位编号返回 SND 分配缓冲区指针或零。

`0x00485CE0` 有 ECX 对象和六个由被调方清理的双字槽。它在播放成功和所有失败路径上都返回 `EAX=0`；一个包装器传播这个恒零值，另外三个直接调用点覆盖或忽略。因此不能给它补造现代“成功为真”的返回合同。

`0x00484550` 是三参数 cdecl，后端选择只读取第二槽低八位；最终 Bink surface 类型既留在 EAX，也写入 `0x0053D06C`，唯一调用者只依赖全局副作用。`0x004846F0` 则把 `BinkWait` 非零规范化为一，帧调用者据此跳过当帧处理。完整失败、所有权和调用点证据见 `audio-video-entry-abi.md`。

## 1:1 还原约束

- 保留调用者是否读取返回值的差异，不统一套成功/失败检查。
- 保留 `AL` 与完整 EAX 的区别；只写 AL 的函数不承诺高 24 位。
- 保留调用点实际栈字节与逻辑窄字段的区别。
- 保留 ECX 对象参数、被调方清栈和未使用栈槽。
- 现代 C++ 内部 API 可以更清楚，但旧行为适配层和差分桩必须显式表达这些边界，不能依赖编译器碰巧生成相同代码。
