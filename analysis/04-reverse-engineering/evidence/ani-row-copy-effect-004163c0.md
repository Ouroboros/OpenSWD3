# ANI framebuffer 逐行复制效果（0x004163C0）

最后更新：2026-08-10

唯一行为真值：`swd3.exe.lst`。字段边界、RNG 调用顺序、循环次数和 framebuffer
写入顺序均以 LST 指令为准。

## 1. 状态与初始化

`0x00411D00` 为本效果建立四组全局状态：

| 地址 | 物理类型 | 项数 | 初值 | 用途 |
|---|---|---:|---:|---|
| `0x004AB2F8` | `i16` | 64 | `1` | 每项连续复制的行数 |
| `0x004AB8FC` | `i16` | 64 | `4` | 每行复制的字节数 |
| `0x004AC9BC` | `u32` | 64 | `0` | 以 16 位像素计的目标偏移 |
| `0x004CAE90` | `u16` | 1 | `0` | 帧计数器 |

重写由 `LegacyAniRowCopyState` 持有这些状态，`reset` 对应上述初始化。原地址之间夹有
其他全局数据，所以跨平台实现保留字段内容和项数，不伪造原进程的绝对地址布局。

## 2. 启用、参数生成与刷新

`0x004163C0` 首先调用 `0x0040DC50(7)`。返回零时立即退出，不改变计数器、RNG 或
framebuffer。启用后借用 `0x00439070` 的第二套无偏 RNG：

- 计数器为零时，以列为外层、区带为内层生成 `8×6=48` 项。每项严格按“宽度、偏移、
  行数”的顺序调用 RNG；宽度为 `2*random(0x26)+0x4C` 字节，偏移为
  `random(3)+band*0xC800+column*0x50+0x27F` 像素，行数为 `random(0x4E)+1`。
- 非零计数器仅在低两位为零时刷新。`(counter>>2)&3` 为 `0` 时刷新 64 项宽度，
  为 `1` 时刷新 48 项偏移，为 `2` 时刷新 64 项行数，为 `3` 时不刷新。
- 因而第 `4/8/12/16` 帧依次是偏移、行数、空档、宽度；周期为 16 帧。
- 参数处理完成后计数器按 `u16` 加一。`0xFFFF` 回绕为零，下一帧重新执行首次生成，
  但仍只覆盖前 48 项，后 16 项保持此前值。

这里的“实际使用 48 项、宽度与行数却周期性刷新 64 项”是汇编的真实 RNG 消耗，不能
把数组缩成 48 项，也不能把 `0x00439070` 换成 CRT `rand()` 或标准库分布。

## 3. framebuffer 写入

参数更新后，函数始终只遍历前 48 项。对有符号行数大于零的项：

1. 将像素偏移乘二得到目标字节地址；
2. 从目标地址后 `0x500` 字节，即下一物理行，向目标复制指定字节宽度；
3. 源和目标均按 `0x500` 字节继续下移，重复指定行数。

原指令使用前向 `rep movsd` 加尾部 `rep movsb`。正常生成的宽度为 `76..150` 偶数字节，
小于一行，源始终位于目标之后且不重叠；重写使用等价的逐段 `memcpy`。固定画布仍是
`640×480×16-bit = 0x96000` 字节，只在传入存储不足时增加现代内存边界隔离。

## 4. 实现与验证

- `LegacyAniRowCopyEffect::reset` 映射 `0x00411D00` 的四组初始化。
- `LegacyAniRowCopyEffect::update` 映射 `0x004163C0`；调用者把 service 7 的结果作为
  `enabled` 传入，避免 asset runtime 反向拥有剧情 service。
- `legacy_ani_row_copy_effect_test.cpp` 覆盖禁用与短存储、首次 48 项生成、三类周期刷新、
  第 12 帧空档、64/48 项差异、前向跨行复制、16 位回绕及后 16 项保留。
- 种子 `0x12345678` 的首次生成最终 RNG 索引为 `38`；固定输入 framebuffer 的输出
  FNV-1a 64 为 `0x8ED9811DCD93C1F1`。

Linux Clang `core` 为 `90/90`，Windows LLVM `app` 为 `94/94` CTest，全套通过。
当前证据状态为 `assembly_exact`；尚未对原程序 framebuffer 做动态差分，保留
`blocked_runtime_oracle`，需要时由 Codex 准备 Frida spawn 工具并等待用户执行。
