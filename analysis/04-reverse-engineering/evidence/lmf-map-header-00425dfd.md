# LMF 地图块固定头 `0x00425DFD..0x00425F94`

状态：B2.14 已实现；`assembly_exact`、`asset_verified`、`platform_adapted`、`unreachable_current_assets`、`blocked_runtime_oracle`

完整汇编是唯一行为真值。IDA 伪码和符号名只用于定位。本单元从 B2.13 返回的地图块偏移继续，只恢复固定头、格式分支、运行时五个零扩展字段和名称边界。

## 1. 固定读取与格式分支

`0x00425DFD` 把文件位置设为地图块偏移，随后固定请求读取 `0x2000` 字节到先前分配的 `0x20000` 字节暂存区。原调用点不检查 seek、read 返回值或实际读取长度，之后直接访问暂存区。

头首双字依次与两个小端签名比较：

```text
0x7046534D = "MSFp" -> format 1
0x3246534D = "MSF2" -> format 2
其他值               -> 装载失败
```

两次比较在汇编中彼此独立；`MSFp` 分支还调用一个当前为空的标记函数。当前 309 张地图全部为 `MSF2`，`MSFp` 只由合成 UT 保留其可达合同，标记为 `unreachable_current_assets`。

格式确定后，函数按 32 位回绕计算 `map_offset + header[+0x04]` 并执行一基 seek；只有这个 seek 的零返回会进入 `Seek2Map fail`。seek 到 EOF 之后本身可以成功，原路径此处不读取数据，不能把它改写成“目标必须位于文件内”的额外验证。

## 2. 字段与失败门

固定头中本段直接读取：

```text
+0x04 u32  首个 seek 相对量
+0x14 u32  后续原样区相对量
+0x18 u32  索引对象表相对量
+0x1C u32  后续原样区相对量
+0x20 u32  CM 头相对量
+0x84 u16  -> runtime +0x00，零扩展
+0x86 u16  -> runtime +0x04，零扩展
+0x88 u16  -> runtime +0x08，零扩展
+0x8A u16  -> runtime +0x0C，零扩展
+0x8C u16  -> runtime +0x10，零扩展
+0x8E u16  非零时立即触发关闭请求并返回失败
```

`+0x8E` 的失败诊断把它作为高 16 位、把 `+0x8A` 作为低 16 位组合输出，但正常路径只把 `+0x8A` 零扩展到运行时字段。当前全部地图的 `+0x8E` 均为零。

## 3. 名称和下一物理边界

通过失败门后，原函数从固定头 `+0x96` 开始逐字节复制到运行时状态 `+0x24`，并把终止 NUL 一同复制。它没有名称容量或 `0x2000` 读取边界检查。循环结束后的源指针直接参与下一次文件定位，所以原样表起点严格为：

```text
raw_table_offset = 0x96 + name_byte_count_including_NUL
```

当前 309 张地图的结果范围为 `0x98..0xA5`。名称仍保持 CP950 原始字节；本单元不提前把它解码成 UTF-16，也不把字符数代入物理偏移。

## 4. 实现与验证

`legacy_lmf_read_map_header` 保留固定 0x2000 读取、两种签名、32 位 seek 加法、`+0x8E` 门、五个零扩展字和包含 NUL 的名称字节。短头、失败 seek 和在固定读取窗口内找不到 NUL 分别返回确定状态，隔离原程序的未初始化读取与越界复制，属于 `platform_adapted` 损坏文件边界。

合成 UT 覆盖 `MSFp/MSF2`、全部直接字段、NUL 包含关系、未知签名、短头、负向 seek、`+0x8E` 非零和无终止名称。真实验证先关闭独立索引读取句柄以服从 `LegacyFile` 的共享模式零合同，再逐一对 309 条有效索引执行地图号查找和固定头读取；309/309 偏移一致、格式均为 `MSF2`、名称均终止且原样表起点均落在 `0x98..0xA5`。Windows LLVM `core`/`app` 的 33/33 CTest 均已通过；原程序动态轨迹仍登记为 `blocked_runtime_oracle`。
