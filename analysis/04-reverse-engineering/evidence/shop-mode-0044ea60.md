# 商店交易模式汇编证据：0x0044EA60

状态：P2.2 顶层交易流程、价格规则和呈现边界已确认；P2.4 关键物品字段与所有权已补齐

来源：`swd3.exe` 完整汇编

函数范围：`0x0044EA60` 至 `0x0044F76F`

直接调用者：`0x0040A570`

调用约定：无栈参数

返回：调用者不读取；函数没有可靠的统一返回值契约

## 1. 模式身份

单帧主循环只在 `[0x004B8740]` 的低位模式号为 `2` 时调用本函数。

本函数及其直接下游实际引用的 Big5 文本包括：

```text
買   賣   離開
購買
賣出
執行
總價 %d 餘額 %d
總共是 %d 銀幣 要買嗎?
總共是 %d 銀幣 要賣嗎?
要馬上裝備嗎?
錢帶多一點再來吧
```

结合交易金额和物品链表的数据流，可以确认 `0x0044EA60` 是商店交易模式的逐帧入口。

## 2. 剧情 VM 建立商店商品表

剧情 VM `0x00427920` 的 opcode `133` handler 从指令流读取一串零结尾的 16 位商品编号：

1. 释放旧 `[0x004B7928]`。
2. 固定分配 `0x100` 字节。
3. 复制商品编号串并补零结尾。
4. 写 `[0x004B8740] = 0x80000002`。
5. 按实际编号数量推进剧情指令指针。

因此 `[0x004B7928]` 是当前商店可售商品编号表，`0x80000002` 是“初始化并进入商店”的模式请求。

## 3. 商店模式位

入口按以下位解释 `[0x004B8740]`：

```text
0x80000000  完整商店初始化请求
0x20000000  从菜单/装备页面返回后的商店 UI 重建请求
低 28 位   模式号；商店为 2
```

最高位置位时，函数先清除该位，再调用 `0x0044D920`。

位 `0x20000000` 置位时，函数调用 `0x0044DAA0` 重建商店 UI 对象，再用 `& 0x0FFFFFFF` 清除高位请求标志。

`0x004415C9` 可写入 `0x20000002`，证明这是从模式 1 菜单分支返回商店的恢复路径。

## 4. 完整初始化与显示背景

`0x0044D920` 执行商店首次建立：

- 切换输入/界面资源状态。
- 获取当前 640×480、16 位帧缓冲。
- 分别分配两个 `0x96000` 字节缓冲区。
- 保存并处理当前画面，形成商店覆盖层使用的静态背景。
- 清空 0xB0 字节的链表头/临时节点区域。
- 把交易页状态 `[0x004FD414]` 写为 `1`。
- 把选择、滚动、数量和总数相关状态归零。
- 调用 `0x0044DAA0` 建立商店控件对象。

`0x0044DA40` 是对应释放路径：释放 `[0x004B7928]`、两个 0x96000 字节缓冲和交易链表，再清空相关指针。

新实现不必复制这两个裸缓冲的所有权方式，但必须保留“进入商店时冻结原世界画面并在其上绘制 UI”的可见行为。

## 5. 商店页状态机

核心页状态位于 `[0x004FD414]`。

### 状态 1：买、卖、离开

低两位选择值来自 `[0x004FD578]`：

- `0`：建立购买列表。
- `1`：建立出售列表。
- `2`：退出商店。

购买列表逐个读取 `[0x004B7928]` 的商品编号，并调用物品节点建立函数加入当前交易链表。

出售列表从玩家物品链表 `[0x004A9940]` 复制候选节点，再把本次交易数量清零。

选择离开时，取消处理最终调用 `0x0044DA40` 释放商店资源，并把 `[0x004B8740]` 写零。

### 状态 2：商品列表和数量选择

当前交易数据由 `0xB0` 字节通用物品节点组成的链表保存。商店节点不是只有交易字段的专用结构；它包含一个完整的 `0xA4` 字节 `mon.dat` 定义快照：

```text
+0x00  下一节点
+0x04  16 位物品编号
+0x06  本次选择数量
+0x08  16 位普通物品数量 A
+0x0A  16 位普通物品数量 B
+0x0C  0xA4 字节 mon.dat 定义快照
+0x0C  名称起点；名义空间 32 字节，但原解析器不检查该边界
+0x2C  32 位分类/能力标志
+0x46  16 位四项资格限制标志
+0x52  16 位单价
+0x5C  16 位通用动作/图形资源编号
+0xAC  动态说明字符串指针
```

出售数量上限由 `+0x08 + +0x0A` 形成，本次交易数量单独保存在 `+0x06`。`+0x2D` 和 `+0x47` 只是前述多字节标志字段的一部分，不能拆成独立字段。

完整布局、`mon.dat` 命令、动态字符串深复制和名称无边界复制证据见 `item-node-mon-dat.md`。

当前页使用 `[0x004FD420]` 作为列表起始偏移，`[0x004FD630]` 作为页内选择项。一次翻页严格移动 13 项。

数量减少和增加分别由 `0x0044E260`、`0x0044E330` 处理，并受库存、玩家已有数量、最大数量与当前金钱门控。

### 状态 3：交易确认

存在非零交易总额时，从状态 2 进入状态 3。

界面根据买/卖方向显示：

```text
總共是 %d 銀幣 要買嗎?
總共是 %d 銀幣 要賣嗎?
```

确认出售时，函数增加玩家银币并从玩家物品链表扣除相应数量。

确认购买时，函数减少玩家银币并向玩家物品链表加入相应数量。若购买物品触发可装备条件，状态继续进入状态 4；否则返回状态 1。

取消确认会清空本次选择数量并返回状态 2。

### 状态 4：购买后立即装备询问

该状态绘制：

```text
要馬上裝備嗎?
```

其中一条确认路径把 `[0x004B8740]` 写为 `0xC0000001`。下一帧主循环会转入 `0x00439FD0` 的模式 1 变体，进入菜单/装备处理；菜单结束后可通过 `0x20000002` 返回商店。

### 状态 10：银币不足

数量增加导致总价超过 `[0x004ACBD0]` 时：

- 撤销刚才的数量增加。
- 播放声音 `0x8C`。
- 把 `[0x004FD414]` 写为 `10`。
- 显示“錢帶多一點再來吧”。

确认后回到状态 2。

## 6. 精确价格规则

`0x0044F770` 遍历交易链表并计算总额。

每个节点的整数公式是：

```text
购买：floor(unit_price × selected_count × 100 / 100)
出售：floor(unit_price × selected_count ×  60 / 100)
```

汇编通过有符号整数乘法和常数除法序列完成 `/ 100`，每个节点计算后再累加。因此出售价格是标价的 60%，并按节点逐项截断；不能改成先汇总后统一乘 0.6。

玩家银币存放在 `[0x004ACBD0]`。主界面同时绘制交易总额和交易后的余额。

## 7. 输入顺序

每帧先调用 `0x0044DBC0` 处理鼠标输入，再调用 `0x0044F920` 处理键盘/控件输入。

两条输入路径最终调用相同的状态操作函数，包括：

- 取消/返回：`0x0044E9D0`。
- 上下移动和翻页：`0x0044DF00`、`0x0044DFF0`、`0x0044E0C0`、`0x0044E1B0`。
- 减少/增加选择量：`0x0044E260`、`0x0044E330`。
- 确认/执行：`0x0044E4A0`。

鼠标路径先调用 `0x0043BA40`，把原始按键归一化到 `[0x004FB8AC]`；键盘路径读取与其他菜单相同的输入状态块。重写时两种输入必须汇合到同一状态转换，而不能维护两套交易逻辑。

## 8. 绘制与呈现边界

完成输入处理后，本函数：

1. 把保存的 640×480 背景复制到当前软件帧缓冲。
2. 根据状态绘制菜单框、商品列表、名称、价格、数量、图标、总价和确认框。
3. 把光标编号写为 `13`。
4. 调用 `0x004149B0` 更新光标/输入显示。
5. 在 `0x0044F765` 直接调用 DirectDraw surface 虚表 `Blt`。

当 `[0x004B8740]` 已变为零或 `0xC0000001` 时，函数在输入处理后提前返回，不再绘制并呈现旧商店画面。

## 9. 重写约束

- 商店商品编号表由剧情 opcode `133` 提供，按零结尾 16 位数组解释。
- 商店使用通用物品节点的定义快照；进入商店时复制名称、价格、分类位、限制位、图形编号和动态说明字符串。
- 买价为 100%，卖价为 60%，且卖价按每个节点分别做整数截断。
- 一页固定 13 项；页内选择和列表起始偏移是两个独立状态。
- 交易先在临时链表累计数量，确认后才修改玩家银币和物品链表。
- 钱不足必须撤销本次增量，再进入专用提示状态。
- 购买装备后的菜单跳转和返回商店是跨模式状态迁移，不能改造成无条件留在商店的弹窗。
- 商店画面在自身分支内呈现，不依赖公共帧尾。
