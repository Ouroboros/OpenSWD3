# `Env.dat` 缓存会话标记 `0x00425570/0x004258E0/0x004259B0`

状态：B2.10 已实现；`assembly_exact` 文件行为，显式路径和可观察返回值为 `platform_adapted`

完整汇编是唯一行为真值。IDA 伪码和符号名只用于定位。

证据输入：

```text
swd3.exe.asm sha256 = f1ee7f32a79c156b75837e176abb733df7a2143d134252e507343e36857affb4
swd3.exe.lst sha256 = 701732b5481ba34876b62ca97535c9463f65ec3feb2ed745c03772dd4bc3ad8b
```

## 1. 两个写入器

`0x004259B0` 以 `OPEN_EXISTING + GENERIC_WRITE` 打开 `Buffer + "env.dat"`，调用 `0x004384C0(-1)` 定位到文件末字节，再由 `0x004385A0` 精确写一个字节 `1`。唯一调用点 `0x00424C81` 位于实际游戏初始化路径：缓存检查和磁盘余量检查完成后、其余资源初始化前。

`0x004258E0` 使用相同打开、末尾定位和单字节写入顺序，但写入 `0`。唯一调用点 `0x0042545A` 位于总销毁尾部：资源、映射、显示和输入后端均已释放之后、恢复鼠标显示之前。

两个函数都忽略定位和写入返回值，打开失败时只执行关闭/析构路径。末尾定位失败也不会阻止写入；因此对已存在的空文件，写入会在未移动的起始位置产生一个字节。它们不创建缺失文件、不截断非空文件，也不改动末字节之前的内容。

## 2. 标记消费者与缓存失效

`0x00425040` 载入 `Env.dat` 后调用 `0x00425570(0)`。该分支以读写方式打开同一文件，读取末字节：

- 末字节为零：直接关闭文件并返回 24 个 `.cm` 的总长度；
- 末字节非零：先回到末字节写零，并把内部重建标志设为一；关闭文件后依次把 `Data/0.cm` 至 `Data/23.cm` 截断到零字节，再把 24 条内存缓存记录重置并覆盖写回 0x180 字节 `mcache.dat`。

`0x00425570(1)` 是另一条缓存失效入口：它比较 `Env.dat +0x1E` 起保存的三个 16 位值与当前环境值，不读取会话标记；不一致时进入同一重建段。

由写入时点和消费者可确定：零表示上次游戏会话正常结束，一表示游戏会话已进入但尚未完成正常销毁。崩溃或强制终止会让一保留到下次启动，从而废弃可能只写入一部分的持久地图缓存。

## 3. 与记录 codec 的关系

`0x00423AF0` 在两个字符串和尾随模式后固定写零，这个零就是新建或重写环境记录的初始“干净”标记。`0x00423FB0` 只解析前一个尾随模式字节；会话标记由 `0x00425570` 独立消费。

当前 63 字节 `Env.dat` 末尾 `02 01` 因而可解释为“尾随模式 2、会话活动标记 1”。末字节一存在本 EXE 的明确生产路径，不再归因于未知版本或未知生产者。

## 4. C++20 映射与测试

`write_legacy_environment_cache_session_marker` 显式接收环境文件路径和 `clean/active` 枚举，复用已按汇编实现的 `LegacyFile`：`OPEN_EXISTING + write`、忽略末尾负一定位结果、精确写一字节、关闭。返回写入是否成功只是现代可观测边界；旧调用者没有消费原函数返回值。

UT 覆盖活动一、正常退出零、只替换末字节、不截断、缺失文件不创建，以及空文件定位失败后仍写一个字节。Windows LLVM `core`/`app` 的 32/32 CTest 均已通过，`openswd3.exe` 已重新链接。缓存截断和 `mcache.dat` 重置属于 `0x00425570` 的下一个独立实现单元，不在本单元伪造未完成的组合行为。
