# 普通世界音频状态协调汇编证据：0x0040CDD0

状态：B5.10 已实现；完整实现证据见
[`legacy-world-music-media-0040cdd0-00411c8b.md`](legacy-world-music-media-0040cdd0-00411c8b.md)

来源：`swd3.exe` 完整汇编

函数范围：`0x0040CDD0` 至 `0x0040CF0D`

直接调用者：`0x0040A570`

参数：无

返回：所有机器级出口都令 `AL = 1`

## 1. 进入门控

函数先调用：

```text
0x004858D0
0x00485830
```

`0x00485830` 最终查询 Miles stream 对象中用户数据编号 `100` 的活动项。只有它返回非零时，`0x0040CDD0` 才继续处理新的音乐状态；返回零时直接令 `AL = 1` 并返回。

因此本函数不会在编号 100 的现有 stream 仍处于门控状态时无条件重开音乐。

## 2. 请求状态读取

函数读取 `[0x004ACDBC]`：

- 低四位先进入局部状态。
- 位 `0x00800000` 决定后续使用的两组掩码。
- 后续完成分支会改写其低字节，同时保留高二十四位。

它还检查两个位置：

- `[0x004B7C80]`
- `[0x004B7C74]`

任一位置的位 `0x80000000` 非零时：

1. 取其低四位写入 `[0x004B7380]`。
2. 清除该位置的最高位。

这证明两者包含“最高位待处理标记 + 低位状态值”。具体业务来源和优先级名称留到 P2.3 的全部写入点交叉引用。

## 3. 音乐条目选择与播放

状态机从 `0x004B7C74` 起的一组双字中选择一个值。

选择值满足以下任一条件时不启动新 stream：

- 值为零。
- 位 `0x00008000` 非零。

其他情况下按顺序执行：

1. 清空 `FileName` 的 1024 字节缓冲区。
2. 调用 `0x0040EB60` 把选择值转换为 `Music\...mp3` 路径。
3. 调用 `0x004856C0`，下游以用户数据编号 `100` 建立 Miles stream。
4. 以 `[0x004C9A0C]` 调用 `0x00485850`，下游设置该编号 stream 的音量。
5. 清除 `[0x004ACDBC]` 的位 `0x00020000`。

`0x0040EB60` 的汇编明确追加 `Music\` 和 `.mp3`，因此这里可以确认是背景音乐/长流路径，不只是泛化的“声音更新”。

## 4. 已确认语义名

P2 语义名：普通世界背景音乐请求/stream 状态协调。

不能在当前证据中继续写死：

- `[0x004ACDBC]` 每个低位状态的业务名称。
- `0x004B7C74` 起各槽位的优先级名称。
- 位 `0x00800000`、`0x00080000`、`0x00040000`、`0x00020000` 对应的完整游戏状态。

这些名称必须在 P2.3 汇总全部读写点后确定。
