# 初始菜单“新游戏”提交与世界切换证据

状态：静态汇编顺序已确认；应用层提交边界已实现；完整菜单与剧情状态实现仍分别属于 B9、B8

来源：`swd3.exe.lst` 完整汇编。汇编是唯一行为真值。

## 1. 这不是启动对话框事件

总初始化只把特殊模式状态写为 `0x80000003`。真正的新游戏选择发生在模式 3 的
`0xEA60` 回调组中：

- `0x0043B8FF` 把首帧输入回调槽 `0x004FC64C` 指向 `sub_448840`；
- `0x0043B96D` 把末帧回调槽 `0x004FBEC8` 指向 `sub_4490C0`；
- `0x0043A47C` 每帧无条件调用首槽；
- `0x0043A6DB` 在 `word [0x004FC900] != 1` 时调用末槽。

因此 SDL 启动窗口里的“开始游戏”只允许进入总初始化和模式 3，不能直接创建地图
81，也不能直接清除特殊模式状态。

## 2. 菜单命中如何产生选择值 1

`sub_448840` 只在内部阶段 `[0x004FD2AC] == 1` 时执行四个主选择区域的命中：

| 选择值 | X 开区间 | Y 开区间 | 写入地址 |
|---:|---:|---:|---|
| `0` | `(0xD2, 0xE8)` | `(0x6E, 0x104)` | `0x00448905` |
| `1` | `(0x107, 0x11D)` | `(0x6E, 0x104)` | `0x00448945` |
| `2` | `(0x140, 0x156)` | `(0x6E, 0x104)` | `0x00448981` |
| `3` | `(0x179, 0x18F)` | `(0x6E, 0x104)` | `0x004489D0` |

边界由 `jbe/jnb` 排除，必须保持严格开区间。命中总会更新 `[0x004FD2B4]`；只有
归一化点击字节 `[0x004FB8AC] & 3` 非零，才调用 `sub_448EE0` 提交。这里的掩码来自
`BL=3` 后的 `TEST BL,DL`，不能缩写成只检查 bit 1。

选择值 `1` 在 `0x00448F8C` 进入名称输入准备路径：

1. `[0x004FD2AC] = 2`；
2. `[0x004FD2C8] = 0x61`；
3. 建立名称输入相关状态和 32 字节对象。

所以“鼠标悬停在新游戏区域”和“新游戏已经提交”不是同一个事件。

## 3. 名称输入与提交门

`sub_4490C0` 在内部阶段二按计数器分成两段：

- `[0x004FD2C8] < 100`：运行名称输入/确认流程；
- `[0x004FD2C8] >= 100`：先递增；结果不大于 `104` 时只执行退场颜色变化；结果
  大于 `104` 时才按 `[0x004FD2B4]` 分派最终选择。

因此 case 1 的真实提交点是 `0x004492BA`，不是最初命中点 `0x00448945`，也不是
初始化模式 3 的调用点。

## 4. case 1 的固定顺序

`0x004492BA..0x00449311` 的顺序为：

1. 清 `[0x004ACEF4]`；
2. 调用 CRT `time(nullptr)`，结果写 `Time2`；
3. `[0x004FD2AC] = 5`；
4. 对 `[0x004CD76C]` 清零 `0x25800` 个 dword，即完整 `640×480×16-bit`
   framebuffer；
5. 调用 `sub_40F160(1)`；
6. `[0x004B8740] = 0`；
7. `[0x004CAEB0] = 0`；
8. `[0x004CAEBC] = 1`；
9. `[0x004CAEC0] = 1`；
10. 调用 `sub_406D30`；
11. 调用 `sub_449D80`；
12. 调用 `sub_409DD0`。

`sub_4490C0` 不检查 `sub_40F160` 的 EAX。现代受检载入器可以额外报告失败，但不
能因为失败而跳过第 6–12 步。

## 5. 三个尾部 helper

- `sub_406D30` 清 `0x004B7CB0` 起 `0x200` 字节输入/菜单状态，重置公共动作记录，
  重建三个存档预览项并刷新相关状态。
- `sub_449D80` 比较两组名称字符串并应用原版隐藏初始属性/金钱覆盖；这属于可观察的
  原始游戏逻辑，后续不能删除或“修正”。
- `sub_409DD0` 读取固定 `0x400` 字节 `Fame.dat`，对编号 `1..500` 逐项调用
  `sub_477780`。打开失败时缓冲保持全零，但循环仍执行。

## 6. `sub_40F160(1)` 的跨模块含义

该调用不是单纯的“打开 LMF”：

```text
MAPS 去 0x200 前缀重新载入
→ sub_40E0B0 全局剧情/游戏状态重置
→ sub_439DE0 特殊模式桥状态重置
→ sub_425B50 世界/角色状态重置
→ 从 MAPS 七 word 初始记录建立请求
→ sub_40C130 创建初始地图会话
```

当前 `LegacyWorldRuntimeSession` 已覆盖最后两项及其 MAPS/LMF/ACT/角色/相机 owner，
不代表 B8 的 `sub_40E0B0` 或 B9 的 `sub_439DE0` 已经实现。应用层接口因此保留一个
显式的“完整新游戏状态与世界初始化”端口；各模块按原顺序接入，不能在 SDL 初始化
阶段提前载图。
