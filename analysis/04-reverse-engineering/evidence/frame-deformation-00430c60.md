# 16 位 framebuffer 变形节点（0x00430C60–0x0043114C）

最后更新：2026-08-10

唯一行为真值：`swd3.exe.lst`。本文中的伪码只用于辅助定位，字段、循环边界和运算顺序
均以 LST 指令为准。

## 1. 物理节点与链头

`0x00430C60` 初始化一个 `0x2C` 字节节点。字段布局为：

| 偏移 | 宽度 | 含义 |
|---:|---:|---|
| `+0x00` | 4 | framebuffer 宽度 |
| `+0x04` | 4 | framebuffer 高度 |
| `+0x08` | 4 | 有符号变形区域原点 x |
| `+0x0C` | 4 | 有符号变形区域原点 y |
| `+0x10` | 4 | 工作场宽度 |
| `+0x14` | 4 | 工作场高度 |
| `+0x18` | 4 | 衰减右移位数，初值 `4` |
| `+0x1C` | 4 | 当前工作场编号，初值 `0` |
| `+0x20` | 4 | 两个连续 `i16` 工作场；共分配 `4*w*h` 字节并清零 |
| `+0x24` | 4 | 16 位 framebuffer 快照；分配 `2*width*height` 字节 |
| `+0x28` | 4 | 下一节点指针，初值为空 |

`0x00401190` 用参数 `(1,1,0,0,1,1)` 原地构造全局哨兵 `0x004AC990`。哨兵的
`+0x28` 恰好位于 `0x004AC9B8`，所以 IDA 标出的 `dword_4AC9B8` 就是哨兵自身的
下一节点字段，并不存在第二个需要同步的链头。

重写用 `LegacyDeformationNode` 保存全部数值字段、两个连续逻辑工作场和完整源快照；
`LegacyDeformationList` 内含同参数的 `1×1` 哨兵，并用拥有型链表表达原 `+0x28`。
32 位裸指针没有照搬进跨平台 ABI，但字段含义、所有权、头插顺序和逐节点释放顺序一致。

## 2. 函数合同

| 地址 | 已确认行为 | 重写映射 |
|---|---|---|
| `0x00430C60` | 写入全部字段，建立并清零双工作场，建立源快照 | `LegacyDeformationNode` 构造 |
| `0x00430CF0` | 依次释放 `+0x20`、`+0x24`，不释放节点本体 | 节点拥有存储析构 |
| `0x00430D10` | 写原点；只做上界钳制到 `surface-field-1`，不做负数下界钳制 | `set_origin` |
| `0x00430D50` | 复制完整 16 位 framebuffer 到 `+0x24` | `capture` |
| `0x00430D80` | 从固定的第 0 工作场计算采样偏移，从快照写回目标 framebuffer | `apply` |
| `0x00430EB0` | 先异或切换工作场，以旧场邻域更新新场并衰减，按写入的低 16 位判断完成 | `advance` |
| `0x00430FF0` | 向当前工作场注入带裁边的径向扰动；负坐标各消费一次 CRT `rand` | `inject` |
| `0x00416CC0` | 对链表逐节点执行快照→变形→推进；完成节点立即摘链、释放并继续 | `LegacyDeformationList::update` |

场景 opcode 179 在 `0x0042CFBD..0x0042D03C` 建立节点：framebuffer 固定为
`640×480`，原点为 `(x-radius,y-radius)`，工作场为 `(2*radius,2*radius)`，随后以
`(radius,radius,24,strength)` 注入并头插。战斗调用者复用同一组 helper，故这些函数
属于 B6 拥有、剧情/战斗借用的公共资产数值运行时。

## 3. 必须保留的非直觉行为

- `0x00430D80` 永远从 `+0x20` 的第 0 工作场读取，不根据 `+0x1C` 选择场。
- warp 内层一次展开两个像素；工作场宽度为奇数时，第二次写入仍会发生，不能改写成
  常规的逐个内点循环。
- `0x00430EB0` 在每行开始前携带上一段留下的纵向和。第一行的初值来自索引 `2` 与
  `2*w+2`；它不是标准的对称五点或九点波纹公式。
- 更新和衰减均使用 32 位回绕、x86 算术右移，最终只保存低 16 位。完成标志只检查
  本次实际写入的新场内点是否全为零。
- 径向注入的循环上界是排他的，且只处理 `dx²+dy² < radius²`。增量为
  `trunc((radius-sqrt(distance²))*strength)`，再以 16 位加法回绕。
- `0x00416CC0` 在判断完成之前已经把该节点的最后一帧变形写入 framebuffer；删除不能
  提前到 warp 之前。

原版对空指针、尺寸乘法溢出和越界采样没有保护。重写只在这些会造成现代进程内存破坏的
非法边界返回状态；所有已确认有效调用仍走逐指令等价的计算路径，不借此修改游戏逻辑。

## 4. 验证

`legacy_frame_deformation_test.cpp` 覆盖：

- `0x2C` 各数值字段的构造值、双场清零和完整快照容量；
- 只钳制上界、不钳制负原点的 setter；
- 成对 warp、固定读取第 0 工作场和外部像素不写；
- `6×5` 工作场的完整 30-word 更新向量，包括每行首点的特殊 carry；
- 径向中心、轴向、对角、边缘裁剪、排他半径以及两次 CRT 随机坐标；
- 哨兵头插、连续删除两个已完成节点、保留非零节点和显式清链。

Linux Clang `core` 为 `89/89`，Windows LLVM `app` 为 `93/93` CTest，全套通过。
当前证据状态为 `assembly_exact`；尚未对原程序 framebuffer 做动态差分，保留
`blocked_runtime_oracle`，需要时仍由 Codex 准备 Frida spawn 工具并等待用户执行。
