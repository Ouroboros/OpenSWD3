# 输入菜单状态复位与三条存档预览重建 `0x00406D30`

状态：`platform_adapted`

## 1. LST锁

权威范围为`swd3.exe.lst`的`0x00406D30..0x00406DF3`，共83行，无外部`FUNCTION CHUNK`。入口无参数，正常机器返回固定为1。caller分布于世界控制、主初始化、主帧、剧情VM和多个特殊模式提交/系统菜单路径。

本入口跨越B9输入菜单状态、B4动作记录和B11存档预览。动作初始化`0x0040DC00`已经关闭，直接复用typed helper；三条预览清理、槽装载和最终刷新callee仍属于后续B11，因此保留窄端口并只在原调用点typed-stop，不伪造存档解析成功。

## 2. B9固定复位前缀

函数严格先执行以下写入：

1. 从输入菜单工作区首地址开始清零`0x80`个dword，即完整`0x200`字节。
2. 第一个菜单字节写0。
3. 第二个菜单字节写1。
4. 预览运行dword写0。
5. 高优先级延迟dword写0。
6. 直接调用公共动作初始化。

公共动作初始化不是整条清零，只按已关闭`0x0040DC00`合同写三个`0xFFFFFFFF`哨兵，清命令cursor、三个等待字、外部模式等规定字段。现代实现不得把它替换为值初始化。

## 3. 三条预览清理与槽分组

固定按地址顺序对三条`0x2A8`字节预览记录调用清理。三次全部完成后才读取当前选中存档槽。

机器用有符号乘法魔数实现向零除3。现代以C++有符号除法保持同一结果；例如槽`-1`得到组0，而槽`-4`得到组`-1`。随后按固定顺序装载：

```text
group * 3 + 0
group * 3 + 1
group * 3 + 2
```

三条装载完成后调用一次预览最终刷新。只有该调用完成才返回1。

## 4. typed-stop前缀

B11端口不可用时只在对应原调用点停止：

- 第二条预览清理停止：完整B9固定复位、公共动作初始化和第一条清理保留；不读取槽号。
- 第二条预览装载停止：三条清理、signed分组和第一条装载保留；第二条目标槽已发布，不装载第三条，也不最终刷新。
- 最终刷新停止：三条记录已全部按目标槽重建，但不发布成功返回1。

原程序这些callee没有可观察失败返回；typed状态只隔离尚未关闭或不可用的跨模块owner，不能改变完整成功路径顺序。

## 5. 验证

`special_modes.legacy_initial_menu`覆盖：

- 完整`0x200`字节清零和四个标量写入。
- 公共动作规定字段初始化，而非整记录清零。
- 选中槽8得到组2并依次装载6、7、8。
- 选中槽`-1`按signed向零除法得到0、1、2。
- 第二条清理、第二条装载和最终刷新不可用时的精确副作用前缀。
- 完整成功事件顺序为三次清理、三次装载、一次最终刷新，最终返回1。
