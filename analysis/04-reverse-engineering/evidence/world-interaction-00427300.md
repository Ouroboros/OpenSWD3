# 普通世界鼠标交互与 Talk 触发汇编证据：0x00427300

状态：P2.2 顶层职责已确认；角色字段名保留到 P2.4

来源：`swd3.exe` 完整汇编

函数范围：`0x00427300` 至 `0x00427919`

直接调用者：`0x0040A570`

参数：无

返回：调用者不读取；函数没有统一显式返回值契约

## 1. 角色记录定位

当前受控角色索引来自 `[0x004AB378]`。

汇编按以下方式计算记录地址：

```text
index × 3 × 9 × 8 = index × 216 = index × 0xD8
record = 0x004BABA8 + index × 0xD8
```

因此本函数把 `0x004BABA8` 起的数据按固定 216 字节记录访问。这个步长已经由实际地址运算确认；记录类型和全部字段名仍需 P2.4 汇总其他访问点。

NPC 扫描从索引一开始，记录总数读取 `[0x0049E0C4]`。索引零对应的当前受控角色不会被当作普通 NPC 命中目标。

## 2. NPC 鼠标命中测试

只有当前 Talk 上下文 `[0x004B72C4] == 0xFFFF`，并且受控角色的 `+0x48` 字段为零或 `0x34` 时，才扫描 NPC。

候选 NPC 必须满足一组记录字段门控，包括：

- 记录 `+0x10` 的位 `0x00008000` 非零。
- 记录 `+0x1E` 非零。
- 记录 `+0x26` 为零。

函数以记录 `+0x8A`、`+0x8C` 调用 `0x00431A20`，取得包含宽高的对象；随后把角色位置、对象偏移和镜头偏移组合成屏幕矩形，并用：

- `[0x004A9924]`：当前鼠标 X。
- `[0x004A9928]`：当前鼠标 Y。

进行严格矩形命中测试。

命中后：

- 记录 `+0x10` 的位 `0x20` 非零时，不改变交互光标。
- 其他情况写 `[0x004ACD20] = 9`。
- 若记录 `+0x10` 的位 `0x40` 非零，再改写为十，并阻止后面的地图事件触发路径。

这里确认的是数值和控制作用，不把九、十直接命名成具体光标图案。

## 3. UI 点击优先于世界交互

内部位编号九为零、`[0x004C8BEC]` 非空且受控角色状态允许时，函数调用 `0x0040DB60`。

`0x0040DB60` 遍历从 `[0x004C8BEC]` 开始的单链表，用当前鼠标坐标与节点中的四个 16 位边界作矩形命中测试：

- `EAX` 返回零基命中序号。
- 输出参数返回命中节点；未命中时为零。

命中节点时：

1. 把序号写入 `[0x004CAE7C]`。
2. 要求 `[0x004B7DA0] != 0` 且 `[0x004B7DAC] == 1`。
3. 调用 `0x0040DBC0` 释放整个矩形链表。
4. 清零 `[0x004B7DA0]`、`0x004B7DA4`、`0x004B7DA8`、`0x004B7DAC`。
5. 立即返回，不再触发 NPC 或地图 Talk。

因此 UI 命中和激活在同一帧中优先消费世界点击。

## 4. NPC Talk 触发

存在鼠标命中的 NPC 时，还必须满足：

- 命中索引有效，且不是当前受控角色。
- `[0x004B72C4] == 0xFFFF`，即没有活动 Talk 上下文。
- NPC 记录 `+0x26` 为零。
- `[0x004B7DA0] != 0`。
- `[0x004B7DAC] == 1`。

通过门控后：

1. `0x0040E030` 根据 NPC 与受控角色的位置计算八方向值。
2. 若 NPC 的记录位 `0x00000800` 非零，保存其旧动作/朝向字段，并让 NPC 转向受控角色。
3. 受控角色转向 NPC；两个方向都经 `0x004321E0` 重建动作记录。
4. 把 NPC 的坐标、标志、Talk 编号、上下文字段等复制到 `0x004B72A4` 起的剧情状态。
5. 清零四个点击/激活全局。
6. 以 NPC 的 16 位 `+0x24` 字段调用 `0x0040C020`，反查对应角色记录索引。
7. 立即返回。

原汇编中的诊断字符串为：

```text
RoleEvent.GUID[%d].Talk[%d].Ridx[%d]
```

它与字段来源共同证明这条路径是角色事件 Talk 触发，不是普通移动。

## 5. 地图格事件 Talk

没有进入 NPC Talk 时，函数可按鼠标位置检查地图格事件。

门控包括：

- `[0x004B72C4] == 0xFFFF`。
- NPC 扫描没有设置禁止地图事件的局部量。
- 受控角色 `+0x48` 为零或 `0x34`。

函数把鼠标坐标与镜头偏移相加后右移四位，即按 16×16 地图格定位；再用 `[0x004B7930]` 作为行跨度，从 `[0x004B7948]` 指向的格数据读取低八位事件编号。

事件编号非零时：

1. `0x0040DC30` 从 `[0x004ACAC0]` 链表按编号查找事件记录。
2. 取事件记录 `+0x0C` 的低 16 位调用内部位查询 `0x0040DC50`。
3. 通过后写 `[0x004ACD20] = 11`。
4. 再等待 `[0x004B7DA0] != 0` 且 `[0x004B7DAC] == 1`。
5. 把事件记录 `+0x08` 的低 15 位写入 `[0x004B72BE]`。
6. 把 `[0x004B72C4]` 写成特殊哨兵 `0xFFFD`。
7. 把鼠标对应位置按 16 像素对齐后写入剧情坐标。
8. 让受控角色朝向点击位置并重建动作。
9. 写 `[0x004A9920] = 0x8000` 后返回。

诊断字符串 `MapEvent.Talk[%d]` 进一步确认这是地图事件 Talk 入口。

## 6. 八方向和边缘状态更新

未触发 Talk 时，函数调用：

```text
0x00411E20 → 根据两个点计算距离和量化角度
0x00411F00 → 把量化角度映射为 0..7 的八方向值
```

若 `[0x004ACD20]` 当前为十三，就用该八方向值覆盖它。

只有受控角色 X/Y 都按 16 像素对齐、`[0x004A9920] == 0`、`[0x004B7D90] != 0` 且目标距离至少为十六时，才按方向组合把 `[0x004B7D90]` 写入四个方向相关全局之一：

- `0x004B7CF0`
- `0x004B7D10`
- `0x004B7CE0`
- `0x004B7D00`

这些全局的最终业务名需要结合移动消费点再确认。

## 7. 延迟点击状态

函数末尾在 `[0x004ACF48] != 0` 且 `[0x004B7CC0] == 0` 时，把：

```text
0x004B7DA0..0x004B7DAC
```

四个双字复制到：

```text
0x004B7CC0..0x004B7CCC
```

这证明存在一组延迟/备份点击状态，但在全部写入和消费点复核前不固定更具体名称。

## 8. 已确认语义名

P2 语义名：普通世界鼠标命中、UI 点击消费、NPC/地图 Talk 触发与方向更新入口。

重写约束：

- UI 点击消费必须先于 NPC 和地图交互。
- NPC Talk 优先于地图格 Talk。
- Talk 活动哨兵 `0xFFFF` 和地图事件哨兵 `0xFFFD` 必须保持区别。
- 点击触发、角色互相转向、剧情状态写入发生在同一调用中。
- 角色记录步长固定为 216 字节；字段布局仍以 P2.4 为准。
