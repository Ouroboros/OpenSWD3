# 战斗资源双层帧绘制 `0x00450530`

状态：`platform_adapted`、`unit_tested`、`fixed_state_tested`。

## 1. 范围、ABI与调用图

权威LST完整范围为`0x00450530..0x004505AA`，从`proc`到`endp`共68行，没有外部`FUNCTION CHUNK`。

cdecl四参数依次为资源号、目标X、目标Y、第二层显式宽度。四个caller位于`0x0045A1F2`、`0x0045A40C`、`0x0045A6AA`和`0x0045A8D8`。

callee只有帧查询`0x004315D0`两次和软件blitter`0x004170E0`一至两次，均已关闭并由typed接口直接组合。

## 2. 第一层固定0号帧

函数保存资源号与入口X/Y，先固定查询0号帧：

1. 发布帧记录与源；
2. 读取记录`+4`尾参数；
3. 按记录u16宽高；
4. 以入口X/Y、`flags=0`绘制一次。

第一遍blitter正常返回时，其公共后缀已经清理单次请求、RGB和跳行状态，并保留跨调用放大位。第二遍不得重新使用入口效果snapshot；它观察第一遍返回后的共享状态。

第一遍在帧记录或blitter实际访问点typed-stop时，后续1号帧查询与绘制均被阻断，并保留第一遍故障前缀。

## 3. 第二层必查1号帧、条件绘制

第一遍正常返回后，函数固定查询同资源的1号帧，并在检查第四参数之前发布新帧记录与新源。

- 第二层宽度为0：正常结束，1号帧record/source发布保留，不读取记录tail或高度，不绘制。
- 第二层宽度非0：读取1号帧tail和u16高度，以入口X/Y、入口宽度、帧高度和`flags=0`绘制。

LST使用`test ecx; jz`，只跳过严格等于0；负宽度不是早退。为避免把已关闭`0x00450490`的signed `jle`语义误用于本函数，typed组合必须为本包装单独保留“非零即调用”的门。

第二层正常返回再次执行公共后缀；第二层typed-stop保留第一层已绘制像素、第一层公共后缀结果及第二次帧记录发布。

## 4. 双向追溯

- `0x00450530..0x0045056A`：资源snapshot、0号帧查询/发布及完整记录尺寸绘制；
- `0x0045056F..0x0045057E`：固定1号帧查询、记录与源发布；
- `0x00450584..0x0045058D`：入口第四参数严格零门；
- `0x0045058F..0x0045059F`：1号帧tail、高度、入口宽度和同坐标绘制；
- `0x004505A4..0x004505AA`：栈与保存寄存器恢复。

C++组合的首层资源帧接口对应前半段；第二层显式宽度接口仅用于查询/发布与绘制机制，包装层负责将原严格零门与其内部边界区分。结果计数只记录真实查询与绘制前缀，不冒充旧返回值合同。

完整正向和反向追溯没有未解释基本块、参数、共享写、callee或出口。

## 5. 验证与动态差分

定向测试覆盖：

- 查询顺序固定为同资源0号、1号帧；
- 首层效果状态作用后由公共后缀清零，第二层以清理后状态覆盖一列并保留另一列首层像素；
- 第二层宽0仍查询并发布1号帧，只绘制首层；
- 首层帧缺失阻断第二次查询；
- 第二层帧缺失保留首层像素与旧source snapshot，同时发布失败的1号帧记录。
