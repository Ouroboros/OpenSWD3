# `0x00439C20..0x00439DDD` 未调用 LZO1X 快速解压变体

## 1. 实际边界

## 3. 汇编行为

物理接口与活动解压器相同：源指针、32 位源长度、目标指针和实际输出长度指针，cdecl 返回 EAX。它识别相同的 LZO1X literal、M2、M3、M4、低两位尾 literal 和 `11 00 00` 结束流。

关键区别不是格式，而是复制策略和结束检查：

- `0x00439C66..0x00439C83` 用 DWORD 超前复制 literal，再按低两位回退源和目标逻辑指针。
- `0x00439C98..0x00439C9C` 的 literal 后三字节短 match 实际写一个 DWORD，但输出逻辑位置只前进三。
- `0x00439CF6..0x00439D0A` 对距离至少三的 match 按 DWORD 超前复制，再把逻辑输出位置设回精确长度。
- `0x00439D30..0x00439D38` 只在近距离重叠时改用逐字节复制。
- `0x00439D80..0x00439D9B` 的 match 状态短分支复制两字节。
- `0x00439DA0..0x00439DDD` 除了按输入消费位置返回 `0/-8/-4`，还在输入恰好结束时要求结束 token 对应的内部长度值为 6，否则返回 `-1`。活动 `0x004399E0` 没有这一额外返回分支。

这些 DWORD 路径会读写逻辑范围之后最多三个字节。后续 token 通常覆盖超前写入，但最后一个 match 后的目标尾部仍可能留下报告长度之外的写入；因此即使合法流的报告输出相同，也不能用该函数解释活动调用者的物理内存行为。

## 4. 逐基本块映射

- `0x00439C20..0x00439C66`：入口、初始 token 和普通 literal 长度。
- `0x00439C66..0x00439CA0`：DWORD literal 复制、逻辑回退和 literal 后短 match。
- `0x00439CA0..0x00439D24`：M2/M3 主分支、扩展长度和尾 literal 状态。
- `0x00439D30..0x00439D9B`：近距离逐字节复制、M4 和 match 状态短分支。
- `0x00439DA0..0x00439DDD`：结束 token 校验、实际输出长度和 `0/-1/-8/-4` 返回。

## 5. 实现判定

该函数不影响当前二进制的任何可观察行为，所以不新增 C++ 公共入口或运行时代码。活动 `0x004399E0` 已由 `decompress_legacy_lzo1x` 单独实现和验证；拿现有实现冒充本函数会丢失 DWORD 超前写和 `-1` 返回差异，复制第二份不可调用实现则只会制造虚假的维护范围。
