# SWD3 原程序架构基线

状态：A1 完成基线

证据版本：`swd3.exe` SHA-256 `0bac897a7557735b22607d8c8f0a79a3e7ae7729deb56593fd91c21e10baee0c`

## 1. 范围与真值规则

本文只恢复足以开始模块化实施的程序骨架：进程入口、初始化、消息泵、单帧调度、普通世界、特殊模式、战斗、保存/读取、视频/暂停和退出。模块内部算法不属于 A1。

**完整汇编是唯一行为真值。** IDA 反编译 C 伪码、函数名、字符串和既有文档只能用于导航；与汇编冲突时一律以汇编的指令、跳转、调用顺序、整数宽度和副作用为准。

本文中的模块是原程序的逻辑职责分区，不声称旧 EXE 本身采用了这些源码目录或类层次。它们为 A2 函数归属提供稳定候选；只有后续汇编证据证明边界错误时才允许调整。

## 2. 模块骨架

| 模块 ID | 主责 | 顶层入口或根函数 | 明确不负责 |
|---|---|---|---|
| `runtime_platform` | PE/CRT 之后的应用生命周期、窗口/事件泵、启动和退出编排、显示激活、单帧门控与互斥模式调度 | `0x0048A740`、`0x00409EC0`、`0x0040A0D0`、`0x0040A570`、`0x0040AB50`、`0x00424B90`、`0x004251B0` | 不实现世界、剧情、菜单、战斗或存档业务 |
| `resource_io` | 工作路径、文件/映射/内存包装、公共解压、原始数据库和资源容器的字节访问 | `0x00425040`、`0x00438000..0x00438640`、`0x004399E0` | 不解释游戏玩法字段，不决定画面模式 |
| `input_time_rng` | 设备采样、旧输入记录归一化、帧时钟、阻塞/让出规则和两套随机序列 | `0x00436FB0`、`0x004372B0`、`0x004050E0`、`0x00438FA0`、`0x00489B10` | 不把按键解释成世界、菜单或战斗操作 |
| `rendering` | 640×480 16 位软件帧缓冲、像素格式、blitter、文字、效果和分支内最终提交 | `0x00416D30..0x00423400`、`0x00435240..0x00436F66`、各分支 `Blt` 点 | 不选择当前游戏模式，不推进业务状态机 |
| `audio_video` | Miles 音频建立/播放/维护、Bink 打开/等待/解码/结束和活动媒体门控 | `0x0040CDD0`、`0x0040CF10`、`0x00484550..0x00486900` | 不拥有 SND/ANI 的玩法引用关系，不推进剧情 |
| `asset_runtime` | TSW、ACT、ANI、SND 的容器解释、缓存、帧/动作数据和公共 action 记录 | `0x004315D0`、`0x004321E0`、`0x00432A50` 及相应加载/动作函数簇 | 不决定场景、角色 AI 或音视频设备生命周期 |
| `story_scene` | Talk/剧情 VM、场景指令、同帧继续、跨帧等待和异步 action 协调 | `0x00427920` | 不拥有底层文件、像素、音频设备或地图碰撞实现 |
| `world_map` | 地图装载与运行态、角色、普通世界交互、移动、碰撞、寻路和世界画面协调 | `0x00427300`、`0x00402F80`、`0x004120B0`、`0x00425BE0..0x00427140` | 不解释剧情 opcode，不执行最终平台提交 |
| `special_modes` | 高优先级画面状态、游戏内菜单、商店及数字模式 `1..6` 的业务状态机 | `0x00406E30`、`0x00439FD0`、`0x0044EA60` | 不序列化存档，不拥有通用输入和渲染底层 |
| `battle` | 战斗请求消费、实例建立、战斗脚本/帧状态机和四值结果合同 | `0x00451B10`、`0x00469D20`、`0x00453200` | 不负责顶层消息泵和战后模式的最终调度 |
| `persistence` | 启动存档扫描、存档槽预览、保存/读取状态机、配置和持久数据装卸 | `0x00409C10`、`0x00409600`、`0x004070A0` | 不取得剧情、世界和战斗状态的业务所有权 |

平台 API、CRT 和第三方库不是以上游戏模块。A2 将另外记录 `code_origin = game / crt / third_party / unknown`；`unresolved` 只表示尚不能归属，并且必须带后续负责模块，不能成为永久杂物箱。

## 3. 进程启动与初始化

### 3.1 进程入口

```text
PE/CRT 0x0048A740                         [runtime_platform]
  → Windows/CRT/argv/env 初始化
  → WinMain 0x00409EC0                    [runtime_platform]
      → 重复窗口检查；命中则返回 0
      → 非空命令行特殊路径；处理后返回 0
      → COM、窗口类和 640×480 窗口建立
      → 同步 SendMessage(0x404)
      → 两次独立 time(NULL) 初始化两套 RNG [input_time_rng]
      → 消息泵
```

两次 `time(NULL)` 是两个调用，不能合并为同一个种子采样。`GetMessageA` 只测试是否为零，`-1` 会被当作普通非零消息继续翻译和分发。

### 3.2 自定义消息 `0x404`

窗口过程按固定顺序执行：

1. 播放启动资源音效，并由 `0x00424390` 初始化 16 个默认按键 dword。
2. `0x00425040` 建立基础路径和 `Save/Data/Music/ScrnShot/Video` 目录（`resource_io`）。
3. `0x00409C10` 扫描槽 `0..98`，只把“是否存在至少一个存档”写入启动位（`persistence`）。
4. 打开模态启动对话框；数字返回值由 `runtime_platform` 原样分支，当前不为全部数值强加业务名。
5. 返回 `1` 或 `2` 都调用 `0x00424910 → 0x00424B90`；返回 `1` 还建立高优先级存取档路径的状态，返回 `6` 同步发送 `WM_DESTROY`。

### 3.3 总初始化 `0x00424B90`

模块级顺序如下；同一行内部仍以汇编调用次序为准：

```text
建立窗口句柄、帧抑制和计数初值；隐藏光标                  [runtime_platform]
  → DirectInput                                            [input_time_rng]
  → Miles 音频对象                                         [audio_video]
  → DirectDraw 独占显示、公共 source surface、Bink 目标     [rendering + audio_video]
  → 鼠标坐标/范围和音频路径                                 [input_time_rng + audio_video]
  → 软件绘图内核与可用内存检查                             [rendering + resource_io]
  → 资源/数据库预备                                        [resource_io]
  → framebuffer 锁定、像素表、三套字体、显示矩形           [rendering]
  → 帧间隔设为 35                                           [input_time_rng]
  → Talk 缓冲、maps 数据、公共列表和游戏状态默认值          [story_scene + world_map + asset_runtime]
  → [0x004B8740] = 0x80000003                               [special_modes]
```

初始化失败不是统一事务回滚。`0x00424EF0` 的 DirectInput 或 DirectDraw 失败会同步发送 `WM_DESTROY` 并返回零，但 `0x00424B90` 不检查该返回值，仍继续后续指令；软件绘图内核失败则直接发送 `WM_DESTROY` 后返回。初步重写不得把这些差异悄悄改成统一“安全失败”，启动兼容例外必须隔离在平台层并另行验证。

## 4. 消息泵与帧入口

消息队列非空时只执行 `GetMessage → TranslateMessage → DispatchMessage`。队列为空时按以下优先级选一条路径：

```text
全局帧执行门为开
  ├─ 视频位 0x20：解码/呈现一帧视频 → Miles 维护           [audio_video]
  ├─ 抑制位 0x01：Sleep(0)                                 [runtime_platform]
  ├─ 过渡抑制非零：Sleep(0)                                [runtime_platform]
  └─ 0x0040A570 单帧                                       [runtime_platform]

全局帧执行门为关
  ├─ 显示有效：反复绘制并呈现暂停提示                       [rendering]
  └─ 显示无效：Sleep(0)                                    [runtime_platform]
```

因此视频、F8 暂停和正常游戏帧互斥。暂停期间不采样游戏输入、不推进逻辑时钟、世界、剧情或战斗，但暂停提示会在空闲循环中反复呈现。

## 5. 单帧精确骨架

一次 `0x0040A570` 调用并不必然形成有效游戏帧：

```text
入口位/显示门控
  → time(NULL)
  → timeGetTime，按无符号 32 位 elapsed 与 interval 比较
  → 接受帧后 previous = now；不补帧、不保留余量
  → 倒计时和内部位迁移
  → 设备状态采样
  → 旧输入记录归一化
  → 三选一：
      A. 高优先级模式
      B. 战斗请求/战斗活动
      C. 普通世界或特殊模式
  → 未提前返回的路径执行 Miles 维护
  → 未提前返回的路径把关闭位转换为同步 WM_CLOSE
```

帧间隔未到时直接返回，不 `Sleep`。默认间隔是 `35` 毫秒，剧情已确认可切换为 `70`，零值意味着每次调用都可通过；比较和回绕必须保持模 `2^32`。

### 5.1 高优先级模式

当 `[0x004CAEB0] != 0`：

1. `runtime_platform` 跳过战斗请求、战斗、世界和剧情。
2. `special_modes::0x00406E30` 推进自身计数和输入状态。
3. 子状态 `[0x004CAEBC] == 0` 调用 `0x00406F70`；等于 `1` 调用 `persistence::0x004070A0`；其他值不调用两者。
4. 状态仍非零时经 `0x00408CF0` 分支内呈现。
5. 返回顶层公共 Miles 维护和关闭检查。

`0x00406EB0` 的特定输入路径在切换子状态前执行 `Sleep(500)`，会阻塞整个单线程泵；这不是异步菜单延迟。

### 5.2 战斗请求与活动战斗

只有高优先级模式未占用时才检查战斗。带最高位的请求值经门控后：

```text
关闭当前地图映射
  → battle::0x00451B10(低 16 位战斗编号)
  → 设置战斗活动门控
```

战斗活动时调用 `battle::0x00469D20`，随后立即执行 Miles 维护。返回值合同严格为：

| 返回值 | 顶层结果 |
|---:|---|
| `1` | 保持战斗活动，立即结束当前帧 |
| `0` | 清活动状态，恢复/重载地图，立即结束当前帧 |
| `2` | 清活动状态，请求特殊模式 `0x80000004`，立即结束当前帧 |
| `3` | 清活动状态，重映射/恢复地图，立即结束当前帧 |

四条战斗出口都不会在同帧继续世界、剧情，也不会到达普通公共关闭检查。战斗 handler 的等待通过“不推进当前指令并返回 `1`”实现，不得改成一次调用跑完整场战斗。

### 5.3 普通世界

无活动战斗时先处理背景音乐请求，然后当 `[0x004B8740] == 0` 执行：

```text
world_map::0x00427300      鼠标/UI/NPC/格事件交互
  → world_map::0x00402F80  玩家控制、移动/碰撞、菜单与遇敌协调
  → 五项门控全部允许时：
      story_scene::0x00427920
        → world_map/rendering 的对象更新、世界绘制和分支内呈现
  → 公共 Miles 维护
  → 关闭检查
```

剧情 VM 每个 handler 自己决定 IP 推进。两个继续量任一非零时同帧继续取指；两者都为零时调用 `AIL_serve` 并返回到下一帧。故事返回值不驱动顶层，实际效果来自状态块和全局请求。

### 5.4 特殊模式

`[0x004B8740] != 0` 时，世界和剧情整条跳过：

| 低 28 位模式 | 入口 | 主责模块 | 呈现 |
|---:|---|---|---|
| `1,3,4,5,6` | `0x00439FD0` | `special_modes` | `0x0043A610 → 0x0043A854` |
| `2` | `0x0044EA60` | `special_modes` | `0x0044F765` |
| 其他 | 无模式入口 | `runtime_platform` 只保留原分派结果 | 无上述提交 |

模式入口自行处理一次性请求位、输入、回调、绘制和提交。商店在输入使模式变为零或跳往模式一后会提前返回，不再提交旧商店画面；顶层仍继续公共音频维护与关闭检查。

## 6. 保存与读取顶层路径

保存/读取不是普通世界中的附加系统，而是高优先级互斥路径：

```text
启动对话框或游戏内生产者写高优先级状态
  → runtime_platform 在有效帧先选择高优先级分支
  → special_modes::0x00406E30
  → [0x004CAEBC] == 1
  → persistence::0x004070A0
      → 三连槽预览 persistence::0x00409600
      → 槽选择、保存或读取、状态恢复
  → high-priority 分支内呈现
  → 世界、剧情、特殊模式和战斗本帧均不执行
```

`0x00409600` 的正常机器返回恒为零；槽缺失/成功分别写预览记录 `+0x30 = 1/2`。`0x004070A0` 没有稳定返回值，唯一调用者不读取。重写可在内部使用明确类型，但不得让新返回值改变旧状态机行为。

存档负责物理容器和装卸编排；剧情位、世界对象和战斗数据的业务所有权仍属于各自模块。完整字段语义留到对应模块闭环，不延长 A1。

## 7. 呈现、等待、互斥与提前返回

### 7.1 呈现边界

原程序没有统一帧尾 `Present`。稳定顶层提交点是：

| 路径 | 提交地址 |
|---|---:|
| 高优先级 | `0x00408D5E` |
| F8 暂停 | `0x00412046` |
| 普通世界 | `0x00412716` |
| 特殊模式 `1,3,4,5,6` | `0x0043A854` |
| 商店模式 `2` | `0x0044F765` |
| 战斗 | `0x0045350A` |
| Bink 视频 | `0x00484A11` |

OpenSWD3 可以把平台提交统一到 SDL3 接口，但调用时点必须仍由各互斥分支决定。`0x0040CF10` 是 Miles 对象维护，不是呈现。

### 7.2 全局关系表

| 条件或动作 | 是否阻塞线程 | 是否推进正常游戏帧 | 提前返回/互斥结果 |
|---|---|---|---|
| 消息队列非空 | 由 Win32 分发决定 | 否 | 本轮不调用游戏帧 |
| 帧执行门关闭 | 否 | 否 | 暂停提示或 `Sleep(0)` |
| 显示无效/过渡抑制 | `Sleep(0)` 或直接返回 | 否 | 世界、剧情、战斗均不执行 |
| 帧间隔未到 | 否 | 否 | `0x0040A570` 直接返回 |
| 高优先级模式 | 部分输入分支 `Sleep(500)` | 只推进该模式 | 排除战斗、世界、剧情、特殊模式 |
| 战斗活动 | handler 可跨帧等待 | 只推进战斗 | 所有结果都在世界前返回 |
| 剧情让出 | 否；调用一次 `AIL_serve` | 已接受当前世界帧 | 返回顶层，下一有效帧重入 |
| 视频活动 | Bink 自己判定是否可推进 | 只推进视频和音频维护 | 排除整个正常单帧入口 |
| 显示恢复 | 旧实现循环恢复/Blt/Flip | 否 | 恢复完成前不进入正常帧 |
| 初始化容量提示 | `Sleep(1024)` | 尚未进入消息泵 | 提示后继续初始化 |

## 8. 失焦、恢复与退出

`0x0040AB50(0)` 的模块级顺序是音频停用/维护、战斗显示停用、三套字体资源释放、显示门清零、过渡抑制置一和隐藏窗口。`0x0040AB50(1)` 先恢复窗口与 surface，再重建三套字体、解除抑制、恢复战斗显示、循环完成显示对象恢复，最后把帧间隔设回 `35`。它不重新初始化或 Acquire DirectInput。

通常退出路径：

```text
子系统设置关闭位 0x04
  → 未提前返回的单帧尾同步 SendMessage(WM_CLOSE)
  → DefWindowProc 销毁窗口
  → WndProc: WM_DESTROY
      → 条件满足时 0x004251B0 总释放
      → CoUninitialize
      → PostQuitMessage(0)
  → GetMessage 返回 0
  → WinMain 返回 msg.wParam
  → CRT _exit
```

启动、图形、地图或 Talk 的若干错误路径会绕过关闭位转换，直接同步发送 `WM_DESTROY`。`WM_DESTROY` 是否调用总释放取决于内部初始化位或关闭位；因此部分初始化不能假设所有模块都已建立。

`0x004251B0` 的固定释放阶段为：字体资源；模式/战斗/游戏对象；链表和缓存；音频；公共 source surface 与显示包装；输入对象；角色、路径、Talk 和像素文件/映射；公共堆缓冲与链表；最终绘图状态和光标。A2 再把其中每个调用机械归属，A1 不提前猜测未确认的私有对象名。
