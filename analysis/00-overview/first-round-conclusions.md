# 首轮调研结论

更新日期：2026-08-02

## 0. 证据原则

汇编是原程序逻辑的唯一真实依据。

IDA 伪码只用于定位和辅助理解。所有类型、参数、分支、符号扩展、调用约定和数据流结论都必须回查汇编；发生冲突时，无条件以汇编为准。

字符串、真实资源和动态运行结果用于解释与验证汇编，不用于覆盖汇编逻辑。

## 0.1 1:1 行为与 BUG 政策

初步还原要求 bug-for-bug 的 1:1 行为兼容。

- 原程序的游戏逻辑 BUG 属于已定义行为，不修复。
- 玩法、数值截断、整数溢出、随机调用顺序、帧内调用顺序、脚本等待规则、资源边界和存档语义都以原汇编为准。
- 只有阻断启动或新系统兼容的平台问题允许最小修正。
- 例外必须留在平台适配层，记录原行为、修正原因和差分验证，并证明不改变正常游戏路径。

内部可以用 RAII、强类型和模块化替代旧架构，但这些只是实现手段，不是修正原行为的授权。

## 1. 可行性

结论：有条件可行。

这里的“可行”不是把 IDA 伪码批量翻译后重新编译，而是以原 EXE 为行为基准，重新实现一个读取原始游戏资产的新引擎。

有利条件：

- EXE 没有加壳迹象，代码段和导入表都能正常分析。
- IDA 共识别 1486 个函数；1202 个已有伪码或汇编文件。
- 只有 5 个函数因过大或反编译失败而退回独立汇编。
- 启动入口、主循环、窗口过程、文件映射、DirectDraw、DirectInput、Miles、Bink 等边界已经定位。
- 原游戏大部分内容位于外部数据文件，不在 EXE 资源段中。
- 已找到通用解压函数。控制流高度符合 LZO1X 解压算法。
- 原始渲染核心是固定 640×480 的 16 位软件帧缓冲，现代化显示层可以与游戏逻辑隔离。

限制条件：

- 绝大多数业务函数没有语义名称。
- 伪码中的类型、结构体边界和有符号性不能直接信任。
- 程序使用大量全局状态，剧情、地图、角色和战斗之间耦合很强。
- 两个最关键的大函数只有汇编：
  - `sub_427920`：23508 字节、6304 行汇编；从调用关系和字符串判断，它是剧情/场景指令解释核心，并包含自定义 `.Ani` 打开流程。
  - `sub_469D20`：16918 字节、4677 行汇编；它由主循环在战斗状态调用，是战斗更新核心。
- 静态分析只能证明“代码路径存在”，不能证明帧时序、随机数、输入边沿和所有异常分支的实际行为。

因此，100% 行为兼容使用以下证据体系：

1. 逻辑真值：逐指令汇编、调用约定、寄存器、栈和内存访问。
2. 辅助静态证据：IDA 伪码、字符串、导入表和数据引用。
3. 数据证据：真实资源和存档样本。
4. 动态验证：原程序运行结果、截图、状态变化和输出文件。

## 2. 语言结论

首选 C++20。

原因：

- 原程序本身是 Visual C++ 时代的 C++ 程序，存在 `thiscall`、构造/析构和 C++ 异常运行库痕迹。
- 需要精确处理二进制布局、位域、16 位像素、压缩流和大量索引表。
- SDL3 与 FFmpeg 都提供稳定的 C 接口，C++ 可直接接入。
- C++ 可以在保留低层控制的同时，用 RAII、值类型和测试隔离掉原程序的大量裸指针与全局状态。
- 相比直接用 C，长期维护和模块边界更容易控制。

Rust 是可行的第二选择，但对当前这种“先快速恢复未知二进制语义，再逐步收紧类型”的任务，迭代成本会高于 C++。

## 3. 技术路线结论

建议的基础组合：

- C++20
- CMake
- SDL3：窗口、输入、计时、音频输出和最终画面呈现
- FFmpeg：`.bik` 与 `.mp3` 解码候选
- 自研兼容层：`.Ani`、`.tsw`、`.act`、`.snd`、`.lmf`、`.dat`、`.sav`
- 单元测试加原程序差分测试

渲染第一阶段不应直接重做成现代 3D/GPU 管线。

原程序反复操作 `0x96000` 字节缓冲区；该值正好等于 `640 × 480 × 2`。大量函数又以 `0x4B000` 为像素数量；该值正好等于 `640 × 480`。

因此最稳的兼容方案是：

1. 先复原 16 位 CPU 软件帧缓冲及其像素运算。
2. 每帧将结果转换为 RGBA8888。
3. 用 SDL3 流式纹理按整数倍或保持宽高比显示。

这样可以把颜色、半透明、文字、遮罩和战斗特效的兼容问题留在可验证的软件渲染层内。

- `0x4380B0` 一带：统一文件对象、映射和读写

- `0x4315D0`：`.tsw` 资源入口

- `0x425BE0`：`huge.lmf` 地图入口
- `0x4859B0` 一带：Miles 音频初始化与音效播放
- `0x484550` 一带：Bink 初始化、打开、逐帧解码和关闭
- `0x427920`：剧情/场景指令解释核心，包含 `.Ani` 打开路径

## 5. 当前最大风险

按优先级排序：

1. 剧情指令解释器 `sub_427920`。
2. 战斗状态机 `sub_469D20`。
3. `.Ani` 自定义视频格式。
4. `.tsw` 图像资源的像素格式、压缩和动作关联。
5. `huge.lmf` 地图索引与分块数据。
6. 存档完整结构和压缩块边界。
7. 原程序以 busy poll、`timeGetTime`、按接受帧计数、显式 Sleep 和 Miles `AIL_serve` 共同形成的时序；当前 EXE 没有多媒体 timer callback API。

## 6. 当前不能下结论的事项

- `.tsw` 的最终像素格式是固定 RGB555、RGB565，还是两者可转换。
- `.Ani` 头部每个字段的完整语义和帧压缩算法。
- 剧情指令总数、每条指令长度和阻塞/异步规则。
- 战斗随机数调用顺序是否必须逐次一致。
- 所有存档版本是否只有一个格式。
- `swd3.exe`、`swd32.exe`、`swd3_fs.exe` 的逻辑差异。

这些内容在证实前只列为待验证项。
