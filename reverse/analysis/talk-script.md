# 剧本指令（Talk<n>.dat，解释器 0x00427920）

依据：0x00427920 的反编译与汇编（`reverse/analysis/decomp/00427920.c`、`asm/00427920.asm`），还原见 `src/talk/talk_event*.cpp`。本文是格式参考，逐函数验证结论以 `reverse/evidence/` 为准。

## 文件与载入

- 事件号 `e` 位于 `Talk<e / 2000 + 1>.dat`。文件头后 0x200 起是 2000 个 dword 偏移表：事件 `e` 的偏移在 `0x200 + 4 × (e % 2000)`。剧本从 `偏移 + 0x200` 读 0x8000 字节到 0x004B8860（先用 0x0C 填满）。
- 运行中的事件由 leader（0x004B72A0，Role 结构）表示：`+0x14` 剧本偏移（0 表示尚未载入）、`+0x1E` 事件号、`+0x20` 当前字节偏移（u16）、`+0x24` 事件角色 id（0xFFFF 无事件，0xFFFD 地图区域事件）。
- 首帧须控制角色站在格子上才载入；事件角色加 flag 0x80000；`scene.unk4A9920 |= 0x8000`（玩家锁定）。
- 跳转（下表“跳 d”）调用 0x0042E430：从文件 `剧本偏移 d + 0x200` 重读 0x8000 字节，偏移归 0。

## 执行规则

- 每条指令以字开头，指令号 = 字 & 0x3FFF。所有操作数为 16 位小端字，除非标为 dword。
- 每条指令返回“继续”或“等待”。等待时本帧结束，下一帧从 `+0x20` 继续。0x400 与 0x401 之间的指令无论返回什么都在同一帧继续。
- 解释器有两个游标：读指令的指针与 `+0x20`。通常同步，但 0x23 跳转后读指针不归零、0x24 跳转后两者各再加 8（原 BUG，已保留）。
- 角色号 0xFFF0 代表事件角色；带 * 的指令中 0xFFF0 改指控制角色的**索引**（0x004AB378，原 BUG）。0xFFFE 代表控制角色。
- 找不到角色时多数指令改写 maps.dat 中该角色的记录（0x0040D460），见各条。
- 未知指令：蜂鸣，停在原处（每帧重复）。
