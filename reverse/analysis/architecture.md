# 代码架构（GOAL 版本 3）

2026-10-16 用户决定重建代码架构。原因：旧实现把汇编逐句写成 C++，使用自动生成的全局结构 `G`（`dword_XXXX` 占位名）、按原地址排布的数据镜像和 `mem::u16(item, 0x5E)` 式数字偏移访问，没有还原数据结构与模块接口，不符合 AGENTS.md 的结构要求。旧实现保存在 git 标签 `legacy-transliteration`，仅作逻辑参考，不再参与构建。

## 代码组织

- 每个原模块是一个 C++ 类或一组相关类型，放在 `src/<模块>/`，用 `.h`／`.cpp` 组织，命名空间 `swd3`。原程序有类名证据的沿用其职责划分（日志字符串中的 `Menu::`、`Botl::`、`MemMgr` 等）。
- 原程序的全局变量归入所属模块类的成员。不允许可写的自由全局变量、全局状态结构或数据镜像。
- 原程序的全局对象（如三个 TextFont、BattleRole[10]、BattleEnemy[8]）成为根对象 `Game` 的成员。子系统通过构造函数取得所依赖子系统的引用；单元测试可单独构造子系统。
- 原程序的静态初始化 thunk（`__xc` 表）对应 `Game` 成员的构造与析构顺序；函数表 source 指向对应的构造／析构代码。
- 数据记录（道具节点 0xB0、怪物数据、角色 0xD8、战斗单位 0x2B28 等）定义为带命名字段的 struct。含义未确定的字段在类型内以 `unkXX`（XX 为十六进制偏移）占位，并注明已知读写者。代码中不得按数字偏移访问记录。
- 原文件格式（MON.DAT、LEVEL.DAT、tsw、act、battle.ffd 等）由读取函数按字段解析到 struct，不依赖主机内存布局。
- 只读常量表（.rdata 与未被写入的 .data）放进所属模块，作为带类型的 `constexpr` 表。表由脚本从 swd32.exe 提取后人工命名，单元测试把表按原布局序列化并与 exe 字节比对，作为数据核对证据。可写全局的非零初值成为成员默认值，同样有比对测试。
- 函数指针表按原用途改写为虚函数、成员函数指针或枚举分派，例如菜单页面处理表写成页面类的虚函数。
- 游戏文本为 Big5 字节串，用 `std::string`／`std::string_view` 保存，不用 `char*`。源码中的文本常量以繁体 `u8"…"` 字面量（`std::u8string_view`）书写，用到时经 `Big5()`（CP950 表，src/text/big5）转成 Big5；格式化与文字绘制也接受 u8 文本并在内部转换。格式化保持原 `wsprintfA` 的输出。
- 动态内存用容器与 `std::unique_ptr` 管理。链表的遍历顺序和插入删除方式会影响可见行为（含原有逻辑 BUG），因此保留为显式链表类型，节点所有权明确。
- 常量、状态码、模式值、声音编号等写成具名常量或 `enum class`。

## 平台层（src/platform/）

不再模拟 Win32、DirectDraw、DirectInput、Miles 与 GDI 的 API。原程序对这些 API 的调用语义（色键 Blt、表面锁定、按键状态、音效与流音乐播放控制等）在游戏模块中以平台类的方法实现，只要求游戏可见行为一致。

- `Display`：SDL3 窗口。逻辑画面 640×480 RGB565，与窗口大小分离。窗口默认 1280×960，可用鼠标拉伸调整大小；画面按最近邻、任意比例等比缩放，不成原始比例时两侧（或上下）留黑边；Alt+Enter 切换无边框全屏；提供窗口坐标到逻辑坐标的换算，黑边内的坐标夹到画面边缘。
- `Surface`：游戏的离屏表面（原 DirectDraw 表面），即宽、高、行距、RGB565 像素与色键。
- `Input`：键盘与鼠标状态（原 DirectInput 设备与窗口消息），鼠标位置换算为逻辑坐标。
- `AudioDevice`：SDL3 音频输出与混音。
- `MediaDecoder`：FFmpeg（MP3、Bink 视频与音频）。
- `GlyphRasterizer`：中文字形栅格化。各平台都用自带字库 swd3font.bin（由用户提供的 mingliu.ttc 生成的完整 Big5 細明體 12/16/20 像素点阵），不依赖系统字体（用户 2026-10-16 要求）。
- `FileSystem`：游戏目录内的文件读取；POSIX 上按大小写不敏感查找。

## 与原程序的已知偏差

只允许下列类别，每一处都在 `reverse/analysis/deviations.md` 逐条记录函数地址、原行为和新行为：

1. 越界读写、破坏内存类 BUG 不复现（用户 2026-10-16 决定），按合理边界处理。
2. 读取未初始化内存：原值依赖 MSVC 调试堆填充或栈残留时，改为确定的初值。
3. 显示方式：窗口化、缩放与全屏切换（用户要求）。
4. 平台 API 替换：只保证游戏可见行为一致。

逻辑类 BUG（计算、分支、顺序、随机数消费、状态副作用）仍完整保留。

## 迁移规则

- 旧映射全部重置为 `pending_implementation`，source 清空；note 列记录旧实现符号，便于按标签查阅。
- 新实现按模块自底向上推进：核心与平台 → 文件与资源 → 绘图 → 字体、输入、音频 → 角色、地图、对话 → 战斗 → 菜单 → 主循环。
- 提交前检查：改动文件中没有 `dword_`／`word_`／`byte_`／`unk_` 形式的地址占位名，没有按数字偏移读写记录的代码。
